## 核心知识点(工程向,标注 来源 doc-XXXX)

<!--KB:NODE05-K01-->
1. **内置SQL提交(填报核心)**(来源 doc-3577):`<ReportWriteAttr>` 下 `BuiltInSQLSubmiter` + 平级多个 `<DMLConfig>`;多个内置 SQL 自上而下**串行且同一事务**,任一失败全回滚;ColumnConfig `isKey=true` 是 SQL where 主键(非库主键)、`skipUnmodified=true` = 未修改不更新;Oracle 等须带 schema。详见 ckzl/lc/05 §9.0。
<!--KB:NODE05-K02-->
2. **填报冻结**(来源 doc-611):`WorkBook.setWebAttr(ReportWebAttr)` + `setFreezeRow/setFreezeCol`(从首行/首列起算,不支持中间/尾行列);⚠ 冻结区**不可圈入可扩展数据单元格**(普通填报预览会把扩展出的全部数据都冻结,长表失去滚动意义),新填报预览只冻结指定行数;冻结区应只覆盖静态表头。详见 ckzl/lc/03 §3.6.2。
<!--KB:NODE05-K03-->
3. **JS 自定义提交按钮**(来源 doc-596):单元格按钮控件通过前端 JS `_g().verifyAndWriteReport()` 触发校验与提交入库,提交处理由服务端内置逻辑完成;**无 Java 构造落点**(按钮控件/事件 JS 属前端 UI 层)。详见 ckzl/lc/05 §12。
<!--KB:NODE05-K04-->
4. **JS 获取/赋值填报单元格值**(来源 doc-1207):预览期前端 API `_g().getCellValue(sheetIndex,col,row)` / `_g().setCellValue(...,value)`,发生在浏览器端 DOM/JS 引擎,**无 Java API 落点**;单元格与按钮控件骨架可经 com.fr.* 构建,但取值/赋值逻辑只能作为 JS 文本写入按钮事件。详见 ckzl/lc/05 §10.4。
<!--KB:NODE05-K05-->
5. **联动自动生成默认值**(来源 doc-1868):联动算法(FR.remoteEvaluate + setCellValue + setTimeout)是浏览器端 JS,Java 侧只能作为 script 文本写入「编辑后事件」节点;但模板骨架可构建:`ComboBox` + `FormulaDictionary`(实际值=sql 公式、显示值=`$$$`)+ `Listener(EDITED)` + `JavaScriptAction`;文档 2.5「关闭脚本调用公式限制」属平台安全管理配置,需另行在决策系统关闭;不支持移动端。详见 ckzl/lc/05 §11.2。
<!--KB:NODE05-K06-->
6. **新填报预览**(来源 doc-2194):`&op=write_plus` 是 HTTP 请求参数(由 Servlet 解析决定预览类型),**非模板属性、无 Java API 落点**;与普通填报预览(op=write)并存,异步加载样式。详见 ckzl/lc/05 §13。
<!--KB:NODE05-K07-->
7. **多级上报(工作流)= 第五类平台产物**(来源 doc-576/2365):写入模型是 **DAO/Controller 而非 Configuration**——`WorkflowContext.getInstance().getReportProcessController()/getProcessNodeController()/getProcessTaskController()`,bean 在 `com.fr.decision.workflow.bean`(Workflow/WorkflowNode/WorkflowTask);五个 Controller 接口**自身 0 声明方法,dump 出来是空表,不能据此判「无 API」**;禁止套 `Configurations.update`(那是 Configuration 模型);`WorkflowNode` 直接 extends BaseEntity(无 createEntity()),另外三个是 BaseDataRecord + createEntity() 双份;`fr_task_id/fr_task_name/fr_task_state/fr_task_sender` 四个 request 依赖内置参数由 `WorkflowBridge#addReportProcessParas` 注入,无头路径恒空 → 叠加过滤条件 IN 右值为空**恒假** → 全部数据被过滤(0 行),处置=手工把 fr_task_sender 以 List 塞进 paraMap。详见 ckzl/lc/05 §16。

## Java API 要点(com.fr.* 类名/方法/与 XML 对应)

1. **内置SQL提交类链**(来源 doc-3577):`com.fr.report.write.BuiltInSQLSubmiter`(`setDsName(String)`←`<Attributes dsName>`;`addDMLConfig(DMLConfig)`)+ `com.fr.write.config.DMLConfig` 抽象基类子类:`DeleteConfig`(删除,isKey=true)/`InsertConfig`/`UpdateConfig`/`IntelliDMLConfig`(智能:依主键自动 insert/update),共性 `setTable(Table)`+`addColumnConfig(ColumnConfig)`;`com.fr.write.config.Table`(`setSchema/setName`);`com.fr.write.config.ColumnConfig`(`setIsKey/setSkipUnmodified`,构造 `ColumnConfig(String name, ColumnRow)` 或 `(String name, Formula)`);`com.fr.base.ColumnRow(int column,int row)`;`com.fr.base.Formula(String)`(以 `=` 开头);`com.fr.report.write.ReportWriteAttr.setSubmitVisitor(BuiltInSQLSubmiter)` 挂到 WorkBook 报表的 ReportAttr;XML `<Report>` 下 `<ReportWriteAttr><SubmitVisitor class="com.fr.report.write.BuiltInSQLSubmiter"><Attributes dsName><DMLConfig ...>...`。
2. **填报冻结**(来源 doc-611):`com.fr.main.workbook.WorkBook.setWebAttr(com.fr.web.core.ReportWebAttr)`;`ReportWebAttr.setFreezeRow(int)/setFreezeCol(int)/setRepeatRowStart/setRepeatRowEnd/setRepeatColStart/setRepeatColEnd`;XML `<WebAttr>(或 <ReportWebAttr>)` 下 `<freezeRow>/<freezeCol>/<repeatRowStart>...` 子节点;落地 `com.fr.io.TemplateWorkBookIO.writeTemplateWorkBook(WorkBook,String)`。
3. **联动模板骨架**(来源 doc-1868):`com.fr.form.ui.ComboBox`(`setWidgetName`/`setDictionary(Dictionary)`)+ `com.fr.data.impl.FormulaDictionary`(valueFormula/showFormula,显示值恒 `$$$`)+ `com.fr.form.event.Listener`(`setType(Listener.EDITED)`)+ `com.fr.form.event.js.JavaScriptAction.setScript(String)`;`CellElement.setWidget(Widget)` 挂单元格;XML `<CellElement><Widget class="com.fr.form.ui.ComboBox" widgetName=..><Dictionary class="com.fr.data.impl.FormulaDictionary"><valueFormula>..<showFormula>$$$<Events><Event><JavaScript><![CDATA[...]]>`。
4. **前端 JS 类无 API 落点**(来源 doc-596/1207/2194):提交触发 `_g().verifyAndWriteReport()`、单元格读写 `_g().getCellValue/setCellValue`、新填报预览 `op=write_plus` 均属预览期前端/URL 参数,com.fr.* 只构建宿主骨架(按钮控件、单元格、事件节点 JS 文本),不表达算法本身。

## 常见错误

<!--KB:NODE05-E01-->
- 按钮 JS 调了 `verifyAndWriteReport()` 但模板没有 `<ReportWriteAttr>` → 按钮能点、不报错、数据进不了库(来源 doc-596/3577)。
<!--KB:NODE05-E02-->
- 多个内置 SQL 的 DMLConfig 顺序即执行顺序,任一失败全部回滚 → 把有依赖的提交顺序排反会静默错数据(来源 doc-3577)。
<!--KB:NODE05-E03-->
- 填报冻结区圈入可扩展数据单元格(如 `=ds.select()/list()`)→ 普通填报预览冻结全部扩展行,长表失去滚动意义(来源 doc-611)。
<!--KB:NODE05-E04-->
- 联动自动默认值漏掉三处命名一致(WidgetName/数据字典 valueFormula 参数/模板参数)→ 下拉不随父级刷新且不报错;`Listener.EDITED` 常量名、`FormulaDictionary` 构造参数顺序各版本可能微调(来源 doc-1868)。
<!--KB:NODE05-E05-->
- 「关闭脚本调用公式限制」未在决策系统关闭 → 联动 JS 里 remoteEvaluate 公式调用被拦,静默失败(来源 doc-1868)。

## 验证清单

- [ ] 提交链路:`<ReportWriteAttr>` + SubmitVisitor 存在,按钮 JS 与提交配置解耦正确(fr_check 应查「按钮提交JS ↔ 有 ReportWriteAttr」)
- [ ] 内置 SQL:每个 DMLConfig 的 Table/ColumnConfig 字段↔单元格绑定正确;isKey 主键语义正确;多个 SQL 顺序=执行顺序
- [ ] 填报冻结:冻结区仅覆盖静态表头,不含扩展数据单元格;freezeRow/freezeCol 从首行/首列起算
- [ ] 联动控件:三处命名(控件名/字典参数/模板参数)一致;编辑后事件 JS 已写入;脚本调用公式限制已关闭
- [ ] 前端 JS 类需求:确认宿主骨架(按钮/单元格/事件节点)已构建,JS 文本按预览期接口书写
