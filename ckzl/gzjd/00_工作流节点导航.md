# ckzl/gzjd导航(操作指南入口)

> **使用方式**:像做选择题一样逐节点判定,只加载当前节点需要的知识。
> 每个节点文件自包含,弱关联,可以独立阅读;不要一次读完所有节点。
> 本文件是节点式工作流的入口,取代"整库通读"式加载。

---

## 一、判定总纲(进入工作流前必答)

> **前置**:每个节点执行时,先 `python ckzl/zsk/gczsk/query_kb.py` 查结构化知识(零件/工艺/机/料)——本ckzl/gzjd是「法」的导航层,
> ckzl/zsk/gczsk是「法」的执行层(工艺路线 R-001~R-012 挂脚本),两者互补,见 AGENTS.md §1.8。

| # | 判定题 | 选项 | 去向 |
|---|--------|------|------|
| Q1 | 模板类型是什么? | FRM 决策报表 / CPT 普通报表 | FRM→NODE-09;CPT→Q2 |
| Q2 | CPT 的业务形态? | 填报(页面填写/导入)/ 明细展示 / 复杂查看(分析/钻取) | 填报→NODE-05;明细→NODE-04;复杂查看→NODE-04+06+08 |
| Q3 | 数据从哪来、要什么字段? | 数据库/Excel/API;字段清单 | NODE-01 |
| Q4 | 需要哪些全局能力? | 数据集 SQL / 参数面板 / 全局样式 | NODE-02 / NODE-03 / NODE-04 样式节 |
| Q5 | 是否需要交互? | 超链/JS 回调/图表联动/刷新 | NODE-08 |
| Q6 | 是否需要导出/导入? | Excel/Word/PDF/大数据 | NODE-07 |
| Q7 | 是否定时调度/权限控制? | 是 | ⚠跨模块依赖,查 ckzl/lc/08 调度章节 |

**执行顺序**:Q1→Q2 定向 → 全局节点 NODE-01→02→03 必过 → 分支节点按需 → 最后 NODE-10 验证。
> 节点出口闸门的机器可执行定义统一在 `ckzl/gzjd/node_gates.yaml`（单一事实源，2026-09-11 起）；执行器 `kfgj/fzpy/node_gate.py`。

## 二、节点清单(每个节点自包含)

| 节点 | 名称 | 加载时机 | 核心内容 |
|------|------|----------|----------|
| NODE-01 | 需求与数据判定 | 任何报表开发的第一步 | 理清数据/字段/想要什么;报表类型与业务形态判定 |
| NODE-02 | 数据集 | 全局必过 | SQL 设计、级联参数、数据字典、DBTableData/EmbeddedTableData |
| NODE-03 | 参数面板 | 全局必过(有参数时) | 控件选型、布局、默认值、标签宽度、级联控件 |
| NODE-04 | 报表主体-明细展示 | CPT 明细/复杂查看 | 单元格构建、样式、行高、冻结窗格、分页、排序 |
| NODE-05 | 填报模块 | CPT 填报(页面填写/导入) | 填报控件、提交配置、校验、导入、去重 |
| NODE-06 | 图表模块 | 需要图表时 | 图表类型选型、数据绑定、样式、联动 |
| NODE-07 | 导入导出 | 需要导出/导入文件时 | Excel/Word/PDF 导出、大数据导出、导入 |
| NODE-08 | 交互联动 | 需要交互时 | 超链、JS 回调、单元格/图表联动、动态参数 |
| NODE-09 | FRM 决策报表 | 模板类型=FRM | 组件布局、跨块联动、决策报表对象 |
| NODE-10 | 预览与验证 | 任何模板交付前 | 验证清单、错误排查、移动端适配 |

## 三、节点文件结构模板(所有节点统一)

```markdown
# NODE-XX 节点名
## 判定题(选择题:先回答,再往下读)
## 核心知识点(工程向,标注 来源 doc-XXXX)
## Java API 要点(com.fr.* 类名/方法/与 XML 对应)
## 常见错误(该节点报错案例)
## 验证清单(交付前逐项勾选)
## 下一步路由(本节点完成后去哪)
```
