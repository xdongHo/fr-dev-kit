## 1. 连接名契约（生成 SOP 前置步骤，doc-299）

> 来源: 帆软官方帮助 doc-299

凡产出含数据集的 .cpt，交付物须附【目标数据连接名清单 / 平台侧连接配置说明】：连接详情（URL/驱动/账号）在服务器、不落 .cpt，无头链路生成不出——漏掉则用户预览必踩错误码 `31300013 找不到数据连接`。

- .cpt 数据集只存 `<Database name="FRDemo"/>`（连接名），预览时 FR 用该名字去服务器连接池查真实连接；
- 连接配置五项（名称/库种/驱动/URL/账号密码）全在服务器侧、不进 XML；
- 连接名正确性是与「控件 WidgetName 同名绑定」「级联三处命名一致」同级的命名铁律，拼错不报错直到预览（`31300013` 指向连接名映射失败，`11300001` 指向数据集 SQL/参数问题，排障先按错误码二分）。

## 2. Excel 导出环境前提（部署清单，doc-786 / doc-1121）

> 来源: 帆软官方帮助 doc-786 / doc-1121

Excel 导出相关环境前提集中成一张表核对（漏一项就得到与预期不符的导出后缀或缺失按钮）：

| 项 | 要求 | 说明 |
|----|------|------|
| poi2007_fat.jar | JAR < 2016-10-10 手动放 `%FR_HOME%\webapps\webroot\WEB-INF\lib`；>= 2016-10-10 已内置 third 包 | 决定默认导出后缀 .xls → .xlsx |
| JDK | 1.8 且小版本 >= 8u102 | .xlsx 导出能力前置条件 |

> ⚠️ **JDK8 的完整理由与三条可执行判据（doc-3814 §2.2 / §2.3）**：JDK 必须 1.8 且 >= 8u102 有**两条并列理由**——① .xlsx 导出（8u102 的由来）；② **JDK9+ 移除了 tools.jar，FR 10.0 工程部署后直接 500**——即 JDK8 是「工程能不能起来」的问题，不是「能不能导 xlsx」的问题，不要在不需要 xlsx 的项目上放宽版本。三条可执行判据（一行命令 / 一次 ls 可判，且失败时报错文本与 JDK 毫无字面关联）：
> - `$JAVA_HOME` 必须指向 **JDK 而非 JRE**：判据 `$JAVA_HOME/lib/tools.jar` 存在；
> - `com.sun.tools.attach.VirtualMachine` 可加载：Windows 对应 `%JRE_HOME%\bin\attach.dll`，缺则启动报 `fine assist start failed`；
> - JVM 位数必须与 OS 一致：否则 `Can't load AMD 64-bit .dll on a IA 32-bit platform`。
> 来源: 帆软官方帮助 doc-3814

> 🛠️ **判据之后补修复动作（doc-2365）**：生产服务器若只装 JRE（无 JDK），按以下步骤修复——
> 1. 将部署机本地 `%JAVA_HOME%/jdk/lib/tools.jar` **同时拷贝到 `%TOMCAT_HOME%/lib` 与 `%TOMCAT_HOME%/webapps/<工程名>/WEB-INF/lib` 两处**（容器不同则拷贝到对应 lib 下）；
> 2. Windows 若 `%JRE_HOME%/bin` 缺 `attach.dll`，再补拷 `%JAVA_HOME%/jdk/jre/bin/attach.dll` 到 `%JRE_HOME%/bin`；
> 3. **tools.jar 必须与「部署服务器本地 JAVA_HOME」版本匹配，不可用开发机文件**（版本不匹配会从「判据失败」变成「启动 500」）。
>
> ⚠️ 无头链路只验证开发机 JDK，交付到 JRE-only 服务器会 500；本修复动作是确定性的环境步骤、零 FR API 成本，应写进交付检查清单。
> 来源: 帆软官方帮助 doc-2365 / doc-2475

> 🩺 **JDK 两态可自查（doc-1163）**：`FineAssist.containsToolsJar()`=false → 缺 tools.jar（报 `Programs does not contain tools.jar`）；`FineAssist.isStartUp()`=false → 版本不匹配（报 `Programs does not match tools.jar`）。**`-Ddebug=true` 会让 `containsToolsJar()` 无条件返回 true**（字节码 pc10 `ifeq→15` 命中即返回）——纯模板生成场景可用它跳过第一道门，省掉「为消错误而拷 JDK tools.jar」这一步（未见于任何官方文档的后门）。
> 来源: 帆软官方帮助 doc-1163 / doc-1342
| 导出方式选择控件插件 | V2.1.4（FR >= 8.0，JAR >= 2016-07-30） | 让 PC 端导出可自选 .xls/.xlsx；**不支持移动端** |

> ⚠️ 行式引擎（RowEngineAttr/@rowEngineEnabled）开启后即便配了 poi2007 jar，Excel 导出仍回退为 2003（.xls）——这是无头生成 .cpt 时真正能控制的开关。

## 3. 含扩展图表的工程硬前置（doc-2474）

> 来源: 帆软官方帮助 doc-2474

凡 .cpt/.frm 含扩展图表（19 种类型：场景地图/地球/地图/GIS/仪表盘/指标卡/时间/柱形/饼图等），交付/部署前必须断言目标 `%FR_HOME%\lib` 下存在 `jxbrowser*.jar`（扩展图表插件 4.0+ 依赖，Win32/Win64/mac 三套不同），否则运行期报「扩展图表初始化失败」且 FR 不报具体原因——纯环境侧静默故障，模板/XML 全对也跑不通（设计器自带、服务器常缺）。可移植 `practice/topic_2474/check_jxbrowser_dep.py`。

> 另注意扩展图表四类静默不支持：**不支持导出 / 不支持移动端 / 不支持任何图表接口 / 只支持 Chrome(>=86) 预览**；且插件未安装/被禁用/版本低于模板创建版本/本地与远程版本不一致时，模板直接打不开（版本须一致才可读写）。

> 🚦 **无头交付前置断言（doc-3836）**：凡产物 .cpt 含扩展图表（类名命中 ExtChart/Gauge/3D/GIS 等，判定式见 05_填报与交互.md §14.4）时，生成器/校验器应在开跑前或写盘后**显式登记「依赖扩展图表插件 4.4 + Chrome>=86 + 不支持导出/移动端」**，并对模板里声明的插件版本标记做一致性校验——「缺插件/版本错」时模板**静默打不开、无日志、fr_check 全过**，实施方拿 Firefox/手机去开才发现，反复排查成「模板 bug」。
> 来源: 帆软官方帮助 doc-3836

> 📌 **jxbrowser 的 2 个 jar 是设计器侧依赖，无头引擎不需要（doc-3836）**：全 12 jar 扫 `jxbrowser`/`teamdev` 字节串唯一命中 `com.fr.jvm.assist.FineAssist#initialize()`，字节码仅一句 `System.setProperty("jxbrowser.license.key", <硬编码>)`；那 2 个 jar 位于 `%FR_HOME%/lib`（设计器 classpath），不在 doc-1163 实证的 12 jar 运行时 classpath 里。故官方 doc-3635 §4.1「扩展图表初始化失败」只发生在设计器，**无头生成/导出链路不受影响**——不要在无头服务器上为它补 jxbrowser jar，也不要误判无头环境不具备扩展图表能力。
> 来源: 帆软官方帮助 doc-3836

## 4. 自动化账号权限前置（doc-4152）

> 来源: 帆软官方帮助 doc-4152

远程设计/批量改模板所用账号缺连接使用权限，在 >= 2022-08-03（10.0.19）的 JAR 上直接打不开数据编辑窗口——纯环境侧硬前置，模板再正确也无用。两条路径的权限组合：

| 路径 | 所需权限 |
|------|----------|
| 设计器建**模板数据集** | 数据连接控制（全局设置）+ 该连接「使用」权限 |
| 决策系统建**服务器数据集** | 分级授权 + 数据连接控制 + 连接「使用」权限 + 模块「管理系统>数据连接」使用权限 |

- 「数据连接控制」**默认关闭**，关闭时不做任何连接级鉴权——「开发环境正常、生产全崩」的根因；
- 权限载体为 部门/角色/用户；
- ⚠️ 超管绕过连接级鉴权，用超管验证等于没验证；失败形态是「无此数据连接权限」出现在**数据编辑窗口**（不是 SQL 报错/超时），判据：同一模板换超管账号打开即正常 → 100% 是权限问题。

## 5. 模板外部依赖清单（数据连接分册，doc-2574）

> 来源: 帆软官方帮助 doc-2574

「模板外部依赖清单」的数据连接分册，除连接名外应补 `driver` / `url` / `schema` 三个字段——schema 缺省行为不确定，跨库迁移会静默改变取数结果，只记连接名不足以复现环境：

- **driver**：HSQL 在 FR 里的驱动类是重打包版 `com.fr.third.org.hsqldb.jdbcDriver`（照抄原生 `org.hsqldb.jdbcDriver` 连不上）；HSQL 驱动 FR 内置，部署清单**不需要「上传 jar」**这一步（与 MySQL/Oracle 不同）；
- **url**：`jdbc:hsqldb:file:[PATH_TO_DB_FILES]` 是本地文件路径，跨环境必然不同，属脚本无法迁移的字段；
- **schema**：HSQL 模式不选默认取第一个，生成的 SQL 一律显式带 `PUBLIC.` 前缀（见 ckzl/lc/02 §8.5）；
- file 型嵌入式库要求提供 **env_overrides**（dev/test/prod 各一份 URL）；可参考 `practice/topic_2574/hsql_conn_manifest.json` 的结构。

> 📌 **移动端外部依赖版本轴（doc-3274）**：移动端功能有**独立于报表服务器的版本轴**，交付物含移动端场景时，清单必须写死两个客户端版本下限（用户侧不可控，须在需求确认阶段写进验收条件）——已有两个样本：①「自定义是否显示切换按钮」要求 **App >= 10.4.61**（服务器只需 10.0）；② 手机重布局 .frm 含图表（见 ckzl/lc/05 §458）要求**服务器 >= 10.0.11 且 HTML5 移动端展现插件 >= 10.4.975**。不满足时**全部静默降级**（设置无效 / 图表转图片并缩小），无任何报错。
> 来源: 帆软官方帮助 doc-3274

## 6. 图表导出/定时调度图表的 Linux 运行门槛（doc-3403）

> 来源: 帆软官方帮助 doc-3403

2020-04-26 之后的 JAR 图表导出底层由 phantomjs 方案切换为 **J2V8** 方案（`libj2v8_linux_x86_64.so`）。Linux 部署要求 JDK >= 1.8，且 GLIBC >= 2.17、GLIBCXX >= 3.4.22（或存在 libj2v8_linux_x86_64.so），否则导出/定时调度的图表空白并硬报错「C library and JDK version do not meet the requirements...」——这是环境门槛报错，不是模板缺陷。前置校验命令：

```bash
strings /lib64/libc.so.6 | grep GLIBC          # 需 >= GLIBC_2.17
strings /usr/lib64/libstdc++.so.6 | grep GLIBCXX  # 需 >= GLIBCXX_3.4.22
```

> 该问题只影响「图表」的导出/展示，普通单元格/表格导出不受 J2V8 缺失影响——排障先区分「图表空白 vs 整表空白」，避免被误判为模板错误。GLIBC 是系统最底层 API，升级须谨慎（系统内有其它重要项目）；GLIBCXX 风险小且可回退。

> ⚠️ **L2: AWT/X11 层（doc-3814 §2.9.1 / §2.9.2）**——Linux 运行门槛是**两层原生依赖**，不能只查 GLIBC（L1）：缺 `libXrender.so.1` / `libXtst.so.6` 时抛 `java.lang.UnsatisfiedLinkError: .../libawt_xawt.so`，Debian/Ubuntu 用 `apt-get install libxrender-dev libxtst-dev`、RHEL 用 `yum install libXrender libXtst`，或加 `-Djava.awt.headless=true` 改走 `libawt_headless.so`。两层判据**必须分开写**：
> - **L1（J2V8）只影响图表**：失败形态 = 图表空白 + 明确英文报错「C library and JDK version do not meet the requirements」；
> - **L2（AWT/X11）影响一切要画东西的路径**，包括 kit 自己用 `Graphics2D.getFontMetrics().getStringBounds()` 做的字体测量（参数面板格式化能力的前置）——失败形态 = 启动或量字宽时直接抛 UnsatisfiedLinkError，无任何 FR 错误码。
> 来源: 帆软官方帮助 doc-3814

## 7. 四层时区链（doc-4068）

> 来源: 帆软官方帮助 doc-4068

时区影响按四层拆解，**定时报表正确性由 JVM 层决定**（kit 现有知识只有 JDBC 一层，须补全）：

| 层 | 控制点 | 影响范围 |
|----|--------|----------|
| L1 OS | `timedatectl` / `/etc/localtime` | 最底层基准 |
| L2 JVM | `-Duser.timezone` > 环境变量 `TZ` > L1；**JVM 启动时解析一次** | 定时调度触发时刻 + `NOW()/TODAY()` 求值 + 日志时间戳 |
| L3 JDBC | 连接串 `serverTimezone=`（见 doc-2560） | 驱动侧时区换算 |
| L4 浏览器 | 本地时区 | **仅影响显示**，以及 10.0.17+ 那条提示条 |

三条结论：

1. **L4 永远不参与决策**——见到提示条应去查 L2，而不是调浏览器；
2. **L2 与 L3 的误差在预览时可能互相抵消**（模板「看着是对的」），而定时触发只由 L2 决定，抵消关系不成立 → 这类模板只在定时跑时出错，手工预览永远复现不了；
3. **推荐修 L2 而非 L1**：改 L1 一样要重启 JVM 省不掉，且启动参数可进版本库/可 diff/随交付包发。

> ⚠️ **官方原文已过时**：官方给的 `/etc/sysconfig/clock` 是 RHEL6 时代的路子，systemd 系（RHEL7+/CentOS7+/Ubuntu16+）上正解是 `timedatectl set-timezone Asia/Shanghai` 或重建 `/etc/localtime` 软链；照抄原文可能改了个没人读的文件，重启后时区纹丝不动**且不报错**。另：JVM 时区落到 `GMT`/`UTC` 通常不是有人配的，而是识别失败的兜底值（容器镜像没装 tzdata 最常见）。

## 8. FineDB 外接库配置（无头，doc-1485 / doc-3898）

> 来源: 帆软官方帮助 doc-1485 / doc-3898

外接库是集群/大数据量部署的前置条件，两条路径：

**① 离线（工程未启动，CI/容器场景首选）**：

```java
new com.fr.stable.db.option.DBOption()
    .driverClass("com.mysql.jdbc.Driver")
    .dialectClass("com.fr.third.org.hibernate.dialect.MySQL5Dialect")
    .url(..).username(..).password(..)
    // → write(OutputStream, com.fr.properties.finedb.DBPropertyCipher.getInstance())
    // → 落 WEB-INF/config/db.properties
```

**② 在线**：`MigrationService.getInstance()` → `testDBConnection` → `updateFineDBConfig` → `getSchemas` → `checkDataExist` → `startTransfer(operatorId)` + 轮询 `getStatus()` / 或 `switchDBConfig()`。

> ⚠️ **离线路径必须自己写死 dialect**：`DBConfigBean#toDBOption()` 字节码把 `dialectClass("")` 无条件置空，靠 `MigrationContext#checkDialect()` 真连库自动探测——这条自动路径在离线写盘时**根本不执行**，照着在线代码抄会产出 dialect 为空的 db.properties，工程启动才炸。同理密码必须过 `DBPropertyCipher.getInstance()`，自造密文 decode 不出来。

**库间差异矩阵**（通用流程只写一份，差异全收进表；新增 Oracle/达梦只加一行）：

| 库类型 | driver 类名 | 驱动是否 FR 自带 | 方言类名（com.fr.third.org.hibernate.dialect.*） | 是否需装插件 | schema 是否必填 | validationQuery |
|--------|------------|----------------|-----------------------------------------------|-------------|----------------|-----------------|
| MySQL5 | `com.mysql.jdbc.Driver` | 自带 | `MySQL5Dialect` | 否 | 无 | — |
| PostgreSQL | `org.postgresql.Driver` | **不自带** | `PostgreSQL94Dialect` | 需插件 | 必填 | `SELECT 1` |

## 9. 预览/跳转 URL 的 contextPath 常量（doc-2188 / doc-3322）

> 来源: 帆软官方帮助 doc-2188 / doc-3322

官方形态是 `http://ip:服务器端口号/项目所在目录/decision`（doc-3322 §2），**`webroot` 只是内置服务器的默认工程名**，客户工程名很少叫 webroot——一旦不同，所有硬编码 `/webroot/decision/...` 拼接出的导出/跳转 JS 会**整片 404 失效**。建议在 ckzl/lc/01 定义环境常量，其余文档与脚本一律从它派生：

```text
FR_BASE = http://<ip>:<port>/<contextPath>/decision
```

> ⚠️ kit 至少 5 处硬编码 `/webroot/decision/...`（ckzl/lc/01 三处、04 的导出 URL、05 的 window.open 示例），迁移时应统一替换为 `FR_BASE` 派生。
