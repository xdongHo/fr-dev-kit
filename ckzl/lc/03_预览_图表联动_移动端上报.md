## 13. 预览模式：op 参数（doc-2194）

> 来源: 帆软官方帮助 doc-2194（新填报预览）

**预览模式由 URL 的 op 参数决定，不在 .cpt XML 里**——无头脚本拼请求时自己加，模板 XML 不含该参数：

| op | 预览模式 | 能力 |
|----|---------|------|
| 无 op | 普通分页预览 | — |
| `op=write` | 普通填报预览 | 支持 `__cutpage__=v` 分页、悬浮元素、列表控件、数据字典、参数面板位置、JS `getWidgetByName` 等 |
| `op=write_plus` | 新填报预览 | **已停更、限制多**；不支持 `__cutpage__=v`、悬浮元素、列表控件、树节点展开折叠、单元格内文本控件样式、数据字典、参数面板位置、JS 取元素、移动端、IE10- |

- **默认生成器选 `op=write`**；仅数据量大、纯录入场景且不用上述受限特性时才考虑 write_plus（官方建议尽量少用）。
- 生成器/校验器应识别「模板特性 → 预览模式」互斥：模板命中悬浮元素/列表控件/数据字典/参数面板位置/JS getWidgetByName 等 → 标注「仅 op=write 可用」，避免误拼 write_plus 导致静默失效。
- op 是预览 URL 参数、归「请求层」而非「模板层」（与 doc-4418 的 sessionID 同理）。

> ⚠️ 官方表述补充（来源: 帆软官方帮助 doc-1168）：**新填报预览（write_plus）页面结构有变化、不兼容文档中大部分 JS 方案**——与上表 write_plus 限制清单互补，进一步强化「默认 op=write」理由。

## 14. 图表联动交互（超链传参 + 自动刷新）

> 六类超链的 XML 形态与总表见 ckzl/lc/03 §11；本节聚焦**联动图表**的落地交互与刷新。

### 14.1 图表单元格联动超链（doc-4207）

> 来源: 帆软官方帮助 doc-4207（图表超链-联动单元格图表）

名称易误读：**「联动单元格」超链联动的不是被点击格本身，而是被点击格所指向的另一个「插入了图表的单元格」**（如 A2 地区 → 图表格 A5），点击后被联动的图表随参数刷新。

配置三要素：
1. 被点击格（A2）加「联动单元格图表」超链；
2. 设置「联动单元格」= 图表所在格坐标（A5）；
3. 加参数 area，值 = 公式 **`=$$$`**（取被点击格自身当前值）。

- 图表所在格（A5）必须插入图表并绑定**参数化数据集**（ds2），超链的 area 喂给该数据集——联动本质是「超链传参 → 图表格数据集重查」；SQL 用 `WHERE 1=1 ${if(len(area)==0,"","and 地区='"+area+"'")}`（参数为空选全部，与 kit ckzl/lc/02 §8.1 一致）。
- 图表标题可公式化 `=$area + "地区销量统计图"`（随参数刷新）。
- 一张模板可放多张图表格 + 多个入口格，各自用不同参数联动不同图表 → 适合声明式批量生成。
- 支持 PC + App + HTML5，无移动端盲区。
- 参考 `practice/topic_4207/gen_link_cell_chart.py`。

### 14.2 超链跳参数化模板（doc-947，主表点击格传参跳子模板）

> 来源: 帆软官方帮助 doc-947（超级链接到有参数的模板）

| 方式 | 超链类 | 移动端 |
|------|--------|--------|
| 网络报表 | `com.fr.js.ReportletHyperlink` | PC+App+HTML5 支持 |
| JS 脚本 | `com.fr.js.JavaScriptHyperlink` | **不支持移动端** |

- `$$$` = 取「当前被点击单元格的值」——点击扩展出来的哪个地区就传哪个；无头生成就是给参数赋字面量 `$$$`。
- **JS 两段式传参**：先把被点击格映射成脚本变量（参数 `A=A2`），再 `window.open("${servletURL}?...&area="+A)` 拼 URL——漏掉变量映射则 A 在 JS 中未定义。
- ⚠️ **子模板必须声明同名模板参数**（如 area），否则主表传参后子表**静默全空**——headless 阶段可前置拦截（fr_check 断言子模板既声明同名参数、又在 `${...}` 内引用）。
- 参考 `practice/topic_947/gen_hyperlink.py`。

> ⚠️ **移动端口径修正（来源: 帆软官方帮助 doc-1396 / doc-946，doc-3741 归口）**：「JS 脚本不支持移动端」指 doc-946 场景（`FR.remoteEvaluate`/`doHyperlinkByPost` 类，仅 PC 分页预览）；JS 超链在移动端是否生效**取决于 JS 内容**——`FR.logoutApp()` 等 App 接口经 JS 超链在 App 生效（doc-1396 实证）。生成器按 JS 接口区分，不得一刀切「JS 超链不支持移动端」。另：JS 脚本超链的载体类名以 ckzl/lc/03 §11.6 修正为准（`com.fr.js.JavaScriptImpl`，非 `JavaScriptHyperlink`）。

### 14.3 填报下拉框 + 编辑后事件 + 联动单元格图表（doc-1995，第三类联动）

> 来源: 帆软官方帮助 doc-1995（下拉框和图表联动）

与「参数面板级联（doc-1284）」「点击数据格联动图表（doc-4207）」并列的**第三类联动**，靠下拉框的**编辑后事件**用 JS 触发。

桥接链路三段：① C1 下拉框选值 → ② JS `contentPane.setCellValue('D1', null, this.getValue())` 写隐藏桥接格 D1 + `$('td[id^=D1] .linkspan').click()` 模拟点击 D1 上的超链 → ③ D1 上的「联动单元格图表」超链把 D1 值传给图表数据集 ds2 → 图表刷新（D1 用公式 `=''` 隐藏）。

- **致命铁律（取值差异）**：联动超链的参数值必须是「单元格号 D1」、**不能用公式 `=$$$`**——D1 的值是 JS 运行时动态写入的，`$$$` 只取静态/设计态值，用它会**静默不刷新**。此点与 doc-4207（用 `=$$$`）恰好相反，根因是值来源不同（静态点击 vs JS 动态注入）——生成器按值来源判，不能只看需求措辞。
- 模板参数「销售员」**必须给默认值**（示例 张珊），否则填报预览图表完全不呈现数据。
- 这是填报（写）模板：需「模板 Web 属性 > 填报页面设置」勾选**直接显示控件**，走填报预览链路。
- 不支持移动端。
- 参考 `practice/topic_1995/gen_dropdown_chart_link.py`。

### 14.4 联动图表自动刷新（doc-1392 dataRefresh + doc-3115 扩展图表修正）

> 来源: 帆软官方帮助 doc-1392（报表块数据变化后刷新联动图表块）/ doc-3115（扩展图表组件刷新）

当图表块（chart1）数据源是报表块（report0）单元格、且 report0 数据因联动变化时，**FR 不会自动刷新 chart1**（跨块数据依赖不在 FR 刷新追踪范围内）——必须前端 JS 强制刷新。

**按图表类型二选一（doc-3115 修正）**：

| 图表类型 | 刷新 API |
|---------|---------|
| 普通图表 | `FR.Chart.WebUtils.getChart("chart1").dataRefresh()` |
| 扩展图表（ExtChart/Gauge/3D/GIS 等类名命中即扩展图表） | `FR.Chart.WebUtils.getChart("chart1").dealReloadChartAjax()` |
| .cpt 单元格点地图（地图>点地图，普通图表） | `FR.Chart.WebUtils.getChart("chartN").dataRefresh()`（**勿用 `dealReloadChartAjax()`**——那是扩展图表专属，doc-1086 实证） |

- ⚠️ **扩展图表不支持 dataRefresh()**——用错 API 时页面能开、点了没反应、控制台无报错（静默）。现有 `practice/topic_1392/inject_refresh_js.py` 只发 dataRefresh()，对扩展图表会静默失效，应升级为按类型选 API 的工厂（`practice/topic_3115/refresh_factory.py`）。
- 必须 `setTimeout(..., 500)` 包裹：report0 是异步刷新，立即 dataRefresh 会拿到旧数据；500ms 是文档写死的经验等待值，数据量大时调大。
- JS 注入点在**触发联动的图表块（chart0）**的点击/联动事件体内（先完成传参联动 → 再延迟刷新目标图表 chart1）。
- `getChart(name)` 在 .frm / .cpt / 移动端通用；name 必须与模板中图表块名完全一致，否则取到 null 导致不刷新。
- 扩展图表刷新方案不支持移动端（doc-3115 注）。

## 15. 移动端填报入口（定时调度自定义链接，doc-1387）

> 来源: 帆软官方帮助 doc-1387（定时调度客户端通知-APP通知）

**APP 通知里唯一的写通道**：定时调度「文件处理 > 客户端通知 > 自定义链接」可挂填报预览 URL，用户在 FineMobile App 内直接填报提交。完整可脚本化链路：

```
无头生成填报 .cpt → 组装 ?viewlet=<路径>.cpt&op=write → 替换为客户端可达 IP
→ 填入定时调度「自定义链接」→ App 内填报提交
```

- ⚠️ **localhost URL 不可外发**（头号静默坑）：kit 预览 URL 默认 `http://localhost:8075/...`，直接粘进自定义链接 = 任务成功 + 消息收到 + 手机点开空白，全链路零报错。必须把 IP 换成客户端可达地址。
- **APP 通知仅支持链接消息**：图文/文件消息只有微信/钉钉支持，配了会被静默降级成一条链接。
- 收件人只能是**默认用户组**（未设默认用户组则消息发不出去）。
- 主题必填且支持公式（限「定时调度支持的公式」子集，如 `${today()}`；注意与短信的 `=$taskname` 语法不同，混写静默失效）。
- 网络前提：报表工程服务器须能访问消息推送服务器（内网需配代理转发）——无头生成解决不了，只能在 spec 显式声明。
- **版本下限告警（doc-1387 §4.1）**：调度对象是设了「手机重布局」的 .frm 且含图表时，服务器 < V10.0.11 或 HTML5 移动端展现插件 < V10.4.975 会把图表转成图片并因自适应明显缩小——结果能出、图也在、就是变小了，不报错、极难归因；生成器在调度对象为 .frm 时应输出该版本下限告警。
- 校验参考：`practice/topic_1387/check_app_notify.py`（R0~R7：推送服务器可达/默认用户组/主题必填与公式语法/仅链接消息/localhost 链接拦截/op=write 可提交性/.frm 图表缩小）。

## 16. 多级上报（工作流，doc-2365）

> 来源: 帆软官方帮助 doc-2365（隐藏行后隔行变色）/ doc-576（单线多级上报，字节码实读）；⚠跨模块依赖（平台类产物：落 FineDB，非 .cpt）

平台类产物的**第五类：工作流**，与已收录四类（定时调度/用户权限/数据连接/用户个性化）的关键差异——**写入模型是 DAO/Controller 而非 Configuration**：

- 入口：`com.fr.decision.workflow.util.WorkflowContext.getInstance().getReportProcessController() / getProcessNodeController() / getProcessTaskController()`；bean 在 `com.fr.decision.workflow.bean`（`Workflow`/`WorkflowNode`/`WorkflowTask`/`WorkflowTaskImpl`），方法 `add/getById/update/remove/find` 全从 `com.fr.decision.authority.controller.BaseController` 泛型继承。
- 三条硬结论：① **这五个 Controller 接口自身 0 个声明方法**，dump 出来是空表——**不能据此判「无 API」**（泛型接口 + 桥接方法的正常形态，与 doc-645/doc-3312 的「空方法体=架构不支持」表象相反，勿反向误读）；② 禁止套用 `Configurations.update(new Worker(){})`（那是 Configuration 模型）；③ `WorkflowNode` 直接 extends `BaseEntity`（自身即实体、无 `createEntity()`），另外三个是 `BaseDataRecord` + `createEntity()` 双份——按同一套写会在 node 上编译失败。
- 与模板类的唯一接点是字符串路径：`ReportControl.setReportPath("/xxx.cpt")`（同 `ScheduleTask#setTemplatePath`）；无头模板验证须手工把 `fr_task_sender` 等内置参数塞进 paraMap（`$fr_task_sender` 依赖请求 `__processtaskid__`，无头下恒空会过滤掉全部数据）。
- 参考 `practice/topic_576_java/StraightLineWorkflowBuilder.java` + `workflow_authority.md`（authority 11 位串速查表）。
