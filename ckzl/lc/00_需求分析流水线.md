# Stage 0: 需求分析流水线（Excel 需求确认清单）

> 定位：**进入开发工艺流程（Stage 1-11）之前**。需求确认清单经用户确认后即为
> 开发的"单一事实源"——后续程序化操作（明细表生成/皮肤/参数面板）都从它派生。
> 价值：把"需求理解偏差"拦截在写模板之前，而不是渲染后发现。

## 1. Excel 需求确认清单结构规范

| Sheet | 名字约定 | 内容 | 来源 |
|---|---|---|---|
| 1 | `物料信息` | **需求总览九区**(见 §1.1/§1.2) — 信息收集关键页 | 逆向自动 + 用户填 |
| 2.. | `T_<表简写>` | **实体表样例**：全表名+字段数+估算行数 / 字段类型清单 / 原始数据前 N 行（information_schema+pg_class 实测） | SQL 代理探查 |
| .. | `<数据集简写名>` | **数据集示例数据**(逻辑层核心数据集)：真执行取数，前 N 行；名字即表样引用前缀。**字典类数据集(dict_*/ds_dict_*)不建页**——逻辑简单，取值枚举并入表样参数区(行2 枚举行/行3 来源标注)与总览五区"取值枚举"列 | agent 真取数 |
| .. | `SQL_<数据集名>` | 核心逻辑 SQL 原文（`${参数}`、`${if(...)}` 全保留；字典类同样不建） | 模板 TableDataMap |
| 末 | `表样_<报表名>` | **Excel 版表样**（见 §2） | 渲染 JSON + 模板 XML |

### 1.1 需求总览九区（Sheet1 信息收集关键页，交付反推定型）

| 二、报表清单 | 报表名/类型/用途说明/对应表样sheet（一页可覆盖项目多报表） | 用途说明 |
| 三、数据库表资源与表结构 | 表名/连接/引用数据集/**字段数/估算行数(实测)**，字段明细在 T_ 页 | — |
| 四、数据集清单 | 名称/类型/连接/总行数/列数/**参数依赖**(`${para}` 自动提取) | — |
| 五、参数清单 | 参数名/控件类型/**取值来源(自动匹配 para_X↔dict_X)**/示例值 | — |
| 六、填报·交互·权限 | **填报回写表/主键/提交器(模板XML提取)**、超链跳转目标清单、脚本量、目录挂载/可访问角色/行级权限口径 | 挂载与角色 |

| 九、确认与变更记录 | 版本/日期/确认人/变更说明（V1.0 逆向底稿行自动生成） | 确认人 |

### 1.2 交付反推矩阵（项目经理推导：从运维交档反推需求输入）

**终点**：frdoc（帆软官方"归档盘点"插件）生成的运维交接文档——章节矩阵 sec0~sec9 + pro 增量（权限清单/血缘图/lint/资产台账）+ DocConfig 三方角色。**反推**：交付文档每一章的数据只有三种来源——

- **A 类·模板自动派生**：ReportParser 同款纯 XML 解析（零引擎依赖）→ req_workbook 已自动提取
- **B 类·环境采集**：需平台运行时查询（权限挂载链 AuthorityContext/调度任务）→ 黄格预埋 + 运维期可补
- **C 类·需求人工**（**过后即焚**：开发完成后再问就问不到，需求清单的存在意义就是在时间窗口锁住它们）→ 黄格

| frdoc 交付章节 | 来源 | 需求清单落点 |
|---|---|---|
| sec0 基本信息 | A | 二区报表清单 |
| sec1 数据准备(数据集/SQL/参数) | A | 三/四区 + SQL页 + 示例页 |
| sec2 组件布局 | A | 五区 + 表样 |
| sec3 字段字典与计算逻辑 | A | 表样引用格(ds.field/公式原文) |
| sec4 图表配置 | A | 表样图表占位 |
| sec5 填报属性 | A | **六区: 回写表/主键/提交器(XML提取)** + 回写口径(C) |
| sec6 交互与事件 | A | **六区: 超链跳转目标清单(viewlet 正则)** |
| sec7 权限与安全 | B+C | **六区: 挂载路径/角色/行级口径(黄格)** |
| sec8 全局配置与样式 | A | 皮肤管理另册引用 |
| sec9 自定义脚本 | A | **六区: 监听/JS 计数** |
| pro 血缘图 | A | 三区表资源+引用关系 |
| pro lint | A | probe_dataset ⚠通道 |
| pro 资产台账 | A | 一区项目信息 |
| DocConfig Dev/Ops/Pm | C | **一区三方负责人** |
| （运维真实诉求，frdoc 也没有） | C | **八区: 调度/SLA/停机影响/下游/质量基线/联系人** |

**原则：需求确认清单 = 运维交付文档的种子。** 同一数据模型的两端视图——正向生成时九区填满，交付文档的 A 类字段自动展开、B 类运行时补齐、C 类无需考古。

## 2. 表样规范

### cpt 明细报表（网格式）
- **顶部 5 行 = 参数面板示例**（`[参数] 控件名` + 示例值；导入设计器后可删）
- 下方 = 单元格网格：列宽/行高按引擎真实值(px÷7 / ×0.75)；合并格=cs/rs
- **数据格三态**（颜色语义）：
  - 🔵 蓝字浅蓝底 `ds.field` — DSColumn 绑定（如 `ds1.budget`）
  - 🔵 蓝字浅蓝底 `=ds.select(字段, 条件)` — 公式引用（比 ds.field 更精确, 含过滤逻辑；写为文本防 Excel 解析）
  - 静态文本 — 原值
  - 🟠 `[图表 类名]` — 图表占位
- **cpt 表格可直接用 Excel 导入设计器** → 明细表类表样 ≈ 定稿

### frm 决策报表（画布式）
- Excel 当画布：坐标 = px÷24(列)/÷20(行)；组件 = **合并单元格区域**
- 区域颜色：橙 `[图表] 名字` / 绿 `[报表块] 名字` / 灰 `[控件类] 名字`
- 层叠卡片组（Tab/条件显示）：第一张占位 merge，后续张 `⧉N` 前缀右侧排开
- 全画布背景层（面积≥70% 画布）不占格，标注在表样头部

## 3. 工具：`ckzl/zsk/xqfx/tools/req_workbook.py`

```bash
# 项目级聚合(推荐): 目录 → 一份项目清单
python ckzl/zsk/xqfx\tools\req_workbook.py <项目目录> [out.xlsx] [--rows 6] [--limit N]
# 单模板模式(= 项目模式 N=1)
python ckzl/zsk/xqfx\tools\req_workbook.py <cpt|frm> [out.xlsx]
# 自检: python ckzl/zsk/xqfx\tools\req_selfcheck.py <xlsx>
```

**页签预算(项目模式)**：1 物料信息(九区) + N 实体页(全项目去重) + **1 数据集逻辑页**(全部核心数据集分节: SQL+示例同屏, 同名合并+来源报表) + N 表样页(每报表一页)。49 模板项目 ≈ 60 页(对比逐模板文件 490+ 页降 87%)。字典类不建页(取值并入参数区/五区)。

**XML 兜底**：引擎提取失败(实证: 老模板混淆 sheet 类 `cellIterator` 抛 UnsupportedOperationException)时自动降级纯 XML 解析——格子布局/静态值/公式/图表位保真，计算值与字体缺席。
数据源三层：fr-agent（数据集元数据+真取数）+ 模板 XML（DSColumn/公式引用）+ 注入渲染（单元格/组件树/图表位）。

**实证战绩（2026-08-23）**：
| 样本 | 结果 |
|---|---|
| 示例报表工程(49 模板) | **项目级聚合**: 43 sheets(1 总览+15 实体页去重+1 数据集逻辑页 39 数据集+26 表样)；23 老模板引擎提取失败 → XML 兜底全救回 |
| 示例驾驶舱工程(6 模板) | 项目级聚合 9 sheets(1+1+1+6) |
| 示例预算表.cpt(单模板) | 10 sheets：九区 + 3 实体页 + 数据集逻辑 + 表样 **940 公式引用格**；参数↔字典自动关联 para_entity→dict_entity |
| 示例驾驶舱 detail.cpt(单模板) | 六区：回写表+6 主键+BuiltInSQLSubmiter(20列)+超链→import_detail |
| dashboard.frm(单模板) | 画布式 **63 占位**(图表13/报表块17/控件33) 完整几何分布 |

**实体表探查 = SQL 代理**（实证）：设计器 JVM 里 `ConnectionConfig` 经全线程类加载器不可达，但**改写模板首个 DBTableData 的 query 再 createDataModel** 即可执行任意 SQL（information_schema/pg_class/SELECT *）——零连接配置，模板有 DBTableData 就能用。

## 4. 工艺闭环（现状与延伸）

```
现状(逆向): 既有 cpt/frm ──req_workbook──► 需求确认清单 ──用户确认/修改──► 定稿
延伸(正向): 需求确认清单 ──字段页+表样参数──► build_detail_cpt / 皮肤管理 ──► 模板
            (表样 Excel 可直接导入设计器; 数据集.字段 引用即取数语义)
```

## 5. 已知边界与坑（实证记录）

- **老模板引擎提取坑（实证）**：execute 成功但 sheet 为混淆类（如 `UkjqeDpwwKykkor`），`cellIterator()` 抛 UnsupportedOperationException 且 getResultCellElement 亦死——渲染 JSON 里表现为 `error=None+产物缺`。解：XML 兜底（模板 XML 即事实源，表样格子全保真）
- **数据引用双态是常态**（时点注记）：08-23 上午逆向时 示例预算表=0 DSColumn+3112 公式（`ds_fs.select()`形态）；当晚 §47-49 改造后=927 DSColumn+0 select（Comments 另有 ValueHighlightAction 306 处）。**同一模板两种形态都真实存在过** → 解析器必须双态（DSColumn + 公式），任一单态都会漏
- 公式写 Excel 必须 `data_type='s'`，否则被当 Excel 公式解析报 `#NAME?`
- openpyxl `merge_cells` **会抹掉区域内已写值** → 必须按面积降序先占大区域
- merge 后**左上格是普通 Cell 而非 MergedCell** → 偏移找空位要同时判"有值"和"MergedCell"，否则层叠卡片互相覆盖
- `getDatabase()` 返回 toString `[name Database]` → 连接名需提纯（正则取 `\[([^\]\s]+)`）
- FROM 解析要排除 pg 函数（`generate_series`/`unnest`/`VALUES`），否则函数被误收为实体表
- 目标 xlsx 被 Excel 打开时保存报 PermissionError → 生成器自动落 `_v2.xlsx` 并提示
- Excel → cpt 导入是设计器 GUI 操作（人工步骤，无法 headless）；参数区 5 行导入后按约定删除
- `${参数}` 无默认值时数据集执行 0 行/失败是**正常现象**（probe_dataset 的 WARN 语义），示例数据页此时标注总行数
