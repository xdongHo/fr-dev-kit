## 26. 下拉树控件（TreeComboBoxEditor）与树数据集自动构建（doc-1042）

### 常见问法：下拉树怎么配置？/ 想按部门层级逐级选择用什么控件？/ 树数据集怎么建？/ 下拉树选项显示不全被截断怎么办？

| 症状/口语问题 | 动作（脚本/公式/操作步骤） | 出处 |
|---|---|---|
| 无头生成下拉树 | 三步：①普通数据集 ds1 → ②树数据集 TreeDefinition（NodeKeyColumn/ParentNodeKeyColumn）→ ③面板 TreeComboBoxEditor + TreeDictionary + ColumnDictAttr(kiName/viName) | 本文件 §26 步骤 1-3（L663-L667）【实测】 |
| 树出不来/断层级/根节点异常 | 三条硬约束：根父键空 ''（非 '0'/NULL）、父键可追溯、节点键唯一 | 本文件 §26（L669-L673）【实测】 |
| 下拉树内容截断 | 宽度走 TREE_INDENT 缩进余量算法，不可落普通下拉 OTHER 分支兜 CTRL_MIN=96 | 本文件 §26 宽度铁律（L675）【实测】 |
| 省市级联算不算树/四条路线怎么选 | 自关联单表→②自动构建；单表多列层级固定→④极速（DependLayer/DependField，无 ${layerN}）；每层异表→①普通分层（${layerN}）；仅联动非树→③级联下拉 | 本文件 §27 表（L685-L692）【实测】 |

> 来源: 帆软官方帮助 doc-1042

「下拉树选部门」的无头生成配方（practice/topic_1042 已落地最小可验证生成器，自检 5/5）：

1. **普通数据集**（ds1）先建好；
2. **树数据集**：`<TreeDefinition>` 声明 `NodeKeyColumn`/`ParentNodeKeyColumn` 引用 ds1（见 02 §1.6 树数据集）；
3. **参数面板 TreeComboBoxEditor 控件**：其 `Dictionary` 用 `TreeDictionary` + `NameTreeTableData` 引用树数据集名、`ColumnDictAttr(kiName/viName)` 配置实际/显示值。

**三条硬约束**（与 02 §1.6 树数据源硬约束互证）：

- 根部门父键必须为空 `''` 而非 `'0'`/NULL；
- 父键须可追溯；
- 节点键唯一。

> 📌 **宽度铁律（doc-1042，复用既有算法）**：下拉树 `TreeComboBoxEditor` 宽度必须走 kit 既有 **TREE_INDENT 缩进余量算法**（见「ckzl/frapi/doc/参数面板格式化API清单.md」），**不可落入普通下拉的 OTHER 分支被兜到 CTRL_MIN=96** 导致树内容截断——该控件与既有 TreeEditor 的宽度规则合并到同一处约束。

## 27. 下拉树构建方式对照（doc-1050 / doc-1990 / doc-1042 / doc-1284）

> 来源: 帆软官方帮助 doc-1050 / doc-1990 / doc-1042 / doc-1284

FR 下拉树四条平行路线（关键词「树/层级/部门」高度相似，按「是否要树状展开 + 数据来源形态」分流，避免无头生成误用）：

| # | 路线 | 结构 | 过滤机制 | 适用 |
|---|------|------|----------|------|
| ① | **普通分层构建**（doc-1050） | 1 个 TreeComboBoxEditor + **N 个独立数据集** | 第 2 层起用 FR 系统内置固定参数 `${layer1}`/`${layer2}`（**不是模板参数**）过滤 | 每层来自不同表/查询、层级固定 |
| ② | **自动构建**（doc-1042） | 1 张自关联表 → `TreeDefinition` 树数据集，FR 递归出整棵 | 树数据集 | 部门树 |
| ③ | **级联下拉**（doc-1284） | N 个 ComboBox 各自绑数据集 + 自定义模板参数 `${area}` | 模板参数 | **不是树**，只是联动下拉 |
| ④ | **极速分层构建**（doc-1990） | 1 个 TreeComboBoxEditor + **1 个扁平数据集**（所有层列同表同列） | 每层 `DependLayer`（层号）+ `DependField`（父层列名）在单表内完成层级过滤，**无 ${layerN}、无每层独立数据集** | 层级固定、每层同源的轻量树 |

> ⚠️ ④「极速」是①普通分层构建的**简化版**，仅适合层级固定、每层同源的轻量树；用户说「选省带出市带出区」时，先在②（要求自关联表）与④（单表多列）之间按数据形态分流。
> 📌 **生成器族（doc-1990）**：新增「极速分层构建生成器」`build_fast_tree(spec)`——输入声明式 LAYERS（每层值列 + DependLayer + DependField），一次生成 ParameterUI 片段 + 单数据集引用；与既有 doc-1042/1050 的 `build_auto_tree`/`build_layered_tree` 并列，统一收敛到「下拉树生成器族」（脚本实现见 practice/topic_1990/gen_dropdown_tree.py，可移植）。

## 28. 控件间赋值联动（doc-1194 / doc-1195）

> 来源: 帆软官方帮助 doc-1194 / doc-1195

### 28.1 控件间赋值（doc-1194）

「选 A 自动带出 B」（控件动态驱动另一控件）四要点：

1. **form API** `this.options.form.getWidgetByName('x')` / `X.setValue(...)` vs **单元格 API** `_g().setCellValue(...)` 的区别：参数面板控件走 form API，正文单元格走 `_g()`，不可互换；
2. 「编辑后」事件名 = `event="afteredit"`；
3. **移动端须把同一段 JS 同时挂「编辑后」+「编辑结束」两事件**（否则移动端静默不触发）；
4. **多选控件 setValue 必须用数组形态** `[['02'],['05']]`（不是字符串）。

### 28.2 条件显隐控件（doc-1195）

参数控件「满足条件才显示」**只能靠运行期 JS，无声明式开关**；须同时产出两段：

1. **被控控件声明式** `<InnerWidget visible="false">`——控件本体与其**标签控件是两套独立控件**，各自设 false、JS 里分别 `setVisible`（无头生成极易只藏控件忘藏标签）；
2. **条件控件挂「编辑后」事件** `Listener event="afteredit"` 调 `this.options.form.getWidgetByName("X").setVisible(true/false)`（另有 `setEnable` 只置灰）。

> ⚠️ `this.getValue().length` 缺 null 守卫会抛 TypeError；**移动端 setVisible 无效**。
> 📌 **与 doc-1194 并族（doc-1195）**：setVisible/setEnable 与 doc-1194 的 setValue 是「参数面板控件互驱」同一族的两种效果——统一复用 form API + afteredit 事件 + 移动端盲区；生成器注入「选 A 带出 B」时 setValue 与 setVisible 常需一起写，不应分两套规则各漏一半。
> 来源: 帆软官方帮助 doc-1194 / doc-1195

## 29. 控件默认值（WidgetValue）配方（doc-1939 / doc-1862 / doc-3059）

> 来源: 帆软官方帮助 doc-1939 / doc-1862 / doc-3059

**两个独立位置别混淆**：`<Dictionary>` 决定「可选什么」，`<WidgetValue>` 决定「默认选中什么」（设计器路径：控件设置 > 属性 > 高级 > 控件值，可选公式）。

**通用配方 =JOINARRAY(value("ds",列号),"分隔符")**：用数据集整列内容动态生成默认值，适用于多选下拉树全选、多选下拉框全选、复选按钮组全选。⚠️ 多选下拉树默认值是**两级分隔符**格式：节点间 `;`、节点内完整路径层间 `,`（如 `总部,财务部,部长;总部,财务部,会计`），只写末级值无效。

**默认选中列表第 1 个值（doc-1862）**：`=sql(conn,sql,1,1)` 公式赋控件值，取结果集首行首列作为默认选中——与 JOINARRAY 全选对照（一个取首、一个取全）；**这不是级联本身**，而是级联之上叠加的「默认选中」，须与 doc-1284 字典链正交共存。

**默认值 = 公式（doc-3059）**：控件默认值可以是 FR 公式（如 `monthdelta($end_time,1)` 实现「起期 = 尾期-1 月」的联动起点），对应 `com.fr.form.ui.Widget.setWidgetValue(Object)` 接收公式对象 + XML `<WidgetValue class="..."><![CDATA[=monthdelta($end_time,1)]]></WidgetValue>`（公式对象类型与节点 class 待字节码核验）——补充了 kit 原来只写「字面量 / `${}` 同参」的默认值能力。

## 30. 动作按钮（FreeButton + click，doc-1992）

> 来源: 帆软官方帮助 doc-1992

参数面板「快捷赋值按钮」范式（一键本周/本月、一键清空/默认是参数面板最高频交互诉求，kit 之前只把 FreeButton 记在 05 填报章节）：

- `com.fr.form.ui.FreeButton` + `Widget.addListener(new Listener("click", JavaScriptImpl))`；
- JS 用 `this.options.form.getWidgetByName(name).setValue(v)` 给同面板控件赋值；**查询仍由 `com.fr.form.parameter.FormSubmitButton` 触发（按钮只填值不提交）**；
- 区间日期实例：`DATEINWEEK`/`DATEINMONTH`/`DATEINQUARTER`/`DATEINYEAR`，第 2 参 `1`=首日 / `-1`=末日；
- 可表驱动生成（practice/doc-1992 已沉淀 Java + XML 双份最小实现）。

### 30.1 JS 求值时机对照（doc-1992）

两条互斥路线，是**所有事件 JS 生成的选型第一问**：

| 写法 | 求值时机 | 能否引用用户当前输入 | 依赖 |
|------|----------|---------------------|------|
| `'${=公式}'` | 服务端**生成参数面板那一刻**求值一次，结果作字面量嵌进 JS | ❌ 只能用于与输入无关的值（如 TODAY()） | 无 |
| `FR.remoteEvaluate('公式')` | **点击/事件触发时**回服务端算 | ✅ 可引用用户刚输入的控件值 | 部署期关闭「安全管理>安全防护>脚本调用公式限制」 |

> ⚠️ `${=}` 有**过期问题**：页面挂机跨零点后仍是旧日期。选错时 FR 不报错：基准日来自控件却用 `${=}`，表现是「点了没反应/永远算成打开页面那天」，极难排查。
