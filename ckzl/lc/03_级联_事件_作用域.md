## 20. 参数面板级联（模板参数驱动，doc-1029）

> 来源: 帆软官方帮助 doc-1029 / doc-1868

参数面板两级联动与填报单元格联动（doc-608）是**两套机制**：此处驱动源是**模板参数 `$p1`**（用 `$p1` 取值），位于参数面板 ParameterUI；填报联动驱动源是单元格引用（C9）。写法：

- P1 用**自定义字典**（实际值=显示值=地区/省份）；
- P2 用**公式字典**，实际值公式：

```text
=if($p1='省份',sql("FRDemo","select 货主省份 from 订单",1),if($p1='地区',sql("FRDemo","select 货主地区 from 订单",1),""))
```

- `sql(连接名, SQL, 列序号1)` 在公式字典内直接取数，返回单列数组充当下拉项，无需预建数据集；
- 多分支用嵌套 if 拼装，默认分支返回空串 `""`；显示值留空时取实际值作显示；
- 大数据量可改「数据集字典 + WHERE ${p1}」复用连接池，但驱动源仍是模板参数 `$p1`。

> ⚠️ 与 doc-608 单元格驱动（C9）区分：参数面板无单元格坐标，把参数级联写成单元格引用会静默失效。

## 21. 参数面板控件事件（doc-3120 / doc-1434 / doc-1197）

> 来源: 帆软官方帮助 doc-3120 / doc-1434 / doc-1197

参数面板控件事件是一类独立能力，三类事件名字面相似但语义不同，无头生成极易选错事件名或读值对象前缀（`parameterEl` vs `contentPane`）：

| 事件 | 用途 | 读值/动作 API | 文档 |
|------|------|---------------|------|
| `beforeedit`（编辑前） | 层级限制：父值为空则拦截 | `_g().parameterEl.getWidgetByName('父控件名').getValue()` + `FR.Msg.alert` | doc-3120 |
| `beforeedit`（编辑前，第二种） | **下拉项 DOM 就绪时机钩子**：`.fr-combo-list-item` 展开时才生成，想操作它只能挂 beforeedit（挂 afterinit 太早，选择器返回空集） | 见下方注记 | doc-4508（原文 doc-4143） |
| `afteredit`（编辑后，PC）/ `aftereditend`（编辑结束，移动端） | 自动查询：选值即 commit | `_g().parameterCommit();` | doc-1434 |
| 查询按钮 `click`（.cpt 参数面板） | 复杂校验（日期区间/跨控件比较） | `this.options.form.getWidgetByName("x").getValue()` | doc-1197 |
| 参数面板 `FreeButton` 的 `click`（.cpt） | 显隐/模式切换开关（快捷赋值按钮） | `this.options.form.getWidgetByName('x').setValue(..)` + `_g().parameterCommit()` | doc-1481（原文 doc-1825） |
| 参数面板 `FreeButton` 的 `click`（.frm） | 读报表主体控件值 | `_g().getWidgetByName('area').getValue()` | doc-1481（原文 doc-1864） |

> 移动端盲区不同：参数面板控件事件（beforeedit/afteredit）在移动端可用（与 doc-1207 单元格读写不支持移动端相反）。

> 📌 **beforeedit 的第三种用途：渲染时机钩子（doc-4508，原文 doc-4143）**——下拉列表项 `.fr-combo-list-item` 在展开时才生成，想在列表项上绑 DOM（如悬浮提示）只能挂 beforeedit（挂 afterinit 太早、选择器返回空集）。**硬约束：beforeedit 每次展开下拉都会重跑，事件里的 DOM 绑定必须幂等**——用 `off('evt.ns').on('evt.ns')`，禁止裸 `.mousemove(fn)`/`.on(...)`，否则 handler 逐次叠加（官方示例本身就是裸 `.mousemove` 反例，照抄即叠加）。

> 📌 **.frm vs .cpt 不可互换（doc-1481，原文 doc-1864）**：上表 FreeButton 两行——`.cpt` 参数面板用 `this.options.form`（与 doc-1197 那行同前缀），`.frm` 参数面板读报表主体控件用 `_g().getWidgetByName('area')`（不经过 parameterEl），二者分属 .frm/.cpt，**不可互换**。

> 📌 **容器控件事件白名单（doc-3836）**：doc-1629 的三层事件白名单补全为四层，新增实读的 `com.fr.form.ui.container.WCardLayout#supportedEvents() = {afterinit, cardchange}`（**Tab 块，没有 click**）；`WAbsoluteLayout` 无 override、沿 `WSortLayout→WLayout` 继承 `{afterinit, click}`。配套硬约束：`Observer#addListener` 白名单不命中即**静默 return** 且 `readXML` 同样走它——**加完 Listener 必须 `getListenerSize()` 回读**，否则「XML 合法、校验通过、脚本一行不跑」的静默失败。
> 来源: 帆软官方帮助 doc-3836

### 21.1 层级限制（beforeedit，doc-3120）

子级控件挂 `beforeedit` 事件：读父控件值，为空则 `FR.Msg.alert(title,msg)` 拦截。与 doc-1284 级联字典链互补（字典链负责「父有值才刷子」，JS 负责「用户硬要先选子级」时弹提示）。

> ⚠️ 官方空值判定 `a.length<=0` 有缺陷：父级未初始化返回 null 时 `.length` 直接 TypeError 抛错 → 静默失效；健壮写法应为 `!a || a.length<=0`。

### 21.2 自动查询（auto_query，doc-1434）

参数面板默认要点「查询」按钮才呈现报表主体；绕过它：控件生成器开放 `auto_query=True`，自动给该控件注入「编辑后」（PC）/「编辑结束」（移动）事件，JS 内容固定为 `_g().parameterCommit();`（等价点击原生查询按钮；.cpt 里同义 API 为 `contentPane.parameterCommit()`）。

> ⚠️ 移动端必须用「编辑结束」事件，否则不生效；该机制常与参数面板级联（doc-1284）组合——父级选完自动 commit → 子级字典数据集随之重查刷新。

### 21.3 查询按钮 Click 校验（doc-1197）

凡「日期区间/跨控件比较」类复杂校验，必须挂在**查询按钮 Click 事件**的 JS 里，不能依赖控件自带校验——FR 控件自带校验只在「点击过该控件」后才触发，未点过的控件不校验 → 空参/非法区间静默漏检。单元格（填报）变体改用 `contentPane.getWidgetByName("x").getValue()`。

### 21.4 隐藏 Label 作状态位（doc-1481，原文 doc-1825）

无头链路里唯一「不新增数据集、不改 SQL」就能做交互显隐的手法（kit 生成器已具备全部零件：Label/FreeButton/HighlightList/参数声明，只缺串成范式的说明）。范式三段缺一即静默失效：

1. **不可见 Label 持有状态**：`<BoundsAttr width="0" height="0"/>` 的 Label 控件存状态字面量；
2. **同名模板参数 `$label`**：官方文档漏写模板参数声明这一步，不成文极易踩；
3. **单元格条件属性消费**：正文单元格条件属性按 `$label` 显隐。

> ⚠️ 状态字面量必须由生成器**统一供给**（勿用中文）；**不支持移动端**。配套触发：参数面板 `FreeButton` 的 `click` 事件 `this.options.form.getWidgetByName('x').setValue(..)` + `_g().parameterCommit()`（见 §21 事件表）。
> 来源: 帆软官方帮助 doc-1481（原文 doc-1825）

### 21.5 初始化后（afterinit，控件级，doc-1899）

控件级 afterinit 是「进场即改控件行为/绑 DOM 事件」的唯一正确生命周期，与 kit 既有 **panel 级** afterinit（`add_para_init_event.py` 注入在 `</Layout>` 后）**层级不同**：

- 控件级：注入在 `<InnerWidget>` 内、`<WidgetName>` 前；panel 级：`</Layout>` 后，二者不可混用；
- 结构：`<Listener event="afterinit"><JavaScript class="com.fr.js.JavaScriptImpl"><Content><![CDATA[...]]></Content></JavaScript></Listener>`；
- 典型用法：下拉框挂 afterinit 调 `self.onTriggerClick()` 实现「点任意位置展开」；若 afterinit 不生效，同样代码再挂 beforeedit；
- **移动端该展开交互无效**（事件仍触发，但展开行为不生效）。

> 来源: 帆软官方帮助 doc-1899

### 21.6 delay 铁律（doc-1481，原文 doc-1864）

`<DelayDisplayContent delay="false"/>` 从「生成器默认值」升格为**条件铁律**：凡 CDATA 内引用 body/主体控件名，delay 必须 false——否则首屏 body 未渲染、`getWidgetByName` 返回 null，整段 JS 静默中断（官方 doc-1864 把这步写在「效果预览」里，极易被当成排版偏好回退）。这两点都是「不报错、只是没反应」的静默失效来源，且都在改存量模板时最容易被误改。

> 来源: 帆软官方帮助 doc-1481（原文 doc-1864）

### 21.7 复选按钮组「默认全选但不显示全选按钮」（doc-1086）

复选按钮组默认全选有**两条路线**，按 §18.5「能改 SQL/声明式就不写 JS」选型默认值并置：

| 路线 | 做法 | 备注 |
|------|------|------|
| ① 声明式（首选） | `<WidgetValue>` 用 `=JOINARRAY(value("ds",列号),"分隔符")` | 见 §29 通用配方 |
| ② 控件级 afterinit JS | 挂 `com.fr.form.event.Listener("afterinit", new com.fr.js.JavaScriptImpl())` + `setContent("this.changeAllState();")` | 「默认全选但**不显示**全选按钮」时用（`this.changeAllState()` 是复选按钮组自带方法） |

> 来源: 帆软官方帮助 doc-1086
### 21.8 参数重置：两条路线（doc-1196）

控件事件小节补「参数重置」两条路线（与 doc-597 控件事件链同族，practice/topic_1196 已沉淀骨架）：

- **① 构建期更优——控件默认值留空**：`setWidgetValue("")` / XML 不写 value 即天然「初始为空」，零 JS；headless 生成参数面板时优先此路线，避免每张模板挂无谓的运行时 JS；
- **② 按钮一键清空/重置全部**：参数面板按钮 `com.fr.form.ui.Button`（`setWidgetName(String)`/`setText(String)`）挂「点击」事件注入 JS：
  - 清空单个：`this.options.form.getWidgetByName("控件名").reset();`（reset() 同时清空值与文本）；
  - 清空全部（PC）：`$.each(this.options.form.name_widgets, fn)` 遍历，排除 `item.options.type === 'label'`（标签控件）后逐个 reset()；**移动端建议逐控件 `getWidgetByName(x).reset()` 写法**（兼容 PC/App/HTML5）；
  - ⚠️ 该方法不支持「新填报预览」和「新分页预览」（老分页预览/App/H5 可用）；
- **待核验登记（与 doc-597 同批）**：Button「点击」事件 Java setter 形态（推断 `Button#setEvents(Event[])` / `com.fr.form.ui.event.ClickEvent` / `Event#setJS(String)`）与控件节点内 Event XML 形态（推断 `<events><event attribute="click"><js>…</js></event></events>`）；核验法=设计器建带点击事件按钮的基线 .cpt diff——控件事件链三篇（doc-597/409/1196）共用该节点形态，**未核验前生成器不得伪造 Event 节点**。

> 来源: 帆软官方帮助 doc-1196

### 21.9 参数面板控件 JS 事件注入 + 弹窗回填模式（doc-3127）

参数面板高频交互（弹窗选值回填），04 此前无事件注入与回填模式沉淀：

- 参数面板控件类：`com.fr.form.ui.TextEditor`（文本，候选待核）/ `com.fr.form.ui.FreeButton`（按钮，已核）；XML 落点 `<ParameterUI><Widgets><Widget class="com.fr.form.ui.X" name="控件名"/>`；
- 控件点击事件 JS 经 `<Events><Event eventName="click"><JavaScript>…</JavaScript></Event></Events>` 注入（Java 挂载类与事件参数序列化形态待核，用官方模板 `%FR_HOME%\webapps\webroot\WEB-INF\reportlets\doc\JS\参数界面JS实例\数据回填_弹窗.cpt` / `数据回填_回填.cpt` 反序列化探针）；
- 两段 JS 模板（沉淀可直接复用）：
  - 回填（子模板按钮 onClick）：`var form = window.parent.contentPane; form.parameterEl.getWidgetByName('控件名').setValue(val); window.parent.FR.closeDialog(); window.parent.FR.destroyDialog();`
  - 弹窗（主模板按钮 onClick）：动态 iframe + `FR.showDialog(title, width, height, $iframe, o)`，src 为 `…/decision/view/report?viewlet=/…/子模板.cpt&ref_t=design&op=view`；
- ⚠️ **控件名即 JS 取参名，大小写敏感**——命名错或事件未注入则回填静默失效（与 doc-2114/2624「组件名即 JS 交互 ID」约定同模式）；
- **移动端不支持弹窗回填**，选型时注明（与 doc-1196 的 reset 移动端支持性相反，勿混）。

> 来源: 帆软官方帮助 doc-3127

## 22. 参数三层作用域与模板参数定义（doc-159 / doc-157）

> 来源: 帆软官方帮助 doc-159 / doc-157

| 层 | 声明位置 | 作用域 | 落点 |
|----|----------|--------|------|
| ① 数据集参数 `${p}` | 写在 `<Query>` | SQL 层下推（doc-158） | .cpt 内 |
| ② 模板参数 | `ReportParameterAttr/Parameters` | 仅本模板可见 | .cpt 内 |
| ③ 全局参数 | 『服务器>全局参数』 | **工程级**，作用于该工程所有模板 | **不落在任何 .cpt 里** |

### 22.1 模板参数定义（doc-157）

模板参数经 模板>模板参数 写入 `ReportParameterAttr/<Parameter name=.../>`，与面板控件按 `WidgetName` 同名绑定。三要素缺一不可：① `ReportParameterAttr` 声明 Parameter ② 面板控件 WidgetName 同名 ③ 数据单元格过滤引用 `$参数`。

> ⚠️ 仅定义参数+控件、漏单元格过滤（`$参数`）→ 表格仍**全量显示**，静默失效（无头生成最易漏第三步）。

### 22.2 全局参数（doc-159）

- `.cpt` 只持有两处「引用」：单元格过滤公式 `$p`、参数面板同名控件；模板的正确性不再由模板本身决定；
- **重名遮蔽**：全局参数与模板参数重名时，界面只显示一个且**以模板参数为准**——批量生成时须持有全局参数清单做名字避让，否则把全局值静默架空；
- **部署须重设**：本地设好全局参数后，跨工程/跨环境搬运模板不会跟着走，须在目标工程重新设定（只拷 .cpt 不够）；
- 缺失**静默降级为空值**，不报错（过滤条件退化 → 空表，全链路零报错）。

> ⚠️ 校验器判定「参数未声明」必须是双输入：.cpt + 工程全局参数清单，否则会把全局参数**误报为未声明**（doc-159 实测：在模板里补声明反而触发同名遮蔽，校验通过却把全局参数架空）。
### 22.4 ${} 参数引用引号规则（用户定稿 2026-08-07，SQL/JS 通用）

> **`${参数}` 不加引号会被当成变量或数值类型**——SQL 里匹配字符串列、JS 里作为字符串参数，都必须显式加单引号（字符串）或转成数值。

**SQL 中**：
```sql
-- ✅ 字符串列: 加单引号 (参数值是字符串字面量)
WHERE version = '${para_version}'
WHERE version IN ('${para_version}')

-- ❌ 不加引号: 被当作列名/数值 → 报错或匹配错误
WHERE version = ${para_version}

-- ✅ 数值列: 不加引号正确 (自动转数值)
WHERE year = ${para_year}
```

**JS 中**：
```javascript
// ✅ 字符串参数: 加引号
_g('${sessionID}')          // 双引号(见下)
_g("${sessionID}")          // FR 封装脚本实测 OK

// ❌ 单引号或裸写: 部分 FR 封装脚本报 SyntaxError: missing ) after argument list
_g('${sessionID}')          // 单引号在部分封装下报错(2026-08-07 实测)
_g(${sessionID})            // 裸写被浏览器当模板插值,直接报错
```

> ⚠️ **例外**：cpt XML 里的 JS（`<Content><![CDATA[...]]></Content>`）可以直接写 `"${sessionID}"`（**双引号**）——FR 服务端渲染时替换为真实值；**必须用双引号**，单引号/裸写在 FR 封装脚本下会 `SyntaxError`（2026-08-07 实测踩坑）。
> 经验：符号错误先换双引号；`sql()` 函数不能用单引号拼参。

### 22.3 URL 传参（get/post）的模板侧要求（doc-1090）

打印/超链/外链以 get（query 串 `?viewlet=xxx&p1=a`）或 post（http body `data.reportlets`）向模板传参时，**模板只需注册同名普通参数即可引用 `$p1`，get/post 对模板 XML 无差异**——勿误以为需要特殊 API：

- 参数注册链与普通参数完全同构：`com.fr.data.impl.ParameterProvider#setName("p1")` + `ReportParameterAttr` 声明（链 doc-250 / §22.1 doc-157），数据集/公式中即可引用 `$p1`；
- post 的 `reportlets` 格式为 **JSON 数组字符串** `"[{reportlet: '模板.cpt', 参数: 值}]"`，`reportlet`=模板相对路径、其余键=目标模板参数名；
- 「参数传不进模板」的根因是参数未注册/键名不一致，而非传参方式；
- 老打印方式（`FR.doURLPDFPrint` flash）已淘汰：10.0 openjdk 无法启动 flash 打印（仅 Oracle/Sun jdk 可以），JAR 2018-04-09+ 应使用[新]打印方式（零客户端/本地打印）。

> 来源: 帆软官方帮助 doc-1090

### 22.5 模板参数声明的 4 种 XML 形态判别（2026-09-15 夜间批次 波实测增补）

> 来源: 夜间批次 夜间作战实测（A18/A27/A28/A29 四棒独立佐证，A44 补 frm 坑）；证据：`_runs/night/campaign/w915/A29_wparam_qx/区域协同族修复报告.md` L92-93、`_runs/night/campaign/w915/A18_fix_prep/FIX预备方案.md` L59/L248、`_runs/night/campaign/w915/A28_wparam_prep/销售看板族修复方案.md` L25、`_runs/night/campaign/w915/A27_wparam_fix/族批量修复报告.md` L22、`_runs/night/campaign/w915/A44_pair_sync/A44_pair_sync_执行报告.md` §2/§6。

FR 模板参数声明存在 **4 种 XML 形态**，检索/校验模板参数时必须**四形态全查**——只查根级 `<Parameters>` 会把既有声明误报为"零声明"：

| 形态 | XML 位置 | 实测 |
|------|---------|------|
| ① 模板级根声明 | 根 `<Parameters>` | 有族全部声明为数据集级、未见模板级（A28） |
| ② RPA 内包装 | `<ReportParameterAttr>` **内部** `<Parameters>` 包装 | 42 件（A29） |
| ③ 裸 Parameter 直挂 | `<Parameter>` 直接挂在 `<ReportParameterAttr>` 下（无包装） | 24 件（A29） |
| ④ 数据集级 | `<TableData><Parameters>` 内声明 | 含 `<Parameter><Attributes name="x"/></Parameter>` 子元素形态，FR10 主流（A18/A28） |

**声明子元素两读法**：`<Parameter name="x">`（少见）与 `<Parameter><Attributes name="x"/></Parameter>`（主流）——检索声明必须两者都查（A18）。

> ⚠️ **frm 语料专属坑（A44 实测）**：frm 的空参数块是**自闭合 `<Parameters />`**（非 cpt 的裸 `<Parameters></Parameters>`），按 cpt 假设写的裸块断言在 frm 上必中止；且 **frm 全文件 CRLF**，cpt 的 `\n` 替换块直接套用会产出异行尾块。补声明前先看同族基准件的字节形态再展开（样板：`_runs/night/campaign/w915/A44_pair_sync/_a44_patch.py`）。
> 另：同一参数可**模板级+数据集级双层声明**（同值）不冲突；后续如改默认值须**双层同步**（A44 四件即双层 `1=2`）。
