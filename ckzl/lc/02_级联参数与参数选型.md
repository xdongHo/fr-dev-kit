## 8. 级联参数
> 问法入口（2026-09-13 收官补，P5-002）：「选了省份后城市框跟着变」「级联下拉/联动过滤怎么实现」→ 本节级联参数 SQL（${if(len(...))} 子查询模式，ORDER BY 在其后）。

父控件值作为子控件字典的查询参数。三者命名必须一致：
- 控件 `WidgetName="para_bu"`
- 字典 `TableData` 参数 `<Parameter name="para_bu"/>`
- SQL 中使用 FR 公式

### 8.1 级联 SQL 写法（正确方式）

使用 `WHERE 1=1` + FR `${if()}` 公式处理空参和多选：

```sql
-- dict_region（级联 para_bu）
SELECT DISTINCT region AS 实际值, region AS 显示值
FROM 数据schema.fin_demo_auth_基础信息表
WHERE 1=1 ${if(len(para_bu)==0,"","and bu in ('"+para_bu+"')")}
ORDER BY 1

-- dict_plant（级联 para_region），plant_code 作实际值
SELECT DISTINCT plant_code AS 实际值, plant AS 显示值
FROM 数据schema.fin_demo_auth_基础信息表
WHERE 1=1 ${if(len(para_region)==0,"","and region in ('"+para_region+"')")}
ORDER BY 1
```

> ⚠️ CDATA 内**不需要**转义引号。直接写 `"` 而非 `"`。
> ❌ 错误写法: `WHERE bu IN ('${para_bu}')` — 不支持多选和空参。

> 📌 **官方原始写法对照（doc-1284）**：官方 `where 字段='${p}'` 仅在「单选 + 必填」下安全——父级未选会退化为 `= ''` 使子下拉恒空，且承载不了多选逗号串。因此 kit 一律用 `WHERE 1=1 ${if(len(p)==0,"","and f in ('"+p+"')")}`（多数人照抄官方文档，需明示「为什么不能照抄」，避免维护者改回官方写法而引入空参 bug）。
> 📌 **官方二次印证（doc-4207 / doc-947）**：doc-4207（图表超链-联动单元格图表）与 doc-947（超级链接到有参数的模板）均用同一 `WHERE 1=1 ${if(len(x)==0,"","and 字段='"+x+"'")}` 实现「参数为空选全部」，可作**标准范式复用**；维护者勿改回不安全的 `='${p}'` 原写法。
> 📌 **生成规范（doc-1284）**：第一级字典 SQL 必须 `DISTINCT` 去重；字典 SQL 统一产出 `AS 实际值 / AS 显示值` 两列，以对齐 `<FormulaDictAttr kiName viName/>`。
> 📌 **铁律适用域（doc-2857）**：`WHERE 1=1 + ${if()}` 针对「参数可空 / 可多选」（参数面板驱动）场景；若参数由图表轮播联动等机制驱动、恒为单值且已配默认值，`WHERE 字段='${p}'` 等值写法成立（doc-2857 官方示例即如此）。但同一数据集一旦被参数面板复用，必须退回 1=1 写法。
> 📌 **多选父控件（ComboCheckBox）的级联约束（doc-1285）**：当父级是**下拉复选框**时，子字典 SQL 的 `in ('"+p+"')` 只有在父控件 `ReturnValues.delimiter="','"`（**含单引号字面量**）被正确设置时才成立；否则多选返回串不带引号，`in (华北,华中)` 语法错或只匹配单值，级联静默失效。**钉死：分隔符与 in 拼接符必须成对一致**——headless 生成 ComboCheckBox 作级联父控件时漏写 `delimiter="','"` 会产出静默坏的模板（XML 节点形态见 04 §23）。
> 来源: 帆软官方帮助 doc-1284 / doc-4207 / doc-947 / doc-2857 / doc-1285

### 8.2 字典引用

子控件 Dictionary 的 NameTableData 必须包含 `<Parameter>` 引用父控件：

```xml
<Dictionary class="com.fr.data.impl.TableDataDictionary">
  <FormulaDictAttr kiName="实际值" viName="显示值"/>
  <TableDataDictAttr>
    <TableData class="com.fr.data.impl.NameTableData">
      <Parameters>
        <Parameter name="para_bu"/>
      </Parameters>
      <Name><![CDATA[dict_region]]></Name>
    </TableData>
  </TableDataDictAttr>
</Dictionary>
```

> 📌 **显示文本 ≠ 传参值：`setCodeCol`(实际值) / `setDescCol`(显示值) 双列映射（doc-1698）**——`com.fr.data.impl.TableDataDictionary` 的双列映射是「预览显示超链文本、点击传另一值」类需求的标准写法（如显示省份名、实际值传地图边界路径）。生成器产出此类字典时，实际值与显示值两列必须**同时**配置，只写一列会静默退化为「显示=实际」。
> 来源: 帆软官方帮助 doc-1698

### 8.3 参数驱动的动态表头/列名（示例模块 模式）

业务需要「选年份 → 表头显示对应年度」时，用**单元格公式拼接**，不写死任何年份：

```text
前年累计表头:  =if(len(para_data_year)>0,CONCATENATE("YTD-",(para_data_year-2)),"")
去年累计表头:  =if(len(para_data_year)>0,CONCATENATE("YTD-",(para_data_year-1)),"")
前年 1 月表头: =if(len(para_data_year)>0,CONCATENATE((para_data_year-2),"-01"),"")
去年 12 月表头:=if(len(para_data_year)>0,CONCATENATE((para_data_year-1),"-12"),"")
```

要点：
- **拼接必须用 `CONCATENATE(...)`**（2026-08-05 实测铁律）：帆软 `+` 对「数值 + 可转数字字符串」按**数值加法**处理——`(para_data_year-2)+"-01"` 会算出 `2024+(-1)=2023`，月份表头倒序错误（示例模块 实测踩坑：显示 2023/2022/2021…）。`"YTD-"+(para_data_year-2)` 因左侧文本不可转数字才侥幸走拼接，但**语义不可靠，一律用 CONCATENATE**。
- 数值计算保持括号：`CONCATENATE("YTD-",(para_data_year-2))`，括号保证先算数值再转字符串。
- 年份控件用 **YearControl**（`com.fr.plugin.widget.year.YearControl`，默认值 `=year(now())`），不要用 ComboCheckBox 装年份；控件名 = 参数名 = `para_data_year`。
- **导入页同样动态表头**：导入报表无数据集，`para_data_year` 从 URL 注入，表头单元格同公式；查看页 Import 按钮 JS 把控件值拼进 URL：`viewlet=…/导入_X.cpt&op=write&para_data_year=<控件值>`。
- 清空旧数据按业务键：DeleteConfig 主键 `data_year` 值 `=para_data_year`（见 ckzl/lc/05 §9.1）。
- 修正工具：`工作区/patch_concat.py` 模式可把存量 `+` 拼接批量替换为 CONCATENATE（YTD×2 + 月份×24）。

### 8.4 数据集参数铁律（doc-158）

把 `1=1 ${if(len(p)==0,"","and ...")}` 钉为**数据集参数唯一推荐写法**，明确禁掉裸 `WHERE col='${p}'`（空参时静默退化为 `WHERE col=''` 返回空集，产「传空=空表」却不报错的模板，排查方向全跑偏）。另补四条：

1. **多选 in 格式**：`... WHERE 字段 in ('${p}')` 要求传入值形如 `华东','华北`（**无首尾引号**），拼接后才成 `in ('华东','华北')`；误输带引号/逗号分隔会语法错或漏数据，且 FR 不报错；
2. **花括号转义**：`${}` 内直接写 `{` / `}` 须用 `CONCATENATE("销量{")` 转义，否则解析失败；
3. **同名共享**：数据集参数「不与数据集绑定」——多个数据集里同名 `${para}` 是同一个参数，值以最后一次赋值为准；需分别传值就**改名**；
4. **字典循环引用**：控件数据字典**不要指向含同名参数的数据集**（控件 WidgetName==参数名，字典指向含同名参数的数据集 → 循环引用，模板出错）。

> 无头生成数据集参数须同时写两处：`<Query>` 的 `${para}` + `ReportParameterAttr` 的 `<Parameter name>`（否则控件无法按名绑定）。
> 来源: 帆软官方帮助 doc-158

> ⚠️ **多值参数 = 受控 SQL 拼接（注入面，doc-2597）**：`IN ('${p}')` + `delimiter="','"` 的多值机制，本质是让参数值**主动闭合外层单引号**、等价于字符串拼接 SQL。凡该参数可能来自 URL/用户自由文本，生成器必须做**值白名单或字符拦截**（拦截 `'` `;` `--`），不能把该范式当普通参数用。可直接移植 `practice/topic_2597/gen_bigdata_export.py` 的 `build_param_literal(strict=True)`。
> 来源: 帆软官方帮助 doc-2597

### 8.5 方言级 SQL 静态约束（doc-2574）

方言层面纯字符串即可判定的错误，生成器应在本地直接拦（目前 kit 校验只覆盖 XML 结构/控件重名/连接名，方言层面空白），不等预览才炸：

1. **HSQL：表名不得以数字开头**（doc-2574 注1），如 `2024_sales` 这类名字应直接报错而非加引号绕过——加引号后标识符变大小写敏感，坑更深；业务库里按年份/月份建表很常见，不拦会等到预览才炸；
2. **显式 schema 前缀**：生成的 SQL 一律显式带 schema（HSQL 默认 `PUBLIC.`），禁止依赖连接侧默认模式——默认模式是服务端连接属性、不在 .cpt 里，同一模板换环境/换库后可能解析到不同的表（静默改数据的高危项）；FROM 与 JOIN **两侧都要带**。

> 来源: 帆软官方帮助 doc-2574

### 8.6 SQL 防注入的实际覆盖面（doc-2219）

`com.fr.data.impl.EscapeSqlHelper` 是 FR 的 SQL 防注入工具，但其**唯一模板侧消费点是 `com.fr.data.impl.DBTableData#getStatementSql`**——即只拦「数据库查询」数据集的参数；以下路径**全部不经过**防注入：

- 存储过程数据集；
- 内置数据集（EmbeddedTableData）/ 文件数据集（FileTableData）；
- `sql()` 公式（doc-846）。

> ⚠️ 官方文档只含糊说「仅针对模板发出的参数请求」，极易误以为全局生效。凡 kit 生成后两类内容（存储过程/`sql()` 公式等非 DBTableData 路径），**参数侧必须自带白名单/下拉约束**，不能依赖引擎层拦截。
> 来源: 帆软官方帮助 doc-2219

## 9. 数据集参数 vs 模板参数选型

> 来源: 帆软官方帮助 doc-157 / doc-2394 / doc-3315

### 9.1 选型分水岭

| 场景 | 选型 | 机制 |
|------|------|------|
| 小数据 / 前端二次过滤 | **模板参数** + 单元格过滤条件 `$参数` | 数据集全量取出后再前端过滤 |
| 大数据 / 过滤下推 | **数据集参数** `${p}`（doc-1284 路线） | SQL 层下推，数据库侧完成过滤 |

doc-157 是官方唯一明确两类参数选型边界的入口：数据量大应改用数据集参数把过滤下推到 SQL，否则先全量取再前端过滤既占内存又慢。kit 02 原只讲数据集参数、04 只讲控件，模板参数这一支完全缺位，无头生成易误把所有过滤都下推 SQL 或都漏单元格过滤而静默不生效。

### 9.2 模板参数三要素硬约束

模板参数要真正生效，三处必须同时成立（缺任一 FR 不报错但行为不符预期）：

1. `ReportParameterAttr` 声明 `<Parameter name="地区"/>`（模板 > 模板参数）；
2. 参数面板控件 `WidgetName` 与参数名**完全一致**（按名绑定，Web 端给控件赋值 = 给参数赋值）；
3. 挂该列的数据单元格加「过滤」条件，值类型=参数、值=`$地区`。

> ⚠️ 只做 ①②、漏做 ③ → 表格仍把数据集**全量显示**，过滤不生效（无头生成最易漏第三步）。
> 只做 ①③、漏做 ② → 没有录入入口，只能靠 URL 传参（`?地区=华东`）才过滤。

### 9.3 参数为空选全部：两种写法（doc-2394）

「下拉框不填值点查询时要显示全部数据」有两条等价路径，按「想在哪一层不过滤」二选一，**不要混用**：

| 方法 | 层次 | 写法 | 边界 |
|------|------|------|------|
| ① 单元格过滤（展示层） | 不改 SQL | 过滤条件 = `等于 if(len($p)==0,nofilter,$p)` | `nofilter` 是单元格过滤层关键字，**绝不能写进 SQL** |
| ② 数据集参数（SQL 层） | 下推前不过滤 | `WHERE 1=1 ${if(len(p)==0,"","and col='"+p+"'")}` | 参数空时退化为 `WHERE 1=1` 永真条件取全表 |

> 来源: 帆软官方帮助 doc-2394

### 9.4 定时调度中的参数约束（doc-3315）

被定时调度引用的模板，其数据集参数必须在「调度对象-参数设置」右侧「设置参数默认值」**加载参数列表后**，才能在调度其它位置引用；且调度**只能取「模板数据集」参数，取不到服务器数据集参数与报表函数**。headless 生成模板若漏建/漏加载参数，调度静默取不到值而无报错。

> 来源: 帆软官方帮助 doc-3315

### 9.5 参数的三个层级（doc-1270）

kit 现有参数知识只覆盖前两层，且默认「参数值可以写公式」——**文件数据集参数是第三层且规则相反（禁公式）**，层级写错不报错：

| 层 | 写法 | 值类型 | XML 落点 / Java API |
|----|------|--------|---------------------|
| ① 模板参数 | 声明 `<Parameter name>` | 任意 | `WorkBook#putParameter(new Parameter(name))` → `<Parameters>` 挂 WorkBook 下 |
| ② SQL 数据集参数 | `${p}` 写在 SQL 里 | **值可为公式** | `<Query>` 内 |
| ③ 文件数据集参数（doc-1270 §3） | 写在**文件路径**里 | **值只能是纯字符串常量，明确不支持单元格公式** | 挂 `<TableData>` 子节点；可被 URL 查询串覆盖 |

> ⚠️ 三层的 XML 落点与 Java API 都不同，层级写错不报错——生成器若按模板参数处理文件数据集参数，会把参数挂错节点、或给出公式默认值：两种错误都表现为「路径拼不出 → 数据为空 → 报表白屏」，无任何报错，归因成本极高。
> 来源: 帆软官方帮助 doc-1270

### 9.6 参数化数据集硬约束与批量导出基石（doc-3460）

「`${ID}` 占位符必须与同名模板参数一一对应」是**硬约束**：headless 生成模板时极易漏建模板参数，导致导出传参后子表全空。该模式是**批量导出（一份模板 + N 参数值）**的基石——doc-3460 的批量导出完全依赖参数化模板，生成器在产出含 `${}` 的数据集时必须同步断言同名模板参数已声明（与 §9.2 模板参数三要素、§12.2 双声明校验同源）。

> 来源: 帆软官方帮助 doc-3460

### 9.7 单元格过滤条件：Compare 常量全表与空值语义（doc-2365）

单元格过滤条件的操作符枚举是 `com.fr.data.core.Compare`（**该类在 fine-core jar，不在 fine-report-engine**），16 个常量全表与易混对高亮：

| 常量 | 值 | 语义 |
|------|----|------|
| `EQUAL` | 1 | 等于 |
| `NOT_EQUAL` | 2 | 不等于 |
| `GREATER` | 3 | 大于 |
| `LESS` | 4 | 小于 |
| `GREATER_EQUAL` | 5 | 大于等于 |
| `LESS_EQUAL` | 7 | 小于等于 |
| `BEGINS_WITH` | 6 | 开始于（**与 `ENDS_WITH` 易混**） |
| `ENDS_WITH` | 8 | 结束于 |
| `CONTAINS` | 10 | 包含（子串匹配，**与 `IN` 易混**） |
| `IN` | 12 | 包含于（集合成员） |
| `NOT_CONTAINS` | 9 | 不包含 |
| `NOT_IN` | 11 | 不包含于 |
| `NULL` | 14 | 为空（**与 `NOT_NULL` 易混**） |
| `NOT_NULL` | 15 | 非空 |
| `BETWEEN` | 13 | 介于 |
| `NOT_BETWEEN` | 16 | 不介于 |

- 单元格过滤入口：`com.fr.report.cell.cellattr.core.group.DSColumn#setCondition(com.fr.general.data.Condition)`；
- 「包含」与「包含于」在 GUI 上只差一个字、在代码里差 2（10 vs 12），写错既不报错也不校验，而语义完全不同（子串匹配 vs 集合成员）；
- **空值语义相反，不可互推**：`ListCondition` 空集求值**恒 true**（doc-4003，排查「数据太多」往这找）；`CommonCondition` 的 IN 右值为空**恒假**（排查「数据为 0」往这找）。

> 来源: 帆软官方帮助 doc-2365
### 9.8 定时区间参数的官方标准形态（doc-692）

doc-2208「调度模板参数必须给默认值」铁律的官方落地形态（调度+模板参数+单元格过滤完整示例，practice/topic_692 已沉淀构建骨架）：

- **日期区间用成对模板参数** starttime / endtime，默认值 = 公式 `Format(today()-1,\"yyyy-MM-dd 00:00:00\")` / `Format(today()-1,\"yyyy-MM-dd 23:59:59\")`——**滚动取昨天、非写死**：日期写死的默认值在无人值守调度下永远生成同一份数据，是定时模板最高频的隐性错误；
- 模板侧三要素（与 §9.2 同构）：`ReportParameterAttr` 定义参数（默认值用 `com.fr.base.Formula`）+ 参数面板同名文本控件（「控件值自动生成」=默认值自动同步模板参数）+ 单元格过滤 `日期 >= $starttime 且 <= $endtime`（两条条件 AND 并存同格，`TemplateCellElement#setFilter` + `FormulaCondition`）；
- 调度执行不渲染参数面板（doc-2208），参数只来自模板默认值或调度参数设置——**过滤公式里的 `$参数` 必须有同名模板参数定义，否则静默不过滤（全量显示）**；
- 生成器可内置「定时区间参数」工厂：一次产出 参数定义（公式默认值）+ 同名文本控件 + 过滤两条件。

> 来源: 帆软官方帮助 doc-692

## 10. 分页 SQL / 行式引擎（doc-996）

> 来源: 帆软官方帮助 doc-996

### 10.1 PageQuery 语义与方言二分

`<TableData>` 下 `<PageQuery>` 是 `<Query>` 的紧邻兄弟：`<Query>` 写整表查询，`<PageQuery>` 写「取当前这一页」，二者并存。**留空 `<PageQuery><![CDATA[]]></PageQuery>` 只对「无需写分页 SQL」的方言安全**，对必须写分页 SQL 的方言 = 不分页且不报错（静默全表取数，大数据量直接 OOM/超时）——kit 现有所有生成器都在输出这个空节点，维护者不知道它是什么就永远不会填。

| 必须写分页 SQL | 无需写（自带分页能力） |
|----------------|------------------------|
| Sqlite、Access、SQLServer2005/2008、INFORMIX、Sybase | Oracle、MySQL、HSQL、SQLServer2012+ |
> 📌 **GBase 8T（doc-2571）**：南大通用基于 Informix 12.1 源码，同属「必须写分页 SQL」列——留空 `<PageQuery>` 会静默全表取数；生成器遇 GBase 8T 连接须强制输出分页 SQL，勿按「国产库=MySQL 系」漏配。
> 来源: 帆软官方帮助 doc-2571


> ⚠️ SQLServer2012+ 虽自带分页，但主查询必须带 `ORDER BY`，否则分页错乱。

### 10.2 三层嵌套「正—倒—正」骨架与三变量

分页 SQL 骨架高度规律化，可模板化生成（LIMIT 系与 TOP 系只差「取 N 行」的语法，骨架相同）：

1. 内层 `ORDER BY k ASC` 取前 `fr_pagesize*fr_pagenumber` 行
2. 中层 `ORDER BY k DESC` 取末页行数公式行（即本页）
3. 外层 `ORDER BY k ASC` 转回正序

三个运行时变量 `fr_pagenumber` / `fr_pagesize` / `fr_rowcount` 由 FR 注入，写在 `${}` 里；**末页行数公式必须原样照抄**（丢了它最后一页会多取行）：

```sql
${if(fr_pagenumber == int((((fr_rowcount-1)/fr_pagesize)+1)), fr_rowcount-(fr_pagesize*(fr_pagenumber-1)), fr_pagesize)}
```

### 10.3 四条硬约束

- **导出一致性**：Query 与 PageQuery 的字段顺序必须一致，否则「导出文件与预览出现差异」（两段 SQL 分别拼接时列序易漂移）；
- **排序键必须唯一**：中层倒序取尾依赖稳定排序；视图/无主键表须先 `row_number() over(order by ...)` 造键，否则多页重复显示；
- **WHERE 同步**：主查询的 WHERE 条件必须原样搬进 PageQuery，否则分页时查不出数据；
- **生效开关 + 移动端盲区**：模板 > 报表引擎属性须同时勾「用行式的引擎来执行报表」+「使用按页运算分段执行报表」；且**行式引擎不支持移动端（App/H5）**——大数据量层式报表与移动端交付不可兼得，应在需求分析阶段就分流。
