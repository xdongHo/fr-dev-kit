## 1. 数据集

### 1.1 EmbeddedTableData（推荐用于离线生成）
```java
EmbeddedTableData ds = new EmbeddedTableData();
ds.setName("ds1");
ds.addColumn("供应商", String.class);
ds.addColumn("订购量", Integer.class);
ds.addColumn("单价", Double.class);

List rows = new ArrayList();
rows.add(Arrays.asList("佳佳乐", 10, 18.0));
rows.add(Arrays.asList("康富食品", 5, 21.35));
ds.getRowDataConf().get().setRowData(rows);  // 每行是 List, 不是 Object[]
wb.putTableData("ds1", ds);
```

### 1.2 ColumnNames 分隔符
XML 中列名用 `,,.,,` 分隔（不是逗号）：
```xml
<ColumnNames><![CDATA[供应商,,.,,订购量,,.,,单价]]></ColumnNames>
```

### 1.3 数据字典（DictPresent）
原始模板中 ID→名称映射用 DictPresent，EmbeddedTableData 不支持，直接用显示值即可。

### 1.4 EmbeddedTableData XML 形态（自包含 demo，doc-1839）

生成**不依赖数据库连接、拷进 reportlets 就能预览**的自包含 demo/最小复现模板时，用 XML 形态（数据随模板走，不依赖 `NameDatabaseConnection(FRDemo)`，换台机器也能跑）：

```xml
<TableData name="ds1" class="com.fr.data.impl.EmbeddedTableData">
  <ColumnNames><![CDATA[供应商,,.,,订购量]]></ColumnNames>
  <!-- 行数据节点（<RowData>/<R>/<C>）待设计器 diff 核验 -->
</TableData>
```

> ⚠️ 列名分隔符见 §1.2（`,,.,,`）；行数据 XML 节点名（`<RowData>/<R>/<C>`）仍为推断，落地前以设计器另存的真实 .cpt diff 为准。
> 来源: 帆软官方帮助 doc-1839

### 1.5 内置数据集作顺序表/字典表（doc-3622）

内置数据集除了做数据源，还可做**顺序表/字典表**：一列、行序即排序序，配 `数据集名.select(列名)` + `inarray()` 供模板层排序使用（N 项顺序 = N 行数据而非一条长公式，脚本生成最受益）。三条铁律：

1. 内置数据集名与列名会被**原样拼进公式**，必须是标识符（无空格/点/括号/运算符）——GUI 用户不会碰到，只有脚本自动命名数据集时才会踩；
2. 顺序值必须与单元格**显示值逐字符相等**（存编码而单元格显示名称 ⇒ inarray 恒 0，静默失效）；
3. 顺序表内不得有重复值（inarray 只取首个位置）。

> 排序键是 inarray 返回的数字序号，倒序可直接 `-1*(inarray(...))`（不受「字符串列不能取负」限制）；未命中恒返回 0，生产模板应写加固版 `=if(inarray(...)=0, 9999, inarray(...))`。
> 来源: 帆软官方帮助 doc-3622

### 1.6 树数据集（TableTreeData，doc-126）

FR 的第二类数据集类型：树数据集**不自己取数**，而是引用一个已存在的普通数据集，按【本ID, 父ID, 显示名称】三列建层级（组织树/部门树/下拉树最高频需求；与 04 的级联下拉是不同拓扑——级联是父子两张数据集，树数据集是一张自关联表出整棵）。节点骨架：

```xml
<TableData class="com.fr.data.impl.TableTreeData" name="Tree1">
  <FromTableName>ds1</FromTableName>
  <IdColumnName/><ParentIdColumnName/><CaptionColumnName/>
</TableData>
```

> ⚠ 节点名待核；Java 侧为 `setFromTableDataName/setIdColumnName/setParentIdColumnName/setCaptionColumnName`。**生成顺序**：普通数据集节点必须先于引用它的树数据集节点。⚠类名 `com.fr.data.impl.TableTreeData` 未经 jar 验证：FR10 全部 44 jar `which/find` 均 0 命中（2026-09-12 实测），真实类名待运行期确证前本骨架仅作结构示意。

**生成规约（父ID模式）**：设计器的两种建树方式中，headless 生成**只使用「父ID模式」**。源表若是「ID 长短有规律」（01/0101/010101），用 SQL 折算出父ID：

```sql
CASE WHEN CHAR_LENGTH(id)<=2 THEN NULL ELSE LEFT(id, CHAR_LENGTH(id)-2) END AS pid
```

（每层位数不同则按长度 CASE 分档），结果与「长度模式」完全等价。「按标记字段长度构建树」的 XML 开关节点名未核实，**核验前禁止生成**。

**树数据源三大硬约束**（三条全是「不报错只出空树/重复节点」的静默故障，都发生在数据层而非 XML 层）：

1. 必须是【本ID, 父ID, 显示名称】固定三列（ID 可为字符串），建议源 SQL 统一 `AS id/pid/caption` 后再绑定；
2. **根节点父ID列必须为空**，写 0/-1/'root' 一律建不出树，源 SQL 加 `NULLIF(上级ID,'')` 归一（与 doc-1042 记录的坑一致，两篇互证）；
3. 同行父子属性的宽表必须先 `UNION ALL` 拆成长表，**每段加 DISTINCT**；层级不定用递归 CTE / CONNECT BY。

> 来源: 帆软官方帮助 doc-126

### 1.7 数据源类型选型表（doc-1269 / doc-1270）

| 数据集 | 实现类 | 部署依赖 | 数据时效 | 需 DB 连接 | 适用场景 |
|--------|--------|----------|----------|-----------|----------|
| DB 数据集 | `DBTableData` | 需连接 | 实时 | 是 | 业务查询 |
| 服务器数据集 | `NameTableData` | 需连接+平台 | 同步 | 是（平台侧） | 可同步用户信息 |
| 内置数据集 | `EmbeddedTableData` | 无 | 自包含快照 | 否 | 离线生成/自包含 demo |
| 文件数据集 | `FileTableData` ⚠待核 | 需部署文件（WEB-INF/reportlets 下） | 读文件 | 否 | 客户只给 log/csv、没有数据库 |

**文件数据集家族**（doc-1270 与 doc-1269 是同一实现类的两个 fileType，共用 `com.fr.data.impl.FileTableData` ⚠待核，共用「相对 WEB-INF/reportlets」路径语义与 DSColumn 消费侧，只有 TableData 那层不同）：txt/csv（doc-1269）/ Excel（doc-1270）/ XML / URL（远程）。子类型差异只三格：

- 分隔符白名单（逗号/空格/制表符，**仅 txt/csv**）；
- 20M 文件上限 + 导入单元格上限（**仅 Excel**）；
- 动态文件名参数（Excel 文档专列；txt 未提但同属 path 层，疑同样支持 ⚠待验）。

文本数据集硬约束：分隔符只支持逗号/空格/制表符；路径相对 reportlets；首行列标题可选。

**文件数据集两种文件位置与无头选型（doc-1985，原文 doc-1938）**：reportlets 相对路径 / 绝对 http URL。无头链路选型结论：**优先「构建期 HTTP 拉取 + EmbeddedTableData 快照」**（全已核验 API、模板自包含）；`com.fr.data.impl.FileTableData` 的 URL 分支类名/setter 标为**待核 API**。三条约束：① URL 无 .xls 后缀故文件类型必须**显式指定**；② URL 非 ASCII 须 percent-encode（官方明确「jsp 文件名请使用英文，否则连接失败」）；③ 数据集级参数值只能是**纯字符串常量，不支持单元格公式**（见 §9.5 参数三个层级）。

> 来源: 帆软官方帮助 doc-1269 / doc-1270 / doc-1985

### 1.8 零数据集模板：元数据公式（doc-3244）

FR 有 `tables(conn)` / `FIELDS(conn,table)` / `RECORDS(conn,table,field)` 这组**元数据公式**，可在不建任何 TableData 的情况下直连数据连接取库表结构与数据（「让用户自选表查看」类需求不必去动态拼 SQL 数据集）。**安全约束**：无 where / 无分页 / 无行列权限，`tables()` 会枚举全库表名——连接名下拉框必须走**白名单自定义字典**，禁止铺出全部连接。定位为运维/数据字典自查工具而非业务报表。

> 来源: 帆软官方帮助 doc-3244

### 1.9 非 SQL 数据源的三条 Java 路线（doc-1985）

对**任何**插件/非 SQL 数据源（JSON、Excel、接口、Hadoop）成立的通用解法，绕开「插件类名不可知」：

1. `com.fr.data.impl.NameTableData(String 数据集名)` + `WorkBook#putTableData` → `<TableData class="com.fr.data.impl.NameTableData"><DataSourceName>`，引用服务器上已定义的数据集（含插件数据集），**构建端不需要插件 jar**；
2. `com.fr.data.impl.EmbeddedTableData#addColumn(String,Class)` + `getRowDataConf().get().setRowData(rows)`，构建期抓数烤成快照，运行期零依赖；
3. `com.fr.data.AbstractTableData` 子类打 jar 放 WEB-INF/lib + `com.fr.data.impl.ClassTableData` 引用（⚠节点名/setter 待核）。

三者与单元格绑定完全解耦（`DSColumn(dsName,colName)` 不变），数据源可整体替换。

> 来源: 帆软官方帮助 doc-1985

### 1.10 为界面服务的辅助数据集（doc-1939）

除业务查询外，常需为**控件默认值**单开一个扁平数据集（如 doc-1939 的 ds4：`a','||b||','||c`），其产物不上报表、只喂给控件值公式（配合 `JOINARRAY(value("ds",列号),"分隔符")` 实现默认全选）。各库字符串连接方言：Oracle/达梦 `||`、MySQL `CONCAT`、SQLServer `+`；建议 `SELECT DISTINCT` 去重。

> ⚠ **`||` 在 MySQL 下默认是逻辑或（非连接符）**，跨库迁移时会静默产出错误默认值；无头生成时容易只建「业务数据集」而漏掉这类「界面辅助数据集」，导致默认全选无从实现。
> 来源: 帆软官方帮助 doc-1939
### 1.11 sql() 公式函数（doc-406）

`sql(连接名, SQL, 列号, 行号)` 是参数面板/单元格公式常用函数，数据建模章节补全签名与边界：

- 返回**单值**；**省略行号参数时返回整列**（参数面板中表现为逗号分隔的多行文本）；
- SQL 内拼参数写法：双引号包单引号——`'\" + $id + \"'`；
- 参数面板场景：标签控件值放 sql() 公式带出关联数据（见 04 §7.11 参数面板内嵌数据展示，doc-406）；级联参数场景：公式字典内 `sql(连接名, SQL, 列序号1)` 返回单列数组充当下拉项（见 §8 级联参数）；
- 与 `value()` 选型：默认 `value()`（性能+扩展，doc-534），跨数据集/复杂查询用 `sql()`。

> 来源: 帆软官方帮助 doc-406
