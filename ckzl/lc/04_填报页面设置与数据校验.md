## 21. 填报页面单独设置（禁用工具栏）

> 📁 脚本: `kfgj/tygs/CPT模板/默认格式/2.参数面板控件布局/set_write_no_toolbar.py`

### 21.1 正确方式：WebWriteContent

FR 10.0 填报页面"为该模板单独设置"不是独立的 `<ReportWriteWebAttr>`，而是在 `<ReportWebAttr>` 内部添加 `<WebWriteContent>`：

```xml
<ReportWebAttr>
  <ServerPrinter/>
  <WebPageContent>                         <!-- 常规预览 -->
    <ToolBars>...<ToolBar/></ToolBars>
  </WebPageContent>
  <WebWriteContent>                        <!-- ✅ 填报单独设置 -->
    <ToolBars/>                            <!-- 空 = 禁用工具栏 -->
    <EditRowColor setColor="false"/>
    <WebWrite SheetPosition="3"/>
    <RptLocation isShowAtLeft="true"/>
    <UnloadCheck/>
    <ShowWidgets/>
    <OtherAttr autoStash="false"/>
  </WebWriteContent>
</ReportWebAttr>
```

> ❌ 错误: 添加独立的 `<ReportWriteWebAttr>` 元素——这不是 FR 10.0 的正确方式。

### 21.1.1 填报页面设置 9 项 ↔ XML 全量映射（doc-136）

> 来源: 帆软官方帮助 doc-136（填报页面设置）

设计器「模板>模板web属性>填报页面」9 项 ↔ XML（doc-136 是官方唯一逐项讲透该面板的文档，kit 内 gen_import.py / gen_fill_v2.py / gen_lta_detail.py 的实际写法与之逐字吻合，可直接升格为已验证事实）：

| 设计器项 | XML | 取值/说明 |
|---------|-----|----------|
| 报表显示位置 | `<WebWrite SheetPosition>` | 取值域 {1,3} |
| 显示位置 | `<RptLocation isShowAtLeft>` | 是否靠左显示 |
| 编辑行背景色 | `<EditRowColor setColor>` + `<SelectedColor color>` | `setColor="true"` 与 `<SelectedColor>` 必须成对 |
| 未提交离开提示 | `<UnloadCheck/>` | 勾选态=空节点（默认） |
| 直接显示控件 | `<ShowWidgets show>` | `show="true"`=勾选；`<ShowWidgets/>`（默认）=不勾选 |
| 自动暂存 | `<OtherAttr autoStash>` | — |
| 工具栏 | `<ToolBars>` | 空=禁用工具栏 |
| 事件 | `<Listener event="writesuccess">` | 填报成功事件（见 §10.1） |

**两条语义注解**：
- ① `<SelectedColor color>` 是**含 alpha 的有符号 32 位 ARGB，正常为负数**（`-2829096==0xFFD4D4D8==RGB(212,212,216)`，见 gen_import.py:39）——写 web 正整数不报错但颜色错乱；且 `setColor="true"` 与 `<SelectedColor>` 必须成对。
- ② doc 表格注明 sheet位置/显示位置/编辑行色/直接显示控件/自动暂存**在移动端全部无意义**——移动端只识别「是否显示填报提交按钮」。

### 21.2 一键命令

```powershell
python "kfgj/tygs/CPT模板/默认格式/2.参数面板控件布局/set_write_no_toolbar.py" <cpt路径>
```

- 已有 `WebWriteContent` 则跳过
- 无 `ReportWebAttr` 则自动新建完整结构
- 自动备份

> ⚠️ **破坏性副作用（doc-136）**：`<WebWriteContent>` 的「存在与否」本身就是语义——不存在=「采用服务器设置」（跟随 服务器>服务器配置>填报预览设置），存在=「为该模板单独设置」，**且写出后模板永久脱离服务器统一配置，XML 上无任何标记可回溯原状态**。故批量格式化脚本只应在「明确需要模板级差异」时补该节点，**禁止无差别补全**；「采用服务器设置」的正确产出是**不产出节点**，而不是产出一个填满默认值的空节点。§21.2 现有「无 ReportWebAttr 则自动新建完整结构」的行为须按此约束收紧——服务器端改填报预览设置将对被误摘模板全部失效，且不可逆。

### 21.3 填报模板生成器强制收尾两件事（doc-136）

> 来源: 帆软官方帮助 doc-136（填报预览）

- ① **交付链接必须拼 `&op=write`**——预览方式**由 URL 决定、不由模板决定**，无 op 即只读分页预览（漏了表现为「用户说填不了」）；
- ② **模板尾部写 `<PreviewType PreviewType="1"/>`**（1=填报/0=分页，实证 gen_import.py:61、gen_fill_v2.py:149 vs gen_template.py:355）——它**只影响设计器再次打开时的默认预览方式，不参与运行时**（漏了表现为「设计师说打开是只读的」）。

两者独立、都容易漏；故障描述完全不同却常被混为一谈——ckzl/lc/01 只把 `&op=write` 当预览命令写在操作步骤里，未把「URL 决定预览方式、模板不决定」这条**机制**说清；PreviewType 则全库只有生成器在闷头写值、无任何文字解释。

### 21.4 直接显示控件 / 未提交离开提示的精确 XML 形态（doc-136，闭合 doc-1828 待核验）

> 来源: 帆软官方帮助 doc-136（填报页面设置）/ doc-1828（填报页面 Web 属性）

**闭合 doc-1828 遗留的待核验项**（此前判断「属 EditReportAttr/WebAttr 范畴、需先抓 GUI 产出 .cpt 核对」——doc-136 直接给出官方界面项清单、与 kit 内生成器写法逐字对上，无需再抓 GUI）：

- 勾选「直接显示控件」= `<ShowWidgets show="true"/>`；不勾选（默认）= `<ShowWidgets/>`；「未提交离开提示」勾选态 = `<UnloadCheck/>`（默认）。均位于 `<ReportWebAttr>/<WebWriteContent>` 内——**kit 全样本已验证两种 ShowWidgets 形态**。
- 落地 headless 生成时应一并写入：不补此项，填报预览会多出「未提交离开」提示或控件不直显（体验级易漏坑）。

## 22. 填报数据校验（强制校验：校验不通过不允许提交）


> 来源：《项目实施表单设计》Step-017/019 + 实践经验。填报数据校验强制：提交前校验不通过则阻止提交（内置校验+自定义校验，详见 22.1-22.4）。

### 22.1 校验类型对照（填报数据校验总览：强制校验，校验不通过不允许提交）

| 校验类型 | 触发时机 | XML 位置 | 适用场景 |
|---------|---------|---------|---------|
| **格式校验** | 控件级别（录入时） | Widget 内部 | 数字框拒绝字母、日期格式 |
| **非空校验** | 提交前 | ReportWriteAttr/TopVerifier | 主键列必填 |
| **业务规则校验** | 提交前 | ReportWriteAttr/TopVerifier | 唯一性、范围、逻辑一致性 |

### 22.2 非空校验（TopVerifier）

```xml
<ReportWriteAttr>
  ...
  <TopVerifier class="com.fr.report.write.ValueVerifier">
    <name><![CDATA[非空校验]]></name>
    <VerifyItem class="com.fr.data.VerifyItem">
      <O t="XMLable" class="com.fr.base.Formula">
        <Attributes><![CDATA[=LEN(A2) > 0]]></Attributes>
      </O>
      <message><![CDATA[="*Required-[BU]A"]]></message>
    </VerifyItem>
    <VerifyItem class="com.fr.data.VerifyItem">
      <O t="XMLable" class="com.fr.base.Formula">
        <Attributes><![CDATA[=LEN(B2) > 0]]></Attributes>
      </O>
      <message><![CDATA[="*Required-[Region]A"]]></message>
    </VerifyItem>
  </TopVerifier>
</ReportWriteAttr>
```

> 每个 VerifyItem 对应一个校验规则。`A2`/`B2` 指向填报单元格，message 是校验失败时的提示。

### 22.3 控件级格式校验

| 控件类型 | 校验方式 | 示例 |
|---------|---------|------|
| NumberEditor | 内置：只接受数字输入 | `<Widget class="com.fr.form.ui.NumberEditor">` |
| DateEditor | 内置：日期格式选择器 | `<Widget class="com.fr.form.ui.DateEditor">` |
| TextEditor + 正则 | WidgetAttr 内配置 | 需通过 JS 事件监听 |

### 22.4 业务规则校验示例

```xml
<!-- 唯一性校验：提交前检查数据库是否已存在相同主键 -->
<VerifyItem class="com.fr.data.VerifyItem">
  <O t="XMLable" class="com.fr.base.Formula">
    <Attributes><![CDATA[=sql("数据连接1","SELECT COUNT(*) FROM 数据schema.fin_demo_input_lta_detail WHERE bu='"+A2+"' AND month='"+F2+"'",1,1) = 0]]></Attributes>
  </O>
  <message><![CDATA[="该BU+Month组合已存在，请检查"]]></message>
</VerifyItem>

<!-- 范围校验：数值必须在 0-100 之间 -->
<VerifyItem class="com.fr.data.VerifyItem">
  <O t="XMLable" class="com.fr.base.Formula">
    <Attributes><![CDATA[=AND(G2 >= 0, G2 <= 100)]]></Attributes>
  </O>
  <message><![CDATA[="LTA 3rd 必须在 0-100 之间"]]></message>
</VerifyItem>
```

### 22.5 校验与提交的关系

```
用户点击提交
    │
    ├─ ① 格式校验（控件级，录入时已限制）
    │
    ├─ ② 非空校验（TopVerifier，提交前触发）
    │     └─ 失败 → 弹出提示，阻止提交
    │
    ├─ ③ 业务规则校验（TopVerifier，提交前触发）
    │     └─ 失败 → 弹出提示，阻止提交
    │
    └─ ④ 提交入库（IntelliDML/Delete+Insert）
          └─ 成功 → writesuccess 回调
```

### 22.6 数据校验 Java API 链路与反直觉点（doc-567）

> 来源: 帆软官方帮助 doc-567（数据校验）

kit 的填报知识此前只覆盖提交侧（BuiltInSQLSubmiter 等），校验侧完全缺位。完整 Java 链路：

```
WorkSheet#addAttributeTarget(new ReportWriteAttr())   // 键为 xmlTag()，一 sheet 只能一份
→ com.fr.report.write.ValueVerifier#setName / addVerifyItem
→ new com.fr.data.VerifyItem(new com.fr.base.Formula("D2>0&&D2<10000"), "销售成本超出范围！")
→ ReportWriteAttr#addVerifier(Verifier)
```

**三个反直觉点（没有一个能从类名/字段名推断出来）**：
- ① XML 标签是 `<TopVerifier class="...ValueVerifier">` **不是 `<Verifier>`**（`Verifier.XML_TAG` 常量实读）——§22.2 现有示例已按正确形态书写；
- ② **`addAttributeTarget` 重复 add 静默覆盖**（一 sheet 只能一份 ReportWriteAttr）——追加校验必须先 `getAttributeTarget("ReportWriteAttr")` 取回；`clearVerifiers(true)` 只删内置校验、`clearVerifiers(false)` 只删类校验（`WClassVerifier`），`getValueVerifierCount()` ≠ `getVerifierCount()`；
- ③ `addVerifier(String,Verifier)` 的 String 形参字节码里**从未被读取**，去重完全按 `v.getName()`；且它与 `addVerifier(Verifier)`（纯 list.add，允许同名重复）语义完全不同。

### 22.7 模板级自定义校验：DefinedVerifyJob 三件套（doc-564）

> 来源: 帆软官方帮助 doc-564（自定义校验）

公式校验难以表达的业务逻辑走 Java 校验类（本质 = 取填报数据 → 自定义程序判断 → 结果返回页面展示；仅支持返回结果展示、支持移动端）：

- 校验类继承 `com.fr.data.DefinedVerifyJob`（接口 `com.fr.data.VerifyJob`），覆写四方法：`doJob(Calculator)`（校验逻辑入口）/ `getMessage()` / `getType()` = `Verifier.Status.parse(0|1)` / `doFinish()`；私有 int type 默认 0；成功时前端固定显示「校验成功」（getMessage 成功文案无效），失败时显示 getMessage() 内容；
- **「属性名 ↔ 字段名」注入契约**：模板「增加属性」的属性名必须与类字段同名——JobValue 类型字段绑定单元格（**不支持单元格组**），String/int 等普通类型按声明类型注入；取值经 `com.fr.base.Utils.objectToString()` 归一化（JobValue.getValue() 可能为 Integer 或字符串，先转字符串再 parseInt）；
- 部署：编译后 .class 按包路径放 `WEB-INF/classes`（或设计器内编译），**替换 class 必须重启设计器/服务**；
- XML 落点：模板级数据校验配置在「报表填报属性」（区别于单元格级校验），预期位于 `.cpt` 的 `<ReportAttr>` 数据校验节点（含校验类全名与属性列表，属性名=Java 字段名；节点名待官方「自定义校验.cpt」对照核实）；
- 参考 `practice/topic_564_hermes`。

### 22.8 Excel 导入场景控件校验静默失效（doc-2711）

> 来源: 帆软官方帮助 doc-2711（填报暂存，数据校验注记）

- **导入不生成控件**，控件级校验（控件内置格式校验 / afteredit JS 校验）在导入链路**一律不触发**——凡填报模板带 Excel 导入且依赖控件校验时，应改用模板级校验（§22.7 或公式校验）兜底（原建议内容在批次生成时截断，此处按完整语义补全）。

## 23. 填报选型前置检查（doc-1168）

> 来源: 帆软官方帮助 doc-1168（填报预览-总览；该 doc 在 LEARNINGS 无独立条目，内容经 §13（doc-2194）write_plus 表述交叉验证一致）

- ① 目标数据库命中**不支持清单**（hive/impala/adb-mysql/MongoDB/行云/MaxCompute/sapbw/麦杰openPlant5.0/presto/doris/星环/oceanbase/StarRocks）时填报方案不可用；clickhouse 仅支持插入提交；
- ② 模板结构避免「类 Excel」（表头非扩展单元格 + 多行同字段重复）；
- ③ 扩展行多时不用 sql() 函数、不开启直接显示控件；
- ④ write_plus 不兼容文档中大部分 JS 方案（官方总述，见 §13 注记）。
