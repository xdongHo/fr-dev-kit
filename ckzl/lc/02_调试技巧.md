### 16.2 常见问题
> 问法入口（2026-09-13 收官补，N-010）：「单元格字体设置出来特别大」「字体异常放大」→ 行高字体单位换算（FU，铁律 C）与样式批量脚本 fix_styles.py；单位换算实证见 kfgj/xlyl/单位换算实证.md。
| 问题 | 原因 | 解决 |
|------|------|------|
| 下拉为空 | Dictionary class 错误 | 用 `TableDataDictionary` + `NameTableData` |
| 字体过大 | FRFont.getInstance size 参数理解错 | size 是 pt 值，不是 pt×8 |
| DSColumn 显示为文本 | 用了紧凑格式 `ds1.G()` | 用 Python XML 生成完整 `<O t="DSColumn">` |
| 行高不协调 | FU 换算错误 | 表头 1442289(10mm), 明细 1153643(8mm) |
| 冻结不生效 | columnrow 索引 | 行号需 +1 |
| 编译找不到类 | classpath 不全 | 必须包含 WEB-INF/lib 全部 22 jar |
| export 报 LicenseContext | 离线环境正常 | 忽略，文件正常生成 |
| setRowData ClassCast | 用了 Object[] | 每行必须是 List |
| 定时附件 0kb / 找不到文件 | 文件名公式展开超 255 | 按公式最坏展开长度校验「文件名称」，报 `Result file creation failed`（doc-3185） |
| 定时结果链接点开报无权查看 | 调度对象勾了「任务结束即清理」 | 改为「仅保留最近 N 次」/不清理（doc-3185） |
| 定时结果链接以 localhost 开头 | 决策系统 URL 未改实际 IP | 改成实际 IP 后**必须重新编辑保存任务**才生效（doc-3185） |
| 定时任务恒定偏移 8 小时 | OS/工程机/JVM 三层时区 | 加 `-Duser.timezone=Asia/Shanghai`（doc-3185） |
| 定时执行偶尔不跑且运行监控无记录 | 多工程共用同一 FineDB（任务"跑到别的工程去"） | 查 `information_schema.processlist`/`v$session` 看几台机器连着 FineDB（doc-3185） |
| 「任务结束即清理」+ 邮件/FTP/SFTP/挂载/打印 | 结果文件被清理，附件发不出 | 定时结果链接报 `Index: 0, Size: 0`；排查口诀：先看清理策略，再看 `%FR_HOME%/webapps/webroot/WEB-INF/schedule` 目录是否有件（doc-2208） |
| 模板能打开、预览无数据/报错 | 连接名/权限问题而非 SQL | 排查顺序：①连接名在目标环境是否存在 ②运行账号（及其角色/部门）对该连接是否有「使用」权限（需先开分级授权+数据连接控制）③才查 SQL/参数（doc-4153） |
| 运行账号看起来有连接权限却取不到数 | 持有的是「授权」而非「使用」权限 | 仅有授权权限的账号可把连接权限委托给他人，但自身预览/取数会失败；headless 必须用持「使用」权限的账号运行 fr_check/fr-agent 预览（doc-4154） |
| 报表变慢/平台整体卡顿，且工程里存在 HSQL 连接 | 连接指向内置 FineDB（URL 路径含 finedb） | 官方禁止非必要创建内置 FineDB 连接：HSQL 使用时建内存数据库，报表取数与平台自身争内存（doc-2574） |
| 导出文件 0 字节/打不开 | OutputStream 未 close | 确保流关闭后再落盘（doc-1108） |
| 模板里 JS 做的效果导出后消失 | **符合预期**：JS 纯前端、导出走服务端 | 凡需体现在产物里的效果必须落到模板/后台属性（doc-1108） |
| 导出 PDF/图片异常 | JDK 版本 | 官方点名 jdk1.8.0_262 / 8u231 / 8u192 不建议用于导出（doc-1108） |
| 导出报 `SQLException: Database lock acquisition failure: lockFile:...` | FineDB 是内置 HSQL 不支持多线程，**设计器开着就锁死** | 删 `WEB-INF/embed/finedb/db.lck` 只能撑一次，根治是迁外接库；结论：**导出机不装/不开设计器**，这是导出能否进 CI 的前置条件（doc-3814） |
| 预览有角标（上下标）、API 导出后丢失 | 后台 Exporter 与前端预览是两条渲染路径，后台不支持角标 | 兜底走 URL 导出 `/decision/view/report?viewlet=X&format=pdf` 读流落盘（doc-3814） |
| HTTP 取数型数据源（URL 文件数据集/远程接口）返回空表或「文件损坏」 | 排查首位是**服务端返回 HTTP 200 + HTML 错误页/登录跳转页**，而非网络不通 | 按内容魔数校验（xls=D0CF11E0、xlsx=504B0304），不要只看响应码（doc-1985） |
| 切库后想回滚，发现回不去 | `MigrationContext#backupDBProperties()` 是 **rename 不是 copy**，且已存在的 `db.properties.bak` 会先被 `delete()`——只保留上一次，连切两次库最初的内置库配置永久丢失 | **切库前必须自己另存一份 db.properties**（doc-1485） |
| 测试连接通过、提示配置成功，之后工程启动/建表报错 | `AbstractTransferManager#afterTransfer()` 会 `addRawProperty("hibernate.hbm2ddl.auto","update")` 再 `db.init()`，由 hibernate 自动建表补列 | 目标库账号**必须有 CREATE/ALTER**；权限不足在「测试连接」阶段完全暴露不出来（doc-1485） |
| 远程设计预览数据集报「数据连接失败」 | **首查设计器与服务器的 JAR 版本是否一致**（官方给的唯一原因） | 不要先去查数据库连通性/账号密码（doc-2188） |
| 决策平台里「没有权限/看不到目录/目录管理点不进去」（含 admin） | **首查功能列表是否注册了「决策平台」功能点** | 表象都指向权限/数据库，实际根因是 jar 版本与注册功能点；不要先翻权限配置（doc-2188） |
| Oracle 场景 `directExportToExcel` 的 `colNames` 静默丢列 | `colNames` 大小写必须与 SQL 返回列名（默认大写）一致 | 按 SQL 返回列名对齐大小写（doc-2597） |
| date/datetime 空值导出失败 | JDBC 驱动对空日期处理差异 | JDBC URL 追加 `zeroDateTimeBehavior=convertToNull`（doc-2597） |
| SQL Server 大数据导出报错 | 未设服务器游标 | 设置服务器游标（doc-2597） |
| Presto 报 `Connection.prepareStatement is not yet implemented` | 驱动过旧 | 升级 `presto-jdbc-339.jar`（doc-2597） |
| `com.microsoft.sqlserver.jdbc.SQLServerException：TCP/IP 连接失败` | 连接链路任一环 | 排查顺序：URL/IP/端口 → databaseName 实例名 → 远程连接 → 用户 → TCP/IP 协议启用 → 服务 → 端口号；「去 databaseName 分段单测」定位（doc-306） |
| 扩展点返回的「名字」显示成一串类全名 | DTO 字段与 provider 方法交叉映射：`ThemeBean.setId(provider.name())` / `setName(provider.text())` / `setCover(provider.coverPath())`——`name()` 返回的是 **id**（习惯用实现类全限定名），`text()` 才是显示名 | 按「name()=id、text()=显示名」交叉映射（doc-2406） |
| 配置里存「类全名」的项在插件卸载后静默失效 | `ThemeService#getActiveThemeStyle` 用 `Iterables.find(set, pred, null)` 三参带默认值版，找不到只 `logger.info("mobile theme '{}' can not find")` 后返回 `emptyMap()` | 插件未装/被卸载时无任何报错，注意排查插件维度（doc-2406） |
| 平台功能异常：掉登录/收不到消息/在线人数不刷新/内存 CPU 不显示 | WebSocket 没起来 | 探针 `com.fr.web.socketio.WebSocketEnv.isStartup()`（`WebSocketChecker#doCheck` 就是这一句）；日志关键词 `WebSocketSever does not startup`（官方拼写少个 r）与 `is already used, cannot start web socket server!`（doc-2512） |
| 改了 WebSocket 端口仍不生效 | 混淆两侧端口 | `WebSocketConfig.port` 是服务端 bind 用（改错→服务起不来）；`WebSocketConfig.requestPorts` 是浏览器/反代连接用（改错→服务起来了但前端连不上）；`getAvailablePorts()` 顺序由 `isUsingProxy()` 决定（true 时 requestPorts 在前）（doc-2512） |
| 模板搬到另一工程/挂到服务器后，某块效果消失但无任何报错 | 插件未安装**或已安装但被禁用**，XML 节点被静默丢弃 | 排查：①grep .cpt 的 `class="com.fr.plugin.*"`；②查工程日志 warn；③`PluginManager.getContexts()` 列已装插件、`PluginContext.isRunning()` 判是否启用；④`PluginCollector.getCollector().getErrorPlugins()` 看加载失败（doc-3531） |
| 超链跳转报 414 Request-URI Too Large | 子表名含中文经 URL 转义后超长 + Nginx 反代默认 header buffer 过小 | 解法在 `nginx.conf`：`client_header_buffer_size 512k;` / `large_client_header_buffers 4 512k;`，**模板层无解**；预防手段是模板名纯 ASCII（doc-4195） |
| 超链到 help.fanruan.com 打不开 | `WebHyperlink#createWebPath` 走前端 `FR.doHyperlinkByGet` 管道会附加时间戳（字节码实读：Java 侧 `createPrefixURL()` 只做 `getURL().render()`，时间戳是前端加的，任何 setter 都关不掉） | 唯一绕法是换类用 `JavaScriptImpl` + `window.open(...)`（doc-4195） |
| 移动端属性改了但没效果 | ①自适应只在 HTML5 端/App 端生效，PC 预览不体现；②误用 `com.fr.report.fit.ReportFitAttr`（那是 PC 自适应 `fitStateInPC`/`fitFont`）；③部分机型横向自适应失效需预留行高余量；④.frm 决策报表是 `Form.setFormMobileAttr` + 报表块 `ElementCaseEditor.setVerticalAttr/setHorziontalAttr` 两套，与 .cpt 不通用 | 按①②③④逐项核对（doc-575） |
| 某个用户就是看不到/看得到某模板 | 该 (userId, entityId, authorityType) 上存在 roleType=USER 的 AuthorityRecord（界面上的黄色小人）——存在即该项权限彻底不继承部门/角色 | 恢复继承的正确操作是**删除该记录**（`clearUserAuthorityValue`），不是把值改成 NONE（doc-773） |
| 用 0mm 行高做条件属性隐藏可能静默失效 | `RowHeightHighlightAction.writeXML` 仅当 `rowHeight.more_than_zero()` 才写出 `<RowHeight>`，字面量 0 会被丢弃（XML 属性静默丢失族） | 需对照真实 .cpt 复核 FR 是否用哨兵/渲染特例；否则隐藏应改用专门「隐藏行列」动作或非零等价值（doc-954） |
| 定时报表数据不是当天的 / 时间戳与预期差 N 小时 | JVM 时区 ≠ 业务时区，触发时刻与 `TODAY()` 共用该时区 | 启动脚本固定 `-Duser.timezone`；跨时区部署改由调度侧显式传数据窗口参数（doc-4068） |
| 报表块跑马灯（滚屏 JS）× 报表块定时刷新 / 移动端（App/H5） | **互斥组合**：定时刷新会重建报表块 DOM，注入的 handler 与 setInterval 句柄全部失效；移动端不走同一套 DOM | 生成器在同一个报表块上同时检测到滚动 JS 与定时刷新配置时应直接报错（而非 WARN）（doc-306/2369） |
| 防注入开关在管理页显示已开、但参数照样放行 | `PreventSqlInjConfig#setUseForbidWord/setUseEscapeSpecialChar` 只写 FineDB、不推 `EscapeSqlHelper` 内存单例；唯一无条件推送只在 `getInstance()` 首次初始化时跑一次（零日志） | 改配置必须走 `ConfigService#setPSIConfig`，或自行补 `EscapeSqlHelper.getInstance().setUseXxx(...)`；已写歪的环境重启即恢复（doc-2219） |
| 引用的 JS/CSS 一个都没加载，页面无任何提示 | 渲染侧 `WebUtils#getImportedJS/getImportedCSS` 先 addAll 服务器级（`getGlobalWebAttr()` = `StableFactory.getMarkedClass("ReportWebAttr", Configuration.class)`，唯一注册点 `com.fr.report.module.EngineModule`）再 addAll 模板级，整段裹 try/catch **只 logger.error**；EngineModule 未启动时首个 addAll 即抛 → 返回空集 → **模板级引用一并丢失** | 排查先看 fanruan.log 该行 error；另同一 Set 去重发生在 `TemplateUtils.render` 与 contextPath 拼接之前、按原始字面量比较：服务器级与模板级引同一路径只加载一次，差一个前导 `/` 会加载两次（doc-615） |
| 中文乱码（填报/查询最高频） | 数据连接 URL 未带 characterEncoding 或 MySQL 服务端字符集不一致 | 检查 `JDBCDatabaseConnection.url` 是否带 `?useUnicode=true&characterEncoding=utf8`，并与 MySQL `SHOW VARIABLES`（character_set_client/connection/database/results/server）对齐（doc-854，细节另见 doc-1127） |
| 插件/配置都对但功能不生效、且无任何日志 | 该功能的开关可能放在 `ThreadLocal` 里：FR 中凡形如 `public static XxxProvider getPreferredXxx()`（无参、返回上下文相关对象）的静态方法，大概率读 ThreadLocal，脱离原始执行线程恒返回 null（实证 `BaseCalculationJob.emailSendProvider`） | 无头复用调度/Web 输出组件（如 `OutputPNG`）前先确认 provider 有值；排查先查 ThreadLocal 归属（doc-1086/2547） |
| 装了邮件正文图片插件，正文仍是 HTML | `sendMail` 返回 false 会 fallback 回 `EmailManager.getInstance().send(...)` 的 HTML 老路，不抛异常、前端零差别 | 唯一判据是 fanruan.log 两行 **info**（不是 error）：`"<全类名> is selected"`（`EmailUtils#getPreferredEmailSendProvider`）与 `"Schedule email provider: {}."`（`EmailPreviewHTML#sendEmailWithParameter`），可区分「没选中」与「选中了但发失败」（doc-1086/2547） |
| 报表出图落盘得到 0 字节文件 / 出图看不出参数生效 | ①`ImageExporter#export` 末端 `ImageIO.write` **返回 boolean 且 FR 不检查**，格式名不在 JDK 已注册 writer 里时静默产空文件、零日志；②`ImageExporter#exportToImage(WorkBook)` 内部传的是**空 HashMap** 且 actor 硬编码 `"page"` → 带参模板出的是参数默认值结果；③宽高任一 >**56364px** 触发 `imageSizeExceedsLimit` | 出图后强制断言 `file.length()>0`；带参模板改走 `TemplateWorkBook#execute(params, ActorFactory.getActor("page"))` + `export(OutputStream, ResultWorkBook)`（doc-1086/2608） |
| 部署后页面能开但功能缺失/只剩诊断页 | 主 Spring 上下文没起：`fanruan.log` 无 `Server started with build:` 行（`DecisionServletInitializer#start()` 末尾唯一输出点），走了 `MockServletStartUp.start(...)` 兜底，只剩四个包 Controller 存活（com.fr.web.controller.common / ...decision.api.deployment / ...decision.entrance / com.fr.decision.webservice.exception）；两类根因：①`FineAssist.containsToolsJar()` 为假（实读 = `"true".equals(System.getProperty("debug"))` 或 attach 类加载成功；**用 JRE 而非 JDK 部署必命中**，日志找 `Cannot not find com.sun.tools.attach.VirtualMachine`，应急 `-Ddebug=true`）；②抛了 `LifecycleFatalError`，看 `ErrorType`（FINEDB/TOOLS/WBESOCKET…） | **第一步只看那行日志，不要先去逐项试配置**（doc-1086） |
| 升级/替换 jar 后进度回读为空，误判「没执行」而重复操作 | `UpdateService$2#run()` 的 exception_table 有 7 条、清一色 catch `java.lang.Exception`，把**每一次 StateHub put 都单独包起来**（其中 handler 体只有 `astore_1; goto 187`，纯吞、无日志）；StateHub 未就绪时 `getUpdateProcess()` 的 8 个键全写不进去，而跑 jar 替换的线程照常执行；互斥锁 `"updating"` 也在 StateHub，读不到=互斥失效=可能并发两次替换 | 轮询进度前一律 `StateHubManager.isReady()`；通用判据：**可观测通道被吞 ⇒ 读不到 ≠ 没执行**（doc-1163） |
| 设计器与服务器版本不一致导致本地预览正常、服务器异常 | 服务端**没有任何小版本强制**：唯一 `com.fr.workspace.engine.validate.impl.VersionNotMatchValidator#validate` 只比 `ProductConstantsBase.MAIN_VERSION`（即 `"10"`），errorCode 11300113——10.0.5 连 10.0.19 照样通过 | 自查：直接读 `WEB-INF/lib` 各 jar 内置戳文件比日期段（core=`build.txt`、report-engine=`report_build.txt`、其余 `build-<模块>.txt`；accumulator/swift-log-adaptor/third/webui 四个 jar 无戳只能比 md5）；⚠ 戳前缀有 `Build#persist-`/`Build#stable-`/裸值三种 ⇒ 只能比前 10 位日期、禁止 equals 原串；可执行版见 `practice/topic_1163_java/VersionGuard.java`（doc-1163） |
| FineDB 不可达 / `please check the database service ... jdbc:hsqldb:file://...` | 内置 HSQL 被锁：URL 由 `FineDBProperties#getDefault()` 按 `WorkContext.getCurrent().getPath()` 拼出，两个 JVM 指同一 root 必冲突 | 释放锁用 `com.fr.decision.db.embed.HsqlDBUtils.shutdownHsqlDB(url)` 优雅 `SHUTDOWN;`，**不要删 db.lck**（doc-1163/1342） |
| 想回退内置库（FineDB） | 只删文件不够：`FineDBProperties#get()` 返回 `option.copy()` 副本、`config/db.properties` 经 `DBPropertyCipher` 加密写入 | `WorkContext.getWorkResource().delete("config/db.properties")` + `FineDBProperties.getInstance().clear()`（`clear()` 只清内存缓存不删文件，漏掉它本次 JVM 仍读旧值）（doc-1163/1342） |
| 配置里存「类全名/插件 id」的值回读正确、但功能完全没变化 | 消费侧静默兜底：`MobileResource#getSelectedStyleSettings()` 未命中即 `new MobileT9DirectoryProvider()`、`DirectoryJsBundleFilter#accept` 不等即不下发 bundle，两处均无异常无日志；与 doc-2406「插件卸载后配置里的类全名静默失效」同源 | **验收必须反查注册表**（如 `ExtraMobileClassManager.getArray(...)` 存在 name()==selected 的 provider），回读相等不算验收通过（doc-1163/3050/2406） |

### 16.3 根因层判据（部署类故障）

**HTTP 状态码对 FR 部署故障不具判别力**——doc-3814 里同一个 404 有三种不相干根因（URL 漏工程名或大小写、`JAVA_HOME` 未设、Tomcat 版本过低），400 是第四种（RFC3986 字符校验），必须落到日志文本二分：

- `RFC` 字样 → relaxedQueryChars；
- `Can't load AMD 64-bit .dll` → 位数；
- `UnsatisfiedLinkError` → 原生库；
- `fine assist start failed` → attach.dll；
- `Database is not initialized` → **内存不足，不是数据库**。

「根因层」分类：模板 / 数据 / 插件 / 决策系统 / **JVM-JDK** / **中间件** / OS-原生库——同现象跨多层根因是常态，不标根因层就会在错误的层里反复试错。

**误导性报错标记**：前端「配置管理员密码出错」+ 后台 `Database is not initialized`，文字全指向数据库，真因是 exe 版 Tomcat 启动内存过小。

**Tomcat 部署速查**：
- 部署清单第 0 步固定为「先配 `WEB-INF/config/log4j.properties` 拿到 fanruan.log」（doc-3814 §2.5，appender 类名是重打包的 `com.fr.third.apache.log4j.*`）——其余 8 条故障的判定几乎全靠读 fanruan.log，日志没配好等于所有排查手段同时失效，它必须排在最前而不是「出问题再配」；
- 其余部署要点：JDK 版本（导出相关点名 jdk1.8.0_262/8u231/8u192 不建议）、Tomcat 8.5.57+、URIEncoding=UTF-8、JVM `-Dfile.encoding=UTF-8 -Djava.awt.headless=true`。

> 来源:帆软官方帮助 doc-3814

### 16.4 定时任务排查口诀（两级判定）

第一级「**有没有件**」：任务显示成功但拿不到产物，一律先看 `%FR_HOME%/webapps/webroot/WEB-INF/schedule/<任务名>/` 有没有件：

- 有件但发不出去 → 清理策略/通道（doc-2208）；
- 有件但 0kb → 文件名公式展开超 255（doc-3185）；
- 根本没件 → 行式引擎缺插件（doc-1481）。

第二级「**件对不对时候**」（有件且内容完整、格式正确时走这一支）：

- 产物时刻整体偏移 N 小时 → 查 L2 JVM 时区（`-Duser.timezone`），任务按 JVM 时区解释「开始时间」，偏移恒定且日志全绿（doc-4068）；
- 数据窗口错一天（「日报少一天/多一天」）→ 模板含服务端日期公式 + 时区错配，触发时刻与 `TODAY()` **一起漂移**，任务越贴近 `00:00` 越易踩（doc-4068）。

补充判据：见到英文 `Not supported yet` 即可判定为「FR 内部显式未实现」，改模板/改调度配置一律无效，直接跳到「缺插件/缺能力」结论（该判据比中文的「快照生成失败」更可靠，doc-1481）。

> 来源:帆软官方帮助 doc-1481/4068

### 16.6 图表空数据提示不生效的四步判定序

全部来自 `com.fr.plugin.chart.ToJSONHelper#addChartEmptyDataStyleConf` / `VanChartGlyph#addEmptyDataTip` 字节码实读（官方 doc-2336 只有 GUI 截图，没提地图不支持/设计器不渲染/附件缓存三件事）：

1. **是不是地图** —— `VanChartGlyph#addEmptyDataTip` 首条门 `plotGlyph.isSupportEmptyData()`，`com.fr.plugin.chart.map.VanChartMapPlotGlyph` 硬返回 false（全 jar 仅两个实现），地图永远不出提示，与配置无关；
2. **是不是在设计器里看** —— 第二道门 `if (!getChartWebPara().isChartInDesigner())`，设计器内预览恒不渲染，只能 Web 预览验收；
3. **换了图没变** —— 出图走 `AttachmentHelper.addAttachmentWithID` 按固定 ID `EMPTY_CHART_IMAGE_ID_PRE` 缓存（命中即 return 旧附件不重编码），靠 `ChartEmptyDataStyleConf.needResetCache` 脏标记失效，而该标记**只有 `setEmptyDataImage()` 会自动置 true**，只改 custom/adjust 或直接改 FineDB 表都不会 → 需手动 `setNeedResetCache(true)`；
4. **只改了「适应」没开自定义** —— `auto = isCustomEmptyDataStyle() ? isAdjust() : true`，内置图恒适应，单改 adjust 零效果。

> 共同特征：配置值写对了、回读也对、就是看不见效果，不给判定序会反复改配置。

### 16.10 WebSocket 启动失败时序（「等 2 分钟再重启」为何是硬约束）

`WebSocketActivator$3#operationComplete` 失败分支实读：`retry.incrementAndGet()` + `iconst_5/if_icmpge`（**≥5 次放弃**）+ `Thread.sleep(5000L)` + 用**同一个端口**重试（不换端口）；外层 `startServer` 只 `countDownLatch.await(30L, SECONDS)`，超时抛 `LifecycleFatalError("Failed to start websocket server.", ErrorType.WEBSOCKET)`。

⇒ 总窗口 ≈ 20~30 秒 ≪ TIME_WAIT。这也解释了「明明 netstat 看着没进程占用」仍会启动失败：TIME_WAIT 状态下 `NetworkUtils.bindable` 用的是客户端 Socket + SO_REUSEADDR 试绑，与 netty 实际 bind 行为不完全等价。

> 来源:帆软官方帮助 doc-4130

### 16.11 交付前集成检查清单

1. 宿主 HTTPS + 报表 HTTP 会被浏览器 block；`upgrade-insecure-requests` 只救静态资源，报表必须真配 SSL；
2. iframe 报 X-Frame-Options 时优先用 `WebSecurityConfig.setContentSecurityPolicyHeader("frame-ancestors 'self' https://宿主域")` 而非 `setFrameOptionsEnabled(false)`，且要先排查 Nginx/Apache/IIS 是否也发了该头；
3. 引 `finereport.js` 必须排在自写 jQuery 之前（FR 内置 jQuery 1.12.4）；
4. 跨域 iframe 只能 postMessage。

> 这四类故障都不在 .cpt 内，fr_check.py 查不出、jcxt/js也没有对应条目，却是模板交付后最常见的「报表本身没问题但页面打不开」场景。

> 来源:帆软官方帮助 doc-4624

### 16.12 NoClassDefFoundError / ClassNotFoundException 的版本归属判据

拿到类名先 `python jar_class_probe.py --jars C:/frjars find <类简单名>`：

- **0 命中 = 版本/插件不匹配（补 jar 无解，须换整套）**——例：doc-1342 §4 的 `NoClassDefFoundError: com/fr/base/theme/ThemedTemplate` 在 12 个 10.0 jar 里全 0 命中，该类是 11.0 引入的，官方「重新替换 jar 包」的真实含义是换整套版本；
- **有命中 = classpath 顺序或 ClassLoader 问题（补 jar 有解）**。

> 一条命令即可把「换 jar 试试」型建议收敛成确定结论，也可用于升级前的静态兼容扫描。

> 来源: 帆软官方帮助 doc-1163

### 16.13 产物 → 写入 API → 失效 API → 是否需重启（第五类：WorkResource 静态资源）

kit 现有产物分类（模板 XML / 平台 FineDB / 图片 / 编译产物）缺**第五类：WorkResource 下的静态资源**（`assets/map/*.json` 等）。其失效链最反直觉——**写入有 API，失效点却在别的模块的 Activator 里**，现象统一为「回读正确、渲染是旧的、零日志」：

| 产物 | 写入 API | 失效点 | 是否需重启 |
|------|---------|--------|-----------|
| 地图 JSON（`assets/map/*.json`） | `MapEditService.saveJSON` / `GEOJSONHelper.saveGeographicGEOJSON` | 三层：L1 `GEOJSONHelper.URL_JSON_MAP` 可 `reload()`/`resetCache(path)`；L2 `com.fr.plugin.chart.map.server.ChartGEOJSONHelper.defaultGeoUrl`（static）全 jar 反查 Methodref **唯一调用点是 `com.fr.chart.activator.ChartBaseActivator#start()`**，运行时无法失效；L3 `GEOJSONHelper#change()` 的 `geoChangeListeners` 全 jar 唯一注册者是设计器侧 `GEOJSONTreeHelper`，无头恒空 | **换地图 JSON 必须在 JVM 启动前完成，或换完重启工程** |

同族条目：附件 ID 缓存（doc-2336）、函数类缓存（doc-1840）。

> 来源: 帆软官方帮助 doc-3836

### 16.14 公式回归的最轻路径（公式级单测）

「公式 = 纯理解级、只能写字符串」的归类应改为可编程面：

1. 每个 FR 公式函数都是 `com.fr.function.<全大写名>` 的 public 类（继承 `com.fr.script.AbstractFunction` → `com.fr.script.CalculatorEmbeddedFunction`，后者在 **fine-third** jar）；
2. **不需要 WorkBook/Workspace/WorkResource**：`com.fr.script.Calculator.createCalculator().evalValue("<公式串>")` 即可求值，适合对生成模板里的每条公式做单测（比全量导出粒度细、失败定位快）；
3. 一部分纯计算函数还下沉到 `com.fr.cbb.func.impl.other.*Func#call(Object[])`（零 FR 上下文）；
4. 断言必须先判 `com.fr.stable.Primitive`（NULL / ERROR_VALUE / ERROR_NAME 三态），`!= null` 恒真。

> 来源: 帆软官方帮助 doc-1191

### 16.16 .cpt/.frm 改写铁律：遍历控件事件一律用 listeners 集合语义（doc-4437）

`TreeNodeToggleButton` 已实证 FR 存在子类把**运行期内建监听器**混进 `getListenerSize()/getListener(int)` 的返回值（`getListenerSize()=super+1`、`getListener(i)` 把内建 `default_listener` 插在 index 0），而 `Observer#writeXML` 只遍历 listeners 字段——读写两条链**错位一位**，任何按索引遍历再回写的 .cpt 改写器都会把运行期监听器落盘，**每改写一轮多一份**（XML 合法、fr_check 通过、零日志）。铁律：**遍历/回写控件事件一律用 `Observer` 的 listeners 集合语义，禁止用 `getListenerSize()/getListener(int)`**；若改写器已按索引遍历过，检查同一 `<Widget class="...TreeNodeToggleButton">` 下是否出现 `event="afterinit"` 且 Content 含 `_node_init()` 的 `<Listener>`（该监听器本不落盘，出现即改写器污染）。

> 来源:帆软官方帮助 doc-4437
