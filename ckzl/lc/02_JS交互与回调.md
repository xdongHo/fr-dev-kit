## 10. JavaScript 交互（js 回调 / 提交后事件 / callback 回调函数）

### 10.1 填报成功回调（提交后事件/writesuccess：提交成功后 js 回调 callback）

> 📌 **位置**：`ReportWebAttr/WebWriteContent` 内（**`<ToolBars/>` 之前**），是**报表级**提交成功事件——
> 任何方式提交（工具栏按钮 / 自定义 FreeButton 调 `verifyAndWriteReport(true)`）成功后都会触发。
> 不配在按钮控件里。真实实例：`导入_示例明细表B.cpt`（关弹窗+刷新父页）、`LTA信息.cpt`（`_g().parameterCommit()` 刷新数据）。

```xml
<WebWriteContent>
  <Listener event="writesuccess">
    <JavaScript class="com.fr.js.JavaScriptImpl">
      <Content><![CDATA[
        // 弹窗场景：关弹窗 + 刷新父页
        window.parent.FR.closeDialog();
        window.parent._g().parameterCommit();
        // 独立填报页场景：提示 + 刷新当前数据
        // FR.Msg.alert("提交成功");
        // _g().parameterCommit();
      ]]></Content>
    </JavaScript>
  </Listener>
  <ToolBars>...</ToolBars>
</WebWriteContent>
```

### 10.3 填报分页（大数据明细，四件套）

> **适用**：填报预览(op=write)下数据量大的明细（如 示例模块 999 行导入/查看），前端渲染会卡 → 分页只加载当前页。
> 官方机制：`__cutpage__=v` 开启填报分页 + **行后分页条件属性**控制每页行数 + 工具栏**占位自定义按钮**承载分页条。
> 实测案例：示例模块 查看页 2026-08-06（43 列 × 999 行，每页 100 行）。

**① 列表展示（前提，避免合并单元格）**：DSColumn 单元格 `<RG class="...FunctionGrouper">` 内加 `<Attr divideMode="1"/>`（详见 ckzl/lc/03 铁律）。缺失时分组展示把相同值行合并成巨大单元格。

**② 行后分页条件属性**（配在**首个数据单元格** A3）：
```xml
<HighlightList>
  <Highlight class="com.fr.report.cell.cellattr.highlight.DefaultHighlight">
    <Name><![CDATA[行后分页]]></Name>
    <Condition class="com.fr.data.condition.FormulaCondition">
      <Formula><![CDATA[(row() - 2) % 100 = 0]]></Formula>
      <!-- N=表头行数：示例模块 2 行表头→-2；1 行表头→-1；每页行数改 100 即可 -->
    </Condition>
    <HighlightAction class="com.fr.report.cell.cellattr.highlight.PageHighlightAction">
      <P i="1"/>
    </HighlightAction>
  </Highlight>
</HighlightList>
```

**③ 模板参数 `__cutpage__=v`**（ReportParameterAttr 内，`</ParameterUI>` 之后）：
```xml
<Parameter>
  <Attributes name="__cutpage__"/>
  <O><![CDATA[v]]></O>
</Parameter>
```

**④ 填报工具栏占位自定义按钮**（WebWriteContent/ToolBars 内，**分页条显示在其下方**；实测 2026-08-06：占位按钮放**底部工具栏 `position="3"`**，分页条随之出现在页面下方）：

> ⚠️ **UI 删不掉**：填报工具栏的自定义按钮一旦添加，设计器 UI 无法删除/移动——增删必须直接改 XML（删整个 `<ToolBarManager>` 块）。示例模块 实测踩坑。

```xml
<ToolBarManager>
  <Location>
    <Embed position="3"/>   <!-- 底部工具栏（顶部为 1） -->
  </Location>
  <ToolBar>
    <Widget class="com.fr.form.ui.CustomToolBarButton">
      <WidgetAttr aspectRatioLocked="false" aspectRatioBackup="-1.0" description="">
        <MobileBookMark useBookMark="false" bookMarkName="" frozen="false" index="-1" oldWidgetName=""/>
        <PrivilegeControl/>
      </WidgetAttr>
      <Text><![CDATA[]]></Text>
      <Hotkeys><![CDATA[]]></Hotkeys>
    </Widget>
  </ToolBar>
</ToolBarManager>
```

⚠️ 注意：填报分页不支持列分页/移动端；分页后 JS 只能取当前页单元格；URL 直开填报页可临时 `&__cutpage__=v` 验证。

**⑤ 配合冻结表头（必须）**：填报分页 + 冻结要生效，表头行必须设**重复标题行** + 报表冻结，缺一不可（官方文档注意事项 + 示例模块 实测 2026-08-06）：
- 表头行单元格：`<CellPageAttr repeat="true"/>`（每页重复表头）
- 数据行单元格：`<CellPageAttr/>`（DSColumn 铁律）
- 报表冻结：`<ReportSettings>` 内 `<FrozenColumnRow columnrow="A3"/>`（A3=冻结前 2 行表头，见 ckzl/lc/03 §3.6）
- ⚠️ 帆软「重复与冻结设置」里**填报预览冻结与分页预览冻结是两套独立配置**；示例模块 实测填报预览冻结由 ReportSettings/FrozenColumnRow 生效，前提是表头行 repeat=true
- ⚠️ **填报冻结区不可圈入可扩展数据单元格**（`=ds.select()/list()` 等）：普通填报预览会把扩展出的全部数据都冻结（长表失去滚动意义）；生成填报长表时冻结区应只覆盖静态表头（详见 ckzl/lc/03 §3.6.2，doc-611）。

**⑥ 行后分页的两种形态：条件断点 vs 静态断点（doc-4068 + doc-1304）**

> 来源: 帆软官方帮助 doc-4068（报表分页）/ doc-1304（行后分页）

「行后分页」是**通用分页断点**能力，不限于填报大数据明细，并列两形态：

| 形态 | 实现 | 适用面 | 状态 |
|------|------|--------|------|
| ① 条件断点 | 现有四件套（`DefaultHighlight` + `FormulaCondition((row()-N)%P=0)` + `PageHighlightAction<P i="1"/>`） | 扩展数据块，页数随行数自适应 | ✅ 已实测，无头链路默认选它 |
| ② 静态断点 | 单元格属性>其他>行后分页，`<CellPageAttr ...>`（属性名 ⚠待核） | 不扩展的固定版式块 | ⚠ doc-1304 官方在 B5/B10/B15 三个死格上用 |

- ⚠️ 静态断点**只适用于不扩展的固定版式块**，数据一扩展断点即漂——「静态/动态两形态的适用面差异」是选错就必错的判据。
- **决策报表的 `gotoPage(pn>1)` 依赖的正是这两者之一**，二者都没有时块只有 1 页（.frm 块翻页需求查本节，不要只查填报语境）。

**⑦ doc-553 边界两条（doc-1213）**：

> 来源: 帆软官方帮助 doc-553（填报分页）

- **分页后 `$$page_number` / `$$totalPage_number` 页码函数失效**——依赖页码函数的模板不能套此方案（§10.3 现有「不支持列分页/移动端」之外补的两条边界之一）。
- **行后分页公式 `(row()-N)%M=0` 里的 `N`=表头行数不能照搬**：文档示例 -1 因仅 1 行表头，实测 2 行表头须 -2——生成器应按实际表头行数计算 N 再写公式（避免误带页码函数或照搬 -1 导致分页错位）。

### 10.4 按钮点击读写单元格（doc-1207）

> 来源: 帆软官方帮助 doc-1207（JS获取填报单元格值或给单元格赋值）

- `_g()` 即 `contentPane`，是填报预览（op=write）下操作单元格的总入口；`getCellValue`/`setCellValue` **仅填报预览生效**，普通分页预览取不到/设不进，且**不支持移动端**（App/H5 白屏）。
- 两种定位方式：坐标法 `(reportIndex, col, row)`（0 基、**列号在前**，`getCellValue(0,1,3)` = B4）适合循环遍历扩展行；名法 `("E4", null)` 适合定点读写。
- **扩展单元格（如 A4 向下扩展 N 行）不能用单点 `getCellValue("A4")`**——必须给点击事件注入**事件参数** `len = COUNT(A4)`（是事件参数、不是模板参数），再 `for(i=0;i<len;i++) getCellValue(0, col, i+row0)` 逐行读写。这是把「实时扩展行数」传入 JS 的唯一官方机制。

标准结构（Button + click + 事件参数 + get/setCellValue）：
```xml
<InnerWidget class="com.fr.form.ui.Button">
  <WidgetName name="ReadExt"/>
  <Listener event="click" name="ReadExt_Click">
    <Parameters>
      <Parameter name="len"><![CDATA[COUNT(A4)]]></Parameter>
    </Parameters>
    <JavaScript>
      <Content><![CDATA[
        for (i = 0; i < len; i++) {
          var v = getCellValue(0, 1, i + 4);   // 逐行读扩展格 B 列
          setCellValue(0, 1, i + 4, v + 1);    // 逐行写回
        }
      ]]></Content>
    </JavaScript>
  </Listener>
</InnerWidget>
```

- `setCellValue` 只改**前端显示值、不触发填报提交**；要入库必须配 `verifyAndWriteReport`/提交按钮（见 §10.1、§12）。
- 坐标与单元格名混用时列号 0 基且列在前（B=1、E=4；行号=文档行-1）——生成期用注释标注真实坐标，避免读错列却不报错。
- 可移植生成器：`practice/topic_1207/gen_cell_js.py`（含坐标映射/len 注入自检）。

### 10.5 通用控件交互注入器（doc-1736 泛化）

> 来源: 帆软官方帮助 doc-1736（JS实现隐藏决策报表组件）

§10.2 的 `<Listener event="click"><JavaScript><Content><![CDATA[...]]></Content>` 模板可**泛化**为注入任意 `_g().getWidgetByName('X').method(...)` 调用（setVisible / setEnable / fireEvent 等），setVisible 只是其一：

```xml
<Listener event="click" name="Toggle_Click">
  <JavaScript>
    <Content><![CDATA[
      _g().getWidgetByName('chart1').setVisible(false);   // 隐藏图表块
      _g().getWidgetByName('report0').setVisible(true);   // 显示报表块
    ]]></Content>
  </JavaScript>
</Listener>
```

- `setVisible` 只对「报表块 / 图表块」（决策报表组件）有效，普通单元格、tab 等不支持——别给非块组件塞这个调用（静默无效）。
- **导出坑（静默类）**：组件被 `setVisible(false)` 后，**导出必须带 sessionID**，否则隐藏组件会被一起导出——不报错，只是导出文件里多一块本该隐藏的内容。无头导出链路遇到含 setVisible(false) 的模板必须确认带 sessionID。
- 前端隐藏 ≠ 服务端隐藏：任何 JS 隐藏的组件，服务端导出/打印不受影响。

### 10.6 适用边界：定时调度不触发 Web 属性自定义事件（doc-3185 §19）

> 来源: 帆软官方帮助 doc-3185（定时调度常见问题 §19）

⚠️ **定时调度不会触发模板 Web 属性设置的自定义事件**（如填报成功事件）。定时填报场景下写在 JS 事件里的业务逻辑（回写下游表、发通知、清缓存）**一律不执行**——生成的定时填报模板会「看起来配好了却什么都没发生」，且无任何报错，排查成本极高。

- 必须下沉到**提交配置 / 存储过程等服务端环节**，不能靠模板 JS 事件。
- 生成器在检出「填报模板 + JS 事件承载业务逻辑」+ 定时调度用途时给出告警。
- 与 doc-3315（调度任务内无法触发报表 JS 事件，见 ckzl/lc/03 §12）同源结论。

### 10.7 事件挂载路径对照表（doc-1206 + doc-4068 + doc-259 + doc-3059）

> 来源: 帆软官方帮助 doc-1206（日期控件联动）/ doc-4068（超级链接-JavaScript）/ doc-259（控件事件）/ doc-3059（手机端模板）/ doc-918（网络报表超链）

| 挂载路径 | 挂载对象 | 事件名来源 | action 可选类型 |
|---------|---------|-----------|----------------|
| ① 单元格控件级 | `TemplateCellElement.setWidget(w)` + `w.addListener(Listener(evt, js))` | 控件类 `supportedEvents()` | `com.fr.js.JavaScript` 接口 |
| ② 参数面板控件级 | `WParameterLayout.addWidget(w)` + `w.addListener(...)` | 同上（①②共用控件事件字典） | 同上 |
| ③ 模板级 | `ReportWebAttr → setWebWrite(WebWrite) → addListener(Listener("afterload", js))` | 独立（模板事件） | 同上 |
| ④ 表单组件级(.frm) | `Form.getWidgetByName(name)` 或 `Form.getBodyContainer()`（WLayout） | `com.fr.form.ui.Widget` 的 **public static** 常量（`AFTERINIT='afterinit'`、`EVENT_CLICK='click'`、`BEFOREEDIT`/`AFTEREDIT`/`STOPEDIT`/`CHANGE`/`EVENT_STATECHANGE`） | 同上 |
| ⑤ .frm 参数面板级 | `Form.getParaContainer()`（cast `WParameterLayout`）→ `addWidget(w)` + `w.addListener(Listener(evt, js))` | 同参数面板控件字典 | 同上 |

**硬规则：控件事件名按具体控件类的 `supportedEvents()` 取，不得统一照抄 FieldEditor 的四件套**——`addListener` 对不支持的事件名**不校验、不报错、静默不触发**。字节码实读：

- `FieldEditor` = {afterinit, beforeedit, afteredit, stopedit}（→ NumberEditor/TextEditor 等）；
- `DateEditor` = {afterinit, **afteredit**, stopedit}（**override 掉了 beforeedit**）；
- `Button` = {afterinit, click}；
- `WLayout.supportedEvents()=={"afterinit","click"}`（所有布局共用，body 亦支持 click，官方文档未提）。
- 查法：`python practice/topic_3274_java/probe_strings.py <类全名> --method supportedEvents`。

**action 可选类型（新增列）**：`Listener` 的第二参是接口 `com.fr.js.JavaScript`——`JavaScriptImpl`（手写 JS）与 `com.fr.js.ReportletHyperlink` 等 Hyperlink 子类**都是它的实现，可直接互换**。**铁律：能用超链对象表达的跳转，一律不写 JS**（`new ReportletHyperlink(path)` + `setReportletPath/setExtendParameters/setShowParameterInterface/setByPost`，父类 `Hyperlink.setTargetFrame("_blank")`/`setLinkTitle`/`setWidth`/`setHeight`）。另记 `Listener` 的 `(String event, String targetWidget, JavaScript action)` 构造器对应 XML `target` 属性，是「A 触发、作用于 B」的可生成期校验写法。

> **doc-918 实证（钉进铁律）**：`com.fr.js.ReportletHyperlink` 的私有常量 `POST_METHOD='FR.doHyperlinkByPost'`、`GET_METHOD='FR.doHyperlinkByGet4Reportlet'`——**官方集成文档让用户手写的那行 JS，就是这个类运行期生成的字符串**。改用 `setByPost(true)` + `setTargetFrame("reportFrame")` + `setShowParameterInterface(false)`（落到 URL 的 `__pi__`）+ `setParameters(ParameterProvider[])`，可白拿 `checkReportletPath` 目录穿越校验与 `.frm→formlet/.fvs→duchamp/其余→reportlet` 的后缀自动分发（`generateLetType` ldc 实读）。官方 JS 方案是 API 方案的退化版，一次装配即两端通用。

**移动端控件事件支持澄清（doc-1206 vs doc-3059 矛盾）**：doc-1206 所谓「afteredit 日期联动不支持移动端」是针对 .cpt 报表块参数面板；doc-3059 在 .frm 决策报表的手机端模板上用了同款联动——**二者冲突，生成器不得据此一刀切「移动端不支持控件事件」**，应以 FR 实际预览行为为最终判据（建议 Chrome 设备仿真 + 真机各验一次）。

### 10.8 控件输入限长/格式约束（doc-1816）

> 来源: 帆软官方帮助 doc-1816（JS实现限制输入长度）

「限制输入长度」是填报模板的高频基础需求，kit 此前完全缺失。FR 10.0 **没有声明式 maxlength 属性**（kit 全库 `<Reg>` 仅 `com.fr.form.ui.reg.NoneReg` 26 处，无长度/正则 Reg 样本），定长只能靠 `<Widget class="com.fr.form.ui.TextEditor">` + 「编辑后」事件 JS 运行期截断。

**官方示例不可直抄的三处加固**：
- ① `getValue()` 可能返回 null（清空输入框）→ 原文 `data.length` 抛 TypeError；
- ② 控件非文本类时 `.length` 为 undefined → 比较恒 false、**静默不校验**；
- ③ 参数模式下 `Number(undefined)=NaN` → `len > NaN` 恒 false、**同样静默不校验**。

**另记**：`substr`→`substring`、原生 `alert`→`FR.Msg.alert`（kit 已验证）、条件必须用 `>` 不可用 `>=`（`>=` 会与 setCellValue 回写自激成死循环）。

**移动端盲区根因归属**：doc-1816 只写「不支持移动端」不给原因——交叉定案：根因是 **`setCellValue` 移动端无效**（§10.4 已记 get/setCellValue 仅 op=write 生效且不支持移动端），**不是 `afteredit` 事件**（ckzl/lc/04 明确参数面板 beforeedit/afteredit 在移动端可用）。故移动端实际表现是「**弹窗照弹、但值不截断**」，而非整体无反应——按「事件不支持」去查会走进死胡同（事件其实触发了）。

## 11. 填报单元格控件联动（doc-608 数据字典联动 + doc-1868 自动默认值）

### 11.0 控件默认值的两个入口（doc-255）

> 来源: 帆软官方帮助 doc-255（填报控件默认值）

⚠️ **同一个控件类在填报/参数两种场景下，默认值入口不同**——这是目前发现的唯一一处「同类 API 因挂载点不同而入口不同」的例子，且两条路径都不会抛异常：

- **参数面板控件** → `Widget#setWidgetValue(new com.fr.form.ui.WidgetValue(value))`（XML `<widgetValue>`，值可为 String / `com.fr.base.Formula` / DataBinding）；
- **填报单元格控件** → **不走 widgetValue**，而是 `TemplateCellElement#setValue(Object)`（doc-255 §2.1.1 原文：「可通过在单元格中添加值的方式设置默认值」，且实际值/显示值都认，填「华东」能选中显示值为「华东」的项）。

> 生成器给填报控件设默认值时若误用 `setWidgetValue`，**不报错、XML 合法、但前端无默认值**——无头生成器通常把「设控件 + 设默认值」封成一个函数，很容易两种场景共用同一实现而在填报场景静默失效。

### 11.1 数据字典联动（doc-608）

> 来源: 帆软官方帮助 doc-608（填报控件数据字典联动）

**与参数面板联动（doc-1284）是两套机制**：填报联动的驱动源是「单元格引用」（如 C9），**不是模板参数** `${p}`，也不是该单元格里控件的控件名——把参数面板套路套到填报单元格会静默失败。

三种实现（均支持控件扩展场景）：
1. **数据集 SQL 筛选**：子数据集 `where 字段='${C9}'`（驱动源=父单元格引用）；
2. **SQL() 函数**：`sql("连接", "select ... where 字段='" + C9 + "'", 1)`；
3. **value() 函数**：同上取数。

约束：
- 「显示值」固定写 **`$$$`**（取实际值作显示）；实际值用 SQL()/value() 取数。
- **移动端硬约束**：联动参数必须设为单元格（如 C9）；设为控件名则移动端（App/H5）不支持——无头生成凡联动一律用单元格引用。
- 触发联动时，被联动控件已选值会被**清空**（地区变 → 城市原值清空），交互设计需预期。
- `SQL()` 大数据量有性能风险，优先用 value() 或数据集 SQL 筛选。
- 参考 `practice/topic_608/gen_linkage.py`。

### 11.2 联动自动生成默认值（doc-1868，doc-608 增强版）

> 来源: 帆软官方帮助 doc-1868（JS实现填报联动自动生成默认值）

核心铁律：**数据字典联动会清空已选单元格值 → 值联动失效**。所以「选父级后子级自动选中第一个值」**不能指望字典默认行为**，必须用 JS 编辑后事件兜底：

- 取数靠运行时 `FR.remoteEvaluate('sql("连接","select ...",1,1)')` 查第一个子值（行1列1），不是靠字典默认选中。
- **关键时序 hack**：`setTimeout(fn, 200/500)` 必须延迟赋值、毫秒数**逐级递增**——字典联动刷新是异步的，立即 setCellValue 会被随后到来的字典刷新覆盖/清空（该类需求最易错、且静默失败的点）。
- 扩展行场景必做：`var row = FR.cellStr2ColumnRow(this.options.location).row + 1;` 取当前行号，不能把单元格名写死（否则多行模板所有行写进同一格）。
- **平台侧硬约束**：决策系统 > 安全管理须关闭「脚本调用公式限制」，否则 remoteEvaluate 调 sql() 被拦——该开关是服务端配置、不落 .cpt XML、生成期无法自检，必须配套平台配置。
- 不支持移动端（App/H5 白屏）。
- 参考 `practice/topic_1868/gen_autodefault.py`。

## 12. 自定义提交按钮（doc-596）

> 来源: 帆软官方帮助 doc-596（JS自定义提交按钮）

自定义按钮要触发提交入库：**不要在按钮里重写 SQL**，给按钮加点击事件调 `_g().verifyAndWriteReport()`——效果等同点工具栏「提交」。

```xml
<Widget class="com.fr.form.ui.Button">
  <WidgetName name="Submit"/>
  <Listener class="com.fr.form.event.Listener">
    <JavaScript><![CDATA[_g().verifyAndWriteReport();]]></JavaScript>
  </Listener>
  <Text><![CDATA[提交]]></Text>
</Widget>
```

- 三个接口：`_g().verifyReport()`（仅校验）/ `_g().writeReport()`（跳过校验直接提交）/ `_g().verifyAndWriteReport()`（先校验后提交，**推荐默认**）。
- **按钮只「触发」已配好的 `<ReportWriteAttr>`、不重写 SQL**——填报配置与触发入口解耦（见 §9）。
- ⚠️ **静默坑**：按钮 JS 调了 verifyAndWriteReport 但模板**没有** `<ReportWriteAttr>` → 按钮能点、不报错、数据进不了库——纯静态 XML 即可检出（fr_check 应加「按钮提交JS ↔ 模板有ReportWriteAttr」一致性规则）。
- 缺 Listener 的按钮只是空壳、点了无反应；业务逻辑可写在提交调用之前（先算值/改单元格，再提交），支持多行 JS。
- `_g()` 接口在「填报预览」（op=write）下生效，移动端（FineMobile）同样可用。
- 参考 `practice/topic_596/inject_submit_button.py`。

### 12.1 打印按钮注入（doc-1071）

> 来源: 帆软官方帮助 doc-1071（JS实现打印）

复用既有 Button+Listener 结构生成打印按钮（打印是集成场景最常见的第二类按钮，与「提交按钮」结构完全同构）：

### 12.2 报表内邮件分发（EmailJavaScript，doc-4195）

> 来源: 帆软官方帮助 doc-4195（超级链接-邮件）

**文档未载能力**：`EmailJavaScript` 的 **mailTo/cc/bcc/title/mainText 五个字段全部经 `getMailAddress`/`sentMail` 内的 `renderTpl` 渲染**——收件人栏同样支持 `${A5}`、`${today()}` 等模板语法，可实现「收件人来自数据行」的动态分发（官方文档只说「标题和正文支持公式」，收件人动态化才是「一键分发日报」类需求的关键）。

**安全提示**：`<EmailJS>` 整节点会随 `FR.sentMail({xmlconf:...})` **明文下发到浏览器**——涉敏收件人应写决策系统用户名（服务端 `getUserByUserName().getEmail()` 解析）而不是硬编码邮箱（官方成品模板要「脱敏清空收件人」正是同一原因）。
