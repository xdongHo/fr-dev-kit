# FR11 国际化（i18n）核心结论

> 降级自 `ckzl/lc/fr11_knowledge/i18n国际化/references/fr11_java_api_i18n.md`、`fr11_i18n_api_optimization.md`、`fr10_i18n_verification_report.md`；完整文档条目见本目录 `references\` 下三篇原文。

### 常见问法别名（业务口吻→本文件落点）
- 「报表要支持英文/日文，界面文字怎么切换？单张报表中英文切换怎么做？」→ 一句话选型见「主题速览」末条；单报表 fr_locale / i18n() / FR.i18nText() 三件套见「核心结论」前三条。
- 「多语言/翻译/国际化怎么配？语言包在哪维护？切换语言失败怎么办？」→ 服务器级键-值在 管理系统>语言配置（支持批量导入导出）；维护与排障见「核心结论」「关键 API 与版本要点」。

## 主题速览
- 验证基础：全量扫描 FR11 离线文档 2289 篇（0 篇解析失败），按 i18n/国际化/多语言/语言包/locale 关键词命中 41 篇并逐篇精读提取。
- 支持语言与 Locale：简体中文 zh_CN、繁体中文 zh_TW、英文 en_US、日文 ja_JP、韩文 ko_KR 共 5 种；浏览器语言不在支持范围时回退备用语言。
- i18n 覆盖层次：模板层公式 i18n()、前端层 FR.i18nText()、URL/参数层 fr_locale、平台层语言配置、插件层（多语言方案/国际化切换接口/本地化公式/文本控件校验国际化）、移动端 App 语言、设计器语言版本。
- 方案选型一句话：单张报表用公式判断+条件判断数据源；多张报表用多语言方案插件（键-值映射）；逐用户切换用国际化切换接口插件；平台整体默认语言用管理系统>语言配置>系统语言偏好。

## 核心结论
- 【已验证】单元格公式 `i18n("键")`：键需先在【模板>模板国际化】设置键-值映射；局限：对提示、弹窗等前端展现文本不生效（doc-view-4591 §3.4/§2.2.10）。
- 【已验证】前端函数 `FR.i18nText("键")`：用于前端工具栏、事件中的文字国际化；原文示例 `var a = FR.i18nText('排名第一'); FR.showDialog("Details",600,400,a);`——前端文本必须走此方案，不能只依赖单元格公式（doc-view-4591 §2.2.10）。
- 【已验证】`fr_locale`：预览 URL 加 `&fr_locale=en_US` 即切换语言；做成模板/全局参数+下拉框数据字典时仅对查询后内容生效（工具栏等查询前载入内容不切换），且参数控件显示值固定、无法多语言（doc-view-4591 §2.2.8/§2.2.9）。
- 【已验证】服务器级键-值：管理系统>语言配置支持新增/删除/修改/查看/批量导入导出（导入 Excel 字段名须满足格式）；语言字段至少填写一个语言的显示内容才可提交；登录页语言切换需平台语言偏好设为简体中文（doc-view-4591 §2.3.1/§2.2.2/§2.3.2）。
- 【已验证·方案选型】多报表场景官方原话：单报表公式法「操作成本过高」，应采用多语言方案插件（模板级/服务器级键-值；要求 jar 10.0.17+）；国际化切换接口插件（V1.9.3，服务器 11.0）在决策系统首页逐用户切换语言（doc-view-4748 §2.4/4591 §1.3/3209）。
- 【已验证·坑点】切换语言只改变管理系统字体，目录和模板字体不变；App 端（V11.0）切换后目录名称/模板名称/模板内容也不自动国际化，需自行设计对应语言模板并改名（doc-view-3209 注2/1362）。
- 【已验证·排障】切换语言失败：① 清理浏览器缓存（仅关闭重启浏览器无效）；② 安全管理>安全防护>Security Headers>开启「浏览器缓存禁用」；③ FineBI 工程安装国际化切换接口插件后需重启 BI 工程（doc-view-3209）。
- 【已验证】本地化公式集合插件（10.0 2019-07-31 / 11.0 2022-03-28）：`ZHMONEY(number,unit,locale)` 金额大写（locale 为 zh_TW 返繁体）、`ZHLUNAR(year,month,day,locale)` 阴历、`DATEFORMAT(date,pattern,locale,chronology)`（chronology "j"=日本年号、"m"=台湾民国历、"t"=泰国佛历）；令和年号正常显示要求 Oracle JDK 7u221/8u211/11.0.3 或 OpenJDK 7u221/8u212-b03/11.0.3+7 之后版本（doc-view-4710）。
- 【已验证】文本控件校验国际化插件：按「区域+数据类型」组合免写正则；中国大陆/台湾/韩国=手机/身份证/邮编，美国=手机/邮编/社会安全码，日本=手机/邮编（doc-view-4778）。
- 【未出现·不作断言】Java 类级 i18n API（LocaleFinder/AbstractLocaleFinder/InterProvider/InterProviderFactory/LanguageConfig 等）在 2289 篇离线 HTML 中零命中；前端 JS 全局对象除 FR.i18nText() 外无其他出现；FineDB 的 FINE_INTERNATIONAL 等表未获确认——须以实际 JAR javap/反编译与真实数据库为准，「未出现」≠「不存在」。
- 【已验证·外围】部署层：Linux 中文乱码需安装中文语言包（doc-view-2028；部署环境准备文档 4409 亦提示）；PDF 导出国际化换行用 itext7 导出及国际化换行插件（doc-view-5031）；单元格英文日期可在单元格格式层实现（doc-view-3720）；设计器有繁中/英/日/韩语言版产品（doc-view-4748 §2.2）。

## 关键 API 与版本要点
- `i18n("键")`：模板层单元格公式，配合【模板>模板国际化】键-值；`FR.i18nText("键")`：前端层函数，与模板级/服务器级键-值映射同源。
- `fr_locale`：URL 参数与模板/全局参数两种用法，取值仅 zh_CN/zh_TW/en_US/ja_JP/ko_KR；「模板语言」工具栏控件在模板 Web 属性>分页预览/填报/数据分析设置中添加，可自定义图标与名称。
- 管理系统>语言配置：服务器级键-值 + 批量导入导出；报表目录、登入标题、平台标题等自定义显示部分均可通过呼叫「键」实现国际化切换。
- 本地化公式 locale 写法："zh"、"zh_TW"、"en_US"、"ja_JP"；可直接套用的组合示例：`=ZHMONEY(3.45,"w","zh_TW")`、`=ZHLUNAR(2020,6,4,"zh_TW")`、`=DATEFORMAT(TODAY(),"YYYY-MM-dd, EEEE","en_US")`。
- 版本要点：多语言方案插件要求 jar 10.0.17 及以上（跨版本兼容提示，非 FR11 特有）；国际化切换接口插件 V1.9.3 适配服务器 11.0；本地化公式集合 11.0 版发布于 2022-03-28。
