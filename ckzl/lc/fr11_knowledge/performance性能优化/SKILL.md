# FR11 性能优化 核心结论

> 降级自 `ckzl/lc/fr11_knowledge/performance性能优化/references/performance_summary.md`；完整文档条目大表（doc-view ID + 标题 + 核心概念 + API）见本目录 `references\performance_summary.md`。

## 主题速览
- 关键词频次：性能 9 篇、缓存 7 篇、数据 4、大数据 3，缓存机制与排查思路是两大重心。
- 全类共 31 篇文档，doc-view ID 覆盖 151~5117，其中 4 篇提及 11.0.x 子ckzl/bb，0 篇解析失败。

## 核心结论
- 优化路径：取数（控制数据量、SQL 提前预处理、避免 SELECT *、用 group by 提前聚合）→ 计算（单元格有设置就占内存，占位格尽量留空白格）→ 全局（日志压缩、缓存）；单张模板加载慢优先按指导手册排查 SQL 执行速度。
- 缓存体系：数据量大且实时性要求不高（可接受约半小时更新频率）时启用缓存。11.0「抽数缓存」复用数据集查询结果免连库；「模板计算结果缓存」直接复用模板计算结果；两者都能降低服务器与数据库压力、提升访问速度。
- 动态参数（如 today()-1）模板当天首次访问仍会慢：用定时调度配合抽数缓存提前一天生成缓存即可避免；「管理系统>抽数缓存>运行监控」可观察缓存状况、手动处理异常缓存。
- 内存机制：Java GC 从主运行对象遍历引用链回收孤立对象；内存溢出按容器调 -Xms/-Xmx（Tomcat/WebLogic/WebSphere/JBoss/Resin 配置文件各异），PermGen 报错可加 -XX:MaxPermSize=256m。
- 性能测试必须先申请注册文件：未注册免费版与注册版运行机制不同，测试结果会严重失准；服务器默认内存偏小，测试前应调大 JVM 参数。
- 大模板治理：「模板限制」限制单元格个数、SQL 执行时长、单数据集行数（11.0.2 模板限制增强插件功能内置），超限模板无法正常预览；可用模板限制推荐插件取推荐数值，必要模板放入「放宽限制」。
- 大数据量排查：大部分加载慢源于 SQL 慢，先在设计器数据集直接查询验证（设计器查询慢可考虑更换驱动）；格子数相同下列越多计算越慢（行列调优、列转行）；图表空数据可能是设计器数据行数限制而非性能不足。
- 10→11 升级后变慢：多因公式计算设置问题，更新至 11.0.10 及之后版本解决；下拉树模糊搜索卡顿在 11.0.3 及之后已做性能优化。
- 坑点：全局参数里写查库公式会在每个模板加载时计算，拖慢全部模板；填报页控件过多致「Internet 脚本运行慢」，改用超链传参填报；.FineReport110 下 ehcache_disk_store（数据库二级缓存+文件服务器缓存）易占满磁盘，需指定缓存路径。
- 10.0 的「性能优化」插件在 11.0 中功能拆分并产品内置；fanruan.log 优化：日志记录模板名、每日零点定时压缩前一天日志减少磁盘占用（不支持移动端）。

## 关键 API 与版本要点
- 抽数缓存（11.0 新增）：管理系统>抽数缓存，含运行监控（普通模式/开发模式）；动态参数缓存=定时调度+抽数缓存。
- 新计算引擎「计算属性」：开启后模板菜单新增入口，勾选即数据集缓存；另有固定行数分页、数据行数汇总、优先使用游标分页等设置（11.0~11.0.2 陆续新增）。
- 11.0.3：下拉树模糊搜索优化；11.0.10：支持单元格数据设置批量修改；折叠树性能可用新计算引擎实验性「折叠树」选项优化前台加载。
- 设计器内存监控插件：实时监控+手动清理设计器内存，生成 dump.hprof 供 MAT（Memory Analyzer Tool）分析。
- 模板检测助手：发现模板潜在性能问题点并给修改建议，结果页新增「功能建议」Tab；最大并发数插件定期统计当日最大并发录入 finedb，供并发采购参考。
