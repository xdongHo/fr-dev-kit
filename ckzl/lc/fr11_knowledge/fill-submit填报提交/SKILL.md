# FR11 填报与提交 核心结论

> 降级自 `ckzl/lc/fr11_knowledge/fill-submit填报提交/references/fill_submit_summary.md`；完整文档条目大表（doc-view ID + 标题 + 核心概念 + API）见本目录 `references\fill_submit_summary.md`。

## 主题速览
- 主题范围：填报/提交/智能提交/数据校验/Excel导入/暂存；共 103 篇文档（doc-view ID 覆盖 136~5119），其中 15 篇提及 FR11 子版本号（11.0.x），0 篇解析失败。
- 标题关键词频次：填报 47、提交 12、数据 8、报表 6、单元格 6、JS 6。
- 填报功能将页面数据写入数据库，支持增加、删除、修改，并支持自定义校验、Excel 导入数据、根据填写值智能联动。
- 「填报预览」（op=write）用于在线录入与修改数据，实现数据采集与入库；移动端也支持填报。
- 报表填报属性三大设置项：提交设置、数据校验设置、填报快捷键设置。

## 核心结论
- 提交类型：智能提交把插入、更新、删除三合一，后台自动判断操作类型（有两种及以上操作需求时选用）；另有内置 SQL 提交与自定义提交（获取页面数据后自行编码处理，代码需自行编写维护）。
- 数据校验：内置校验设置校验公式+出错信息，前端填报或直接提交时对所有 sheet 按各自设置校验，不满足则提交终止并弹错；重复值校验可用 GREPARRAY 遍历扩展值统计个数实现。
- 提交优化：「提交条件」可过滤不入库的数据（如单价为空的无效数据）；勾选「未修改不更新」后未修改的记录不参与提交，提高提交性能。
- 主键机制是多人填报的关键：后填报内容覆盖先填报内容，是因主键未按用户区分（主键一致会执行更新）；无主键字段时可用数据库自增长 ID，或内置 UUID()/UUID(32) 函数生成唯一主键。
- 笛卡尔积防护：提交的一行中含两个及以上数组类型数据会被判定为笛卡尔积，阻止提交并失败（建议更新最新 jar 包，出错时有定位提示）。
- Excel 导入：匹配方式含按位置匹配（模板与 Excel 样式完全一致时内置触发）、按标题匹配、根据单元格位置匹配、双向扩展格导入；多次导入分清空/覆盖/增量三种；「Excel标记导入」插件整合原有导入逻辑，导入的显示值可经单元格形态数据字典转为实际值入库。
- 填报暂存：暂存数据存于内置库 FINE_WRITE_STASH 表；11.0.1 起页面存在暂存数据时重新加载会提醒「当前页面已读取暂存数据」；清空暂存用 _g().clear(undefined, false)。
- 大数据量填报：预览慢可用填报分页（URL 加 &__cutpage__=v 配合条件属性分页）；无修改需求的数据可在 URL 加 &format=submit 不预览直接后台提交入库；11.0.2 起 URL 加 &async_insert=true 开启插入行局部刷新，提升大数据量插行速度。
- 决策报表（frm）不支持 cpt 的填报预览，可通过按钮控件的「提交入库」事件或网页框控件插入报表实现填报；移动端支持普通报表与决策报表填报。
- 多级上报三种模式：单线（直线）上报、联合上报（节点多操作人员共同填报）、分发逐级上报；个性化上报审核流程也可用「标记字段+自制填报模板」实现。
- 性能坑：填报预览比分页预览加载时间明显更长；11.0.5 之前模板 JS 事件/消息插件中公式取的是初始值，无法实时获取最新填报值；11.0.2 起校验/提交会校验所有控件的「允许自定义值」，数据字典量大时此过程耗时明显。

## 关键 API 与版本要点
- 常用 JS：_g().writeReport() 提交、_g().getWidgetByName(name) 取控件、_g().setCellValue() 给单元格赋值、_g().refreshAllSheets() 刷新填报所有 sheet、fr_submitinfo.failinfo 获取提交失败信息。
- 填报专有接口：getWidgetByCell/getWidgetsByName、_g().appendReportRow 插入行（需配合「插入行按钮」）、_g().deleteReportRC 删除行。
- 内置 SQL 提交的值处理：列对应值不绑定单元格也有 9 种格式可选（参数值、日期、当前时间等），空数据可保存为 0 入库。
- 11.0.2：内置 SQL 提交配置表时支持从数据库模糊搜索表；「Excel标记导入」插件要求报表工程 11.0.2 及以上。
- 11.0.11：修复 Excel 导入后数据错位、部分数据缺失问题（升级到 11.0.11 及之后重启即可）。
- 填报调试插件（11.0.2+）：把部分后台计算结果转化为前端可视化数据，便于定位「所见非所得」的提交计算问题。
- 定时自动填报可定时完成数据加载、汇总、入库；但定时调度自动填报后不支持自动执行「发送邮件」事件。
