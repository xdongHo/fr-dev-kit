## 3. 单元格构建

### 3.0 通配规则分类总纲（用户定稿 2026-08-07）

> **执行策略**：以下通配规则默认执行，用户不主动提出新调整就不改。

| 类别 | 规则 | 适用报表 | 默认行为 |
|------|------|---------|---------|
| **通用样式类** | 参数面板布局（紧凑单行/区块）、数据查询格式化、文本字体（微软雅黑9号）、单元格文本展示形态（对齐/格式/隔行换色） | **所有报表** | 默认执行，无需判断 |
| **列表展示类** | 列宽（内容宽度自适应）、冻结表头 | **常规明细表**（行式展示） | 默认执行；树形/折叠透视报表不启用（用户显式要求时才加） |

**判断标准**：
- 常规明细表（普通行式列表）→ 列表展示类规则默认启用
- 树形折叠/透视/交叉表（如树形交叉）→ 仅通用样式类启用
- 大多数报表是常规明细表，所以"默认使用"是安全策略

**通配脚本统一入口**：`fmt_copa.py` 风格的一体化后处理脚本（列宽 + 参数面板 CSS + 紧凑重排 + 冻结表头 + 隔行换色），生成器产出后自动跑一遍即可（通用版见 `kfgj/tygs/CPT模板/默认格式/fmt_wildcard.py`）。

### 3.1 Java API 方式
```java
// 文本单元格
DefaultTemplateCellElement cell = new DefaultTemplateCellElement(col, row, "文本内容");
cell.setStyle(myStyle);
sheet.addCellElement(cell);

// 合并单元格
DefaultTemplateCellElement cell = new DefaultTemplateCellElement(col, row, colSpan, rowSpan, "文本");

// DSColumn 数据列
DSColumn dsCol = new DSColumn();
dsCol.setDSName("ds1");
dsCol.setColumnName("供应商");
dsCol.setGrouper(new FunctionGrouper());    // 分组
// dsCol.setGrouper(new SummaryGrouper()); // 汇总

DefaultTemplateCellElement cell = new DefaultTemplateCellElement(col, row, dsCol);
cell.setStyle(myStyle);

// 扩展方向
CellExpandAttr expand = new CellExpandAttr();
expand.setExtendable(CellExpandAttr.Vertical_EXTENDABLE);   // 纵向
// expand.setExtendable(CellExpandAttr.Horizontal_EXTENDABLE); // 横向
cell.setCellExpandAttr(expand);

sheet.addCellElement(cell);
```

### 3.2 ⚠️ Java API 产物格式
`export()` 会将 DSColumn 序列化为紧凑格式：
```xml
<C c="0" r="5" s="2">
  <O><![CDATA[ds1.G(供应商)]]></O>    <!-- G()=FunctionGrouper, S()=SummaryGrouper -->
  <PrivilegeControl/>
  <Expand extendable="1"/>
</C>
```
- 运行时功能正确，但 FR 设计器中不显示为数据集列
- 无法控制父子格（rs 属性）
- **生产级交付推荐 Python XML 精确控制**

### 3.3 Python XML 方式（精确格式：父子格 rs 行合并 / cs 列合并，合并显示不全排查）
```python
def ds_cell(c, r, ds, col, s="0", cs="", rs="", grouper="FunctionGrouper", expand_dir="0"):
    ca = f' cs="{cs}"' if cs else ""
    ra = f' rs="{rs}"' if rs else ""
    return f'''<C c="{c}" r="{r}"{ca}{ra} s="{s}">
<O t="DSColumn">
<Attributes dsName="{ds}" columnName="{col}"/>
<Complex/>
<RG class="com.fr.report.cell.cellattr.core.group.{grouper}">
<Attr divideMode="1"/>
</RG>
<Parameters/>
</O>
<PrivilegeControl/>
<CellGUIAttr/>
<CellPageAttr/>
<Expand dir="{expand_dir}"/>
</C>'''
```

- `expand_dir="0"` = 纵向, `"1"` = 横向
- **列表展示**：RG 添加 `<Attr divideMode="1"/>` 使数据以列表形式展示（每行独立），否则默认分组展示会将同值行合并
- `rs="3"` = 行合并（父子格层级显示）
- `cs="2"` = 列合并
- 必须包含 `<CellGUIAttr/>` 和 `<CellPageAttr/>`

> ⚠️ **DSColumn 默认配置铁律**：纵向扩展(`dir="0"`) + `FunctionGrouper` + `divideMode="1"`（列表展示）。这是明细报表的标准写法。
- 症状速查（父子格 合并 显示不全）：父子格层级合并（`rs="3"` 行合并）后内容显示不全/被截断 → 依次查 ①行高不足（§5 行高 FU，合并区域 ≥1,800,000 FU 触发表头保护不压缩）②冻结边界未覆盖合并格全部行列（FR_HEADLESS 铁律 L）③误把分组展示当列表展示致同值行被合并（本节 divideMode）。

### 3.4 隔行换色（通配样式，配首个数据单元格 + 整行跟随）

> 用户定稿 2026-08-06（示例模块 实测）：条件属性只配在**首个数据单元格（A3）**，`<Scope val="1"/>` 使**整行样式跟随**——无需每列配置。
> 公式 `row()%2=0`（数据从第 3 行起时效果正确；若表头仅 1 行、数据从第 2 行起则用 `(row()-1)%2=0`）。

```xml
<HighlightList>
  <Highlight class="com.fr.report.cell.cellattr.highlight.DefaultHighlight">
    <Name><![CDATA[隔行换色]]></Name>
    <Condition class="com.fr.data.condition.FormulaCondition">
      <Formula><![CDATA[row()%2=0]]></Formula>
    </Condition>
    <HighlightAction class="com.fr.report.cell.cellattr.highlight.BackgroundHighlightAction">
      <Scope val="1"/>                      <!-- 整行作用域：该行所有列跟随 -->
      <Background name="ColorBackground" color="-657929"/>
    </HighlightAction>
  </Highlight>
</HighlightList>
```

> ⚠️ **颜色换算易错**（用户定稿 2026-08-07）：`#F5F5F7` → `-657929`（灰白）；`-651769` 是**红色 `#F60E07`**，勿混用！奇数行白色 `-1`。
> ⚠️ **HighlightList 顺序**：隔行换色必须放第一位，行后分页放第二位（示例模块 标准）；生成器已内置 HighlightList，后处理脚本**跳过**已有 HighlightList 的报表，避免二次添加互相覆盖。
> ⚠️ **只改背景色**（BackgroundHighlightAction），不要在 Style 里带 `horizontal_alignment`——否则会覆盖数值列的右对齐。
> 📁 已内置进生成器 `gen_vave_reports.py` 的 `data_cell(idx==0)`——新报表自动带隔行换色。与行后分页条件属性可共存（同一 HighlightList，见 ckzl/lc/05 §10.3）。

### 3.4.1 条件属性（HighlightList）动作族总表（doc-1481 + doc-958）

> 来源: 帆软官方帮助 doc-1481（条件属性）/ doc-958（条件属性-新值）/ doc-1825（行高=0 隐藏行）/ doc-865（列宽=0 隐藏列）

`<HighlightList><Highlight class="...DefaultHighlight">` 的固定骨架是**所有**条件属性的通用外壳，动作只是换 `HighlightAction` 类名：

```xml
<HighlightList>
  <Highlight class="com.fr.report.cell.cellattr.highlight.DefaultHighlight">
    <Name><![CDATA[动作名]]></Name>
    <Condition class="com.fr.data.condition.FormulaCondition">
      <Formula><![CDATA[条件公式（不带前导 =）]]></Formula>
    </Condition>
    <HighlightAction class="...HighlightAction">...</HighlightAction>
  </Highlight>
</HighlightList>
```

**动作类对照表**：

| 动作 | 类名 | 状态 |
|------|------|------|
| 背景色 | `BackgroundHighlightAction` | ✅ 已验证（§3.4 隔行换色） |
| 行高=0（隐藏行） | `RowHeightHighlightAction` | ⚠ 待核（doc-1825） |
| 列宽=0（隐藏列） | （列宽动作类） | ⚠ 待核（doc-865） |
| 行后分页 | `PageHighlightAction` | ✅ 已验证（ckzl/lc/05 §10.3） |
| 新值 | `ValueHighlightAction` | ✅ 已验证（见 §3.4.2） |

- 条件统一 `<Condition class="com.fr.data.condition.FormulaCondition"><Formula>`；**多条 Highlight 可共存于同一 `<HighlightList>`**（隔行换色 + 隐藏行可叠加，kit 已有实例）。
- ⚠️ **有/无 Scope 分栏（doc-958 字节码实读，14 个动作类）**：
  - 继承 `AbstractStyleHighlightAction`（私有字段 `int scope` → XML `<Scope val="1"/>`，配首格+整行跟随）：`Background / Foreground / FRFont / Border / Padding`；
  - 直接继承 `AbstractHighlightAction`（**无 Scope**）：`Value / Page / ColWidth / RowHeight / Widget / Hyperlink / Present`。
  - ⚠️ 新值/行高/列宽类动作**没有 Scope**——照抄「配首格 + Scope=1 整行跟随」的写法会得到「只有首列生效」的静默错误（与 §3.4 背景色不同，背景色才吃 Scope）。
  - **`<Scope val>` 取值表（2026-09-12 javap -c 字节码实读 `AbstractStyleHighlightAction.action`，lookupswitch 仅 3 分支）**：

    | val | 语义 | 证据 |
    |-----|------|------|
    | `0` | 只作用当前单元格（**默认值**；writeXML 对 0 **不写出** `<Scope>` 标签，readXML 缺省 `getAttrAsInt("val",0)`） | 两个 `<init>` 均 `iconst_0`；writeXML pc4 `ifeq` 跳过 |
    | `1` | 扩到**整行**：`getRow(i)` 迭代器遍历行内全部单元格逐格套用样式动作 | lookupswitch case 1 |
    | `2` | 扩到**整列**：`getColumn(i)` 迭代遍历整列 | lookupswitch case 2 |
    | 其他任何值 | 落 default 分支 = 等价 `0`（只作用当前单元格，静默不报错） | lookupswitch 无其他 case |

    - `scope` 是 plain int 字段非 enum，**无常量可引用**，Java/XML 侧只能传字面量（0.11「值可读 ≠ 常量可引用」）。
    - 行/列遍历优先 `PageRWorkSheet`（分页预览态），空则回落 `ElementCase`（`Report.KEY`/`ElementCase.KEY` 取自 CalculatorProvider，字节码实读）。
- Java 骨架：`DefaultHighlight.setName/setCondition(new FormulaCondition(...))/addHighlightAction(...)` → `new HighlightGroup(Highlight[])` → `TemplateCellElement.setHighlightGroup(...)`，XML 外层为 `<HighlightList>`。

> ➕ 逻辑函数即条件（来源: 帆软官方帮助 doc-817）：IF/SWITCH/AND/OR/REVERSE 等逻辑函数**可直接作为** `com.fr.data.condition.FormulaCondition(String)`（不带前导 `=`）的条件表达式，覆盖「按公式分支/多值改写显示值」的高频场景（如 `new FormulaCondition("SWITCH(A1,1,"低",2,"中")")`）——不要误以为条件只能写 row()/比较式。示例见 `practice/topic_817_java/LogicFormulaCell.java`。

### 3.4.2 条件属性「新值」动作：ValueHighlightAction + HTML 显示（doc-2167 + doc-1485）

> 来源: 帆软官方帮助 doc-2167（条件属性-新值）/ doc-1485（条件属性-其他动作）

**新值（ValueHighlightAction）**：`com.fr.report.cell.cellattr.highlight.ValueHighlightAction#setValue(com.fr.base.Formula(...))` 注入新值公式（同格按条件改显示值/置空/按公式改写——条件属性里最高频的一类，不能用样式类动作表达）。工厂 `valueHighlight(name, cond, formula, scope)`。其值经 `GeneralXMLTools.writeObject` 序列化为 `<O t="Formula" class="com.fr.base.Formula"><Attributes>`，**空值=空 Formula（非裸 `<Value>`）**。

**HTML 显示（CellGUIAttr.setShowAsHTML）**：`com.fr.report.cell.AbstractCellElement#setCellGUIAttr` + `CellGUIAttr#setShowAsHTML(true)`；XML 为 `<CellGUIAttr showAsHTML="true" ../>`（注意是 **showAsHTML 布尔属性**，非单一 ShowContent 字段，已读 `CellGUIAttr.writeXML` 字节码确认）。

- ⚠️ **二者必须成对出现**：「新值公式 + 未开 HTML 显示」是 doc-2167 类需求最高频的静默失效点——设计器能打开、fr_check 通过，但 `<div align>` 当纯文本显示，对齐完全不生效。生成器可加断言：凡检测到 `<HighlightAction class="..ValueHighlightAction">` 且单元格无 `showAsHTML`，自动补写。
- ⚠️ **对齐提醒**：「新值+HTML 改对齐」是对齐的 **HTML 变通技巧**，非真正改 Style 对齐；纯条件对齐需求优先评估 `com.fr.report.cell.cellattr.core.style.Style#setHorizontalAlignment(...)`。HTML 技巧仅用于「同格多条件不同对齐且不动基础样式」的场景，且对导出/打印不如 Style 干净。
- **官方范例引用（doc-987）**：「单元格用 HTML 显示 GIF 图片」=「值含 `<embed>` + 必须开 showAsHTML」的配对静默失效标准案例——值写了 HTML 但漏开 `setShowAsHTML(true)` 时 `<embed>` 当纯文本显示。归口（CellGUIAttr 三态）：showAsHTML（本节）/ 单元格形态 Present（§3.9）/ 条件属性 HTML（本节「新值」动作）三者同属 `CellGUIAttr` 一个入口，改动一处时对照另两处，避免三处各写一份。（来源: 帆软官方帮助 doc-987 / doc-615）

### 3.4.3 条件属性 Java 双路径构建链（doc-615 + doc-315 字节码实读）

> 来源: 帆软官方帮助 doc-615（条件属性）/ doc-315（条件属性，字节码实读）

条件属性有 Java + XML 双路径；Java 侧完整链（已实读）：

```java
DefaultHighlight h = new DefaultHighlight();
h.setName("...");
h.setCondition(new FormulaCondition("row()%2=0"));       // 条件公式不带前导 '='
h.addHighlightAction(new BackgroundHighlightAction(ColorBackground.getInstance(Color)));  // 见动作族
HighlightGroup g = new HighlightGroup(new Highlight[]{h}); // ⚠ 该类无 add 方法
((AbstractDynamicCellElement) cell).setHighlightGroup(g);   // 声明类见下
```

- ⚠ **修正声明类**：`setHighlightGroup` **不在** `TemplateCellElement`/`CellElement` 接口上，声明在 `com.fr.report.cell.DynamicAttrElem`（实现于 `AbstractDynamicCellElement`，全 jar 仅此两处含该方法名）——按接口 dump 找不到是正常现象。
- 动作族 setter：`BackgroundHighlightAction#setBackground(ColorBackground.getInstance(Color))` / `ForegroundHighlightAction#setForegroundColor` / `FRFontHighlightAction#setFRFont` / `ValueHighlightAction#setValue`。
- 条件两种：`FormulaCondition(String)`（不带前导 `=`）或 `CommonCondition` + `Compare(op, value)`（op 取值见 `com.fr.data.core.Compare` 常量表，如 GREATER_THAN=2）。
- XML 形态（标签/属性名全部实读）：`practice/topic_315_java/highlight_xml_shape.xml`（`<HighlightList>` / `<Scope val>` / `<Background class="com.fr.base.background.ColorBackground"><FineColor .../>` / `<Compare op>` 等）。⚠ 旧记法 `HighlightList#addHighlight` 的类不存在，不要用。

### 3.4.4 条件属性 scope 取值表（doc-615 + doc-3240 实读）

`AbstractStyleHighlightAction#setScope(int)`（= XML `<Scope val="N"/>`）：

| 值 | 作用域 |
|----|--------|
| 0 | 当前格子（default） |
| 1 | 当前行 |
| 2 | 当前列 |

- 取值来自 `#action` 的 `lookupswitch`（default→本格 / case 1→整行 / case 2→整列），jar 里**无具名常量**，只能写魔数。
- ⚠ **传其余任意 int 落 default = 静默退化为「只改本格」**，不报错、不记日志——scope 写错是条件属性最隐蔽的失败形态（GUI 中文名「当前行/当前列」与 int 无任何可推导关系）。§3.4 的 `<Scope val="1"/>` 即「当前行整行跟随」。XML 读取缺省即 `readXML` 的 `getAttrAsInt("val",0)`——字节码级细节见 §3.4.1 动作族总表。

### 3.4.5 条件属性运行期语义：HighlightGroup#execute（多条件属性执行顺序/覆盖：同时满足全执行、后添加优先级更高；doc-2365 + doc-3240 字节码实读）

> 来源: 帆软官方帮助 doc-2365（隐藏行后隔行变色）/ doc-3240（列重复值高亮，FR 10.0.19 / build 2024.03.19 实读）

§3.4.1~3.4.4 讲「怎么装」，本节讲「装好之后怎么跑」——三条实读结论直接决定「同格叠加多条条件属性时谁赢」：

1. **两遍扫描**：`HighlightGroup#execute(CellElement, Calculator)` 第一遍全部 `Highlight.eval` 并把命中下标存进 `com.fr.cache.list.IntList`，第二遍才按下标顺序 `Highlight.action`。
2. **不是「首条命中即停」**：全部命中都会执行，**数组下标大的最后写、即最终生效** ⇒ `appendHighlight()` 追加到数组尾 = 新条件优先级最高（与 GUI「后配的盖先配的」一致）。
3. **同组内没有链式触发**：命中集合在任何 action 执行前就已冻结——一条 Highlight 的 `ValueHighlightAction` 改值**不会**影响同组其它条件的判定；同格多条条件属性的书写顺序**只影响样式覆盖、不影响条件成立与否** ⇒ 生成器可自由排列（隔行换色 + 空值隐藏 + 超阈值标红叠加），省掉「靠人工排序回避」的一整类防御代码。

- 另补 scope 分派实读：`AbstractStyleHighlightAction#action` 是 `lookupswitch default->__mod(cell)`（case 1 整行 / case 2 整列），且 case 1/2 各带一对 `ifnonnull`+`return`（`ElementCase` 与 `PageRWorkSheet` 都取不到即**静默不着色**）；case 0 不碰任何容器、无条件生效。
- ⚠ `cell==null ⇒ 条件恒真`（`AbstractHighlight#eval` 首句 `ifnonnull`）——空格子配条件属性会「多染色」，配条件属性前必须先建单元格元素（§3.12）。

### 3.4.6 折叠/展开范式：状态参数 + 超链翻转 + 条件属性（doc-4248）

> 来源: 帆软官方帮助 doc-4248（超链实现报表块内容折叠和展开）

「状态参数 + 超链翻转 + 条件属性」是通用交互范式（与点击排序 doc-1894 参数翻转同构），可沉淀 `build_toggle_hyperlink(cell, param, val)` 生成器原语：

- **状态参数 d**：模板参数，默认值必须设 `"0"`（`ReportParameterAttr/<Parameter>` + 默认值节点）——**无默认值首屏两条条件属性都不命中，静默无效果**；
- **两条互补条件属性**（同一格）：`$d=1` → 行高动作(0)（折叠）；`$d=0` → 背景图（上箭头）+ 超链翻转参数 d="1" 与 `$d=1` → 背景图（下箭头）+ 超链翻转 d="0"——**两公式互补覆盖，状态才不漏切换**；
- **行高=0 是 FR 折叠隐藏的标准手段**，配合列宽=0 双保险（doc-225/1118 隐藏行列同族）；
- **超链参数值是字符串字面量翻转值**（`com.fr.js.ReportletHyperlink` 指向本模板，参数传字符串字面量，非 =$$$）——第三种取值形态，区别于 `=$$$`（doc-4207）与单元格号（doc-1995）；
- 待核验：条件属性 XML 外层包裹（ConditionAttrList/ConditionAttr 层级）、行高/背景/超链动作类名；核验样本 = `%FR_HOME%\webapps\webroot\WEB-INF\reportlets\doc\SpecialSubject\HyplinkReport\超链实现报表块内容折叠和展开.frm`。

### 3.4.7 权限超链：条件公式 + 超链效果（doc-4292）

### 3.5 明细单元格格式化（通配规则，用户定稿 2026-08-06）

> 📁 脚本：`kfgj/tygs/CPT模板/默认格式/fmt_detail_cells.py`（后处理，自动备份+XML校验）
> 用法：`python fmt_detail_cells.py <cpt> --numeric-labels 标签1,标签2,...`（数值列清单从建表 SQL 的 numeric 列提取，最准）

| 类型 | 判断规则 | 对齐 | 格式 | 样式要点 |
|------|----------|------|------|----------|
| 数值 | 建表 numeric 列 / 标签含累计/月/金额 | 右 | `#,##0.00` | `CoreDecimalFormat` |
| 百分比 | 标签含 `%` 或 `Rate` | 右 | `#0.00%` | `CoreDecimalFormat` |
| 文本 | 其余 | 左 | — | `TextFormat` |
| 序号 | 标签=序号/Seq/SEQ | 居中 | — | — |
| 日期 | 标签含 Date/日期 | 左 | `yyyy-MM-dd` | `FineDateFormat` |

> ⚠️ **对齐值权威映射**：FR 中 `horizontal_alignment="0"`=**居中**, `"1"`=**居左**, `"2"`=**居右**。
> 表中"左"对应 `1`，"右"对应 `2`，"居中"对应 `0`（2026-08-07 实测修正，旧文档将文本误标为居右(2)、数值误标为居左(0)）。

字体统一 **微软雅黑 9 号**（FRFont `size="72"`）。样式经 StyleList 共享：数据行各列按类型引用不同样式 s（文本 s=1 复用改造，数值/百分比/日期为新增 s）。

```xml
<Format class="com.fr.base.CoreDecimalFormat"><![CDATA[#,##0.00]]></Format>   <!-- 数值 -->
<Format class="com.fr.base.CoreDecimalFormat"><![CDATA[#0.00%]]></Format>      <!-- 百分比 -->
<Format class="com.fr.general.date.FineDateFormat"><![CDATA[yyyy-MM-dd]]></Format> <!-- 日期 -->
```

> ⚠️ 注意：`FX Rate` 表头含 Rate 会按百分比规则命中（示例模块 中汇率列也如此）——若汇率不需百分比，将其从 `--numeric-labels` 传入即可覆盖优先级。

### 3.6 冻结表头（通配规则，用户定稿 2026-08-06）

> 📁 脚本：`kfgj/tygs/CPT模板/默认格式/freeze_header.py`
> 用法：`python freeze_header.py <cpt> [--rows N]`（默认 N=2 冻结 2 行表头；1 行表头用 `--rows 1`）

```xml
<ReportSettings headerHeight="0" footerHeight="0">
  <FrozenColumnRow columnrow="A3"/>   <!-- 冻结 A3 左上区域 = 前 2 行表头 -->
  <PaperSetting/>
  <Background name="ColorBackground" color="-1"/>
</ReportSettings>
```

- `columnrow="A{N+1}"`：冻结前 N 行（A2=1 行、A3=2 行）
- 与填报分页（ckzl/lc/05 §10.3）配合：翻页时表头保持不动
- 设计器保存会自动补全 ReportSettings（生成器可省略）；已有冻结配置时脚本自动跳过
- ⚠️ **导入报表（先删后插型）常漏冻结配置**（2026-08-14 实测）：此类报表无数据集、XML 里可能整个 `<ReportAttrSet>` 缺失，生成/改造后要专门检查；补插时若文件无 ReportAttrSet，在 **CellElementList 之后、ReportWriteAttr 之前**插入完整 `<ReportAttrSet><ReportSettings ...><FrozenColumnRow columnrow="A{N+1}"/></ReportSettings></ReportAttrSet>` 块。成对的填报/导入报表冻结方式必须一致

#### 3.6.1 列冻结 / 行列组合与重复标题（doc-368 扩展）

- `columnrow` 是「冻结区右下角坐标」：`A3`=前 2 行、`C1`=前 2 列、`B3`=前 2 行+前 2 列（行列组合）。现有 §3.6 只覆盖行冻结，宽表需要列冻结时按此扩展。
- **冻结 ≠ 重复标题**：冻结=滚动固定，重复标题=换页重印。重复标题行/列用 `<RepeatRow><![CDATA[0,1]]></RepeatRow>` / `<RepeatColumn>`（索引从 0 起）；设计器顺序「先重复后冻结」不能反。
- 纯冻结标题行时**无需**设重复列与列冻结。
- ⚠️ 冻结区若含合并单元格，`columnrow` 必须覆盖合并单元格的**全部**行/列，否则第一页冻结内容不显示（doc-368 注意事项）。
- 移动端：App 端冻结可缩放、HTML5 端不可；双向自适应无冻结效果。

#### 3.6.2 填报预览冻结的特殊行为（doc-611）

- **冻结区不可圈入可扩展数据单元格**（`=ds.select()/list()` 等）：普通填报预览会把扩展出的**全部数据**都冻结（长表失去滚动意义）；新填报预览只冻结指定行数。生成填报模板时冻结区应只覆盖静态表头，或显式改用新填报预览。
- `columnrow` 从**首行/首列起算**，不支持从中间行/列冻结，不支持单独冻结尾行/尾列——用户传「冻结第 5~8 行」时直接在生成期拒掉/纠正。

> 📁 脚本：`kfgj/tygs/CPT模板/默认格式/freeze_header.py` 已支持 `--rows`；列冻结/组合与填报冻结约束需按上述规则扩展。

### 3.7 预览/打印/导出开关（单元格级呈现分离，doc-225）

> 设计器入口：单元格 → 右键 → 其他。三开关按**单元格粒度**生效，用来分离浏览器预览 / 打印 / 导出三种呈现，不是模板级也不是参数级开关（来源: 帆软官方帮助 doc-225）。

| 开关 | 含义 |
|------|------|
| 预览单元格内容 | 浏览器预览是否显示该单元格 |
| 打印/导出单元格内容 | 打印/导出是否带出该单元格 |
| 打印/导出单元格背景 | 打印/导出是否带出背景（含颜色/图片） |

**三开关组合效果（3 个官方场景）**：
- 场景1（预览可见但打印/导出不带此格）：取消「打印/导出单元格内容」即可，无需改数据集或隐藏列。
- 场景2（预览隐藏但打印/导出带出）：取消「预览单元格内容」+ 勾选「打印/导出单元格内容」。⚠️ **填报预览不支持该场景**（doc-225 明确）。
- 场景3（背景进打印/导出）：勾选「打印/导出单元格背景」。

**导出格式差异（硬约束）**：Word/Excel 导出**仅支持颜色背景**（图片背景不支持），PDF 全部支持；**移动端不支持任何打印/导出**，该能力只在 PC/Web 预览链路生效。

> .cpt 即 XML，三开关本质是单元格元素属性，无头生成可直接按坐标注入（参考 `practice/topic_225/inject_cell_flags.py`）。

### 3.8 权限锚点定位（ElementTree 坑，doc-866）

> 细粒度权限全部持久化在 .cpt 里，锚点是生成器已产出的空标签（`<PrivilegeControl/>`、`<RowPrivilegeControl/>`、`<ColumnPrivilegeControl/>`）——注入是「填空」而非新增结构（来源: 帆软官方帮助 doc-866）。

- ❌ **禁止用 `cell.find('.//PrivilegeControl')`**：带控件的单元格下有 **2 个同名节点**（单元格权限 + `Widget/WidgetAttr` 里的控件权限），递归查找会命中错的那个——表现为「藏了单元格没藏控件」或反之，无任何报错。
- ✅ 必须用**直接子节点**区分：`cell.find('PrivilegeControl')`（单元格权限）vs `cell.find('Widget/WidgetAttr/PrivilegeControl')`（控件权限）。
- 整行/整列不可见用 `<RowPrivilegeControl/>`/`<ColumnPrivilegeControl/>` 单条搞定，不要逐个 `<C>` 写权限（N 个节点膨胀且难维护）。
- 权限载体是「部门>职务」形态角色名（如 `销售部>sale`），写进 XML 需转义 `&gt;`；删除权限 = 移除锚点内条目但**保留空标签**（空标签是合法写法，不可整个删掉）。
- 头号静默坑：控件不可见 + 单元格可见 + 控件属「加载即初始化」类型（单选按钮组/复选框/下拉复选框）→ **该单元格数据也不显示**；想「只藏控件留数据」须换非即时初始化控件。
- 只输出受限角色的 deny 条目；默认全可见，给「该看的角色」写 visible=True 是纯冗余。
- 模板内权限生效前提：该角色在决策系统对目录有「查看」权限（先进门、再筛内容）。

### 3.9 单元格形态（CellGUIAttr.setPresent，doc-1026）

> 来源: 帆软官方帮助 doc-1026（单元格形态）

单元格「形态」是**独立于控件字典的展示层能力**：控件字典管「编辑时下拉选项」，形态管「失焦后显示什么」。无头构建落点 = `TemplateCellElement.setCellGUIAttr(DefaultCellGUIAttr)` + `CellGUIAttr.setPresent(DictPresent)`；数据字典形态用 `com.fr.report.cell.present.DictPresent` 包一个 `com.fr.data.impl.TableDataDictionary`。

- ⚠️ **不是控件形态** `com.fr.report.cell.cellattr.form.DataDictionaryForm`——二者一个管显示、一个管编辑选项，不能混用（此前草稿误用控件形态 API `setForm/DataDictionaryForm`，必须以正确 cell 形态 API 落文档，否则误导生成器）。
- **通用生成规则**：凡控件字典存在且想「失焦保留显示值」，自动给该单元格补一个同源 DictPresent——解决「填报后显示名字不显示 ID」这类需求。
- **生成器后处理 `apply_cell_dict_present(cell_xml, dict_spec)`**：仅写 `<CellGUIAttr><Present class="com.fr.report.cell.present.DictPresent"><Dictionary>`、**不碰控件 `<Dictionary>`**；输入同源字典 spec（数据集名 + 实际/显示列），与控件字典生成器**共用同一 dict_spec，强制同源**——两处各写一份字典易漂移成「选了名字提交 ID、界面却显示别的」静默坑。

> ⚠️ **勘误（doc-1191/doc-3075 字节码实读，FR 10.0）**：`com.fr.report.cell.cellattr.CellGUIAttr` **无 `setPresent(Present)` 方法、也无 Present 字段**——上文「`TemplateCellElement.setCellGUIAttr(DefaultCellGUIAttr)` + `CellGUIAttr.setPresent(DictPresent)`」是旧版记法，10.0 不成立；`DefaultCellGUIAttr` 在 10.0 jar 里也不存在（真实类就是 `CellGUIAttr`）。无头构建统一走 XML 落点：`<CellGUIAttr><Present class="...">…</Present></CellGUIAttr>`（由 `Present#writeXML` 产出，与既有 DictPresent 的容器形态一致，见 `practice/topic_3075_java/code128_present.xml`）。

**单元格形态实现类清单（包名分裂，setter 不可互用）**：

| 形态 | 类名 | 包 | 说明 |
|------|------|----|------|
| 数据字典形态 | `DictPresent` | `com.fr.report.cell.present` | 包一个 `com.fr.data.impl.TableDataDictionary`（上文 §3.9） |
| 条形码形态 | `BarcodePresent` | `com.fr.report.cell.cellattr` | 包裹 `com.fr.code.bar.core.BarcodeAttr`（fine-core），`setType(BarcodeAttr.CODE128)/setBarWidth/setBarHeight/setDrawingText`（doc-3075 实读） |

两形态同属 `com.fr.base.present.Present` 接口，但**分处两个包、setter 不可互用**——对 BarcodePresent 调 DictPresent 的 setter 会编译/运行期错。参考 `practice/topic_3075_java/`（Code128BarcodePresent.java + code128_present.xml）。
