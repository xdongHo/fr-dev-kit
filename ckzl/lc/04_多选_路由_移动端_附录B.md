## 23. 多选控件配置铁律：字符串返回值 + 分隔符（doc-3707）

> 来源: 帆软官方帮助 doc-3707

「多选下拉复选框 + 批量导出」的控件配置铁律：

- 返回值类型必须选「**字符串**」、分隔符手动输入 `','`（**含单引号字面量**），使其返回串形如 `北京','上海`，从而数据集 SQL 可直接 `and 字段 in ('"+仓库+"')` 承载多选；
- **分隔符与 SQL 拼接符必须成对一致**，改其一须同步改另一处——漏设则返回串不带引号、SQL 拼出 `in (北京,上海)` 语法错或只导出单个值，运行时全部静默。

> 📌 **级联父控件场景同样适用（doc-1285）**：该铁律不仅限批量导出——「复选框作级联父控件」时子字典 SQL 的 `in ('"+p+"')` 同样依赖分隔符正确（见 02 §8.1 多选父控件级联约束）。XML 节点形态供生成器直接抄写：
> ```xml
> <ReturnValues returnString="true" type="String" delimiter="','">
> ```
> 来源: 帆软官方帮助 doc-3707 / doc-1285

## 24. 报表路由面板（doc-3710）

> 来源: 帆软官方帮助 doc-3710

「根据参数选择导出不同报表」模式：一个参数面板充当**路由器**——本模板不含真实数据，只负责把用户导向另一份模板的导出 URL：

- 下拉框（自定义字典，**显示值=报表名称，实际值=reportlets 相对路径**，路径用 `/` 不用 `\`）选目标模板；
- 文本控件自定义文件名（不支持为空）；
- 按钮 click 事件把 `window.location` 重定向到：

```text
${servletURL}?viewlet=<报表路径>&format=<excel|word|pdf>&extype=sheet&__filename__=<名>
```

- 三个格式按钮（excel/word/pdf）的 JS 几乎相同，仅 `&format=` 一处不同，可声明式生成；
- 文件名的取值：`this.options.form.getWidgetByName("NAME").getValue()`；
- 约束：自定义文件名不支持为空；不支持移动端。

## 25. 移动端样式插件作用范围（doc-3260 / doc-3045 / doc-3195 / doc-3643）

> 来源: 帆软官方帮助 doc-3260 / doc-3045 / doc-3195 / doc-3643

两个移动端样式插件的结论同构：**表单 body 内控件可覆盖 / 参数面板控件不可覆盖**——参数面板的移动端美化统一走 `06_Web呈现层.md §22.5` 的 CSS 注入路线（param_panel_style.py），与插件是两条正交路线，不可互相替代。

| 插件 | 覆盖 | 不覆盖 | 作用层 | 额外前提 |
|------|------|--------|--------|----------|
| 「移动端简约下拉样式插件」（doc-3260） | 表单 body 内的 ComboBox/ComboCheckBox | 参数面板下拉框、填报 CPT 下拉框、视图树、与顶部参数面板插件组合 | 控件壳 | body 内 |
| 「日期移动端日历样式插件」（doc-3045） | 决策报表 .frm body 内的日期控件（DateEditor） | 参数面板内的 DateEditor（文档明确「不支持参数面板」） | **弹出的日历面板** | .frm body 内 |
| 「移动端简约日历样式插件」（doc-3195） | 决策报表 .frm body 内的日期控件 | 参数面板内的 DateEditor | 控件壳 | body 内 且必须是「手机端专属决策报表模板」 |

> ⚠️ 同一个 DateEditor 可被 3045 与 3195 两个插件从两层分别改造（一个改面板、一个改控件壳），**二者不互斥也不互替**——先分清要改哪一层再选插件；3195 独有的「手机端专属模板」前提恰是照抄 3045 结论会被漏掉的点。

**「是否写模板」分类（doc-3643）**：doc-3260 简约下拉 / doc-3045 日历样式 = **纯样式、不写模板**（卸载后 .cpt 无任何变化，与 headless 生成无关）；「移动端折叠展开树插件」（doc-3643，作用范围：普通报表单元格 + 决策报表报表块单元格）则**往 `<C>` 里写属性**——卸载后模板残留无人认领的节点，且该节点是模板功能的一部分不是装饰，**必须参与 .cpt 生成与校验**。

> ⚠️ headless 生成时指望该插件美化参数面板 = 静默无效果；参数面板下拉/日期移动端美化应改走 CSS 注入。

## 附录B+: 参数面板标准布局引擎（G2 双段式·2026-09-06 正式工艺）

**定位**：参数面板的像素级布局由程序引擎标准化，**不再走"描述逐像素→装配重建"路线**（G2 双段式裁决：描述写语义层，像素归引擎）。

- **引擎**：`kfgj/tygs/panel_layout_engine.py`（CLI: `python panel_layout_engine.py <in.cpt> [-o out.cpt] [--cols 7]`）
- **规格**（用户裁决 2026-09-06）：标准容器=【label+控件】横排；每行 7 容器超出换行；按钮容器=标准容器半宽；任一 label>8 字符→全面板切竖排（label 高 15 在上 + 控件高 25 在下 + 容器间行距 5px，容器高 40）；label 去尾冒号、居左（textalign=2，FR 常量 LEFT=2/CENTER=0/RIGHT=4，字节码实证）、8 号字不加粗（FRFont style=0 size=80）
- **主流水线接线**：`_t1_assemble.py` 装配产物后自动后处理（含 ParameterUI 的产物标准化，frm 无面板自动跳过）；v3wave_run.py 全链继承
- **desc 契约（随双段式修订）**：面板只写**语义层**（参数名/类型/三态：上面板|隐藏|自动栏），Bounds 像素坐标从描述要素移除——L9B 字数压力与面板判级噪声双消
- **评判口径**：面板布局类差异=无实质差异+panel-engine-standardized limitation（_attribution.py R10）；控件缺失/参数缺失/绑定缺失仍照常判

## 附录B: 参数面板批量处理脚本参考（Ver0.3 新增）

```python
# 控件尺寸常量
LABEL_W, LABEL_H = "auto", "26"     # 自适应
CTRL_W, CTRL_H = "180", "26"        # 输入控件
BTN_W, BTN_H = "80", "26"           # 按钮

# 间距常量
LABEL_CTRL_GAP = 4   # Label ↔ 控件
CTRL_GAP = 12        # 控件列之间
BTN_GAP = 8          # 按钮之间

# 按钮顺序
BTN_ORDER = ["Query", "Export", "Submit", "Import", "Adj Data"]

# 行高常量（修正后的正确值）
H_HEADER = "1442289"  # 10mm
H_DETAIL = "1153643"  # 8mm

# 列聚类容差
COL_TOLERANCE = 80    # px

# 多控件阈值
MANY_CTRLS_THRESHOLD = 8       # 控件数
WIDE_PANEL_THRESHOLD = 1000    # 最右控件 x 坐标
```

处理流程：
1. 标签宽度自适应 → 根据文本计算
2. 输入控件 → 统一 180×26
3. 年/日期 ComboCheckBox → YearControl/DateEditor
4. 按钮 → 统一 80×26
5. 列聚类 → 对齐到最右侧
6. 标签贴控件左侧
7. 列间间距统一 12px
8. 按钮排序 + 布局
9. 面板宽度自适应
10. 行高自动分类
