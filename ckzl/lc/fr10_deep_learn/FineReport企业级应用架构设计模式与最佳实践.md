## 一、企业级报表架构设计模式

### 1.1 集团企业多层级报表体系

#### 架构模式：总部-分公司-部门三级报表体系

```
决策平台目录树
├── 集团总部
│   ├── 经营驾驶舱（.frm 决策报表，1920×1080 大屏）
│   ├── 集团合并报表（.cpt 普通报表）
│   └── 战略分析面板（图表+报表混合）
├── 分公司
│   ├── 区域销售日报（参数化模板，按区域过滤）
│   ├── 分公司KPI看板（.frm，Tab页切换）
│   └── 区域财务报表
├── 部门
│   ├── 部门明细报表（行级权限控制）
│   ├── 填报模板（数据采集）
│   └── 部门分析报表
└── 公共
    ├── 通知公告
    └── 系统使用指南
```

**目录权限分配策略**：
| 层级 | 角色 | 目录权限 | 数据权限 |
|------|------|---------|---------|
| 集团管理层 | 超级管理员/高管 | 全部目录可见 | 全量数据 |
| 分公司经理 | 次级管理员 | 本分公司+公共目录 | 本公司数据 |
| 部门主管 | 部门角色 | 本部门+公共目录 | 本部门数据 |
| 普通员工 | 普通用户 | 本部门基础报表 | 仅个人相关数据 |

**权限继承机制**：
- 子目录默认继承父目录权限，可单独覆盖
- 权限采用"并集"原则：用户最终权限 = 用户直接权限 ∪ 角色权限 ∪ 部门权限 ∪ 职位权限
- 数据行权限特殊：采用"交集"原则（更严格）

### 1.2 决策报表（.frm）大屏架构模式

#### 标准大屏骨架（1920×1080）

```
Form
 └─ Layout (WBorderLayout)
     └─ Center (WFitLayout)           ← 外层：布局策略
         └─ Widget (BoundsWidget)
             └─ WAbsoluteBodyLayout   ← 内层：绝对坐标
                 ├── 顶部标题区 (y=0~97)
                 ├── 左侧面板 (x=0~208, 报表块+图表)
                 ├── 中央主图 (216×345, 地图/主图表)
                 ├── 右侧面板 (x=705+, KPI/明细)
                 └── 底部图表行 (y=356+, 趋势图)
```

**关键设计参数**：
| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 设计分辨率 | 1920×1080（16:9） | 最常见大屏比例 |
| ResolutionScalingAttr | 1.2 | 1920宽度对应系数（percent属性） |
| BodyLayoutType | type="1"（绝对布局） | 大屏必须绝对定位 |
| WidgetScalingAttr | compState="0"（适应区域） | 等比缩放 |
| 组件间间隙 | ≥8px | 禁止重叠，否则定时导出报错 |

**命名规范**：
| 前缀 | 类型 | 示例 |
|------|------|------|
| reportN | 报表块 | report0, report1 |
| chartN | 图表块 | chart0, chart1 |
| labelN | 标签 | label0, label1 |
| tabN | Tab块 | tab0, tab1 |
| para_N | 参数控件 | para_area, para_month |

## 二、数据权限实现方案

### 2.1 三层权限防护体系

```
第一层：目录权限（可见性控制）
  → 控制用户能看到哪些报表目录
  → 配置路径：管理系统 > 权限管理 > 目录权限
  → 子目录默认继承父目录权限

第二层：功能权限（操作控制）
  → 控制用户能使用哪些系统功能
  → 包括：目录管理/用户管理/数据连接/定时调度/插件管理等

第三层：数据权限（行级+列级安全控制）
  → 行权限：控制用户能看到哪些数据行
  → 列权限：控制用户能看到报表中的哪些列
```

### 2.2 行级数据权限实现

#### 方式一：SQL参数化过滤（推荐）

```sql
-- 按用户过滤：仅查看自己创建的数据
WHERE 创建人 = '${fine_username}'

-- 按部门过滤：仅查看本部门数据
WHERE 部门 = '${fine_department}'

-- 按角色过滤：按角色对应的区域
WHERE 销售区域 IN (${fine_role_area})

-- 组合过滤（级联参数宏）
WHERE 1=1
  ${if(len(para_dept)==0, "", " AND 部门='" + para_dept + "'")}
  ${if(len(para_user)==0, "", " AND 创建人='" + para_user + "'")}
```

**关键规则**：
- `ORDER BY` 必须在 `${if(...)}` 宏之后，否则级联静默失败
- 参数宏中的字符串拼接注意SQL注入风险
- 生产环境建议使用平台的防注入开关（`ConfigService#setPSIConfig`）

#### 方式二：数据权限配置（平台级）

```
管理系统 > 权限管理 > 数据权限
选择 用户/角色/部门 → 选择报表/数据集 → 配置行列权限
```

**权限计算规则**：
| 权限类型 | 计算规则 | 说明 |
|---------|---------|------|
| 目录权限 | 并集 | 取最大权限 |
| 功能权限 | 并集 | 取最大权限 |
| 数据行权限 | 交集 | 取最严格限制 |
| 数据列权限 | 并集 | 可见列合并 |

#### 方式三：自定义认证+权限传递

```java
// 自定义密码加密类（基础示例）
public class PasswordEncoder extends AbstractPasswordValidator {
    @Override
    public String encode(String originText) {
        return Base64.getEncoder().encodeToString(originText.getBytes());
    }
}
```

> 来源: 管理系统_batch7.md §加密验证逻辑。注意：实际加密流程为四步（明文→自定义加密→SHA256→写入FineDB），同步用户与导入用户的加密步骤不同。

**用户同步流程**：
1. 从LDAP/AD/HR系统同步用户组织架构
2. 字段映射：外部字段 → FR平台字段
3. 同步策略：全量同步 / 增量同步
4. 密码处理：自定义加密类 + SHA256二次加密

### 2.3 FineDB权限相关表

| 表名 | 说明 |
|------|------|
| FINE_USER | 用户信息 |
| FINE_ROLE | 角色信息 |
| FINE_DEPARTMENT | 部门信息 |
| FINE_AUTHORITY | 权限分配记录 |

> ⚠️ **注意**：FineDB 为平台内部数据库，表名（FINE_USER/FINE_ROLE/FINE_DEPARTMENT/FINE_AUTHORITY）仅作概念参考。实际权限查询应通过平台 API 或管理系统界面操作，不建议直接查询 FineDB。
> 来源: 管理系统_batch7.md §FineDB 关键表

## 三、多数据源整合最佳实践

### 3.1 支持的数据源类型

| 分类 | 数据源 | 典型场景 |
|------|--------|---------|
| 关系型 | MySQL, Oracle, SQLServer, PostgreSQL, DB2 | ERP/CRM/财务系统 |
| 大数据/NoSQL | HBase, MongoDB, Redis, Elasticsearch | 海量数据/日志分析/实时大屏 |
| 文件/接口 | API, JSON, XML, Excel, CSV | 第三方对接/文件导入 |
| 基础设施 | 连接池, 测试, 优化, 安全 | 性能调优/运维监控 |

### 3.2 多数据源整合架构

```
┌──────────────────────────────────────┐
│         FineReport 报表引擎           │
├──────────┬───────────┬───────────────┤
│ 数据集1  │ 数据集2   │ 数据集3        │
│ (MySQL)  │ (Oracle)  │ (API/JSON)    │
├──────────┴───────────┴───────────────┤
│           数据连接池管理              │
├──────────┬───────────┬───────────────┤
│ MySQL    │ Oracle    │ REST API      │
│ Pool     │ Pool      │ Adapter       │
└──────────┴───────────┴───────────────┘
```

### 3.3 数据集复用策略

| 策略 | 适用场景 | 实现方式 |
|------|---------|---------|
| 共享数据集 | 多模板共用相同查询 | 服务器数据集 |
| 数据集复用 | 同模板内多处引用 | 同一数据集ds1 |
| 文件数据集 | 静态数据/Excel导入 | Excel/CSV文件数据集 |
| 数据固化导出 | 避免重复查库 | `EmbeddedTableDataExporter` |

### 3.4 连接池配置最佳实践

```
MySQL:
  驱动: com.mysql.jdbc.Driver (5.x) / com.mysql.cj.jdbc.Driver (8.x)
  URL: jdbc:mysql://host:3306/db?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai
  JAR: mysql-connector-java-x.x.x.jar

Oracle:
  驱动: oracle.jdbc.driver.OracleDriver
  URL: jdbc:oracle:thin:@host:1521:SID 或 jdbc:oracle:thin:@//host:1521/service
  JAR: ojdbc8.jar
  注意: 关注 processes 上限（V$process / V$parameter）

SQLServer:
  驱动: com.microsoft.sqlserver.jdbc.SQLServerDriver
  URL: jdbc:sqlserver://host:1433;databaseName=dbname
  注意: sendStringParametersAsUnicode=true

PostgreSQL:
  驱动: org.postgresql.Driver
  URL: jdbc:postgresql://host:5432/database
```

**连接池参数**：
| 参数 | 推荐值 | 说明 |
|------|--------|------|
| maxConn | 50-100 | 最大连接数（视并发量，公式：并发数×1.5） |
| minConn | 5-10 | 最小空闲连接 |
| maxWaitTime | 30s (30000ms) | 连接超时 |
| 禁用HSQL | ✅ | 官方禁止非必要创建内置FineDB连接 |

> 来源: 操作指南_batch2.md §1.2, 数据连接_batch1.md §17
| 禁用HSQL | ✅ | 官方禁止非必要创建内置FineDB连接 |

### 3.5 API/JSON数据源对接

```json
// JSON数据源配置
{
  "source": "http://api.example.com/data",
  "method": "GET",
  "headers": {"Authorization": "Bearer xxx"},
  "jsonPath": "$.data.records[*]",
  "fields": ["id", "name", "amount"]
}
```

**注意事项**：
- API调用可能有频率限制，需做好缓存
- 大数据量接口需分页处理
- API密钥安全存储（不明文写入模板）

## 四、移动端报表与响应式设计

### 4.1 决策报表移动端布局模式

| GUI选项 | 布局类型 | XML配置 | 适用场景 |
|---------|---------|---------|---------|
| 双向自适应 | 自适应+组件缩放(全) | `<BodyLayoutType type="0"/><WidgetZoomAttr compState="0"/>` | 手机端简单报表 |
| 横向自适应 | 自适应+组件缩放(横) | `<BodyLayoutType type="0"/><WidgetZoomAttr compState="1"/>` | 平板横屏 |
| 适应区域 | 绝对+缩放逻辑(适) | `<BodyLayoutType type="1"/><WidgetScalingAttr compState="0"/>` | 移动端大屏 |
| 固定大小 | 绝对+缩放逻辑(固) | `<BodyLayoutType type="1"/><WidgetScalingAttr compState="1"/>` | 精确控制 |

### 4.2 分辨率折算系数

| 设计宽度 | percent系数 |
|---------|------------|
| 1920 | 1.2 |
| 1440 | 1.0 |
| 1366 | 0.9 |
| 1280 | 0.85 |
| 1024 | 0.6 |

> 宽度 <1024 按 1024、>1920 按 1920

### 4.3 移动端适配要点

1. **图表提示**：富文本提示文案 ≤6行并控宽
2. **组件间隔**：绝对布局组件间留 ≥8px 间隙
3. **自适应属性**：`<ReportFitAttr fitStateInPC="2" fitFont="false"/>`
4. **移动专属配置**：`<FormMobileAttr>` 节点单独配置移动端参数
5. **value() vs $参数**：`.frm` body 中 `value('ds1',col)` 不会随输入控件变化重算，需联动时用 `$参数名`

### 4.4 移动端性能优化

- 使用 `gotoPage(pn, para, "lazy")` 局部刷新（只重算当前块）
- 首屏加载：`afterinit + setTimeout` 延迟加载非核心组件
- 轮播联动：使用 `noCache="lazy"` 而非 `noCache=true`
- 数据预聚合：限制图表返回行数

## 五、性能优化清单

### 5.1 SQL与数据层优化

| # | 优化项 | 具体措施 | 优先级 |
|---|--------|---------|--------|
| 1 | 数据集复用 | 多单元格引用相同数据时使用同一数据集ds1 | 高 |
| 2 | SQL参数化 | 使用 `${if(len(para)==0, "1=1", ...)}` 避免全表扫描 | 高 |
| 3 | 共享数据集 | 多模板共用查询使用「服务器数据集」 | 高 |
| 4 | 禁用HSQL | 不创建内置FineDB连接，避免内存争抢 | 高 |
| 5 | 连接池调优 | maxConn=50-100, minConn=5-10, maxWaitTime=30s | 中 |
| 6 | 文件数据集 | 静态数据用Excel/CSV文件数据集 | 中 |
| 7 | 数据固化 | `EmbeddedTableDataExporter` 避免重复查库 | 中 |

### 5.2 渲染与前端优化

| # | 优化项 | 具体措施 | 优先级 |
|---|--------|---------|--------|
| 1 | 局部刷新 | `gotoPage(pn, para, "lazy")` 只重算当前块 | 高 |
| 2 | 延迟加载 | `afterinit + setTimeout` 延迟非核心组件 | 高 |
| 3 | 图表数据限制 | 百万级数据预聚合，限制返回行数 | 高 |
| 4 | 合并数据集 | 减少组件绑不同数据集导致的并发查询 | 中 |
| 5 | 缓存策略 | 模板缓存256MB(LRU)，数据缓存512MB(TTL+LRU) | 中 |
| 6 | 组件间隙 | 绝对布局组件间≥8px，禁止重叠 | 中 |

### 5.3 导出与调度优化

| # | 优化项 | 具体措施 | 优先级 |
|---|--------|---------|--------|
| 1 | 行式引擎 | 大数据量导出使用行式引擎插件 | 高 |
| 2 | JDK版本 | 避免 jdk1.8.0_262/8u231/8u192 | 高 |
| 3 | 流关闭 | OutputStream 必须关闭后再落盘 | 高 |
| 4 | 导出行数限制 | 设置合理上限防止内存溢出（默认100万） | 中 |
| 5 | 调度参数默认值 | 定时调度模板所有参数必须有默认值 | 中 |
| 6 | 文件名公式 | 展开后≤255字符 | 中 |

### 5.4 JVM与服务器优化

```bash
# 生产环境推荐JVM参数
-Xms4096m                    # 初始堆内存
-Xmx4096m                    # 最大堆内存
-XX:MetaspaceSize=256m       # 元空间初始
-XX:MaxMetaspaceSize=512m    # 元空间最大
-Dfile.encoding=UTF-8        # 字符编码
-Djava.awt.headless=true     # 无头模式
-Duser.timezone=Asia/Shanghai # 时区（定时调度关键！）
```

| 参数 | 默认值 | 推荐值 | 说明 |
|------|--------|--------|------|
| 数据缓存大小 | 参考512MB | 1-2GB | 生产环境按需增大 |
| 并发查询数 | 参考50 | 100-200 | 按CPU核心数调整 |
| 查询超时 | 参考60s | 30-120s | 复杂报表增大 |
| Tomcat版本 | - | 8.5.57+ | 必须升级 |
| URIEncoding | - | UTF-8 | 必须配置 |

> ⚠️ 默认值为参考值，具体以平台实际配置为准。

### 5.5 缓存管理

| 缓存类型 | 内容 | 参考大小 | 清理策略 |
|---------|------|---------|---------|
| 模板缓存 | 解析后的模板对象 | 256MB | LRU |
| 数据缓存 | 查询结果集 | 512MB | TTL+LRU |
| 会话缓存 | 用户会话信息 | 128MB | 超时清理 |
| 资源缓存 | 图片/CSS/JS | 64MB | 版本更新 |

> ⚠️ 缓存大小为参考值，具体以平台实际配置为准。生产环境应监控缓存命中率，低于 70% 需优化。

| 等级 | 影响 | RTO | RPO | 恢复策略 |
|------|------|-----|-----|---------|
| L1-轻微 | 单节点故障 | 5分钟 | 0 | 自动故障转移 |
| L2-中等 | 部分服务不可用 | 30分钟 | 15分钟 | 本地备份恢复 |
| L3-严重 | 整个集群不可用 | 4小时 | 1小时 | 异地备份恢复 |
| L4-灾难 | 数据中心不可用 | 24小时 | 24小时 | 灾备中心切换 |

## 八、备份与运维

### 8.1 3-2-1备份策略

- **3份副本**：生产数据 + 本地备份 + 异地备份
- **2种介质**：磁盘存储 + 磁带/云存储
- **1份异地**：至少一份备份存放在异地数据中心

### 8.2 备份时间表

| 场景 | 方式 | 频率 | 保留周期 |
|------|------|------|---------|
| 日常数据保护 | 增量备份 | 每6小时 | 7天 |
| 日终全量备份 | 全量备份 | 每日02:00 | 30天 |
| 周末完整备份 | 全量备份 | 每周日03:00 | 12周 |
| 月度归档 | 全量+归档 | 每月1日 | 12个月 |
| 重大变更前 | 手动备份 | 按需 | 长期 |

### 8.3 故障排查SOP

```
1. 确认日志：先配 log4j.properties 拿到 fanruan.log
2. 读日志关键词：按根因判据表定位
   - RFC → relaxedQueryChars 配置
   - Can't load AMD 64-bit .dll → JDK位数不匹配
   - Database is not initialized → 内存不足（非数据库问题）
3. 分层排查：模板 → 数据 → 插件 → 决策系统 → JVM → 中间件 → OS
4. 验证修复：重新部署 → 浏览器预览 → 功能验证
```

## 九、核心铁律速查

| # | 铁律 | 说明 |
|---|------|------|
| A | SQL 多行格式化 | 数据集 SQL 必须换行，不可单行 |
| B | 行高用 FU | 表头 1442289(10mm), 明细 1153643(8mm) |
| C | ORDER BY 位置 | 必须在 `${if(...)}` 宏之后 |
| D | 级联参数非自闭合 | `<Parameter>` 不能写成 `/>` 自闭合 |
| E | TableDataMap 非自闭合 | 必须有完整闭合标签 |
| F | 参数面板布局完整 | `<Layout>` 节点存在且非空 |
| G | 导出流必须关闭 | OutputStream 关闭后才落盘 |
| H | 禁用 HSQL 连接 | 不创建内置 FineDB 连接 |
| I | CSS 注入走后台 | 不依赖前台 JS 效果 |
| J | JDK 版本避坑 | 避免 1.8.0_262/8u231/8u192 |
| K | 定时调度参数默认值 | 所有参数必须有默认值 |
