## 0. 开发环境

### 0.1 目录结构
```
{FR_HOME}/                         # FineReport_10.0 安装根目录
├── lib/fine-report-designer-10.0.jar    (21MB, 设计器类)
├── webapps/webroot/WEB-INF/lib/         (22 jars, 运行时类)
│   ├── fine-core-10.0.jar
│   ├── fine-report-engine-10.0.jar
│   ├── fine-datasource-10.0.jar
│   ├── fine-decision-10.0.jar
│   ├── fine-third-10.0.jar
│   └── ...
├── jre/                                 (Java 8)
└── webapps/webroot/WEB-INF/reportlets/  (模板目录)
```

> FR_HOME 定位方式：
> ```powershell
> # Windows: 在 C:\Program Files\ 下搜索
> Get-ChildItem -Path "C:\Program Files" -Directory -Filter "FineReport*" | Select-Object -First 1
> ```
> ```bash
> # Linux/Mac
> find /opt -maxdepth 2 -type d -name 'FineReport_10.0' 2>/dev/null
> ```

### 0.2 编译命令
```bash
# FR_HOME = FineReport_10.0 安装目录
# javac — 必须包含 WEB-INF/lib 全部 22 jar
CP=$(find "$FR_HOME/webapps/webroot/WEB-INF/lib" -name "*.jar" | tr '\n' ';')
javac -encoding UTF-8 -cp "$CP" -proc:none MyBuilder.java

# java 运行
java -cp "$CP;." MyBuilder
```

> ⚠️ export 时会报 `ClassNotFoundException: com.fr.license.selector.LicenseContext`，可忽略，文件正常生成。
>
> 问：LicenseContext ClassNotFound 报错要处理吗？→ 不用。独立 JVM（非 Designer 注入）跑 FR Java 时
> License/环境不可用，此报错是许可校验缺席的噪声，文件正常生成；场景行见 ckzl/gf/FR_HEADLESS_GUIDE.md 铁律 K。

> 📌 **classpath 必须三目录全覆盖（doc-1698）**：仅 `WEB-INF/lib` 不够——当 Java 实践用到设计器类（报表设计/写盘 API 在 `lib/` 下）时会 ClassNotFound 编译失败。官方 doc-744 明确三目录全覆盖，javac classpath 应包含：
> ```bash
> CP=$(find "$FR_HOME/lib" "$FR_HOME/server/lib" "$FR_HOME/webapps/webroot/WEB-INF/lib" -name "*.jar" | tr '\n' ';')
> CP="$CP;$JAVA_HOME/lib/tools.jar"   # 编译期 tools.jar（见 §2）
> ```
> 来源: 帆软官方帮助 doc-1698 / doc-744

### 0.5 本地开发预览

> FR 本地服务器: `http://localhost:8075`

```
path:  C:\Program Files\FineReport_10.0\webapps\webroot\WEB-INF\reportlets\
url:   http://localhost:8075/webroot/decision/view/report?viewlet=...

**预览模式**:

http://localhost:8075/webroot/decision/view/report?viewlet=项目报表目录/明细报表/FS%20实际.cpt&op=write
```

**登录**: admin / admin（获取 token）
### 0.5.1 设计器选项与预览环境（doc-194）

设计器「文件>选项」全部为**环境级配置**，与 .cpt/.frm 构建解耦（无头构建既不需要、也无法在模板中表达），但影响预览验证链路，预览打不开时**先查环境层再查模板**：

- **配置存储**：所有选项存于 `%USERPROFILE%\.FineReport100\FineReportEnv.xml`，与 .cpt 模板内容完全解耦；统一环境靠改该文件而非模板；
- **内置服务器端口默认 8075**（选项>高级>端口设置，改后重启设计器生效）：kit 校验流程 `localhost:8075` 预览即依赖此默认值，端口被占时预览不可达属**环境问题而非模板问题**；
- **「高级>内置服务器>使用时启动」默认不勾选**：勾选后设计器启动不拉起内置服务器、首次预览才自启动——预览类验证前需确认内置服务器已启动；
- 「模板预览性能>图片压缩」仅压缩设计器预览图片，不改模板文件、不影响导出结果，无头构建无需处理。

> 来源: 帆软官方帮助 doc-194

### 0.7 模板验证流程

> 每次修改 .cpt 后，通过浏览器访问确认模板无损坏、无运行时异常。

```
1. 模板放入 reportlets/ 目录
2. 浏览器打开: http://localhost:8075/webroot/decision/view/report?viewlet=路径.cpt&op=write
3. 检查:
   - 页面是否正常渲染（非白屏/非报错页）
   - 参数面板控件是否显示、布局是否正常
   - 数据集是否加载、报表数据是否正确
4. 如页面报错，查看服务器日志定位根因:
   - 日志路径: C:\Program Files\FineReport_10.0\webapps\webroot\WEB-INF\logs\
   - 关键错误: 11300003 死循环、NS_Exception_ReadError 模板损坏、SQL 异常
```

> **HTTP 200 = 页面成功渲染**。若内容无 "错误"/"死循环"/"Exception" 关键词则模板健康。

### 0.4 操作前备份（强制规则）

> ⚠️ **每次修改文件前，必须自动创建备份。**

#### 模板备份
备份目录命名：`_backup_YYYYMMDD_HHMMSS/`，位于目标目录同级。

#### 指南备份
更新 `ckzl/gf/FR_HEADLESS_GUIDE.md` 前，先复制到 `FR_HEADLESS_GUIDE_Ver历史备份/<当前日期>/`。

```python
from datetime import datetime
BACKUP_DIR = BASE_DIR / f"_backup_{datetime.now().strftime('%Y%m%d_%H%M%S')}"

# 修改前备份
shutil.copy2(original_path, BACKUP_DIR / relative_path)

# 修改后写入
with open(target_path, 'w', encoding='utf-8') as f:
    f.write(modified_content)
```

**备份保留策略**：所有备份目录保留不删除。出现问题时从最近备份恢复：
```python
# 恢复
for f in backup_dir.glob('**/*.cpt'):
    shutil.copy2(f, BASE_DIR / f.relative_to(backup_dir))
```
