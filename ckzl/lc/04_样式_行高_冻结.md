## 4. 样式构建

### 4.1 Java API
```java
// Style 不可变，所有修改返回新 Style
Style s = Style.DEFAULT_STYLE
    .deriveFRFont(FRFont.getInstance("微软雅黑", 1, 9))   // name, bold(0/1), pt_size
    .deriveBackground(ColorBackground.getInstance(new Color(0x4F9EC2)))
    .deriveBorder(1, gray, 1, gray, 1, gray, 1, gray)    // topStyle,topColor, bottom, left, right
    .deriveFormat(new CoreDecimalFormat("#0.00"));
```
- `FRFont.getInstance(name, style, pt)` — size 是 **pt 值**（9=9pt），不是 pt×8
- XML 中序列化为 `size="72"`（9×8=72）
- `ColorBackground` 用静态工厂 `getInstance(Color)`，构造函数是 private
- `FU` 用 `FU.getInstance(long)`，构造函数是 protected

### 4.2 Python XML
```python
def style(i, font="微软雅黑", fs=72, bold=0, fg="-16777216", align="0",
          bg_name="NullBackground", bg_color="", fmt="", border=""):
    bg = f'<Background name="{bg_name}" color="{bg_color}"/>' if bg_color else f'<Background name="{bg_name}"/>'
    fm = f'<Format class="com.fr.base.CoreDecimalFormat"><![CDATA[{fmt}]]></Format>' if fmt else ""
    bd = border if border else '<Border/>'
    return f'''<Style horizontal_alignment="{align}" imageLayout="1">
<FRFont name="{font}" style="{bold}" size="{fs}" foreground="{fg}"/>
{bg}{fm}{bd}
</Style>'''
```
- `fs=72` = 9pt（XML 中 size=pt×8）
- `bg_color` 用 FR 内部值（`-1`=白, `-11555390`=标准蓝）
- `bold`: `style="1"`=加粗, `style="0"`=常规

### 4.3 颜色对照
| 颜色 | FR 内部值 | 用途 |
|------|----------|------|
| 白色 | `-1` | 数据行背景 |
| 标准蓝 | `-11555390` | 表头背景 |
| 浅蓝 | `-917761` | 分组行背景 |
| 灰绿 | `-2297104` | 小计行背景 |
| 深蓝 | `-4660244` | 汇总行背景 |
| 边框灰 | `-5973270` | 标准边框 |

### 4.4 统一样式规范
```xml
<!-- 所有 Style 必须包含 -->
<Style paddingLeft="6" paddingRight="6" ...>
  <FRFont name="微软雅黑" .../>
  ...
</Style>
```
- 字体统一用 `微软雅黑`（禁止 SimSun）
- 左右缩进 `paddingLeft="6" paddingRight="6"`

### 4.5 格式符铁律（doc-217，脚本生成 pattern 必检）

### 常见问法：单元格内容太长怎么自动换行？/ 字段有空格想换行怎么办？/ 设了换行行高却不跟变怎么修？

| 症状/口语问题 | 动作（脚本/公式/操作步骤） | 出处 |
|---|---|---|
| 设了自动换行但行高不变、内容被压住 | 自动换行必须同时配「自动调整行高」，仅设换行无效；批量调行高用 fix_row_heights | 本文件 §4.5 规则⑤（L763）【实测】；脚本在册 kfgj/tygs/索引目录.md L96【实测】 |
| Excel 导出后换行错乱/字号变大 | 字体>14 且自动换行时导出字号×0.95；页边距不一致把模板上下边距设 12.7mm | 本文件 §10.1（L1314）【实测】 |
| Word 导出后二次编辑换行时行高死板 | `<WordExportAttr>` 的 fixRowHeight="false"=不固定行高（仅 PC 分页预览生效，移动端不支持） | 本文件 §10.4（L1339）【实测；fixRowHeight 原文自标推断待核】 |
| 脚本生成的显示 pattern 不生效（静默错位） | 生成器输出 pattern 必检：月份大写 MM、0/# 补位、¤0 货币；与 §3.5 明细格式化配合 | 本文件 §4.5（L755-L765）【实测】 |

> 注：选节 q 原词含「字段空格」，本文件无「按空格拆分换行」专述——检索落点即本节换行主题；按字数拆行属公式处理，可查 §2.6 常用报表函数速查。【推演·缺口登记】

> 显示格式 pattern 写在 `<Format>` 的 CDATA。以下规则是**静默失效型坑**——写出 `yyyy-mm-dd` 或小写 m 日期列不会报错，只是显示错位/空白，headless 极易漏检（来源: 帆软官方帮助 doc-217）。

| 规则 | 说明 |
|------|------|
| ① 日期月份必须大写 **M** | 小写 `m` 不识别（`yyyy-mm-dd` ❌ / `yyyy-MM-dd` ✅） |
| ② `0` 占位补 0，`#` 不补 0 | 金额 `#,##0.00`；补位用 `00.00` |
| ③ 货币用 `¤0` 前缀 | 自动带货币符号（`¤0.00`） |
| ④ 百分比 `0.00%` 取小数按「奇进偶不进」 | 银行家舍入，只改显示不改值；下游按显示值汇总/导出需警惕偏差 |
| ⑤ 自动换行必须配合「自动调整行高」 | 仅设自动换行无效；导出模板保持默认对齐（分散对齐/自定义角度在 word/excel 导出失效） |

> 生成器/格式化助手输出日期/数值 pattern 时必须过此校验（与 §3.5 明细格式化表配合使用）。

### 4.6 字体名对齐部署字体库铁律（doc-3836/doc-4063）

> 来源: 帆软官方帮助 doc-3836 / doc-4063（字体）

- HEADLESS 经 `com.fr.report.style.Style#setFont(java.awt.Font)` 写入的 `<FRFont name>` 必须与**目标服务器字体库一致**；预览走浏览器字体、导出/打印走服务器字体，**两者可以不同**。
- 跨平台交付优先用服务器必装字体（宋体/微软雅黑/等线），或在安装字体清单登记；不能用服务器没有的字体。
- **静默失败形态**：字体缺失 → 静默回退默认字体（同构 doc-2664 空白图、doc-1162 actorName 兜底），Excel 导出连提示都没有——无日志、fr_check 通过。
- 验收断言必须判「关键字体名 ∈ 目标 JRE 字体库」，而非仅「导出未抛异常」。参考 `practice/topic_4063_java/FontMissingDetector.java`。

## 5. 行高与列宽

### 5.1 FU 单位换算（⚠️ 本节为旧推算值，权威换算以 §5.5 为准：10mm=1440000、8mm=1152000）

### 常见问法：行高怎么设置？1mm 等于多少 FU？/ 导出 Excel 行高和预览不一致怎么办？/ 行太挤太松怎么调？

| 症状/口语问题 | 动作（脚本/公式/操作步骤） | 出处 |
|---|---|---|
| 问 1mm 等于多少 FU | 权威换算 1mm=144000 FU（UNITConstants 实读）；§5.1 的 144229/mm 系旧推算差 0.16%，生成器以 §5.5 为准 | 本文件 §5.5（L822-L834）【实测】 |
| 表头/明细标准行高 | 表头 10mm、明细 8mm；XML 写 `<RowHeight defaultValue="1153643">` + CDATA 逐行值 | 本文件 §5.1 表（L789-L793）+ §5.3（L802-L808）【实测】；铁律 C 同值（GUIDE L110-L111）【实测】 |
| 导出 Excel 行高与预览不一致 | 行高按内容自动分类：纯文本=表头 10mm、DSColumn/公式=明细 8mm、Row 0 强制保护 10mm；Word 侧另有 fixRowHeight 开关 | 本文件 §5.4（L810-L816）+ §10.4（L1339）【实测】 |
| 批量修行高/一键编排 | 批量修行高 = fix_row_heights 单跑（Skills 封装在册）；一键编排 run_defaults.py 默认 6 步 = SQL美化/明细样式/冻结/面板/CSS/导出查询按钮——编排链**不含行高步**，修行高须单跑 fix_row_heights | kfgj/tygs/索引目录.md L96 / L32【实测】；run_defaults.py STEPS 源码实读（QA1 勘误 2026-09-12） |
| Java 里设行高编译不过 | 用 FU.getInstance(long)；new FU(...) 编译不过（构造器 protected） | 本文件 §5.5（L834）【实测】 |

> **关键**: FR 行高/列宽以 FU 计量，权威换算 **1mm = 144,000 FU**（UNITConstants 实读 + 活 JVM 双向闭环实证，见 §5.5 与 kfgj/xlyl/单位换算实证.md）；历史值 144228.9 FU/mm 偏差 +0.16%。
> Ver0.2 中的 `804330≈10mm` 实际对应约 5.58mm，是错误的。
> ColumnWidth 与 RowHeight 用相同的 FU 单位。

| 用途 | FU 值 | 实际高度 |
|------|-------|---------|
| 表头（纯文本标题行） | `1440000` | 10mm |
| 明细（DSColumn/公式数据行） | `1152000` | 8mm |
| FR 默认行高 | `723900` | ~5mm |

### 5.2 Java API
```java
// Java API 中 FU 换算与 XML 一致
sheet.setRowHeight(0, FU.getInstance(1440000));   // 表头 10mm
sheet.setRowHeight(1, FU.getInstance(1152000));   // 明细 8mm
```

### 5.3 Python XML
```xml
<RowHeight defaultValue="1152000">
<![CDATA[1440000,1152000,1152000,...]]></RowHeight>
<ColumnWidth defaultValue="2743200">
<![CDATA[6629400,5524500,4991100,...]]></ColumnWidth>
```

### 5.4 行高自动分类
根据 CellElementList 中单元格内容自动区分表头/明细：
- **纯文本行**（`<O><![CDATA[text]]></O>`，无 `t=` 属性）→ 表头 10mm
- **DSColumn 行**（`t="DSColumn"` 或紧凑格式 `ds1.G()`）→ 明细 8mm
- **公式行**（`t="XMLable" class="Formula"`）→ 明细 8mm
- **Row 0 强制保护** → 表头 10mm（FR 报表 Row 0 通常为标题行）
- **原始高度 ≥ 1,800,000 FU** → 表头保护（合并区域不压缩）

### 5.5 FU 权威换算表与默认值（doc-1698 实读）

> 来源: 帆软官方帮助 doc-1698（地图边界获取传参，UNITConstants 字节码实读）

行高/列宽的度量统一用 FU，权威换算表（`com.fr.stable.unit.UNITConstants` 实读）：

| 单位 | FU 值 |
|------|-------|
| 1 inch | 3657600 |
| 1 pt | 50800 |
| 1 px | 38100（=`UNITConstants.DELTA`） |
| 1 mm | 144000 |
| 1 cm | 1440000 |

- 默认行高 `UNITConstants.DEFAULT_ROW_HEIGHT` = 723900（=19px）；默认列宽 `DEFAULT_COL_WIDTH` = 2743200（=72px，与 §5.3 既有 XML 一致）。
- ⚠️ **与 §5.1 冲突勘误**：§5.1 的「1mm ≈ 144,229 FU / 10mm = 1442289」是旧推算值；按 UNITConstants 精确体系 **10mm = 1,440,000 FU**（1mm = 144,000，1 inch=25.4mm 整除），两者差 0.16%——生成器以本节换算表为准（附录 A 示例里的 1442289 属 §5.1 旧值，需按 1440000 校正）。
- 类约束：`UNIT` 是抽象类、`FU` 构造器 protected（只能 `FU.getInstance(long)`）；`PT/MM/CM/INCH/OLDPIX` 才有 `public <init>(float)`——`new FU(...)` 编译不过。

### 5.6 隐藏行列（doc-1698 字节码实读）

### 常见问法：怎么隐藏某一列？/ 查询结果不想显示某列怎么办？/ 行高设 0 能隐藏整行吗？/ 有没有 setHidden？

| 症状/口语问题 | 动作（脚本/公式/操作步骤） | 出处 |
|---|---|---|
| 隐藏某列 | 列宽置 0：setColumnWidth(int, UNIT.ZERO)；隐藏行同理 setRowHeight(int, UNIT.ZERO)；负值被静默 clamp 成 0 | 本文件 §5.6①（L840）【实测】 |
| 满足条件才隐藏（条件隐藏行/列） | RowHeightHighlightAction / ColWidthHighlightAction（无参构造即 ZERO）挂 DefaultHighlight → HighlightGroup（无 add 方法，数组构造） | 本文件 §5.6②（L841）【实测】 |
| 取消隐藏 | 无独立 API：写回默认常量 DEFAULT_ROW_HEIGHT=723900 / DEFAULT_COL_WIDTH=2743200 | 本文件 §5.6③（L842）+ §5.5（L832）【实测】 |
| 找 setHidden / hidden 布尔位 | 不存在：FR 无 hidden 位（getRangeValueExcludeHidden 全 jar 零外部调用点），别去找 setHidden | 本文件 §5.6④（L843）【实测】 |

> 来源: 帆软官方帮助 doc-1698 / doc-1825（行高=0）/ doc-865（列宽=0）

- ① **静态隐藏**：`ElementCase#setRowHeight(int, UNIT.ZERO)` / `setColumnWidth(int, UNIT.ZERO)`；负值被静默 clamp 成 0。
- ② **条件隐藏**：`RowHeightHighlightAction` / `ColWidthHighlightAction`（无参构造器已是 `UNIT.ZERO`）挂 `DefaultHighlight` → `new HighlightGroup(Highlight[])`（⚠ 该类无 add 方法）→ `AbstractDynamicCellElement#setHighlightGroup`（§3.4.3）。这也闭合 §3.4.1 动作表中「行高=0（隐藏行）⚠待核 doc-1825」「列宽=0（隐藏列）⚠待核 doc-865」两行的类名。
- ③ **取消隐藏无独立 API**：写回默认常量（`DEFAULT_ROW_HEIGHT` / `DEFAULT_COL_WIDTH`，见 §5.5）。
- ④ FR **无 `hidden` 布尔位**（`getRangeValueExcludeHidden` 全 jar 零外部调用点）——别去找 `setHidden`。
