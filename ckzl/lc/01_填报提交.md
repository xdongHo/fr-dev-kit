## 9. 填报提交
> 问法入口（2026-09-13 收官补，M-016）：「按钮 后台执行存储过程」「点击按钮执行SQL/存储过程」→ 先看本节提交机制（BuiltInSQLSubmiter/自定义提交），类名与签名再查 ckzl/zsk/gczsk query_kb.py part <类名>。

```xml
<ReportWriteAttr>
  <SubmitVisitor class="com.fr.report.write.BuiltInSQLSubmiter">
    <Attributes dsName="数据连接1"/>
    <DMLConfig class="com.fr.write.config.IntelliDMLConfig">
      <Table schema="数据schema" name="fin_demo_input"/>
      <ColumnConfig name="bu" isKey="true" skipUnmodified="false">
        <ColumnRow column="2" row="1"/>
      </ColumnConfig>
    </DMLConfig>
  </SubmitVisitor>
</ReportWriteAttr>
```

审计字段：
```xml
<ColumnConfig name="create_by">
  <O t="XMLable" class="com.fr.base.Formula">
    <Attributes><![CDATA[=$fine_username]]></Attributes>
  </O>
</ColumnConfig>
<ColumnConfig name="create_time">
  <O t="XMLable" class="com.fr.base.Formula">
    <Attributes><![CDATA[=now()]]></Attributes>
  </O>
</ColumnConfig>
```

### 9.0 内置 SQL 提交补充铁律（doc-3577 + doc-217 待核验项）

> 来源: 帆软官方帮助 doc-3577（内置SQL提交）/ doc-217（提交条件/提交事件待核验）

| 铁律 | 说明 |
|------|------|
| ① **Oracle 等必须带 Table.schema** | `<Table schema="..." name="..."/>`——生成填报目标表时 `<Table>` 应接受 schema 入参，缺失则字段绑定取不到（尤其 Oracle 需选模式） |
| ② **多个内置 SQL 串行 + 同一事务** | 从上到下串行执行、任一失败全部回滚（doc-3577 §1.3）——DMLConfig 的 XML 顺序即执行顺序 |
| ③ **isKey 不等同数据库主键** | `isKey="true"` 充当更新/删除的 where 条件，涉及修改/删除必须勾选 |
| ④ **「未修改不更新」= `skipUnmodified="true"`** | 大数据量回填场景默认开启可显著提升提交性能；kit 示例用 `"false"` 仅作演示，生成器应暴露该开关策略（doc-3577 §3.4） |
| ⑤ 提交条件 / 提交事件（待核验） | 提交条件（§3.5 入库前过滤、不中断）与提交事件（§3.6 每条影响数据各执行一次）真实 XML 节点名/位置需先抓 GUI 产生的 .cpt 样本核对后再补示例——不要贸然猜测节点名写进铁律 |

> `skipUnmodified="true"` 示例：`<ColumnConfig name="bu" isKey="true" skipUnmodified="true">`。参考 `practice/topic_3577/submit_fragment.xml`（Oracle schema + 主键 + 串行双 DML + 未修改不更新）。

**提交条件核验样本（doc-3713，闭合 §9.0 ⑤ 的「待核验」）**：doc-3713 提供了最小可复现用例（提交条件 `=G2='true'`，删除提交，雇员表主键 雇员ID）。核验步骤：设计器按该例配一次 → 保存 .cpt → 解压对比 `<DMLConfig>` 下新增的子节点名 → 同时 `javap -classpath fine-write.jar com.fr.write.config.DMLConfig` 取 setter 签名 → 固化进铁律表。

### 9.1 delete_flag 先删后插（清空表/按业务键清空）

**表结构约定**：所有导入/填报目标表默认带审计字段 `delete_flag integer DEFAULT 1 NULL`（放在 create_by/create_time/update_by/update_time 之前），用于「清空表」语义。

**清空整表（无业务键）**：
```xml
<!-- DeleteConfig: delete_flag 常量 1 作 isKey，先删全部 -->
<DMLConfig class="com.fr.write.config.DeleteConfig">
  <Table schema="数据schema" name="fin_demo_input_ci_lane_mapping"/>
  <ColumnConfig name="delete_flag" isKey="true">
    <O><![CDATA[1]]></O>
  </ColumnConfig>
</DMLConfig>
```

**按业务键清空（如按 data_year 删旧年度）**：主键列用公式引用参数——
```xml
<DMLConfig class="com.fr.write.config.DeleteConfig">
  <Table schema="数据schema" name="fin_demo_input_vave_detail"/>
  <ColumnConfig name="data_year" isKey="true">
    <O t="XMLable" class="com.fr.base.Formula">
      <Attributes><![CDATA[=para_data_year]]></Attributes>
    </O>
  </ColumnConfig>
</DMLConfig>
```

> 导入页标准模式 = DeleteConfig（清旧）+ InsertConfig（插新）；InsertConfig 的业务列 ColumnRow 全部指向输入行（如 `(c, 2)`），审计字段用公式，delete_flag 恒插 1。

### 9.2 按行勾选批量提交/删除（doc-3713）

> 来源: 帆软官方帮助 doc-3713（按行勾选批量提交）

「按行勾选后批量操作」是填报需求里复用率最高的交互（kit 现有章节只覆盖「整表提交」）。范式三段式：

- **① 行内勾选框 + 表头全选框**：行内 `com.fr.form.ui.CheckBox`，设左父格 `<Expand leftParentDefault="false" left="C2"/>` 随数据行扩展；表头全选框联动靠公式 `=if(B1 = 'true','true','false')` 而**非 JS**；
- **② 隐藏辅助格**：`G2 = B2` 把控件值**物化成引擎可读值**（列宽=0 隐藏，**不可删列**）；
- **③ 提交配置**：`<ReportWriteAttr>` 里 `com.fr.write.config.DeleteConfig` + `isKey="true"` 主键 + 提交条件 `=G2='true'`；按钮只 `contentPane.verifyAndWriteReport();`。

> 缺范式会导致每次重新设计辅助格与扩展父级关系（错了就删错行）。

### 9.3 填报控件与「条件属性>新值」互斥（doc-958）

> 来源: 帆软官方帮助 doc-958（条件属性）

⚠️ **填报控件与「条件属性>新值」不能同时用**，同时配置时新值**静默失效**；填报模板的默认值/空值兜底应走控件默认值或数据集，不要用 `ValueHighlightAction`（官方在 doc-958 里以一行小字注记给出，极易漏读——填报模板同时用控件和条件属性是常规操作，踩中后表现为「条件属性明明配了但没反应」）。

### 9.4 智能添加单元格组（doc-605）

> 来源: 帆软官方帮助 doc-605（智能添加单元格组）

「一字段多格」形态：同一 `<ColumnConfig name="字段">` 下多个 `<ColumnRow>` = 单元格组（同一字段绑到多个固定录入格，如期初/期末余额列），提交时 FR 拆为多个内置 SQL **串行提交（同一事务）**；GUI 的「智能添加」（拖选连续/点选不连续）无头侧无对应操作，直接重复 ColumnRow 节点即等价：

```xml
<ColumnConfig name="amount" isKey="false">
  <ColumnRow column="3" row="2"/>
  <ColumnRow column="3" row="3"/>
</ColumnConfig>
```

- **两条硬约束**：① 被绑定格不得是扩展数据（不得挂 `<Expand>`/CellExpandAttr——扩展格与固定格不可混绑，违反仅提示不阻断）；② 所有字段绑定格数须一致（违反仅提示不阻断，提交结果错乱属静默风险）；
- 键列（isKey）取非录入固定格；
- 待核验：ColumnConfig/ColumnRow Java setter 签名（疑 addColumnRow/setKey，javap fine-write.jar 实读）、ColumnRow 坐标是否 1-based、单元格组是否有组包装节点、录入格文本控件类名（疑 `com.fr.form.ui.TextField`）；核验样本 = `%FR_HOME%\webapps\webroot\WEB-INF\reportlets\doc\Form\TypicalApp\CellsArrayForm.cpt`；
- 参考 `practice/topic_605_hermes`（XML 片段）。

### 9.5 多级上报填报模板主键策略（doc-589）

> 来源: 帆软官方帮助 doc-589（多级上报参数）

- 主键选「任务ID + 申请人」**双 isKey**（`ColumnConfig isKey="true"`）：不勾选「该节点所有操作人员完成后流转」时**每人一任务**（$fr_task_id 为每个操作人员各生成一个任务），单主键会互相覆盖——官方 报销录入.cpt 即此做法；
- $fr_task_id/$fr_task_name/$fr_task_sender/$fr_task_state 为数据决策系统**运行时注入的模板参数**，模板内以公式直接引用、无需在 `<reportParameters>` 声明；SWITCH 状态映射公式整串注入，如 `SWITCH($fr_task_state,-1,"异常",0,"等待上报",1,"等待审核",2,"审核通过",3,"审核回退",4,"关闭",5,"超时")`。

### 9.6 导入页 Import 按钮统一样式（批量对齐模式，2026-08-14 实测）

同一目录下多个导入/填报报表都有查看页跳转 Import 按钮时，历史生成批次不同会导致样式漂移，统一检查三类问题（批量清理前先整目录备份）：

1. **遗留错误 LabelName**：克隆生成的按钮可能带源报表的 `LabelName="..."`（错误标签）→ 直接删除该 `<LabelName>` 节点
2. **边框脚本缺失**：标准 = Import 按钮点击 JS 内含 `1px #3676c5 solid` 蓝色边框脚本（与查询按钮同色系）→ 缺失的报表补齐
3. **字体/hover 缺失**：标准 = `FRFont 微软雅黑` + `initial/over/click` 三状态 + `isCustomType` → 缺失的补齐

**验证清单**（每报表 4 项）：XML 合法（ET.parse）/ LabelName 无残留 / 边框脚本存在 / 字体样式存在。
