## 9. 图表（总纲：配置正交三分 + 数据绑定 + 样式）

> 来源: 帆软官方帮助 doc-1672（图表样式）/ doc-176（定义图表数据集数据源）/ doc-175（定义图表单元格数据源）/ doc-4138（图表样式FAQ）

### 9.1 图表配置正交三分总纲（doc-1672）

一个图表的配置切成三个**互不覆盖**的子树，可对同一 `<Chart>` **分三次幂等注入**（改样式不碰数据与联动）：

| 子树 | 文档路由 | 内容 |
|------|---------|------|
| ① 数据绑定 | doc-176 数据集数据 / doc-175 单元格数据 | 分类/系列/值 + 汇总方式 |
| ② 样式 | doc-1672 九类 + doc-4138 FAQ | 标题/图例/标签/系列/坐标轴/数据表/背景/提示/配色 |
| ③ 交互特效 | doc-4207/651 超链联动、doc-2857 轮播联动、doc-3115/1392 刷新 | 超链/JS 注入 |

> 缺这张总纲时，生成器面对「给已有图表加个图例」会倾向整体重写图表节点，顺带把已配好的联动/数据绑定冲掉——这是「写得出跑不对」的典型形态。

### 9.2 图表数据来源二分（doc-176 + doc-175 路线选择）

- 数据源已是**干净事实表** → 走 doc-176 数据集字段绑定；
- 数据需先在**单元格二次汇总/转换** → 走 doc-175 单元格绑定。

两条并列生成路线，生成器按「数据是否已在单元格算好」决定走哪条。用错路线（对已汇总单元格再走数据集绑定）会重复汇总或取不到值，且多静默。

### 9.3 图表数据集数据源（doc-176）

绑定 = 选数据集 → 分类（X 轴）/系列名（图例）/值（Y 轴）+ 汇总方式，全部是 `<Chart>` 数据配置节点。

**系列名二分铁律（对应不同源表形状，错配静默空白）**：

| 系列名模式 | 源表形状 | 示例 |
|-----------|---------|------|
| 字段值 | 窄表（含产品列） | (地区, 产品, 销量)，图例=「产品」列的值 |
| 字段名 | 宽表（列名即图例） | (地区, 花生, 牛奶)，图例=列名 |

- 二者画出同一张图，但 XML 配置与源表形状必须**成对**；生成器按「系列名取值来源」开关（fieldValue vs fieldName）+ spec 源表形状联动输出。
- 汇总方式必须显式给出；分类/系列名/值缺任一项图表都不渲染且**不报错**（静默失败）。
- **版本约束**：10.0.9+ 才支持系列名设「无」（此时以值的字段名当系列）；老版本无此选项，降级为字段名兜底。

> 参考 `practice/topic_176/gen_chart_dataset.py`。

### 9.4 图表单元格数据源（doc-175）

- **必须走公式入口 F(x)**：分类/系列/值绑单元格时值须以 `=` 开头（直接输入框写文本会被判为「普通文本」，不绑定）。
- 连续用 `=[A1:A3]`（冒号）；不连续用 `=[A1,A3,A5]`（逗号）；单格 `=[A2]`。
- **父子格链必须有**：分类是系列的父格、系列是值的父格（`B2 父格=A2、C2 父格=B2`），否则分类/系列错位且不报错。
- ⚠️ 二次计算 `A1+10` 会**丢失单元格属性**（图表取不到父子格关系）；非用不可时保证原始格是列表展示且顺序/个数恰好对应。
- **插件盲区（选型硬约束）**：图表单元格数据源 V1.0 不支持 地图/钻取地图/热力地图/甘特/扩展图表；V1.1 不支持扩展图表。地图经纬度定位下「同经纬度异区域名」只取最后区域（汇总=最后一个）——headless 选型时不提示会生成无法渲染的图表。

> 参考 `practice/topic_175/gen_cell_chart.py`。

### 9.5 图表样式（doc-1672，九类封闭枚举 + 两层模型）

- **九类通用样式注册表**：标题 / 图例 / 标签 / 系列 / 坐标轴 / 数据表 / 背景 / 提示 + **配色**。
- ⚠️ **文档内部打架**：正文 1.2 说「共 8 种」，索引表却有 9 行——多出的「配色（图表预定义配色）」不在 8 种之列。生成器按 8 种实现会**整类漏掉配色**，出图颜色全走默认且无报错。封闭集合可枚举 → 生成器内置注册表做覆盖度/拼写检查（类别名拼错 = 该类样式静默丢失）。
- **两层模型**：通用层 + 图表类型特有层（饼图半径/仪表盘刻度/地图区域样式等，原文「会单独在这些图表的文档中说明」）。**凡类型特有样式，spec 必须同时携带 chart_type**；套到不支持的类型上 FR 静默忽略。
- **通则（与 doc-3115 合并）**：图表能力按类型分叉、错配即静默失效——**图表相关的一切生成动作都要先判 chart_type**。
- 配色是「引用命名方案」而非「逐系列铺色」：一等形态是引用已命名方案，逐系列自定义色板属覆盖态，二者同时给出时结果不可预期，应判 ERROR 强制二选一。
- 样式层可写公式引用模板参数（`=$area+"地区销量统计图"`）：该 `$area` 走**模板参数**（ReportParameterAttr），数据集过滤 `${area}` 走**数据集参数**——同名两套声明少一边 = 「数据变了但标题不变」。
- ⚠️ **节点名未核验前不要伪造 XML**：kit 尚无含图表样式的真实 .cpt 导出样例，样式子节点名须以设计器 diff 为准；确定部分（枚举+一致性规则）固化为代码，不确定的节点名集中到 NODE_MAP 待核验映射表（参考 `practice/topic_1672/chart_style_registry.py`）。

### 9.6 图表样式预设（doc-4138，声明式 spec → 样式子节点）

输入声明式 spec、输出 `<Chart>` 样式子节点（参考 `practice/topic_4138/gen_chart_style.py`）：

```text
spec { legend{visible, position, bg} / label{style=auto|custom, size, color, bold}
       / series{colors[], column_width} / tooltip{format, bg}
       / axis{x_label, y_label, x_area, x_rotation} / background{grid, border}
       / conditions[]{formula, color, animation} }
```

两条硬规则：
- ① **图例顺序 = 数据源顺序**：`series.colors` 须与系列数据顺序一致（改图例排列只能调数据源顺序，不可单独拖图例）；
- ② 标签要改字号/颜色/加粗前，**必须先把字符选「自定义」**（否则不生效）。

### 9.7 图表排序：模板属性 vs JS 选型表（doc-1695 + doc-2332）

> 来源: 帆软官方帮助 doc-1695（图表交互属性-排序）/ doc-2332（JS实现图表排序）

| 路线 | 能力 | 限制 |
|------|------|------|
| ① 交互属性工具栏勾「排序」（doc-1695） | 模板态、支持 H5/App、无时序问题 | 只能由用户点击切换 |
| ② `FR.Chart.WebUtils...sortChart()`（doc-2332） | 可指定升/降序与自定义触发 | 8 种图表白名单、必须 setTimeout、**不支持移动端**、普通报表还受预览方式约束 |

- **规约：能用①表达的一律不生成 JS**（kit 现有 topic_2332 只有 JS 一条路，检索「图表排序」会给出更复杂且移动端不可用的方案）。
- **doc-1695 版本注记**：JAR < 2020-08-31 时工具栏排序按**绝对值**排序——含负值指标必须升级；不报错，表现是「负数排在中间」，用户只会说「排序是乱的」。

### 9.8 图表条件显示 / 特效（doc-1701）

> 来源: 帆软官方帮助 doc-1701（图表条件显示）

服务端载体类：`com.fr.chart.chartglyph.ConditionCollection` / `ConditionAttr` / `ConditionAttrFactory`（改配色/背景/标记可用 Java 构建）。**关键限制**：「闪烁动画」属前端 JS 特效，**FR 10.0 jar 中无 FlashAnimation 类，纯 Java 无法实现**——无头场景不能误以为能纯 API 实现闪烁，涉及该需求必须标注前端 JS 依赖。

### 9.9 图表（VanChart）属性的无头写法（doc-3245）

> 来源: 帆软官方帮助 doc-3245（图表属性）

VanChart 属性的通用范式：`plot.getConditionCollection().getDefaultAttr()` → **先 `getExisted(Attr*.class)` 再决定 new** → `addDataSeriesCondition(attr)`。两个反直觉点（字节码实读）：

- ① `ConditionAttr#getExisted(Class)` 是**类名字符串全等**（`x.getClass().getName().equals(clazz.getName())`）；多态版是另一个方法 `getExistedClass`（`isAssignableFrom`）。
- ② `addDataSeriesCondition` 就是裸 `list.add`，**零去重**——重复挂载后 `getExisted` 只返回第一个、后加的永远读不到但 XML 里看得见。
- 最小样例：tooltip（`AttrTooltip` / `AttrTooltipContent` / `VanChartHtmlLabel`）；同一 `ConditionAttr` 上还挂着 `AttrLabel` / `AttrAlpha` / `AttrBorder` / `AttrTrendLine` 等，纪律一体适用。
- 批量改造须 `instanceof VanChart` + `instanceof VanChartPlot` 双判；`ChartCollection#getChart(int)` 实读是 `getChart(i, Chart.class)`，不匹配返回 **null 而非抛异常**。

### 9.10 图表组（多图表切换，doc-3274）

> 来源: 帆软官方帮助 doc-3274（图表组）

把图表模型从「一格一图」扩成「图表组」：载体是 `com.fr.chart.chartattr.ChartCollection`（1..N 个 Chart，切换顺序=addChart 顺序），两个宿主分别是 CPT 单元格图表（单元格 value 挂 collection）与 FRM 图表组件（`com.fr.form.ui.ChartEditor`，类名 kit 已核验）。

- 切换属性三项挂在 collection 上：切换方式（按钮/轮播）、是否显示切换按钮、轮播间隔。
- ⚠️ 文档明确「切换按钮」与「轮播箭头」是**同一个按钮**，API 侧只应有一个显隐开关。
- 所有具体 setter/节点名标 ⚠ 待核（「多图容器 + 切换属性」可 API 化，值得先把模型立起来）。

### 9.11 地图边界参数化（doc-1698）

> 来源: 帆软官方帮助 doc-1698（地图边界获取传参）

- `com.fr.chart.chartattr.MapPlot#setMapName(String)` 设地图边界；区域地图 `setMapType(MapType.Map_Normal)`（`com.fr.chart.base.ChartEnumDefinitions.MapType`）。
- mapName 取值必须为 `geographic` 目录相对路径（映射 `WEB-INF/assets/map/geographic/<path>.json`，形如 `geographic/中国/江苏省`）；**绑定模板参数时 mapName 填公式字符串（如 `$province`）而非字面量**。
- ⚠ 常见错误：mapName 写成字面量或错路径 → 预览空图，官方仅在设计器弹注、不报错。
- 参考 `practice/topic_1698_java/MapAcceptParameters.java`（参数化地图边界完整链：`TemplateParameterAttr#addParameter` 挂 `$province` → `MapPlot` 绑定）。

### 9.12 地图 GIS 图层（doc-1698）

> 来源: 帆软官方帮助 doc-1698 / doc-4258（读写两侧最小写入集不对称）

可纯 Java 落地的图表 API 面：

### 9.13 图表 Java 构建铁律：待核验清单与扩展图表排除（doc-1086 + doc-3475 + doc-3836）

> 来源: 帆软官方帮助 doc-1086（点地图）/ doc-3475（H5设置）/ doc-3836（轮播条形图）/ doc-2490 / doc-2857

**① 待核验清单（Java 构建 API 尚未字节码核验的图表）**：点地图/地图（.cpt 单元格）、雷达图（载体 ChartCollection / `<CellChart>` / frm 组件已知，但极角轴/极径轴/系列样式对应 `com.fr.chart.chartattr.*` 属性类未核验）。一律走「**设计器基线 .cpt/.frm + 程序 read→改属性→write**」，禁止从零 `new` 图表对象。

- 生产密钥（高德 Key 等）从参数/配置注入，**不写进模板 JS 明文**。

**② 扩展图表插件类显式排除**：**轮播条形图**（扩展图表-柱形图类，扩展图表插件 4.4）**显式点名**并入「扩展图表插件类（三维地球/流向地图/轮播联动，doc-2490/doc-2857）无标准 com.fr.* API 落点」归类——它挂在「柱形图类」下，极易被误判成核心柱图丢进 `gen_cell_chart.py` 等核心单元格数据源生成器。硬特征：**不支持条件属性、不支持自定义标签样式**（插件前端自绘、不走核心单元格渲染，与核心 `BarPlot` 完全不同）。此类 .cpt 仅能由设计器/插件 GUI 产出后做 XML 级微调（§9.4 插件盲区之外的选型隔离）。

### 9.14 图表无头构建：VanChart 五段式链（doc-3475 + doc-1953 甘特实证）

> 来源: 帆软官方帮助 doc-3475 / doc-1953（机器状态甘特图）

VanChart 族无头构建的**五段式通用链**（甘特图为首个完整实证样本，对全部 VanChart 类型同构）：

```
① XxxTableDefinition（列名字符串）→ ② XxxDefinition（中间聚合层，不可省）
→ ③ new com.fr.plugin.chart.vanchart.VanChart(new XxxPlot())
→ ④ Chart#setFilterDefinition(TopDefinitionProvider)
→ ⑤ new com.fr.chart.chartattr.ChartCollection(chart) → DefaultTemplateCellElement#setValue(cc)
     + setColumnSpan/setRowSpan → TemplateWorkBookIO.writeTemplateWorkBook
```

- 甘特图实证五步：① `new VanChartGanttPlot()` ② **手工 seed 默认条件**——`plot.getConditionCollection().getDefaultAttr()` + `getExisted(AttrLabel.class)==null` 时 `addDataSeriesCondition(plot.getDefaultAttrLabel())`（官方 `AbstractIndependentVanChartProvider#createDefault*Condition` 是 **protected static、跨包不可调**，无头必须手工复刻，漏掉则标签/提示整块不出）③ 改条件集合里的 `AttrLabel`/`AttrTooltip` ④ `chart.setFilterDefinition(...)`（甘特图是**两层**：`VanGanttDefinition` 包 `VanGanttTableDefinition`）⑤ 落盘 + 跨抽象层 `java.io.File` 断言（`writeTemplateWorkBook` 返回值恒 true，见 doc-2637 批注）。
- `com.fr.plugin.chart.*`（含 `com.fr.plugin.chart.gantt.*`）**全部在 fine-report-engine-10.0.jar**——包名带 `plugin` 但**不需要装任何插件**，可 100% 无头构建。
- XML 节点字典：`com.fr.plugin.chart.helper.DefinitionXmlHelper.<clinit>` 实读出的「XML 标签名 → 定义类」注册表（14 条）可直接当图表 XML 节点对照（见 `practice/topic_1953_java/GanttMachineStatusBuilder.java` 注释）。
- 参考 `practice/topic_1953_java/GanttMachineStatusBuilder.java`。

### 9.15 图表图例 Java 装配链（doc-1675）

> 来源: 帆软官方帮助 doc-1675（图表图例）

- 图例对象 = `com.fr.chart.chartattr.Legend`：优先 `plot.getLegend()` 复用默认实例再改属性，或 `new Legend()` 后 `plot.setLegend(Legend)`（避免 new 后漏 setLegend 丢失关联）；
- 位置 = `legend.setPosition(LegendPosition)`：`TOP/BOTTOM/LEFT/RIGHT(默认)/RIGHT_TOP/FLOAT` + `setLeftPercent/setTopPercent`（悬浮位置）；样式 `setFont(java.awt.Font)`；边框 `setBorder(LineBorder)`；背景 `setBackground(BackgroundFactory.*)`；显示策略 `setFixDisplay(boolean)`（10.0.18 起，旧名「高亮」；勾选=悬浮固钉+高亮系列 100% 不透明度，不勾=单击隐藏/再击显示）；
- XML 对照：`<chart><legend>` 节点（节点名/position 数值以设计器导出为准，**建议 Java API 产出而非手写 XML**）；
- **「图例类型由系列颜色划分决定」因果链**：普通/连续渐变/区域段图例不由 Legend 决定，由「图表系列>颜色」的颜色划分方式决定——仅地图/钻取地图/热力地图/气泡图/散点图/词云图 6 类且颜色划分=「值」时才出现「格式」属性；**框架图/仪表盘不支持图例**；
- 版本演进（10.0.9/10.0.18/10.0.19）：图例与轴标签重叠时图例难触发 → 升级 10.0.19+ 修复（无配置项）；图例字号小于浏览器最小字号时按浏览器字号渲染（如 Chrome 12px）——非模板缺陷，调浏览器或字号。

### 9.16 图表条件显示：挂载链 + 操作符约束 + 参数陷阱（doc-1691）

> 来源: 帆软官方帮助 doc-1691（图表条件显示）

与 §9.8（doc-1701）互补——§9.8 讲服务端载体类/闪烁限制，本篇给完整挂载链与约束：

- **挂载链**：`Plot.setSeriesConditions(SeriesConditions)`（getSeriesConditions 取旧值保留既有条目）；单条 = `ConditionAttr`（判定条件 + 1..N 条件属性项）；XML 落点 `<SeriesConditions>/<ConditionAttr>`；
- **12 种条件属性项类**（均在 `com.fr.chart.chartattr.*`，命名待核验）：ColorAttr(配色)/AlphaAttr(不透明度)/FloatColorAttr(悬浮颜色)/TwinkleAttr(闪烁动画)/BorderAttr(边框格式)/LabelAttr 等，分三类——通用（图片填充/不透明度/数据点提示/配色/悬浮颜色/闪烁/边框/标签）、仅系列（趋势线/线型）、图表特例（气泡-气泡图、节点-框架图）；「最大值特殊色/大于0红小于0绿」类需求走此机制（与 doc-72 系列换色同一机制）；
- **操作符约束（§3.3-3.5）**：值（int 标量）与数据列（数组）**仅支持 包含/不包含/包含于/不包含于**，禁止 等于/大于/小于（照搬 CommonCondition 等于/大于会静默不命中）；分类条件只对最细分类生效；数据绑定设「形态」后条件须用显示值；
- **参数陷阱（§1.2/§1.3/§2.2/§3.1/§3.2）**：不透明度值越小越不透明（0≈不透明）；图片填充系列不生效；范围图例仅图形填充生效；配色透明 → 图形填充/图例图标/牵引线/标签全透明；条件冲突时**最下方优先**；仪表盘无条件显示。

### 9.17 图表超链-网络报表：跨报表参数联动（doc-1696）

> 来源: 帆软官方帮助 doc-1696（图表超链-网络报表）

图表超链 ≠ 单元格超链（`CellElement#setHyperlink` + `com.fr.report.cell.impl.ReportHyperlink`），两条路径必须区分：

- **挂载**：图表超链挂 Chart 交互属性（推断 `com.fr.chart.interactive.ChartLinkAttr`，`setInteractiveAttrList` 挂载；类名/方法/XML 节点 `interactiveAttrs` 待导出核对），与单元格超链同挂载入口不同实现；
- **超链构成** = 目标报表路径（相对路径，如 doc/Advanced/Chart/销售员销量分析.cpt）+ 打开方式（新窗口/对话框/当前窗口，对话框可设大小位置）+ 参数列表（参数名 + 值公式）；
- **参数值公式用图表内置变量**：`=SERIES`(系列名称) / `=CATEGORY`(分类名称) / `=VALUE`(值)——点哪个系列就传哪个系列名；
- **联动前提**：目标报表须有同名数据集参数（如 `WHERE 地区='${area}'`）才联动；不传参也能打开但无联动；
- 链接填报模板路径后加 `&op=write`；
- 移动端三者打开方式效果相同，且**无法从子报表返回主报表**（高频移动端坑）。

## 10. 导出（Excel / Word 硬约束）

> 来源: 帆软官方帮助 doc-1123（Excel导出）/ doc-1121（导出Excel2007）/ doc-1120（大数据量导出Excel）/ doc-1130（Word 导出页眉页脚）/ doc-1128（Word 导出自动调整行高）

### 10.1 Excel 导出三模式与行式引擎约束（doc-1123）

| 模式 | URL 参数 | 行为 |
|------|---------|------|
| 分页导出 | `format=excel&extype=page` | 按模板分页结果导出（重复标题也重复） |
| 原样导出 | `format=excel&extype=simple` | 连续不分页（重复标题只一次） |
| 分页分 Sheet | `format=excel&extype=sheet` | 每页一个 sheet，sheet 名 page1/page2... |

- ⚠️ **行式引擎开启后不支持分页分 Sheet 导出**（`extype=sheet` 静默失效，doc-1123 注1）——生成器须把「行式引擎开关」与「是否依赖分Sheet导出」作为一致性单元管理。
- 列宽/行高导出偏小属 FR↔Excel 换算差异：默认宽度系数 **34.742**、高度系数 **20.1**（A4/特定页边距/宋体前提）；想一致改 FineDB `fine_conf_entity.CustomConfig.excelAdjustWidth/Height`。
- Excel 仅识别前 15 位数字（身份证/银行卡导出变 0）；导出与预览页边距不一致时把模板上下边距设 12.7mm；字体>14 且自动换行时导出字号×0.95。

> 参考 `practice/topic_1123/export_urls.py`；与 topic_3233（分 Sheet）/3460（批量导出）URL 范式互补。

### 10.2 Excel2007(.xlsx) 是「环境能力」而非「模板属性」（doc-1121 + doc-1123）

- `.xlsx` 导出靠**部署** `poi2007_fat.jar` + **JDK8u102+** 获得（JAR≥2016-10-10 已内置 poi 到 third 包）；与模板内部无关——「触发方式」（URL 范式）与「导出格式由谁决定」是两回事。
- **模板级唯一影响点**：行式引擎（`RowEngineAttr/@rowEngineEnabled`）开启后即便配了 poi2007 jar，Excel 导出仍**回退 2003(.xls)**——大数据量报表因 2003 行数上限被切 sheet 却查不到原因，多半就是它。
- 2003 上限 65536 行/256 列；`.xlsx` 链路不支持移动端。

### 10.3 行式引擎的产物形态与行数算术（doc-1120）

- **产物形态三选一**：① 未开行式引擎+量在临界点内 → 单个 Excel（超限数据**溢出到下一 sheet**）；② 未开+超临界 → **导出失败，产物是「内容无效的 Excel」**（HTTP 200 + 文件非空 + 打不开——无头脚本必须校验字节头：OLE2 `D0CF11E0`=.xls、`PK\x03\x04`=zip/xlsx、`<html`=错误页，不能只判状态码/文件大小）；③ 开行式引擎 → **始终成功，产物是「多个 .xls 打包成 1 个 zip」**——下游必须按 zip 收再解压逐个读。
- **行数整数倍算术**：「单个 Excel 最大行数」必须**同时**是固定行数分页每页行数的整数倍且 ≤ 65536 → **65536 本身几乎永远非法**（每页 40 行 → 最大 65520；每页 100 行 → 65500）。生成器应 `(65536 // 每页行数) * 每页行数` 计算而非硬编码；且**必须先设固定行数分页**，行数约束才有基数。
- 「行式引擎 + 想要单个 .xlsx」是天然矛盾：不装「Excel 流式导出支持行式引擎」插件（doc-1407）就只能拿到 zip 里的一堆 .xls。
- 临界点不可预测（数据量×列数×内存），官方不给公式——要么开行式引擎（始终成功），要么导出后强校验产物。

> 参考 `practice/topic_1120/bigdata_export_plan.py`（行数规划 + 8 条静态体检 + 产物魔数校验）。

### 10.4 Word 导出模板（doc-1130 页眉页脚 + doc-1128 行高）

**页眉页脚两条静默陷阱（doc-1130，FR 零报错）**：
- ① Word 页眉默认距顶端 **12.7mm**：凡 spec 声明导出 Word，页面设置须强制**四边距 12.7mm**，否则除第一页外每页多出一行空白行；
- ② 页眉/页脚图片必须走「背景元素>图片」（BackgroundImage）而非直接 Image 元素——直接放 Image 会把页面撑开 → 导出多出空白页。

**Word 导出行高（doc-1128）**：`<ReportExportAttr><WordExportAttr>` 的 `fixRowHeight` 开关——默认（空节点）= 固定行高，`fixRowHeight="false"` = 不固定行高（二次编辑换行时行高自动变化）。kit 生成器当前恒输出空 `<WordExportAttr/>`（=固定行高），需脚本注入才能产出「可二次编辑自动调行高」的模板；该开关仅 **PC 分页预览**生效、**移动端不支持**。（`fixRowHeight` 为推断值，待设计器 diff 核验。）

> 参考 `practice/topic_1130/set_word_export_headerfooter.py`、`practice/topic_1128/set_word_rowheight.py`。

### 10.5 行式引擎闸门总表（doc-1481 + doc-996 + doc-1120 + doc-1123 + doc-1407）

> 来源: 帆软官方帮助 doc-1481（定时调度附件导出）/ doc-996（行式引擎）/ doc-1120（大数据量导出）/ doc-1123（Excel导出）/ doc-1407（Excel流式导出插件）

同一 boolean 开关（行式引擎）的约束被切在 6 处文档里各记一句，且这 5 条**没有一条会在生成期报错**——收成一张「链路 × 后果 × 失败形态 × 可否补救 × 来源」闸门表：

| 链路 | 后果 | 失败形态 | 可否补救 | 来源 |
|------|------|---------|---------|------|

### 10.7 报表输出/服务端导出：URL 参数对照表（doc-1142）

> 来源: 帆软官方帮助 doc-1142（URL直接导出报表内容）

| URL 参数 | 取值 | 说明 |
|---------|------|------|
| `format` | pdf / excel / word / image / text / svg / csv | 导出格式；默认导出文件名 = 报表名称 |
| `excel + extype` | page / simple / sheet | page=分页导出（默认）、simple=原样导出、sheet=分页分 Sheet |
| `isExcel2003` | true | xls 需追加（默认 xlsx） |
| `sheets` | [0,1] | 指定 sheet 导出 |
| `image + extype` | JPG/PNG/GIF/BMP | 图片导出 |

- **Java API 等价**：`readTemplate(WorkContext, path)` → `exportExcel(OutputStream, ExcelExport)`（`ExcelExport.EXPORT_PAGE/SIMPLE/SHEET` + `setSheetIndex`）/ `exportPDF(OutputStream, PDFExport)`（format=pdf）/ `exportWord` / `exportImage` / `exportText`；
- 导出是**运行期动作**，不写入 .cpt/.frm 模板 XML；模板只需能被读取（数据集/参数已配好）即可导出；
- **URL 直接导出 = 模板渲染验证手段**：构建 .cpt 后访问 `decision/view/report?viewlet=...&format=pdf` 或 `&format=excel`，能成功下载即代表模板可被服务器渲染——比打开设计器/浏览器预览更快，可脚本化接入校验流程（localhost:8075 预览的补充）。
