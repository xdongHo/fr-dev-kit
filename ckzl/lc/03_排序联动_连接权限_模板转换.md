## 11. 排序选型与 ORDER BY 安全构造

> 来源: 帆软官方帮助 doc-2684 / doc-903

### 11.1 模板层「扩展后排序」 vs SQL 预排序兜底（doc-2684）

按分组汇总结果排序（分组格 + 各层小计 + 明细列表）时，SQL 的 `ORDER BY` 做不到（只能按明细列排），必须走模板层「扩展后排序」+ 左父格。无头场景下若 .cpt 排序节点名未核验，**SQL 预排序**是唯一可立即验证的替代方案：

- 窗口函数 `SUM(x) OVER (PARTITION BY 分组列)` 作兜底；
- **每层排序键后必须补上该层分组列本身**——否则汇总值相等时不同分组的行会交错、分组在报表里被切碎；
- 模板层排序「先分组后排序」，天然无此问题。

> 来源: 帆软官方帮助 doc-2684

### 11.2 ORDER BY 安全构造器 build_order_by()（doc-903）

数据集排序 = SQL `ORDER BY`，性能最佳；但 `${a}` 直接拼进 ORDER BY 是典型注入/报错向量（doc-903 靠超链公式 `if(a="desc","asc","desc")` 锁死取值，默认空串 = ASC）。kit 已有 `WHERE 1=1+${if()}` 级联范式，ORDER BY 应同等地做成**受约束的构造器**而非裸拼：

- 输入 `(cols, directions?, dynamic?, mysql_pinyin?)`，输出 ORDER BY 子句；
- 方向**白名单 {asc, desc, ""}**（默认空串 = ASC）；
- 多列方向数与列数**对齐**校验；
- 动态形态输出 `${a}` 内联；
- MySQL 中文拼音排序：UTF-8 下 `order by 中文列` 不按拼音，需 `convert(列 using gbk)`（依赖 GBK 字符集已安装，否则报错）。

> 可直接移植 `practice/topic_903/order_by.py`。
> 来源: 帆软官方帮助 doc-903

## 12. 联动场景数据集分工与参数双声明

> 来源: 帆软官方帮助 doc-3556 / doc-4204 / doc-947

### 12.1 全量集绑「联动源」、含参集绑「被联动」（doc-3556）

组件联动模板中数据集分两类：

- **全量集**绑「联动源」（图表/表格 A）；
- **含参集**绑「被联动」（图表/表格 B），且**含参集的参数必须有默认值**（首屏不空）。

> ⚠️ 最高频静默失效：目标组件误绑全量集 → 参数无处落地，点击毫无反应，服务端零报错。生成器应在建模阶段按「源/目标」给数据集打标（doc-3556/4207/4209/2857 四篇复用同一分工模式）。

### 12.2 参数双声明铁律与生成器通用校验（doc-4204 / doc-947）

- 「参数为空选全部」SQL 模板 `WHERE 1=1 ${if(len(x)==0,"","and 字段='"+x+"'")}` 与「超链参数须**数据集 + 模板双声明**」应沉淀为**生成器通用校验**：超链参数名在图表/子模板数据集 `${...}` 与 `ReportParameterAttr` 模板参数中双声明（doc-947：漏一则子表静默全空；doc-4204/4209/1029 多篇复用同一模式）；
- 标题公式 `=$area+"..."` 走**模板参数**，而联动传参走**数据集参数**——同名但两套声明，少一边就是标题空白/联动不生效；
- 取值用 `=$$$`（被点击格自身值，doc-4207/947 静态点击场景）。

### 12.3 超链「继承报表的参数」机制与参数命名硬约束（doc-2637）

「继承报表的参数」**不是全量继承**，实现为 `Hyperlink#putExtendParameters(Map,Map,JSONObject)` 挂两个 Filter：`GlobalParamFilter` + `UnnecessaryParamFilter`。生成器/校验器必须落实**命名硬约束三条**，违反后的统一现象是「子表/目标报表 0 行、无异常无日志」：

1. **长度 ≤ 20 字符**：`putExtendParameters` pc80-88 实读 `key.length()` / `bipush 20` / `if_icmple→91`，名字超 20 的参数在「继承报表的参数」时被直接跳过；
2. **不得命中引擎保留字**：`UnnecessaryParamFilter#accept` 会从继承集里 remove `com.fr.general.web.ParameterConstants.ALL`（viewlet/viewlets/op/reportlet/reportlets/resultlet/formlet/sessionID/`__parameters__`/`__pi__`/`__redirect__`/`__filename__`/`__showtoolbar__`/`__bypagesize__`/`__embed__`/fine_username/fine_password/fine_role/fine_position/fine_auth_token/cluster_redirect）以及 `fine_hyperlink`/`__CHARTSIZE__`/`__CHARTSOURCENAME__`；
3. **必须是合法 JS 标识符 `[A-Za-z_$][A-Za-z0-9_$]*`**：`JavaScriptImpl#createContentFunction` 把参数名原样拼进 `(function(<name>,...){...})` 形参表且零校验，中文名/带空格/数字开头会生成语法错误的函数。

> ⚠️ 三条限制在设计器 GUI 里全无阻力（中文名/超长名都能正常保存），文档从未提及，只能字节码实读；失败形态完全一致且无日志，是实施方最难自查的一类问题。

**全局参数永远传不到目标报表（`GlobalParamFilter`）**：`Hyperlink#<clinit>` 装的 `FILTERS` 先跑 `GlobalParamFilter#accept`，按 `com.fr.base.ParameterConfig.getInstance().getGlobalParameters()` 把**所有全局参数逐个 `map.remove`** ⇒ 勾选「继承报表的参数」时全局参数被硬编码排除，**必须在超链上显式声明为超链参数**。「主表能取到全局参数、子表取不到」即此现象。
> 来源: 帆软官方帮助 doc-2637

### 12.4 图表数据绑定：雷达图极径轴映射（doc-3475）

雷达图与基础图表的差异集中在**轴与系列**，数据建模阶段不能当普通单系列柱图处理：

- 极径轴「值定义=分别指定」可绑定数据集选**各分类的最大值/最小值**；
- 雷达图通常需**多列 / 多数据集**映射到多个轴，按单系列图处理会漏掉「分别指定」带来的多数据集绑定需求。

> 来源: 帆软官方帮助 doc-3475

## 13. 数据连接名与权限

> 来源: 帆软官方帮助 doc-299 / doc-4153 / doc-2457 / doc-3610

### 13.1 连接名契约（doc-299）

数据连接名是 .cpt 与服务器连接池之间的**外部契约**：.cpt 数据集只存 `<Database name="FRDemo"/>`（连接名），不存 JDBC URL/驱动/密码；预览时 FR 用该名字去服务器连接池查真实连接——名字拼错或服务器没有这个名字 → 错误码 `31300013 找不到数据连接`。

- 连接配置五项（名称/数据库种类/驱动器/URL/用户名密码）全在服务器，不落 .cpt；
- headless 链路生成不出它们，交付物须附【目标数据连接名清单 / 平台侧连接配置说明】，漏掉则用户预览必踩 31300013；
- 数据集问题（SQL/参数）是另一路：错误码 `11300001 数据集配置错误`。排障先按错误码二分。

### 13.2 连接名是唯一引用、可被管理员改名（doc-4153）

- `.cpt` 只存 `NameDatabaseConnection/DatabaseName` 字符串，不存 URL/账号密码；拥有「管理」权限的用户可对连接**重命名/删除**，改名后模板 XML 仍完全合法、只是取不到数——静默失败，无头批量生成场景下一次改名可能拖垮几十张模板；
- 生成器必须把连接名收敛为**顶部常量 CONN**，禁止多处字面量；并提供引用清点/批量改名脚本（参考 `practice/topic_4153/scan_conn_refs.py`）。

### 13.3 服务器数据集依赖清点（doc-4153）

服务器数据集在 .cpt 里是 `com.fr.data.impl.NameTableData` + `<DataSourceName>`，**不含连接名**，但其背后连接同样受权限约束；依赖清点**不能只 grep DatabaseName**，否则漏掉服务器数据集这条依赖链。

### 13.4 数据连接权限模型（概述，doc-2457）

连接权限分**使用 / 管理 / 授权**三类且相互独立，由超管在「权限管理」按部门/角色/人员授予：

- **使用**：取数前提。运行账号无使用权限则预览/取数失败，与模板 XML 对错无关；
- **管理**：复制/重命名/修改/删除连接（必定含使用）；
- **授权**：把连接权限再分配给他人（委托）。

`.cpt` 仅以连接名引用，连接与权限属**服务端外部依赖**；headless 生成 .cpt 时模板只写连接名，运行账号须持有该连接「使用」权限才能取数。

### 13.5 数据集连接自检硬约束（doc-3610）

大数据集导出/取数链路对连接侧有硬约束，应在数据集定义期前置校验（导出/取数时才暴露会静默失败：空值丢失/游标不支持）：

- MySQL 空 datetime 需 JDBC URL 加 `zeroDateTimeBehavior=convertToNull`（Oracle 不用）；
- SQL Server 需把游标设为**服务器游标**；
- 仅支持**关系型数据库**；存储过程调用方式受限。

### 13.6 模式（schema）是第二个外部契约（doc-2563）

把交付契约从「连接名」一项扩成**四元组「连接名 + 模式 + 驱动类 + URL」**：

1. **PG 建连时在测试连接成功后还要单独选模式**，官方明写「若不进行选择，则默认为第一个模式」；
2. 模式存在连接配置里、**不进 .cpt**，故同一张模板换环境后可能静默取到另一个模式下的同名表——不报错、不报 31300013；
3. 无头侧对抗手段：PG 场景 SQL **默认写 `schema.table` 全限定名**（把模式信息留在模板里），或 URL 加驱动原生参数 `currentSchema=`；
4. Oracle/达梦等同样有模式概念，本条是通用条目而非 PG 专条。

> ⚠️ 连接名错了会报 31300013 有明确错误码可排查；**模式错了完全静默**（表名相同、数据不同），归因成本远高于前者。
> 来源: 帆软官方帮助 doc-2563

### 13.7 数据库连接能力矩阵（doc-2563 / doc-3751）

按库种查的表，供生成器决策（选了 PG12 自动禁用存储过程数据集、选 PG 自动把驱动 jar 列进外部依赖清单）：

| 列 | PostgreSQL | MySQL | SQL Server | MySQL8 | GBase 8T |
|----|-----------|-------|-----------|--------|---------|
| 驱动是否 FR 内置 | ❌不内置，需自放包+重启 | ✅内置 5.1.49 @10.0.15+ | ✅内置 sqljdbc @10.0.15+ | ❌cj 不内置，但插件 `com.fr.plugin.connection.mysql8` 内置 mysql-connector-java-8.0.20 | ❌不内置（ifxjdbc.jar，放 WEB-INF/lib + 重启） |
| URL 库名是否必填 | 必填路径段 | 可省 | `databaseName=` 参数 | 必填 serverTimezone（缺失=连接期 ERROR） | 必填 INFORMIXSERVER 参数 |
| 是否有模式概念 | **有** | 无 | 用 `[dbo].` 前缀 | 无 | **有**（测试连接后选模式，默认第一个） |
| 存储过程是否可用 | **V12 不支持存储过程** | 支持 | 支持 | 支持 | 待核（Informix 系） |
| 必填 URL 修复参数 | 无 | 5 个编码时区参数 | 无 | serverTimezone（缺失=连接期 ERROR） | INFORMIXSERVER |
| 官方已验证版本 | 9.2.3·9.4.7·9.5.0·9.5.2·9.6.0·12 | 见 doc-2560 | 见 doc-2559 | 仅 10.0.11+ | Informix 12.1（源码） |

> ⚠️ **MySQL8 时区陷阱**：serverTimezone=UTC 对 GMT+8 境内系统预览快 8h，应默认 `Asia/Shanghai`；且**设计器不支持 MySQL8 连接**（只能平台侧建连）——无头场景的建连入口见 §13.8/§13.9。
> 📌 **MySQL8 外部依赖登记（doc-3751）**：必须登记插件依赖——插件名 `fr-plugin-connection-mysql8`（插件ID `com.fr.plugin.connection.mysql8-1.0.0`）+ 报表服务器 >= 10.0.11 + JAR >= 2020-11-27；这类环境依赖在 .cpt XML 完全不可见（模板合法、设计器能开、PC 预览正常，仅缺插件时连接失败且无提示），无头交付缺了「设计器会提示插件缺失」这层保护，必须靠清单补。
> 来源: 帆软官方帮助 doc-2563 / doc-3751 / doc-2571

### 13.8 数据连接定义：XML 形状与 Java 侧（doc-306 / doc-3860）

kit 之前只记了「按名引用」，连接本身如何无头定义是前置盲区，补三种形态：

- **内联定义**（等价 `WEB-INF/resources/datasource.xml` 的 `<JDBCDatabaseConnection>` 节点）：

```xml
<Connection class="com.fr.data.impl.JDBCDatabaseConnection">
  <DatabaseAttr originalCharsetName newCharsetName creator/>
  <JDBCDatabaseAttr url driver auth user password encryptPassword/>
</Connection>
```

> 📌 `<DatabaseAttr originalCharsetName newCharsetName creator/>` 对应设计器「编码设置为自动」的字符集协商字段——**自动 = 字符集由连接协商，FR 端不强制转码**（doc-1127 官方佐证，可消除原说明仅列属性名的歧义）。

- **按名引用**：`<Connection class="com.fr.data.impl.NameDatabaseConnection"><DatabaseName>xxx</DatabaseName></Connection>`（**文本节点**非属性）；
- **Java 侧**：`new JDBCDatabaseConnection(driver, url, user, password)`——**四参里没有 database**，`setDatabase()` 是另一个字段；⚠️ 无参构造的默认驱动是 `sun.jdbc.odbc.JdbcOdbcDriver`（JDK8 已移除），忘了 setDriver 会得到误导性的「找不到驱动」。

**SQL Server 连接模板与排查清单（doc-306）**：驱动类 `com.microsoft.sqlserver.jdbc.SQLServerDriver`、URL `jdbc:sqlserver://IP:1433;databaseName=db`。排查清单：URL / IP / 端口（1433）/ 实例名一致 / 允许远程连接 / TCP-IP 启用 / 服务启动。

**MySQL8 两个常量（doc-3860）**：驱动 `com.mysql.cj.jdbc.Driver`；URL 后缀 `?useUnicode=true&characterEncoding=UTF-8&useSSL=false&serverTimezone=Asia/Shanghai&zeroDateTimeBehavior=CONVERT_TO_NULL`。漏写 `serverTimezone` 是最高频的「连不上」，且驱动抛的时区错与真实原因看着毫不相干。

> 来源: 帆软官方帮助 doc-306 / doc-3860

### 13.9 无头创建平台数据连接的可执行链路（doc-2406）

修正旧结论（LEARNINGS.md doc-2560 曾把方法名标为「⚠ ConnectionConfig.putConnection 待核」并据此判定 headless 不可用；本篇字节码实读证伪——真实方法是 `addConnection`/`addConnectionWithoutCheck`，链路完整可用）：

```java
new com.fr.data.impl.JDBCDatabaseConnection(driver, url, user, password)  // → testConnection()
com.fr.transaction.Configurations.update(new Worker(){
    public void run() { ConnectionConfig.getInstance().addConnectionWithoutCheck(name, conn); }
    public Class<?>[] targets() { return new Class[]{ ConnectionConfig.class }; }
});
// 回读断言: getConnectionWithoutCheck(name)
```

保存前必须复刻官方两个前置检查：`getConnectionsWithoutCheck().containsKey(name)`（重名）+ `isPutPermitted()`（限额）。

> 来源: 帆软官方帮助 doc-2406

### 13.10 SQL Server 多 schema / 多实例与连接名一致性（doc-2699）

- .cpt 数据集的 `<Connection>` 文本必须与平台 `ConnectionConfig` 中的连接名**严格一致**，否则预览报连接不存在（同 §13.1）；
- SQL Server 多 schema 查询须带模式前缀，如 `SELECT * FROM [dbo].[table]`；
- 非默认实例 URL 用 `instanceName=` 或 `ip\实例名`。

> 来源: 帆软官方帮助 doc-2699

### 13.11 连接乱码排查决策树（doc-854）

乱码类问题按以下顺序排查（问题往往出在三层中的某一层，逐层排除）：

1. **连接 URL 编码**：检查 JDBC URL 是否带 `useUnicode=true&characterEncoding=UTF-8`（MySQL 五参数模板见 §13.8/§13.9，doc-306/3860 的 JDBC 模板已覆盖本问题）；
2. **MySQL 服务端字符集**：`my.ini` 配置 / `SET NAMES` / 建库建表字符集，服务端与连接串不一致时数据在存储层已乱；
3. **系统字体**：纯显示层乱码（数据库与模板都正常）查服务器字体缺失。

> 📌 本篇 FR 相关要点全部落在既有 JDBC 连接知识上（doc-306/3860 已覆盖），此处只作**统一排查入口索引**，后续同类文档勿再重复沉淀乱码细节。
> 来源: 帆软官方帮助 doc-854
### 13.12 自定义 JDBC 驱动（第三方数据库，以 Presto/Trino、GBase 8T 为例）（doc-2577 / doc-2571）

kit 02 此前只覆盖内置驱动库种；第三方/信创库本质是「标准 JDBC + 驱动部署」，无新类，补全链路：

- **驱动 jar 部署（部署动作，非模板构建）**：驱动 jar 放 `%FR_HOME%\webapps\webroot\WEB-INF\lib` 并重启报表服务器；无头构建侧如需本地测试连接，把驱动 jar 加入测试 classpath；
- **Java 装配**：`com.fr.data.impl.JDBCDatabaseConnection` 的 `setName/setDriverName/setURL/setUserName/setPassWord`，对应平台 `datasource.xml` 的 `<JDBCDatabaseConnection name="...">` 下 `<DriverName>/<URL>/<UserName>/<PassWord>` 节点（节点名以设计器导出为准）；
- **数据集按连接名引用、与驱动类型解耦**：`com.fr.data.impl.DBTableDataSource` 的 `<DatabaseName>` 节点值 = 连接 name，无需为第三方库做特殊数据集配置；
- **易错点**：
  - URL **必须含 catalog 段**（`jdbc:presto://host:port/catalog`，catalog 对应元数据目录，与 JDBC 库名语义不同——缺 catalog 是最常见连接失败点）；
  - 驱动类名必须与 jar 内 Driver 注册名一致；Presto 更名 Trino 后驱动为 `io.trino.jdbc.TrinoDriver` / 前缀 `jdbc:trino://`（旧版 `com.facebook.presto.jdbc.PrestoDriver` 仅作历史依据）；
  - GBase 8T：驱动 `com.informix.jdbc.IfxDriver`（ifxjdbc.jar 不内置）、URL `jdbc:informix-sqli://{host}:{port}/{database}:INFORMIXSERVER={server}`（INFORMIXSERVER 必填）、**必须写分页 SQL**（§10.1 方言二分）；
- **平台建连 = 库种无关通用 SOP**（链 §13.9 doc-2406）：`new JDBCDatabaseConnection(driver, url, user, password)` 四参构造 + `ConnectionConfig.addConnectionWithoutCheck` 两段式（前置检查重名/限额），库种只换驱动类与 URL 常量表。

> 来源: 帆软官方帮助 doc-2577 / doc-2571

## 14. 模板转换管道

从原始模板生成可脱离数据库运行的副本：
