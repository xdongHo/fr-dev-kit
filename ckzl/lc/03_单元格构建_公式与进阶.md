### 3.10 公式分组 Grouper：FormulaGrouper（doc-316）

> 来源: 帆软官方帮助 doc-316（按公式分组）

在已验证的 `FunctionGrouper`（普通分组）与 `SummaryGrouper`（汇总）之外，「公式分组」Grouper = `com.fr.report.cell.cellattr.core.group.FormulaGrouper`，携带一个公式字符串（`$$$`=当前值）。统一认知：**分组键 = 公式计算结果**（公式分组与普通分组仅差 Grouper 是否带公式）——「按年/周重新分组」这类高频需求用公式分组。⚠️ 构造参数 / `setFormula(String)` 待 javap 核验。

### 3.11 公式构建铁律：前导 = 差异（doc-1914）

> 来源: 帆软官方帮助 doc-1914（公式）/ doc-4058（提交条件）

- **单元格值公式**：`new Formula("=...")`（**带 `=`**），对应 XML `<O t="XMLable" class="com.fr.base.Formula"><Attributes><![CDATA[=...]]></Attributes></O>`；
- **条件公式 / 排序公式**：条件属性 `FormulaCondition#setFormula("L3=1")`、`CellExpandAttr` 排序公式等**不带 `=`**。
- 两类反写会**静默失效**——凡用 `com.fr.base.Formula` 写单元格都应先判带不带 `=`（doc-4058 已标记此坑但散落在填报提交条件里，此处集中固化）。

> ⚠️ 旁注（来源: 帆软官方帮助 doc-817）：IF 字符串相等存在隐式转换坑——`if("003"="03",匹配,不匹配)` 因数字隐式转换返回「匹配」(true)；需改用 `EXACT("003","03")` 做字符级精确匹配。无头生成含 IF 字符串比较的模板时会静默产生错误匹配。

### 3.12 空单元格必须先建元素（doc-958）

> 来源: 帆软官方帮助 doc-958（条件属性）

空单元格在 .cpt 里**不存在 `<C>` 节点**；`WorkSheet#getTemplateCellElement(col,row)` 对空格返回 `null`。凡要给「没有内容的单元格」加条件属性/样式/控件，必须先 `new DefaultTemplateCellElement(col,row,null)` + `sheet.addCellElement(...)`——GUI 里天然存在的格子在 API 侧是 null，这是把 GUI 步骤直译成 Java 代码时最高频的 NPE 来源。

### 3.13 控件 writeXML 条件写出（doc-259）

> 来源: 帆软官方帮助 doc-259（控件属性）

FR 控件的 writeXML **一律「非默认才写出」**，缺省属性等于默认值而非 0/false（NumberEditor 实测：`allowDecimals=true`/`allowNegative=true`/`allowBlank=true`/`fontSize=12`/`maxIntegerLength=32`/`maxDecimalLength=16` 全部不落盘）。⇒ ① 校验脚本不能因「缺属性」判丢配置；② 与设计器另存结果 diff 时属性数量不对等是常态；③ 想让某属性显式落盘，只能把它设成非默认值。

### 3.14 单元格的两个公式槽：值 vs 显示值（doc-854 + doc-3836）

> 来源: 帆软官方帮助 doc-854（TOIMAGE 函数显示单元格图片）/ doc-3836

FR 单元格有**两个公式槽**，无头构建必须分清：

- **值槽**：`new DefaultTemplateCellElement(col, row, new com.fr.base.Formula(...))`（`<C>` 内，`<O t="Formula">`）——决定单元格底层值；
- **显示值槽**：`AbstractCellElement#setCellGUIAttribute(com.fr.report.cell.cellattr.CellGUIAttribute)` + `CellGUIAttribute#setResultFormula(Formula)`（落 `<CI>` 下 `<ResultFormula>`；`$$$` = 运行期本格值占位符）。⚠ `setResultFormula` 方法名**待字节码核验**；「存在第二个公式槽」这一事实已由文档「显示值」入口确证。

- 凡文档出现「高级>显示值」「自定义显示的值」「$$$」，一律归到**显示值槽**而非值槽：如 doc-854「引用数据库字段」场景把 `TOIMAGE($$$)` 填进「显示值」，实现「原始值来自数据集、显示值经 TOIMAGE 包装」——把 DB 路径图的显示值硬塞进值槽，与设计器产物结构不一致（值槽/显示值槽是**不同 XML 节点**），且无法表达「原始值来自数据集、显示值经 TOIMAGE 包装」的语义。
- DSColumn 显示值/Present 同属「显示不改底层值」族：`nvl(switch($$$,'Class1','一班',...),'兜底')` 类映射（§3.15）与 Present 形态（§3.9 勘误：10.0 无 setPresent，走 XML）都只改展示层。参考 `practice/topic_843_java/SwitchMultiAssign.java`（值槽/显示值槽双落点）。

### 3.15 公式：多条件赋值 switch/nvl 与 $$$ 上下文 token（doc-3836/doc-843）

> 来源: 帆软官方帮助 doc-3836（公式）/ doc-843（Switch 函数多条件赋值）

- 惯用法：`nvl(switch($$$,'Class1','一班','Class2','二班',...),'兜底值')`——`switch(表达式,值1,结果1,...)` 多条件映射 + `nvl(...,兜底)` 兜底；表达式为 `$$$` 时即「按当前值映射显示」。
- `$$$` = **公式上下文 token**（当前格/当前数据列值占位符），与 FormulaGrouper 的 `$$$` 同义（§3.10，另见 §7.5/§7.6 排序公式）——凡公式出现 `$$$` 一律按 token 理解，**勿当作字面量**。
- 双落点：可直接作单元格【值】公式（`new Formula("=nvl(switch(...))")`），也可填「自定义显示的值」（显示值槽，§3.14）——后者不改底层值、仅展示层映射。

### 3.16 内置公式函数 = 一等公民 Java 类（doc-3836/doc-816/doc-1840）

> 来源: 帆软官方帮助 doc-3836 / doc-816（数组函数概述）/ doc-1840

- 凡 FineReport 内置函数（数组/文本/数学等），底层都是 **`com.fr.function.<函数名全大写>`**（继承 `com.fr.script.AbstractCellFunction`，`public Object run(Object[])`）——**不要因帮助文档只写公式语法就判为「理解级、无 API」**。
- 写入 .cpt：`new com.fr.base.Formula("=<函数>(...)")` → `WorkSheet.setCellValue(row, col, formula)` / `addCellElement`（XML 节点 `<O t="Formula">`）；也可直接 `new com.fr.function.XXX().run(Object[])` 在 Java 侧调用（需公式引擎 Calculator 上下文）。
- 命名解析规则：`"com.fr.function." + name.toUpperCase()`（doc-1840）——**自定义函数封装须遵守全大写简单名约定**。
- 分类判据（修正样本）：当「公式/JS/配置」外壳下存在可落 `com.fr.*` 的构建内核时，给【API】构建要点（怎么嵌进单元格 / 怎么直接 new 类调用）；仅纯语法/语义差异才降理解级。数组函数是最典型样本（doc-816 实读 13 个数组函数类全存在，见 `practice/topic_816_java/ArrayFormulaDemo.java`）。
- 与 §7.10 呼应：`MAPARRAY` 实现类 `com.fr.function.MAPARRAY extends com.fr.function.LambdaFunction`——lambda 隐式变量无 Java 构建 API，只能拼字符串。

### 3.17 Excel 导入「按单元格位置匹配」的扩展铁律（doc-1086）

> 来源: 帆软官方帮助 doc-1086（根据单元格位置匹配）

- 凡是「按单元格位置匹配」导入的模板，**导入数据区的每个单元格都必须设可扩展**（有数据字段还要设列表展示 `divideMode="1"`，§3.3），否则与 Excel 的列对齐会漂移错位、且无任何报错。
- 对应核心 API：`com.fr.report.cell.cellattr.CellExpandAttr`（向下扩展 `Vertical_EXTENDABLE`，XML `<Expand dir="0"/>`）；headless 生成器应在产出导入区单元格时**强制带扩展属性**，不能只填空值。

### 3.18 单元格元素 8 类与 <V> 形态对照 + 插入行列（doc-1245）

> 来源: 帆软官方帮助 doc-1245（插入）

「插入」总纲 = 三类目标（单元格元素/悬浮元素/行列），headless 按此三分法分派：

- **单元格元素 8 类**（统一挂载链 `TemplateCellElement`（`DefaultTemplateCellElement`）+ `WorkSheet.addCellElement`），按值形态区分：

| 元素 | <V> 形态 |
|------|---------|
| 文本 | 纯字符串 |
| 公式 | 以 `=` 开头（运行时公式引擎求值，无额外开关） |
| 数据列 | `"数据集名.列名"` |
| 富文本/图表/图片/斜线/子报表 | 对象型序列化（富文本对象/图表集合对象/FRImage 或 byte[]/斜线对象/子报表对象，Java 类名与构造链待核验，建议设计器分别插入后导出 .cpt diff 反查，同 doc-997 模式） |

- **插入行/列（XML 操作法）** = `<Rows>` 内插 `<Row height=../>`（选中行上方）、`<Columns>` 内插 `<Column width=../>`（选中列左侧），**同时必须平移 `<Cells>` 中所有受影响单元格坐标**：行插上方 → 行号 ≥ 新行位的 `R` 全部 +1；列插左侧 → 列号 ≥ 新列位的 `C` 全部 +1——GUI 自动做、headless 必漏，漏则整表数据错位（静默）；
- 悬浮元素独立于单元格体系：`FloatElement` 抽象基类 + 子类 `FloatTextField`/`FloatChart`/`FloatImage`（类名待核验）、`WorkSheet.addFloatElement`（签名待核验）、XML 落点 `<Floats>`；**悬浮元素不参与扩展链、移动端/Word 导出不支持**。

### 3.19 可伸展性：横向/纵向可伸展（doc-215）

### 常见问法：父子格怎么设置？/ 单元格怎么扩展？/ 扩展后表头被拉大怎么办？/ 相同值的单元格想合并怎么配？

| 症状/口语问题 | 动作（脚本/公式/操作步骤） | 出处 |
|---|---|---|
| 扩展数据列把静态表头/邻格拉大 | 取消本格横向/纵向可伸展（默认开）= 本格不被相邻扩展格拉大 | 本文件 §3.19（L630）【实测】 |
| 同值行合并还是不合并 | DSColumn 默认 divideMode="1" 列表展示、不合并同值行 | 铁律 B（GUIDE L95-L97）【实测】 |
| 排序/汇总结果不可预期 | 排序公式与左父格耦合：先挂左父格再设排序公式；汇总逐层上卷 D4=SUM(D3) 而非 SUM(D2) | 铁律 L（GUIDE L232-L233）【实测；任务书 B/C 之外、铁律区白名单内——R5 备案】 |
| 左父格 XML 怎么写 | XML 层 leftParentDefault/left 已核；CellExpandAttr 上/左父格 setter 与 NO_EXPAND 常量待核，禁编造 | 本文件 §3.19（L631-L632）【实测】 |

> 来源: 帆软官方帮助 doc-215（扩展属性）

- 横向/纵向可伸展开关**默认开**；取消勾选 = 本格**不被相邻扩展格拉大**（doc-215 §3）——无头生成「数据区扩展拉大静态表头」需求时靠它约束表头格；
- 待核验：设计器「单元格属性-扩展-高级」取消「横向可伸展」对应的 `<Expand>` 属性名与 `CellExpandAttr` setter；`CellExpandAttr` 上/左父格 setter 签名（当前仅 XML 层 `leftParentDefault/left` 已核，doc-2684）与「不扩展」的显式表达（NO_EXPAND 方向常量待核）；
- 核验样本 = doc-215 附件模板或「扩展数据列+静态表头」.cpt 的设计器另存 diff；javap 实读 CellExpandAttr 后补全。

### 3.20 固定行数分页页内合计（doc-329）

> 来源: 帆软官方帮助 doc-329（每页固定行数页内合计）

「重复结尾行 + 页合计」路线（doc-330）的页合计会随结尾行**每页重复**——正解 = 高级分组把明细切成 N 条一组，分组键格加「条件属性>行前分页」，让**分组本身成为分页单元**：

- ① 分组键列用 `FormulaGrouper`（§3.10 已核类名）+ `CEILING(INARRAY($$$,ds.group(列))/N)` 把明细切 N 条一组（普通分组显示，不加 divideMode）；
- ② 分组键格加条件属性「分页>行前分页」，条件 = 组号≠1（`CommonCondition`+`Compare`，或 `FormulaCondition("A5!=1")`），使组 = 分页单元；
- ③ 页合计/组合计/总合计 = **同一** `=sum(E5)` 公式、仅左父格不同——**汇总层次 = 左父格层次**（E6 左父格 A5 / E7 左父格 B4 / E8 无父格），这是汇总区的通用模型；
- ④ 分组键列设列宽 0 隐藏（`setColumnWidth(int, UNIT.ZERO)`，§5.6；负值静默 clamp 0，FR 无 hidden 布尔位）；
- ⑤ 页码 `{A5}` + `count(A5)` 挂重复结尾行，合计格须挂空白编辑行（A11 空格）避让；
- 待核验：FormulaGrouper 构造器/setFormula 签名与 `<RG class="...FormulaGrouper">` 下公式属性名；PageHighlightAction 行前/行后 flag（行后已核 `<P i="1"/>`，§3.4.1/05 §10.3）；`{A5}` 序号形态与已核 `&A5` 扩展序号的关系（§7.3/§7.11）；Compare「不等于」常量值。核验样本 = 官方随装 `%FR_HOME%\webroot\WEB-INF\reportlets\doc\Advanced\Pagination\分组分页合计.cpt`。

### 3.21 单元格形态(Form)体系：条形码/二维码生成（BarCodeForm，QRCode 纠错级别；doc-221）

> 来源: 帆软官方帮助 doc-221（条形码）。
> 报表内生成二维码速答：不用插件也有内置形态——`BarCodeForm` 换 `<Barcode class>` 为 QRCode 类即生成（纠错 L/M/Q/H），限制见下；JS 临时二维码（doc-3287）不支持导出，生产交付走本节形态。

形态（Form）与控件（Widget）是**两套独立体系**——「单元格显示为条形码/二维码」走形态，不得用 setWidget 挂条码：

- 条形码形态 = `com.fr.report.cell.cellattr.form.BarCodeForm`（经 `CellElement#setCellForm` 挂载，签名未核实），内嵌具体条码类 `com.fr.report.cell.cellattr.form.barcode.*`（Code39/Code39check/Codabar/Code128 族/EAN128/EAN13/ITF25/NW-7/USPS/PDF417/QRCode 等，类名以 jar 为准）；
- XML 落点：`<Cell><Attr class="com.fr.report.cell.cellattr.form.BarCodeForm"><Barcode class="...">...</Barcode></Attr>`（「选择条码类型」即 `<Barcode class>` 切换，一维/二维仅换类）；
- QR 专属属性在 QRCode 类上：版本/纠错级别 L/M/Q/H（可修正 7%/15%/25%/30%）/像素；「显示条形码的文本」= Barcode 级 showText setter（签名未核实）；
- ⚠ **限制清单**：不支持靠左/靠右显示、文字竖排、移动端填报预览；**行高不足致预览堆叠**（构建期按条码高度+文本预留行高）；UPC 需自定义函数生成、国标 Code128 需插件，均非 BarCodeForm 内置能力；
- **单元格形态(Format)**（doc-221 同篇补）：挂载点 `CellAttr.setFormat(com.fr.base.Format)`（签名待核验）；数字格式 `com.fr.base.NumberFormat`（`new NumberFormat("#0.0")` 或 FormatString）；金额线形态类（推断 `com.fr.report.*`，原建议内容截断，类名待核验后固化）。

### 3.22 富文本构建与 HTML 导出兼容（doc-3729 + doc-3202）

> 来源: 帆软官方帮助 doc-3729（HTML 解析插件）/ doc-3202（移动端弹窗-富文本）

富文本 = 单元格内 HTML 渲染文本（一段单元格多种样式），落点 = .cpt 单元格 `<RichTextValue>` 节点的 CDATA 内（无 com.fr.* API，doc-3729 为纯理解级）；写入的 HTML 受导出支持矩阵约束：

- **跨导出格式安全属性清单**：字体系列 font-* + color 全格式支持；`border/padding/margin/text-align` 仅 PDF/图片支持，Word/Excel 不支持或转图片（Excel 是最受限目标，大量 CSS 以图片显示）；
- **生成规则**：img src 须绝对路径或 base64；background 图片须非相对路径；ul/ol/li 不嵌套块级标签；颜色用名称/16进制/rgb；需导出 Excel 时边框优先用 FR 单元格原生样式而非 HTML border；下划线与删除线只跟随字体同步；
- ⚠ 注意「报表导出性能优化插件」与 HTML 解析插件支持面差异（性能插件多数属性不支持、不支持 img），目标环境装有性能插件时按两插件支持交集取值；
- 参考 `practice/topic_3729_hermes/richtext_html_safe.cpt.xml`。

### 3.24 动态列三公式骨架（doc-1288）

> 来源: 帆软官方帮助 doc-1288（下拉复选框-动态列）

宽表转列展示的「动态列」三公式骨架（与「数据集参数 SQL 方案」（ckzl/lc/02）并列标注为两条路线）：

```
A2 = ds1.select(#0)             // 纵向扩展（行）
B1 = $colname                   // 横向扩展（列，模板参数 colname 由下拉复选框勾选字段名注入）
B2 = ds1.value(A2, B1)          // 不扩展（取交叉值）
```

- 扩展方向用 `CellExpandAttr#setExtendable(Vertical/Horizontal_EXTENDABLE)`（§3.1 已登记）；
- **边界：不支持行式引擎**、列多但数据量不大——不登记会踩运行时坑；
- 配套：下拉复选框 + 公式字典动态列配方（实际值公式 `=TABLEDATAFIELDS("ds1")` 取数据集全部字段名、显示值 `=$$$` 原样）→ 模板参数 colname → 单元格公式 `$colname`（详细见 ckzl/lc/04）。
