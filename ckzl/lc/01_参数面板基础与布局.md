## 7. 参数面板

> ⚠️ **联动机制二分（doc-608）**：参数面板联动 = **模板参数驱动**（显式 `<Parameter>` 声明，doc-1284/1029）；填报单元格联动 = **单元格引用驱动**（隐式，SQL/公式里写 C9，doc-608）。二者不可混用——把 `${p}` 参数套路错用于填报单元格，移动端直接失效且无报错。

### 7.1 控件字典（正确方式）
```xml
<Dictionary class="com.fr.data.impl.TableDataDictionary">
  <FormulaDictAttr kiName="bu" viName="bu"/>
  <TableDataDictAttr>
    <TableData class="com.fr.data.impl.NameTableData">
      <Name><![CDATA[dict001_bu]]></Name>
    </TableData>
  </TableDataDictAttr>
</Dictionary>
```

**TableDataDictAttr 节点形态速答（控件字典的参数声明）**：§7.1 代码块即标准形态——`<Dictionary class="com.fr.data.impl.TableDataDictionary">` 下并列 `<FormulaDictAttr kiName="实际值列" viName="显示值列"/>` 与 `<TableDataDictAttr>`（内含 `<TableData class="com.fr.data.impl.NameTableData"><Name><![CDATA[字典数据集名]]></Name></TableData>`）；**子控件依赖声明**走 `TableDataDictAttr/TableData/Parameters/<Parameter name="父参数"/>`（§7.3 三处命名一致；⚠公式字典 `FormulaDictionary` **没有**这层 Parameters 声明，见 §7.4）。

> 📌 **地图联动：实际值=地图边界路径，显示值=省份名（doc-1698）**——地图联动场景下「参数值即地图路径」是隐式编码约定，二者**不可颠倒**；无头脚本若只生成显示值会联动失败且无明显报错。

### 7.2 查询按钮
```xml
<InnerWidget class="com.fr.form.parameter.FormSubmitButton">
  <WidgetName name="search"/>
  <Text><![CDATA[Query]]></Text>
  <Hotkeys><![CDATA[enter]]></Hotkeys>
</InnerWidget>
```

### 7.3 联动三处命名一致（doc-1284）

下拉框联动的本质是「一级一个字典数据集」，联动成立的唯一前提是**三处命名严格一致**：

| # | 位置 | 写法 |
|---|------|------|
| ① | 控件 | `<WidgetName name="p"/>` |
| ② | 子控件字典 | `Dictionary/TableDataDictAttr/TableData/Parameters/<Parameter name="p"/>`（声明依赖） |
| ③ | 字典数据集 SQL | `${p}` |

| 缺 ② 时 FR **不报错**、只是子下拉不随父级刷新——无头生成最高频的静默失败。隐含约束：

- 父控件须**先于子控件**定义（否则首次加载取不到父值）；
- 不得成环；
- 每个参数须同时存在于 `ReportParameterAttr`。

> 来源: 帆软官方帮助 doc-1284

### 7.4 字典类型速查：公式字典（doc-3244）

现有字典知识全部围绕 TableDataDictionary；补入**公式字典 `com.fr.data.impl.FormulaDictionary`**（选项来自公式/元数据/无数据集时，如选数据连接、选库表）：

- 实际值填公式（如 `tables($cone)`）、显示值填 `$$$`（=实际值原样，公式字典专用占位符）；
- XML 形态（⚠待核）：`<Dictionary class="com.fr.data.impl.FormulaDictionary"><Formula .../><DisplayFormula .../></Dictionary>`；
- **依赖声明差异**：公式字典的父参数 `$cone` 直接写在公式里，**不需要** `<TableDataDictAttr>/<Parameters><Parameter name="p"/>` 那层声明——§7.3「三处命名一致」规则对公式字典**不适用**，误套会去校验一个根本不存在的声明节点。

> 来源: 帆软官方帮助 doc-3244

### 7.5 「让用户看到实际值」的两条路线（doc-4508，官方原文 doc-4143）

| 路线 | 做法 | 支持移动端 | 依赖 |
|------|------|-----------|------|
| ① 纯 SQL（**推荐，headless 首选**） | 显示值列在 SQL 里拼好 `CONCAT(name,'(',user,')')`，字典 `viName` 指向该列 | ✅ | 无 |
| ② JS 悬浮（doc-4143） | beforeedit + `FR.remoteEvaluate("map(..)")`，保留「平时只看显示值」体验 | ❌ | 需关闭「脚本调用公式限制」+ `.fr-combo-list-item`/`title` 两个非公开 DOM 契约 |

> ⚠️ 官方文档只给了 JS 路线，模型容易默认照搬；无头链路里改一行 SQL 的成本远低于注入 JS，且能同时消掉移动端盲区、服务端开关依赖、DOM 契约依赖三项风险——**「能改 SQL 就别写 JS」应作为选型默认值**。
> 来源: 帆软官方帮助 doc-4508 / doc-4143
### 7.6 文件控件移动端上传方式（doc-1389）

控件 cookbook 补「文件控件移动端上传方式」最小无头构建（kit 控件章节此前零移动端属性覆盖，属能力盲区）：

- 控件本体 `com.fr.form.ui.MultiFileEditor`（fine-report-engine），移动端上传方式挂其 `mobileAttr` 字段（`com.fr.base.mobile.MultiFileUploaderMobileAttr`）；
- 装配链：`getMobileAttr()` / `setMobileAttr(new com.fr.base.mobile.MultiFileUploaderMobileAttr())` → `setFileUploadModeState(com.fr.base.mobile.FileUploadModeState.{ONLY_TAKE_PHOTOS | TAKE_PHOTOS_AND_CHOOSE_FROM_ALBUM})`（仅拍照 / 拍照+相册，对应设计器 2.1 下拉两项）；
- XML 落点（等价 Java 装配）：`<Widget class="com.fr.form.ui.MultiFileEditor">` 内含 `<MobileAttr class="com.fr.base.mobile.MultiFileUploaderMobileAttr">`（其内子节点精确标签名待核，对照设计器另存 .cpt 的 writeXML）；
- ⚠️ **铁律：生成后必须 `getMobileAttr()` 回读断言**（防移动端配置静默丢失）——`FileUploadModeState` 是枚举哑值（同 doc-2415 `targetFrame` 形态），误拼/漏配时控件照生成、移动端静默退化为默认，只能靠生成期回读兜底；
- 拍摄/重拍/翻转摄像头/选原图等为 App/HTML5 客户端 UI 行为（App ≥ V10.4.76 才支持翻转/原图），无服务端对应，交付时作环境前置断言。

> 来源: 帆软官方帮助 doc-1389

### 7.7 文本域控件 TextArea（doc-266）

「多值查询」参数控件与多行填报的高频载体，Java 装配链：

- 类 `com.fr.form.ui.TextArea`（填报/参数通用）：填报挂单元格 `DefaultTemplateCellElement#setWidget(TextArea)` ↔ `<Cell><Widget class="com.fr.form.ui.TextArea"><Attr>…</Attr></Widget>`；参数面板挂 `ParameterUI>WidgetManager>Widgets` 下同名 Widget 节点；
- 基本属性：`setName(String)`（⚠️ 参数控件默认名 `textArea#`，多控件需显式命名防 WidgetName 重复）、`setVisible(boolean)`、`setEnabled(boolean)` → `<Name>/<Visible>/<Enabled>`；水印 `setWaterMark(String)` → `<WaterMark>`；允许为空 `setAllowBlank(boolean)` → `<AllowBlank>`；
- 填写规则 `setValidate(Validate)`：长度 `com.fr.form.validate.LengthValidate(int min, int max)` → `<Validate class="…LengthValidate"><MinLength>/<MaxLength>`；正则 `com.fr.form.validate.RegexpValidate`（setRegex/setErrorMessage）→ `<Regex>/<ErrorMessage>`（XML 节点名以设计器导出为准）；
- 参数控件默认值 `setWidgetValue(WidgetValue)`（字符串/数据集字段/公式）→ `<WidgetValue><String>…`。

> 来源: 帆软官方帮助 doc-266

### 7.8 下拉复选框控件 ComboCheckBox（doc-256；多选下拉 / 复选下拉控件）
> 问法入口（2026-09-13 收官补，S-008）：「下拉复选框控件」「多选下拉/复选下拉怎么配多个值」→ 即本节 ComboCheckBox（doc-256）。

多选参数/填报常用控件，构建链与高频配置点：

- 类 `com.fr.form.ui.ComboCheckBox` + 数据字典 **必设**：`setDataDictionary(com.fr.data.Dictionary)`，字典数据 `Dictionary.setDataResult(DataResult)`，常用 `com.fr.data.impl.ArrayDataResult(new String[]{…})`——**不设字典则无下拉选项**；XML `<dataDictionary class="com.fr.data.Dictionary"><dataResult>…<result>华东,华北</result>`；
- 返回值类型二选一：数组（默认）或字符串（自定义分隔符+开始符+结束符拼接，如 '值1,值2'）——**决定提交入库/参数查询取值格式**；XML `<returnValueType>` 及分隔符节点，setter 名待核；
- 10.0.18 前后「允许自定义值」行为差异：之前不勾仅提示「不在列表中」；之后与「标签形式显示」组合（二者都未勾→不清除输入并提示；勾了标签→自动清除输入并提示），无头构建须按目标版本设置属性组合；
- 模糊搜索 = 勾「允许直接编辑」（按输入字符拆开顺序匹配，非连续子串）；
- 默认值挂载分场景：填报=单元格值（逗号分隔，可用实际值或显示值）；参数=控件值（字符串逗号分隔 / 数据集字段 / 公式，多值则多选）；
- 「标签形式显示」「允许直接编辑」不支持移动端。

> 来源: 帆软官方帮助 doc-256

### 7.9 标签控件 Label（doc-4543）

参数面板「说明文字/标题」的标准载体（与 doc-266 TextArea 同链，ParameterUI>WidgetManager>Widgets 挂载）：

- 类 `com.fr.form.ui.Label`；基本属性 `setName(String)`（默认无，勿与其他面板控件重名）、`setVisible(boolean)`、`setEnabled(boolean)` → `<Name>/<Visible>/<Enabled>`；
- 控件值 `setWidgetValue(WidgetValue)`：字符串/数据集字段/公式三形态（如 A1 单元格值）→ `<WidgetValue>`；自动换行/垂直居中/字体 setter 签名未核实（疑 setAutoWrap/setVerticalCenter/setFont，以 jar 为准）；
- ⚠️ **两条静默限制**：**仅参数面板可用、不支持填报应用**（填报/单元格说明文字用普通控件或单元格文本）；**移动端参数界面不显示 Label**，移动端用普通控件「标签名称」属性实现标签——漏记会导致交付后控件不显示；
- 「值改变」事件在页面加载渲染赋值时会额外触发一次（初始化赋值即触发）——预期行为，勿当 bug 排查。

> 来源: 帆软官方帮助 doc-4543

### 7.10 按钮控件（doc-265）

### 常见问法：查询按钮怎么做？/ 自定义按钮点击没反应怎么办？/ 插入行按钮为什么失效？/ 按钮怎么挂 JS 赋值给时间控件？

| 症状/口语问题 | 动作（脚本/公式/操作步骤） | 出处 |
|---|---|---|
| 查询按钮怎么做 | 原生 com.fr.form.parameter.FormSubmitButton（WidgetName=search、Hotkeys=enter，框架自动查询无需 JS）；勿用 FreeButton+空 JS 冒充（点击无反应，示例模块 实测） | 铁律 G（GUIDE L185）【实测】 |
| 增/删行按钮样式类名 | WidgetName 对应 CSS 类 add/delete（小写） | 铁律 G（GUIDE L181）【实测】 |
| 单元格按钮默认蓝想改白 | 背景 ColorBackground color="-1"；极简 `<C>`+Widget+Expand，无 s/Background/Border | 铁律 G（GUIDE L182-L183）【实测】 |
| 插入行按钮失效 | 参照格必须纵向扩展：CellExpandAttr.setExtendable(Vertical_EXTENDABLE) ↔ `<Expand dir="0"/>` | 本文件 §7.10（L152）【实测】 |
| 按钮类族/挂载/图标 | Button/InsertRowButton/DeleteRowButton/TreeButton（com.fr.form.ui.*）；面板=WParameterLayout.addWidget+setBounds；未核验子类禁从零 new；「按钮赋值给另一控件」的 JS 写法见 §28.1 四要点 | 本文件 §7.10（L149-L153）【实测】；§28.1（L701-L708）【实测】 |

- 类族（com.fr.form.ui.*，fr-core.jar）：普通/自定义=`com.fr.form.ui.Button`；插入行=`com.fr.form.ui.InsertRowButton`、删除行=`com.fr.form.ui.DeleteRowButton`（指定单元格/行数 setter ⚠️待核）；树节点=`com.fr.form.ui.TreeButton`（仅数据分析预览）；**参数提交按钮类名⚠️待核**（疑 ParameterCommitButton 或 Button+预设 parameterCommit 事件，禁编造）；
- 两处挂载：参数面板=`WParameterLayout.addWidget` + `Widget#setBounds`（doc-258/2188 已核验，参数面板按钮默认名 `button#`）；填报单元格=CellElement 挂 Widget（CellWidget 包装，05 §9.x/§10.4 doc-958 已沉淀）；
- 基础属性：控件名称 `Widget#setWidgetName(String)`（已核验）、可用 `setEnabled(boolean)`、可见 `setVisible(boolean)`、按钮名字 `Button#setText(String)`、图标 `setIcon(Icon)`（自定义建议 16×16 PNG）、快捷键——签名均⚠️待核；
- **插入行硬约束**：指定单元格（参照格）必须纵向扩展——`CellExpandAttr.setExtendable(CellExpandAttr.Vertical_EXTENDABLE)` ↔ `<Expand dir="0"/>`，否则插入行失效；
- 移动端不支持 参数提交 与 树节点 按钮；删除行按钮不支持「提交入库」事件；未核验子类（插删行/树节点/参数提交）禁从零 new，生产走「设计器基线 .cpt + read→改→write」。

> 来源: 帆软官方帮助 doc-265

### 7.11 参数面板内嵌数据展示（doc-406）

「参数选中后参数面板直接显示关联数据」的轻量展示模式（04 此前只覆盖级联/布局，缺「控件值用公式 + 事件控制显隐」构建知识）：

- 标签控件值用 sql() 公式带出关联数据：`Label.setText(Formula)`（`com.fr.formula.Formula`，公式文本不带 `=` 前缀，如 `sql("FRDemo",…,1,1)`）；
- 初始隐藏：标签控件 `setVisible(false)`（XML `visible="false"`），首屏只显示下拉框；
- 下拉框「编辑后」事件 JS 控制显隐：`Widget.addEvent(new com.fr.form.event.Event("afteredit", js))`（事件名 afteredit=编辑后），JS 用 `this.options.form.getWidgetByName("标签名").setVisible(true)`；
- 下拉框数据字典 `ComboBox.setDataDictionary(Dictionary)` + `Dictionary.setConnection(String)/setSql(String)` ↔ XML Widget 下 `DataDictionary` 节点；
- 整套可无头构建（参数→数据集→控件→事件），事件 JS 固定存于 `<Events><Event eventName="afteredit">…`；报表主体单元格过滤可再引用模板参数 `$id`；**不支持移动端**。

> 来源: 帆软官方帮助 doc-406
