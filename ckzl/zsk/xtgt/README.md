# AI↔用户ckzl/zsk/xtgt框架

← [返回主路由](../AGENTS.md)

> **核心理念**：AI 不只是执行者，更是项目的管理者。通过"向下管理"的方式主动收集需求、确认方案、推进开发，而不是被动等待用户指令。

> **两个维度**：
> - **怎么问**（沟通效率）：标注 > 判断 > 选择 > 填空 > 问答（下文 §0-§4）
> - **问什么**（内容维度）：5W1H + KANO + 需求边界（下文 §5-§7）

---

## 沟通效率五级模型

从高到低排列，**优先使用高效形式**，仅在信息不足时降级：

```
效率高 ←────────────────────────────────────────────────→ 效率低

  ⓪ 标注        ① 判断        ② 选择        ③ 填空        ④ 问答
  (在制品上)    (是/否)       (多选一)      (补全信息)    (开放回答)
```

### ⓪ 标注（效率最高，复杂报表首选）

**适用场景**：空间类/批量类确认——哪些区域是表头、哪些列删掉、哪些格子重算。**用语言描述几十个区域必然失真，直接在制品（cpt）上染色，让用户看着实物确认。**

> 来源：示例报表工程项目实战（2026-08-18）。一张 12MB 五 sheet 复杂模板，靠"三色标注 + 红标删除"两轮视觉确认完成结构定型，零歧义。

**标准颜色语义**（ kit 全局统一，勿改）：

| 颜色 | 语义 | 用户动作 |
|------|------|---------|
| ⬛ 黑底白字 | 表头/标题区 | 确认或指出错标 |
| 🟩 绿底 | 业务逻辑区（取数/输入/绑定） | 确认或指出错标 |
| ⬜ 灰底 | 常量/纯公式区（不需要绑数据） | 确认或指出错标 |
| 🟥 红底 | **建议删除**（仅标记，绝不先删） | 逐区确认删/留 |
| （不标） | 尚未判定/维度文本列 | 由用户归类 |

**AI 输出要点**：标注完成后必须配 **区域清单表**（区号/行列范围/格数/内容样例/判断理由），用户按区号回复（"A-I 删，J 留"），而不是逐格看。

```
✅ 正确用法（配套输出）：

  红标区域清单（共 15,434 格）：
  | 区 | 行列 | 格数 | 内容样例 | 判断 |
  | A | FS预算 108-853 | 7,389 | Scenario# 草稿区 | 删 |
  | J | FS预算 N列 40-103 | 64 | 分母科目说明 | 待你定 |
  请按区号回复删除范围。

❌ 错误用法：

  我把没用的格子标红了，你看哪些删？
  （9 万个红格没有清单，用户无从下手）
```

**技术注意**：Excel 转换产物里大量纯格式空格——标注前先清空格（本次 9.7 万红格中 8.2 万是空的），否则标注数字吓人且无意义。

### ① 判断（效率最高）

**适用场景**：AI 已有足够信息形成完整方案，需要用户拍板。

AI 输出要点：展示**完整理解 + 完整方案**，让用户只需回答"执行/不执行"。

```
✅ 正确用法：

  我理解你要做的是：
  - 填报表，表名 fin_demo_input_lta_detail
  - PK: month + bu + region + plant_code + program
  - IntelliDMLConfig 智能提交
  - 6 个级联控件，顺序：年份→月份→BU→地区→工厂→项目
  - 分页、隔行换色、数字格式 #,##0.00

  以上理解是否正确？确认后我将开始生成模板。

❌ 错误用法：

  你想用什么提交方式？（太开放，用户可能不知道选项）
```

### ② 选择（效率高）

**适用场景**：某个字段/配置有多种可能，AI 无法自动判断。

AI 输出要点：列出**有限选项 + 每项的推荐理由**，让用户选。

```
✅ 正确用法：

  字段「month」的数据类型我无法从建表语句确定：
  
  A. 文本 ("2026-01")   ← 推荐，与你其他 varchar 字段一致
  B. 数字 (1-12)        ← 需改 ComboCheckBox 显示格式
  C. 日期              ← 需用 DateEditor 控件

  请选择（A/B/C）：

❌ 错误用法：

  month 是什么格式的？
```

### ③ 填空（效率中）

**适用场景**：需要用户提供具体的命名、标识符或少量确定值。

AI 输出要点：给出**清晰的模板 + 示例**，用户只需填入值。

```
✅ 正确用法：

  请提供以下信息（可直接填入）：

  | 项目 | 值 | 示例 |
  |------|-----|------|
  | 报表名称 | _______ | lta_detail_fill |
  | 输出目录 | _______ | reportlets/test/ |
  | 数据连接名 | _______ | 数据连接1 |

❌ 错误用法：

  报表叫什么名字？放在哪？用什么数据库？
```

### ④ 问答（效率低，信息密度高）

**适用场景**：复杂问题需要用户输入开放性信息，或需要用户提供领域知识。

AI 输出要点：**一次只问一个核心问题**，避免连续追问。

```
✅ 正确用法：

  这张表的数据来源是什么？
  是从 SAP 接口同步、Excel 手工导入、还是下游系统推送？
  这影响我设计数据校验规则和提交逻辑。

❌ 错误用法：

  连续问 5 个问题，用户需要逐一回答，认知负担大。
```

## 需求内容维度（问什么）

### 5. 5W1H 需求分析框架

> 来源：《项目实施表单设计》§一 — 结合 5W1H 法，确保需求理解全面。

| 维度 | 问什么 | FR 报报场景示例 |
|------|--------|---------------|
| **What** | 做什么报表？类型？ | "示例项目报表-LTA明细表" — 填报报表 |
| **Why** | 为什么做？业务目标？ | "每月采购示例项目数据需要人工填报到系统" |
| **Who** | 谁用？角色/部门？ | "采购部门填报，管理层查看" |
| **Where** | 用在哪？部署环境？ | "FineReport 10.0，数据连接 数据连接1" |
| **When** | 什么时候要？数据周期？ | "月度填报，月底前完成" |
| **How** | 怎么实现？技术方案？ | "IntelliDMLConfig 智能提交 + 级联参数面板" |

> AI 应在需求收集阶段自然地覆盖这 6 个维度，不需要每次都像表单一样逐项询问。能从上下文推断的就推断，推断不了的选择对应沟通层级去问。

### 6. KANO 需求优先级模型

> 来源：《项目实施表单设计》§1.3 — 科学分配开发资源，先做必须的，后做锦上添花的。

| KANO 类别 | 含义 | FR 场景对应 | 优先级 |
|-----------|------|-----------|--------|
| **M (Must-be)** 基本型 | 不做就不能用 | 数据集、提交逻辑、基本控件 | **P0 必做** |
| **O (One-dimensional)** 期望型 | 做了更好，不做有怨言 | 导出按钮、分页、冻结表头 | **P1 重要** |
| **A (Attractive)** 兴奋型 | 做了惊喜，不做也行 | 隔行换色、列宽自适应、自定义 CSS | **P2 一般** |
| **I (Indifferent)** 无差异 | 做不做都无所谓 | 移动端适配（内部报表很少用） | 不做 |
| **R (Reverse)** 反向型 | 做了反而不好 | 过度自动化（用户需要手动确认） | 避免 |

> AI 使用规则：M/O 类需求**必须问用户确认**；A 类需求可以**默认提供**但用户可以拒绝；I/R 类需求**主动忽略**。

### 7. 需求边界明确化

> 来源：《项目实施表单设计》§1.4 — 开发前定义"做什么"和"不做什么"，防止范围蔓延。

AI 在输出方案摘要（① 判断）时，应包含**明确的需求边界**：

```
✅ 方案摘要示例：

  本次开发范围：
  ✅ 包含：填报模板 + 导入模板，共用参数面板
  ❌ 不包含：查看模板（用户未要求）、移动端适配、数据权限配置

  如需调整范围，请告诉我。
```

## 破坏性操作三步协议（§10）

> 来源：示例项目删除草稿区实战。**任何删 sheet/删区域/批量改公式，禁止一步到位。**

```
第一步 标记（不改动任何内容）
  · 红底标出建议删除范围 → 用户看得见
  · 配套输出区域清单表（区号/范围/格数/样例/理由）
  · 用户确认删除范围（按区号回复）

第二步 依赖扫描（执行前，必做）
  · 公式引用扫描：区外是否有公式引用区内格子？
    ——本次发现 28 个可见区公式引用草稿区（=L108 类），草稿区实为取数暂存区！
  · 处置：静态化为缓存值 / 内联公式 / 保留区域，三种方案告知用户
  · 区内互引：随区删除，无需处理

第三步 执行（备份先行）
  · 备份命名：<文件>.bak<N>_<YYYYMMDD>，N 递增形成备份链
  · 写出后立即 XML 校验；失败 → 从备份恢复再来
  · 执行后复扫：断链引用 = 0 才算完
```

**红线**：跳过第二步直接删 = 数据链断在用户看不见的地方。本次草稿区若直接删除，FS 表头 33-35 行的 28 个取数格全部 #REF!，且用户要到绑定数据时才会发现。

## 证据式沟通（§11）

> 原则：**技术断言必须带引擎实测证据**，"我觉得 FR 支持这个函数"不算结论。

| 断言类型 | 取证方式 | 本次实战证据 |
|---------|---------|------------|
| 函数可用性 | fr-agent `/exec` Calculator 逐个 eval | IFERROR/VLOOKUP/IRR "no function found" → 定替换方案 |
| 替换方案可行性 | 同引擎 eval 改写后的公式 | `=IF(J31=0,0,N31/J31-1)` OK |
| 语法边界 | 变体矩阵测试 | 前导负号 `-A1` 报错 / `0-A1` OK → 32 个公式改写依据 |
| 文件可打开 | Excel COM 真实打开（openpyxl 通过≠Excel 通过） | 拆分 xlsx 20/20 全过 |

沟通模板：**断言 + 证据 + 影响面 + 方案**，四要素齐了才发给用户拍板。

## 待决事项台账（§12）

> 复杂项目必有"现在定不了/等你给资料"的事项。**禁止散落在对话里**，统一编号挂账，每轮交付时同步状态。

```
台账格式（示例来自示例项目）：
| # | 事项 | 类型 | 状态 | 责任 |
| 13 | QS 分类口径 | 数据缺口 | 待用户 | 用户 |
| 20 | fact 表 entity_label 为空 | 数据缺口 | 已绕过(SQL 兜底) | - |
| 22 | VLOOKUP 110 个的映射方案 | 方案选择 | 待定 A/B | 双方 |
| 23 | ztbdp01 无 PACT 数据/无 2025 | 数据缺口 | 已确认 | - |
```

规则：
- 编号只增不复用，关闭写结论不删行
- 每轮交付附"台账变化"（新增/关闭/阻塞）
- 用户长期未答的项，连续 3 轮提示后标记 `挂起`，不再每轮追问

## 何时升级/降级沟通层级

```
要确认的是什么？
│
├─ 空间/批量区域（表头？删除？归类？） → ⓪ 标注：在制品上染色 + 区域清单
│
├─ 方案整体（信息充分） → ① 判断：输出方案，请求确认
│
├─ 差一个关键信息 → ② 选择：给选项
│
├─ 差多个命名/标识 → ③ 填空：给模板
│
└─ 差领域知识/背景 → ④ 问答：开放式提问
```

### 开发报表的标准沟通流程

```
阶段 1：需求收集（③ 填空 + ④ 问答）
├─ 用户提供建表语句 → AI 自动提取字段
├─ AI 输出填空表单（填空）：报表名、目录、数据连接
├─ AI 问主键和提交逻辑（选择）
└─ AI 问控件顺序和类型（选择）
│
阶段 2：方案确认（① 判断）
├─ AI 输出完整方案摘要（含需求边界 §7）
└─ 用户确认"执行"或修改
│
阶段 3：开发执行（自动，无需沟通）
├─ 按 §8 步骤拆分依次执行
└─ 如遇技术不确定 → ④ 问答
│
阶段 4：交付验收（① 判断 + §9 验收清单）
├─ AI 报告执行结果 + 验收清单
└─ 用户在 Designer 中预览验收
```

## 需求问卷

`questionnaires/` 目录下存放标准化问卷模板：

| 文件 | 适用场景 | 形式 |
|------|---------|------|
| `填报报表需求问卷.md` | 创建填报报表前 | 填空 + 选择 |

> 后续可增加：查看报表需求问卷、导入报表需求问卷、模板格式化问卷等。

### 何时使用问卷

当 AI 判断**当前需求信息不足以启动开发**时，选择对应的问卷发送给用户。

判断标准：
- 缺少主键信息 → 必须问（P0）
- 缺少控件顺序 → 必须问（P0）
- 缺少数据连接名 → 可从已有模板推断（P1）
- 缺少报表名称 → 可自动生成，用①判断确认（P2）
