# DSColumn 悬空数据集引用与超链死链分析

> 实战来源：2026-09-06/07 示例报表工程/明细报表 示例实际表.cpt / 示例预算表.cpt（含 `明细报表 - 副本` 病灶对照版）。
> 检查工具源起 `kfgj/fzpy\check_cpt_integrity.py`（2026-09-07 三合一完整性体检，检查1=数据集引用、检查3=超链目标）。

---

## 1. 现象

**悬空数据集（检查1 族）**：模板打开默认视图**零报错**（设计器不告警、服务端日志干净）；版本参数（PY/CUR）一选中，大片列（LTA/PACT/示例模块/CI 四组）瞬间整列空白。根因是格子 `<O t="DSColumn">` 绑定的 `dsName` 在 TableDataMap 里**不存在**——而平时这些列恰好被列显隐（colShower）公式隐藏，悬空被遮蔽不暴露。

**超链死链（检查3 族，同族引用完整性问题）**：钻取目标页（FS 钻取明细/钻取明细预算.cpt）删除后，若主表 `ReportletName` 超链漏摘，用户点击即弹"报表不存在"。示例实际表/预算 本轮已**同步摘除 172+41 处**钻取超链（做法正确，作为对照）；但工具复查又发现 **示例实际表（含副本）另有 21 处超链指向 `/示例报表工程/明细报表/FS ADJ填报.cpt`——该文件在本部署从未存在**，属历史遗留死链，等待裁决（补文件或摘链）。

两族的共同点：**引用方与被引用方分处模板两处（或跨文件），删除/改名一侧时没有静态检查拦截另一侧**。

## 2. 根因与盲区本质

```xml
<!-- 格子侧：引用 ds_cr_lta -->
<O t="DSColumn">
<Attributes dsName="ds_cr_lta" columnName="val"/>
...
<!-- 定义侧：TableDataMap 必须有同名 <TableData name="ds_cr_lta"> -->
```

- 悬空判定纯机械：全部 `DSColumn@dsName` ⊆ `TableDataMap/TableData@name`。副本版 示例预算表实测 4 个基础名悬空共 **403 处**（ds_cr_ci 102 / ds_cr_vave 102 / ds_cr_pact 100 / ds_cr_lta 99）。
- **遮蔽机制**：列显隐公式为假时列不渲染，悬空数据集根本不参与计算 → 页面无任何异常；只有展开该列的参数组合被选中才触发"数据集不存在→空列"。这就是"平时好好的，一选版本就空"的成因。
- **盲区本质**：`fr_check` 查模板级规则（参数闭合/连接名等），**没有"数据集引用完整性"静态检查**；运行期对悬空 dsName 也只静默出空，两道都不拦。

**数字勘误（工具实测为准，2026-09-07）**：

| 事故流传数字 | 工具实测 | 说明 |
|---|---|---|
| "悬空 408 处" | **403 处**（100+102+102+99） | 且**全部在副本版 示例预算表**；示例实际表副本版 TableDataMap 齐全、悬空为 0 |
| "主表 408 处超链" | 钻取超链 **172（实际）+41（预算）=213 处** | 408 系与悬空数混淆；该批已随删页同步摘除 |
| "2175" | **示例预算表 DSColumn 引用总数 2175**（示例实际表为 1090） | 是引用总量口径，非悬空数、非超链数 |

## 3. 定位方法：引用完整性静态检查（工具化）

```bash
python kfgj/fzpy/check_cpt_integrity.py <a.cpt> [--fr-home <FR根>] [--reportlets-root <reportlets根>]
```

- **检查1 数据集引用**：ET 解析收集全部 `<O t="DSColumn">` 的 `dsName`（附绑定列与格位），比对 TableDataMap 定义集，悬空的按数据集报"次数/绑定列/首现格位"，并提示遮蔽机制。副本 示例预算表实测输出：`ds_cr_ci 102 处 绑定列[val] 首现 (AJ5)(AX5)...`。
- **检查3 超链目标**：收集全部 `<ReportletName>` CDATA 路径，相对 reportlets 根逐一验存在性；根可显式传参、可用"已存在目标反推"或本机默认路径。副本 示例实际表实测：`172 处 → FS 钻取明细.cpt 首现(G6)(I6)...`、`21 处 → FS ADJ填报.cpt`。
- 退出码同 fr_check 惯例：0=PASS / 1=ERROR / 2=WARN；`--json` 出机器可读结果；修复版回扫应 PASS。

无工具时的手工等价：解压/文本打开 cpt，正则抓 `dsName="..."` 与 `<TableData name="..."` 两个集合做差；超链抓 `<ReportletName>` CDATA 到 reportlets 目录 `ls` 验证——工具只是把这两步做成带格位的免思考检查。

## 4. 修复

- **悬空数据集**：二选一——① TableDataMap 补建同名数据集（沿用 `_runs\cr_ds_cr_lta.sql` 等既有的 ds_cr_* 建库脚本口径）；② 摘除悬空绑定（整列删除或改绑正确数据集）。示例实际表/预算 修复版即"定义补齐"路线，回扫 PASS。
- **死链超链**：删除目标页前先查引用（工具检查3）、同步摘链后再删文件；已发生的死链按摘链处理。172+41 处钻取超链已随删页同步摘除；遗留的 21 处 `FS ADJ填报.cpt` 死链待主控裁决（补文件或摘链，本工具每次回扫都会持续拦截提示）。

## 5. 预防

1. **删除/改名类操作前置引用查询（操作纪律）**：删目标页 → 先跑检查3 摘链 → 再删文件；删/改数据集 → 先跑检查1 清引用。顺序不可反。
2. **落盘前完整性体检（工具化已实现）**：程序化生成/批量改写后，`check_cpt_integrity.py` 三检查全过再落盘；生成器把"新数据集必须先注册进 TableDataMap"做成硬断言。
3. **fr_check 待补规则（登记 R-0005/R-0006，未实现）**：① DSColumn dsName ⊄ TableDataMap 即 FAIL；② ReportletName 目标相对 reportlets 根不存在即 FAIL（需 reportlets 根配置项）。
4. **遮蔽是放大器**：列显隐/条件属性把坏引用藏到"特定参数组合才暴露"，比直接报错更危险——凡用列显隐的模板，合并参数矩阵抽查（PY/CUR/EXT 各选一遍）应进验收清单。

## 6. 触发案例

- 程序化生成多版本块（PY/CUR/BUD/FY）时基础名数据集（ds_cr_lta/pact/vave/ci）漏注册进 TableDataMap，而列显隐公式恰好按版本参数控制这些列 → 平时零报错、选版本即空列（示例预算表副本版 403 处）。
- 删除钻取明细页（FS 钻取明细.cpt / FS 钻取明细预算.cpt）时主表 172+41 处 ReportletName 超链需同步摘除——本轮已正确同步；对照发现 FS ADJ填报.cpt 21 处死链系更早遗留，证明"删页必查引用"没有制度就会漏。
