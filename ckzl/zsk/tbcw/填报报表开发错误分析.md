# 填报报表开发错误分析
> 问法入口（2026-09-13 收官补，N-009）：「SQL 放数据库能跑 放报表里就报参数错」→ 常见为报表侧参数宏与数据库占位差异（${if(len(...))} 未替换/参数名不符），查下方错误索引表「参数」相关行；SQL 本身先用 kfgj/fzpy/verify_sql.py 静态验证。

> 本目录只存放错误原因分析，不在指南文件中记录错误。指南只写正确做法。

## 1. SQL ORDER BY 位置错误

**现象**: ORDER BY 出现在 ${if()} 条件之前，SQL 语法错误。

**错误 SQL**:
```sql
select * from table where 1=1
order by field1, field2${if(len(p)==0,"","and ...")}
```

**正确 SQL**:
```sql
select * from table where 1=1
${if(len(p)==0,"","and ...")}
${if(len(p)==0,"","and ...")}
order by field1, field2
```

**根因**: 生成器中先写了 WHERE 1=1 + ORDER BY，再循环追加 ${if()} 条件，导致 ORDER BY 被夹在中间。

**修复**: 先循环追加所有 ${if()} 条件，最后再加 ORDER BY。

---

## 2. 级联参数 Dataset Parameter 格式错误

**现象**: 字典数据集的级联参数不被 FR 识别，子控件下拉不联动。

**错误格式**:
```xml
<Parameters><Parameter name="p_app_no"/></Parameters>
```

**正确格式**:
```xml
<Parameters>
  <Parameter>
    <Attributes name="p_app_no"/>
    <O><![CDATA[]]></O>
  </Parameter>
</Parameters>
```

**根因**: FR 10.0 需要 Parameter 使用完整 Attributes+O 格式才能识别级联参数，自闭合形式被忽略。

**其他要点**:
- ComboCheckBox 控件的 TableData 不需要 Parameters
- 主数据集 (m_data) 也需要 Parameters 声明所有 `${}` 中使用的参数
- SQL 必须多行格式化才能被识别

---

## 3. SQL 多行格式化是级联生效的必要条件

**现象**: 单行 SQL 的字典数据集即使参数格式正确，级联也不生效。

**根因**: FR 10.0 只在多行格式化的 SQL 中解析和建立参数绑定。单行 SQL 中即使写入了 `${}` 公式，FR 也无法识别其中的参数。

**修复**: 生成器输出多行 SQL：
```sql
SELECT
    DISTINCT field AS v,
    field AS d
FROM
    table
WHERE
    1=1 ${if(len(p)==0,"","and ...")}
ORDER BY
    1
```

---

## 4. `<TableDataMap/>` 自闭合导致 FR Designer 崩溃

**现象**: 打开导入模板时报 "Index: 0, Size: 0" 错误。

**根因**: 导入模板不需要数据集，但 `<TableDataMap/>`（自闭合）导致 FR 解析失败。

**修复**: 完全删除 `<TableDataMap>` 元素（不出现，不是自闭合，不是空标签）。

---

## 5. batch_optimize_cpt.py 面板宽度计算 Bug

**现象**: 参数面板宽度被缩减到 960px，控件溢出。

**Bug 1**: `btn_new_row` 判断使用 `RIGHT_ALIGN_MAX=1200` 过于保守。
**修复**: 改用 `SINGLE_ROW_MAX=1500`。

**Bug 2**: `panel_w = all_right + MARGIN` 漏算按钮宽度。
**修复**: `panel_w = max(all_right, bx) + MARGIN`。

---

## 6. 按钮单元格背景/边框无法通过 XML 属性清除

**现象**: AppendRowButton/DeleteRowButton 单元格始终有蓝色背景和边框。

**根因**: 
- 按钮控件由 FR CSS (`.fr-btn-up`) 渲染蓝色背景
- 继承 `s="1"` 样式有边框
- `<Border style="0">` 仍可能渲染
- `<initial>` 背景设置不一定覆盖 CSS

**修复**: 极简化单元格——`<C>` + Widget + `<Expand>`，无 s/Background/Border。

---

## 7. Import 按钮弹窗控件名与 CSS 不一致

**现象**: 使用自定义控件名导致样式不生效。

**修复**: 按钮控件名使用 CSS 类名 (add, delete, x-emb-* 等)。

---

## 8. 数据集 SQL 挂着不存在的字段参数过滤（埋雷）

**现象（示例映射A 实测 2026-08-05）**: 填报版「费用类型」sheet 的数据集 `m_data` 查的是费用类型表，但 SQL 里挂着对**另一张表旧字段**（`main_bbp_metric` 等）的 `${if(len(para_xxx)...)}` 过滤——字段根本不存在。

**为什么当时没炸**: `${if()}` 参数为空时拼接出 `""`，SQL 不包含该过滤条件，照常执行；只有**用户真选了值**才生成 `and main_bbp_metric in (...)`，此时数据库报「列不存在」。

**排查要点**:
- 数据集 SQL 引用的过滤字段必须**属于该 SQL 的 FROM 表**；跨表字段过滤是历史复制粘贴残留。
- 单 sheet 精简/删表后，检查遗留数据集是否还挂着旧字段过滤（删表→该数据集本应一并删除）。
- 用 `grep 'FROM \|in (' 报表.cpt` 对每个数据集核对字段来源。

**修复**: 删除失效过滤条件，或把数据集切到新表新字段（参照 `ckzl/lc/02_数据建模.md` §8 级联 SQL 规范）。
