# 附：实体列名与值域错配排查方法论（entity vs entity_code）

> 供主控裁决：单独成条，或作为"空白列排查方法论"小节并入《DSColumn悬空数据集引用.md》。
> 实战来源：2026-09-06 示例实际表 ds_cr_lta / ds_cr_pact 相关 102 处引用空白（已修复），此处沉淀通用打法。

---

## 现象特征

数据集预览**有数据**、SQL 直连正常，模板里引用它的扩展行却**整片空白且零报错**——与悬空数据集的区别在于：数据集本身存在且出数，是**行级过滤条件恒不匹配**把行全滤没了。

## 根因形态

同义双列并存的中文字段视图是高发地：`entity`=中文厂名（"HWY 北京工厂"），`entity_code`=编码（"1000"）。权限门/层级过滤/参数联动一侧传**编码**，条件里 CNAME 却拿**名字**字段去比：

```xml
<Condition class="com.fr.data.condition.CommonCondition">
<CNAME><![CDATA[entity]]></CNAME>          <!-- ❌ 名字字段 -->
<Compare op="0"/>                           <!-- 等于 -->
<!-- 比较值来自权限门/参数： entity_code 编码值 -->
</Condition>
```

编码值 ≠ 任何中文厂名 → 恒 false → 全部行被滤掉 → 空白。引擎对"过滤后 0 行"不做任何提示，与悬空数据集一样是**静默失败**。

## 排查方法论（空白列五步定位法）

1. **分层二分**：数据集预览/SQL 直连有数 → 问题在模板侧（过滤/条件），无数 → 问题在数据侧（SQL/连接）。本例第一步即锁定模板侧。
2. **抓过滤条件清单**：找该数据集全部 `<Condition>`（ListCondition/CommonCondition），逐条记 `CNAME`（比什么字段）与比较值来源（写死值/参数/权限门注入）。
3. **列名-值域核对表**：对每条条件做两侧核对——
   - `CNAME` 字段真实存在？（列名拼写/大小写/别名）
   - 比较值的**值域**与该字段一致？（编码 vs 名称、`'1000'` vs `'HWY 北京工厂'`、前导零/全半角/空格）
   - 口诀：**"字段拿一个样，值给另一个样，等于必为假"**。
4. **恒不匹配验证**：取比较值域内一个真实值手工代入条件求值（或临时改条件为恒真）确认"一改就出数"，锁定错配对。
5. **修复与回归**：`CNAME` 改为与值域同侧的字段（本例 `entity` → `entity_code`），修后用原参数组合回扫出数确认。

## 沉淀建议

凡"空白且零报错"，先按悬空数据集查（`check_cpt_integrity.py` 检查1），数据集在再按本方法论查过滤两侧；两步都不中才怀疑计算/父格问题。列名-值域核对表可并入排查清单模板。
