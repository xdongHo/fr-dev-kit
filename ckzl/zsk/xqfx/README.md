## 需求分析流程

```
用户需求(口头/截图/Excel)
    │
    ├─① 报表类型判定
    │   ├─ 只看不改     → 查看报表
    │   ├─ 需要录入     → 填报报表
    │   └─ 批量Excel    → 导入报表
    │
    ├─② 筛选条件提取
    │   ├─ 单选/多选    → ComboCheckBox
    │   ├─ 年份         → YearControl（年份控件，默认值 =now()；勿用 ComboCheckBox 装年份）
    │   ├─ 日期         → DateEditor
    │   └─ 级联关系     → 父→子 SQL 依赖
    │
    ├─③ 字段清单整理
    │   ├─ 表头中文名
    │   ├─ 数据库列名
    │   ├─ 数据类型(文本/数值/日期)
    │   └─ 是否可编辑(填报列 vs 展示列)
    │
    ├─④ 提交逻辑设计
    │   ├─ 插入提交     → InsertConfig
    │   ├─ 智能提交     → IntelliDMLConfig
    │   ├─ 删除+插入    → DeleteConfig + InsertConfig
    │   └─ 隐藏列       → flag 等系统字段
    │
    └─⑤ 交付物清单
        ├─ 查看.cpt
        ├─ 填报.cpt (+ 提交按钮)
        └─ 导入.cpt (+ Import showDialog)
```

## 三种模板类型的决策树

```
用户需要修改数据吗?
    │
    ├─ 否 ──────────────→ 查看(查询)报表
    │                      └─ 只需 Query + Export 按钮
    │
    └─ 是 ──────────────→ 数据量多大?
                              │
                              ├─ 单条/少量录入 → 填报报表
                              │                   └─ TextEditor/NumberEditor + Submit
                              │
                              └─ 批量Excel导入 → 导入报表
                                                   └─ 工具栏 Import + 提交
                                                   └─ 填报表里放 Import 按钮弹窗
```

## 交付产物：模板外部依赖清单（来源 doc-159）


| 依赖类型 | 内容 |
|---------|------|
| 数据连接 | `<Database name="X"/>` 引用的连接名清单（.cpt 不存 JDBC 详情，连接是否存在取决于目标工程） |
| 工程全局参数 | 名称 + 默认值（引用了全局参数的 .cpt 非自包含，不得单独交付） |

## 需求清单补充项（2026-08-08 官方文档持续学习沉淀）

### 交付渠道声明 delivery_channels.json（doc-1481/4068）

需求分析阶段必须确认「模板要交付到哪些渠道」，结构化为 `delivery_channels.json`（与外部依赖清单配对：前者声明模板要去哪儿，后者声明目标环境要准备什么），字段建议：

| 字段 | 含义 | 触发约束示例 |
|------|------|-------------|
| `mobile` | 是否交付移动端(App/H5) | 行式引擎⊥移动端(doc-996)、扩展图表不支持移动端、.xlsx 链路不支持移动端 |
| `schedule_attachment`(+格式) | 是否挂定时调度附件 | 行式引擎需「定时器导出任务支持行式引擎」插件(doc-1481) |
| `excel_sheet_split` | 是否分 Sheet 导出 | `extype=sheet` 需行前分页(doc-3233) |
| `need_xlsx` | 是否要单个 .xlsx | 行式引擎会回退 2003 .xls(doc-1121/1407) |
| `paging_sql` | 是否行式引擎分页 SQL | PageQuery 须与「按页运算分段执行」成对开启(doc-996) |
| `server_timezone` / `business_timezone` | 服务器 JVM 时区 / 业务期望时区(IANA ID) | 不一致且模板含 `TODAY()` 类公式 → ERROR，数据窗口改由调度侧显式传参；**禁止存 int 小时偏移**（无法表达 +5:30 等） |

### 平台用户口径必问项（doc-2188）

凡交付涉及「按用户/角色分权限」「模板里用 `$fine_username` 过滤数据」，需求探查必须问清：**平台用户是「同步用户」还是「导入用户」**？二者互斥——开启同步后平台不能手动新增用户/改密码（只能回源数据集改再同步）、平台用户来源只能是当前那一个数据集、切换同步数据集会清空之前同步的全部用户；导入是一次性操作、可由多个数据集叠加。

### 移动端图表切换的宿主互斥（doc-3274）

需求同时含「不要左右箭头/切换按钮」+「轮播要能从最后一张自动回到第一张」时**无解**：前者只有 FRM 重布局图表组件能做到，而该宿主不支持末→首循环；其余宿主支持循环但箭头恒显示。必须在需求分析阶段二选一，不能做完再发现（= FRM 布局推倒重来）。

## 缺资料→向用户索要清单（人机料法环「人」维度,2026-08-12 落地）

> 原则：**缺料不问=返工**。AI 是项目管理者，资料不齐时按ckzl/zsk/xtgt五级框架（标注>判断>选择>填空>问答）主动索要，
> 不要猜测后开做。索要优先级 = 影响构建顺序的排前面。

| # | 缺什么 | 影响什么 | 怎么问（效率从高到低） | 对应物料/工艺 |
|---|--------|----------|------------------------|---------------|
| 1 | 表名/库名/数据连接 | 数据集无从写 | 判断：先给候选库表清单让用户确认 | NODE-02 / R-010 |
| 2 | 字段清单（中文名/列名/类型/可否编辑） | 单元格构建 | 填空：让用户补 Excel 或贴建表语句 | NODE-01 / NODE-04 |
| 3 | 提交逻辑（插入/智能/删+插） | 填报配置 | 选择：列三种提交方式+推荐理由 | NODE-05 / R-001 |
| 4 | 级联关系（父→子依赖） | 参数面板 SQL | 判断：按业务常识给候选级联让用户确认 | NODE-03 / R-005 |
| 5 | 筛选条件/控件类型 | 参数面板 | 选择：列控件选项（ComboCheckBox/年份/日期）+推荐 | NODE-03 |
| 6 | 样式基线（字体/行高/配色/画布尺寸） | 全局默认格式 | 判断：有 FRM全局默认格式 直接用；没有给默认方案 | M-0042 / R-009 |
| 7 | Excel 样例/参考模板 | 布局参照 | 填空：让用户提供样例文件或 demo 截图 | M-0022 / R-006 |
| 8 | 交付渠道（移动端/定时调度/权限） | 交付物范围 | 判断：按 delivery_channels.json 字段逐项确认 | 需求清单补充项 |
| 9 | 平台用户口径（同步/导入用户） | $fine_username 过滤 | 选择：同步用户 vs 导入用户（互斥,doc-2188） | 需求清单补充项 |
| 10 | 权限要求（按角色/部门） | 权限配置 | 判断：参数驱动(doc-865) vs 声明式(doc-866) vs 平台侧 | 路由表权限行 |

**索要时机**：需求分析阶段（NODE-01）一次问清 1-7；构建中发现的缺口（如字段类型歧义）即时问，不等交付。
**记录**：用户答复沉淀到项目经验 `YYYY-MM/<项目>/` 的需求文档，避免同一问题二次索要。
