# 表单控件插件验收测试单（v2）

← [返回ckzl/zsk/csff](README.md)

> **适用范围**：自研表单控件插件（继承增强型与从零型均适用）。与 `模板验证清单.md`（模板层）互补：本单验收**插件产物本身**，模板清单验收**用控件做出来的模板**。

### 1.4 启动三前置（装载期三坑的静态拦截；来源：11 篇排查实录）

> 背景：目录部署插件 `reload()` 后 `running=false error=false errorCode=0` 的三大根因，全部可在**装进服务器之前**用字节码/文本静态检出。规则速记：**凡直接 implements 接口的类必须对齐 level；凡 extends Abstract*Provider 的不用管；function-recorder 指向入口类且该类必须带注解；jartime 必须是历史日期。**

| # | 检查项 | 方法 / 通过标准 | 等级 |
|---|--------|----------------|------|
| 19a | **@FunctionRecorder 注解核对** | 对 plugin.xml 每个 `<function-recorder class="X">` 指向的类跑 `javap -v -cp <插件jar> X`，输出须含 `RuntimeVisibleAnnotations` 段且出现 `Lcom/fr/plugin/transform/FunctionRecorder;`（注解在 fine-core `com.fr.plugin.transform` 包）。注意指向的应是**入口 Provider 类**而非业务类；ASM 转换器扫不到注解 → 装载抛 `LockOfFunctionRecorder`（内部码 49/对外码 41） | [可脚本]（思路：check_plugin_pkg.py 扩展——javap -v 解析 RuntimeVisibleAnnotations 区块，比对注解类型串；11.0 新式可顺带核 `localeKey` 值在 properties 中存在，即 v1 #7 的加强） |
| 19b | **currentAPILevel 对齐** | 对每个扩展点实现类分两支：`extends Abstract*Provider` → 免检（基类已给默认 level）；直接 `implements XxxProvider` → `javap -c -cp <插件jar>类类` 反汇编 `currentAPILevel()`，取 `iconst/sipush` 指令后的常量值，与接口常量 `javap -constants ...XxxProvider` 的 `CURRENT_API_LEVEL`（如 FormWidgetOptionProvider 等 decision 侧多为 1，chart 侧为 3）比对：**插件值 ≥ 接口值**才放行，低于即 `BelowSystem` | [可脚本]（思路：javap -c 抓 `currentAPILevel` 方法体的 iconst_N/sipush N 字节码立即数；接口侧 javap -constants 抓 CURRENT_API_LEVEL 常量；注意个别接口常量名为 `CURRENT_LEVEL`，两种都试） |
| 19c | **jartime 历史日期断言** | 解析 plugin.xml `<jartime>`，断言 `yyyy-MM-dd` 且 **≤ 部署当天**（未来日期 → 构造期 `JarTimePluginValidator` 抛 `BeyondSystem`；notepad 实坑：误写 2026-08-19）。同时建议 ≤ 引擎发布日（demo 惯例 2018-08-08 这类"老日期"最稳） | [自动]（`datetime.strptime(jartime,'%Y-%m-%d') <= date.today()` 一行；可并入 check_plugin_pkg.py phase2） |

三前置与 v1 #7（function-recorder 类存在性）的关系：#7 只验"类在 jar 里"，19a 深到"注解真的打上了"——自研插件最常见的翻车点正是"类对、注解忘打"。

## 七、可脚本化汇总（一个 `verify_widget_plugin.py` 的骨架）

> 现有 kit 无插件级脚本，不与 `模板验证清单.md` 的 verify 脚本重复——那个吃 .cpt，这个吃插件 zip。思路：

```
输入: 插件 zip 路径
phase1 解包: zip → plugin.xml + jar entries 清单 + 解出 .js/.properties
phase2 plugin.xml: 检查 1-4/9/19c（ElementTree + bytes BOM 检查 + jartime 历史断言）
phase3 一致性: 扩展点 class → jar entries 存在；icon/js 路径存在（#5/19）
phase3b 启动三前置: 19a（javap -v 抓 RuntimeVisibleAnnotations 的 FunctionRecorder）
                  + 19b（javap -c 抓 currentAPILevel 立即数 vs 接口 CURRENT_API_LEVEL 常量）
phase4 xtype 三线: 反编译 getXType（调 fr_plugin_learn/decompile.py）↔
        正则抓 $.shortcut('x') ↔ provider.set('x',...) ↔ BI.shortcut('report.x')
phase5 locale 闭环: 基名文件存在 + getLocText key ⊆ properties keys（#7/8）
phase6 javap 批量: #14-18 逐条 javap 断言方法签名（pwsh 循环，本文 1.3 命令）
phase7 运行时(可选,需活服务器): hot_reload→force_start→running 三态断言（§六 R1-R3）
输出: markdown 报告，pass/fail 逐条 + 需人工项列表（#20 起自动打印成纸质核对单）
```

phase4 是全单性价比最高的一条：**三处 xtype 失配是表单控件插件"不渲染"的第一死因**，且纯字符串比对，零 GUI 依赖。phase3b 则是"装不上/起不来"的第一拦截线——三前置全过仍 running=false 才需要 R4/R5 深挖。
