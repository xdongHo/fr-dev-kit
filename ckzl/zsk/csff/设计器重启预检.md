# 设计器重启预检清单（2026-08-19 晨）

← [返回ckzl/zsk/csff](README.md)

> **背景**：目录部署的 4 个复刻插件（progressring / notepad / maskid / websvc.demo 基座）此前靠 `force_start2.py` 反射 W() 强启。11 篇深夜修正已证实：**`reload()` 不发现新目录，新目录插件的唯一自动入口是启动扫描**——本次重启是它们第一次走"正规装载路径"，四件（尤其 maskid 是纯目录部署从未被扫描过）是否自动 `running=true` 就在此一举。
> 全过 → 复刻插件工程闭环；任何一点不过 → 按 11 篇 §1-§3 排查链走（错误码先换枚举名）。

## 重启后 5 个检查点（顺序执行，2 分钟）

| # | 检查点 | 怎么查 | 预期结果 |
|---|--------|--------|---------|
| 1 | **4 插件在列且运行** | 设计器 帮助→插件管理（或服务器 管理系统→插件管理），找 progressring / notepad / maskid / demo 四项 | 4 项全部在列、状态"已启用"（不再是仅目录存在） |
| 2 | **progressring 图表类型出现** | 新建 .cpt → 图表工具箱/插入图表向导，翻图表类型列表 | 出现「进度环」（ProgressRingProvider 注册成功的 GUI 证据；四注入面 chart/chart-designer/report/core 同时生效的最终判据） |
| 3 | **maskid 公式提示** | 任意单元格输入 `=MASKID(`（或设计的函数名，见 DESIGN.md） | 公式编辑器出现参数提示/函数名自动补全（FunctionManager.addFunctionDef 通道在正规启动路径下生效） |
| 4 | **notepad 管理页 console** | 打开 notepad 管理页（decision 侧路由），F12 看 Console | 页面正常加载，console 有预期的初始化日志（WebResourceProvider 注入的 js 执行了）；无红色报错 |
| 5 | **日志无 error 行** | 看 `FineReport_10.0\logs\` 下最新日志文件（catalina/fine 两者都扫），重点搜插件 id 与 "error\|Exception" | 4 个插件 id 附近无 ERROR 级行（启动扫描 Z()=G.M() 期间无装载异常/类冲突） |

## 任一点失败的快速分诊

- **#1 不过**（不在列）：plugin.xml 五要素/目录名笔误 → 跑 `check_plugin_pkg.py` 静态校验；在列但"未启用"→ active=yes 检查。
- **#2/#3/#4 不过**（在列但功能缺）：插件在列≠running——用 fr-agent /exec 跑 `force_start2.py` 同款探针看 o/p/funcRecorderVerified 三布尔；再按 19a/19b/19c 三前置（注解/level/jartime）逐项 javap 复核。
- **#5 有 error**：抄下异常枚举 name()（别看数字码，内部码≠对外码），对照 11 篇 §3 三坑直取。

## 顺手补两项（GUI 在跟前，一次做完）

- [ ] progressring 画布往返：拖一个进度环进 .cpt → 保存 → 重开，图表仍在、配置保留（模板序列化冒烟）
- [ ] notepad REST：带 admin 登录态访问 `/decision/v10/notepad/list`，应返回 JSON（401/数据皆可，不再是无认证的登录页 HTML——11 篇遗留待验项）
