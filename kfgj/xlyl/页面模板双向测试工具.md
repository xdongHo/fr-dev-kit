# 页面↔模板双向自动化测试工具

> 解决设计时"对页面展示效果不清楚"的问题：模板⇄页面双向通道 + 一一匹配核对。
> 问题清单对已命中率：**模板不可用/损坏**（exit 2 直接证据）、**布局/参数面板**（round-trip 逐格核对）。

## 布局设计自辅助（设计→自检→调整闭环）

本工具链可直接作为 **agent 设计布局时的自辅助回路**（已实测有效）：

1. **生成**：按设计目标写模板（骨架/组件，行列用 FU=px×38100，字号 FRSize=pt×8，见 单位换算实证.md）
2. **看真实效果**：`python kfgj/xlyl\tpl2page.py <模板> --open` → 秒级得到真实比例页面
   （列宽/行高来自引擎真实值；图表区大小=设计器所见比例，不再压扁）
3. **机器自检**：round-trip T1-T9（保真核对）+ **L1-L4 布局合理性断言**（layout_check.py，已并入 page2tpl 报告）：
   - **L1 意外重叠**：控件两两相交（自动识别**层叠卡片组**=Tab/条件显示合法叠放、**浮钮**=FreeButton 悬浮豁免，
     其余才是坏味候选）— 实测：真实驾驶舱 627 处原始相交 → 聚合后 1 合法层叠组 + **0 意外重叠**
   - **L2 越界/负坐标**：超出 8000px 画域或坐标为负
   - **L3 零尺寸/极小**：w/h≤0（FAIL 不可见）；<4px（WARN）
   - **L4 图表区过小**：按真实 colW/rowH 求和，<120×90px WARN（用户实测发现的"图表太小"类问题，机器可判）
4. **调整**：按 WARN/FAIL 改模板 → 回到 2（秒级迭代）

> 判定阈值全部可调（layout_check.py 顶部常量，注明单位来源）。guard `--roundtrip`（G12）自动携带 L 断言。

## 双向架构

```
           ┌───────────── A: page2tpl (逆向+核对) ─────────────┐
页面URL ──►│ viewlet→模板 → 真引擎渲染(agent,免登录) → 渲染JSON  │
           │   → 逆向cpt(内嵌数据集=页面数据,布局逐格还原)        │
           │   → 逆向模板再渲染 → round-trip T1-T5 一一核对      │──► 差异=问题猎物
           └────────────────────────────────────────────────────┘
           ┌───────────── B: tpl2page (快速页面) ───────────────┐
模板 ──────► 真引擎渲染 → 渲染JSON → json_page.py → 高保真HTML   │──► 设计迭代秒级看效果
           └────────────────────────────────────────────────────┘
```

## A: page2tpl.py — 页面→模板逆向 + round-trip

```bash
# 三种输入(页面URL / viewlet相对路径 / 文件绝对路径)
python kfgj/xlyl\page2tpl.py "http://localhost:8075/webroot/decision/view/report?viewlet=示例报表工程/.../示例预算表.cpt"
python kfgj/xlyl\page2tpl.py "ckzl/hbfa\组件模板\图表组件-柱形.cpt"
python kfgj/xlyl\page2tpl.py "C:\...\示例预算表.cpt" --skip-orig-render   # 复用已有 orig.json
```

**流程**：原模板真引擎渲染（复用 injected 通道，免登录免浏览器）→ 逆向构建 cpt
（非空格→静态文本单元格，坐标/跨度/值逐格还原；图表格→`[图表 类名]` 占位标记；
每 sheet 内嵌数据集 `page_data_N` = 该页展示数据宽表；manifest 参数→TextEditor 参数面板）
→ 逆向模板再渲染 → 一一核对。

**round-trip 断言（cpt T1-T5/T9 + L / frm T6-T8 + L）**：
| 规则 | 内容 | 猎物 |
|------|------|------|
| T1 | 非空格规模 | 数据格丢失 |
| T2 | 坐标一一命中（含合并位置） | 布局错位/单元格丢失 |
| T3 | 值逐一精确相等 | 文本/数据渲染错误 |
| T4 | 图表格↔占位标记互认 | 图表静默不渲染 |
| T5 | sheet 数 | sheet 丢失 |
| **T9** | **参数面板布局**（控件名→x,y,w,h 逐件相等 + 控件数；原类保真重建 ComboBox/DateEditor 等 8 类） | **参数面板布局错位/控件丢失/控件降级** |
| T6 | frm 控件坐标逐件相等（按名 x,y,w,h） | **参数面板/组件布局错位** |
| T7 | frm 叶子控件数 | 控件丢失 |
| T8 | frm 类保真率（8 种编辑器原类重建） | 控件类型错乱 |
| **L1-L4** | **布局合理性**（意外重叠[层叠组/浮钮自动豁免]/越界/零尺寸/图表区过小）— layout_check.py，在原模板渲染产物上跑 | **布局坏味自动检出**（真实模板 627 处原始相交→0 意外重叠实证）|

**退出码**：0 全过 / 2 原模板不可渲染（**损坏模板直接证据**）/ 3 逆向器缺陷。

**frm 逆向**（v1.1）：渲染组件树 → 每叶子控件按**原坐标**重建到绝对画布；8 种已知控件
（TextEditor/ComboBox/DateEditor/NumberEditor/ComboCheckBox/TreeComboBoxEditor/FreeButton/Label）
**原类保真重建**；未知/插件/降级类（RHIframe/WidgetErrorMarker/Chart…）→ Label 占位标注原类
（结构扁平化、几何保真——这是参数面板布局核对的载体）。自适应 frm 无坐标时合成纵排（报告注明）。
实测：FR绝对骨架 12 件（8 保真+4 占位）坐标 1:1；**41/41 frm 样本全过**。

**cpt 参数面板**（v1.2）：渲染器从 `getReportParameterAttr().getParameterUI().getParaContainer()`
walk 参数控件树（含坐标）；逆向按**原控件类 + 原 BoundsAttr 坐标**重建参数面板（已知 8 类保真，
未知→Label 占位）；T9 逐件核对。json_page 在表格上方画参数面板条（红色警示块同样适用）。
无渲染参数数据时降级 manifest 参数名→TextEditor（合成坐标，报告注明）。

## B: tpl2page — 一键页面（HTML+PDF+JSON）

```bash
python kfgj/xlyl\tpl2page.py <模板.cpt/.frm> [--open] [--no-pdf]
```
一条命令：真引擎渲染 JSON → json_page 高保真 HTML（cpt 表格网格/frm 绝对画布/降级红色警示）
→ 真引擎 PDF（cpt；图表/样式完整绘制）。`--open` 完成即看页面。

## guard G12 整合

```bash
python kfgj/guard.py --task format --cpt <模板> --attest G10 --no-backup --roundtrip   # 最强通道
python kfgj/guard.py --task format --cpt <模板> --attest G10 --no-backup --render      # 仅渲染
```
`--roundtrip`：G12 走 page2tpl 一一核对——0→PASS；模板不可渲染→**FAIL『模板不可用/损坏』**
（问题清单第一类的机器可读证据）；agent/设计器不可达→WARN 回退人工。

## 快速迭代闭环（示例）

```bash
# 1. 改模板后快速看页面
python kfgj/xlyl\render_check.py <模板.cpt> --backend injected --html-dir kfgj/xlyl\out
python kfgj/xlyl\json_page.py kfgj/xlyl\out\<名>.json kfgj/xlyl\out\<名>_page.html

# 2. 疑难页面逆向核对(给URL即可)
python kfgj/xlyl\page2tpl.py "<页面URL>"   # 出 roundtrip.md 报告
```

## 坐标一致性验证（渲染位置 vs 设计器原生位置）

| 布局形态 | 一致性 | 说明 |
|---|---|---|
| **绝对布局 frm** | ✅ **1:1 完全一致** | 渲染 bounds == XML BoundsAttr（设计器编辑所见坐标），FR绝对骨架 12/12 实证 |
| **自适应布局 frm**（如 YFI 驾驶舱 dashboard.frm 62 件） | ✅ **与设计器显示一致** | x/宽/高全部一致；y 为**引擎计算的堆叠绝对坐标**（34→127→221→…→2309），XML 里的 y 是容器局部值（多为 0）。设计器画布/浏览器预览显示的正是计算后位置，故渲染侧=设计器所见。29/62 件为此类 y 偏移，均正常 |
| 参数编辑器高度 | ⚠️ 1 例外 | p_role_name h:21→31——引擎对编辑器套用标准控件高度（FR 常态行为），核对时按 WARN 级 |

> 结论：**绝对布局逐像素一致；自适应布局 y 是"计算后的真实页面位置"（比 XML 原值更接近设计器所见）**。
> 验证脚本：`kfgj/xlyl/_cmp_bounds.py`（XML BoundsAttr vs 渲染 bounds 逐件比对）。
> 单位体系（FU/FRSize/px）实证表：`kfgj/xlyl/单位换算实证.md`（字号 size=pt×8，72=9pt 默认）。

## 边界（诚实声明）

1. 图表**内部配置**不在渲染产物中——cpt 图表格/frm 图表件逆向为占位标记（T4 互认）；图表数据系列逆向属 v2。
2. 单元格**样式**（字体/颜色/边框细节）当前未逆向（值级核对；样式断言属 Layer 5）。
3. frm 逆向为**几何保真**（坐标/数量/已知类逐件 1:1），布局容器结构扁平化到一个绝对画布；参数控件默认值/数据绑定不还原（cpt 参数面板布局/控件类已保真，默认值与数据字典不还原）。
4. 自适应 frm（无坐标渲染）→ 合成纵排坐标（报告注明"非原始布局"），核对价值=可用性+数量。
5. DB 模板需 FR10 设计器运行（平台加载 FineDB 连接）；内嵌数据模板任何设计器 JVM 皆可。
6. 远端服务器页面：URL 需本机 reportlets 可及（viewlet 解析）；否则先把模板拷到本机。
