# FR 单位体系实证（活 JVM 内用 FR 自身 API 验证）

> 方法：注入 FR10 设计器 JVM（fr-agent /exec），调 `com.fr.stable.unit.FU` 与
> `com.fr.general.FRFont` 的官方换算方法读真实返回值——非文档推测，全部实测。
> 验证日期：2026-08-22。**FR10 + FR11 双版本实证一致**（FR11 复验：shutdown FR10 agent
> 释放 18999/19000 后 attach FR11 PID 424，同常数同字号表；frm 像素坐标 FR11 渲染
> vs XML 8/8 一致）。
> ⚠ 复验操作坑：双设计器并跑时 agent 端口只归一个 JVM——ping 返回的 PID 才是当前
> 响应者，attach 成功 ≠ 端口已易主，必须先 shutdown 旧 agent。

## 一、长度单位 FU（FineReport Unit）

RowHeight / ColumnWidth 的 CDATA 值、PaperSetting 等全部以 FU 存储。

**换算常数（FU.getInstance(v) → toMM/toPT/toINCH/toPixD(96) 实测）：**

| 换算 | 数值 | 验证 |
|---|---|---|
| **1 px @96dpi** | **38100 FU** | `valueOfPix(5,96)=190500FU` 与 `190500FU.toPixD(96)=5.0` 双向闭环 |
| **1 pt** | **50800 FU** | 914400FU=18pt=0.25in ✓ |
| **1 mm** | **144000 FU** | 2743200FU=19.05mm ✓ |
| 1 inch | 3657600 FU | 914400FU=0.25in ✓ |

**已知值对照（全部运行时读出）：**

| 存储值 | 换算结果 | 是什么 |
|---|---|---|
| 2743200 | 54pt = 19.05mm = **72px** | 默认列宽（设计器默认 72px ✓）|
| 1153643 | 22.7pt = 8.01mm ≈ **30.28px** | 默认行高（设计器显示≈30px）|
| 190500 | 3.75pt = **5px** | 骨架 5px 细格（gen_skeletons 按 38100/px 写入 ✓）|
| 38100 | 0.75pt = **1px** | 最小换算基准 |

设计器 UI 的 mm/px 显示 = FU 除以上表常数；**设计器切换单位只改显示，不改存储**。

## 二、字号单位 FRSize（FRFont 的 size 属性）

XML 里 `<FRFont size="72">` 的 72 不是 pt。**FRSize = pt × 8**。

`FRFont.getInstanceFromFRSize(name, style, frSize).getSize2D()` 实测：

| XML size | 实际字号 | 场景 |
|---|---|---|
| **72** | **9pt** | FR 默认正文字号（模板里最常见的 72 = 默认 9pt！）|
| 80 | 10pt | 骨架标题 |
| 88 | 11pt | dashboard 正文（微软雅黑/Verdana 88 ×165 处）|
| 96 | 12pt | dashboard 标题 |
| 128 | 16pt | dashboard 大标题 |
| 432 | 54pt | （反例警示：异常大值，见于个别未应用样式分支）|

> 附注：`FRFont.getInstance(name, style, float)` 传**真 pt**；`getInstanceFromFRSize` 传 XML 整数。
> 生成模板写字号时：**目标pt × 8**（写 9pt → size="72"，写 12pt → size="96"）。

## 三、frm 组件坐标 BoundsAttr

`<BoundsAttr x="107" y="69" width="160" height="80"/>` = **像素直存**（非 FU）。
设计器画布坐标、浏览器预览坐标、`getBounds()` 返回值三者同一套 px（FR绝对骨架
1024×720 画布与设计器显示一致实证；渲染 bounds 逐件比对见 页面模板双向测试工具.md）。

## 五、验证脚本要点（可复跑）

- FU：`FU.getInstance(long)` → `toMMValue4Scale2/toPTValue4Scale2/toPixD(96)`；反向 `valueOfPix(px, 96)`
- 字号：`FRFont.getInstanceFromFRSize(String,int,int).getSize2D()`
- 真模板交叉验证：cpt 单元格 `cell.getStyle().getFRFont().getSize2D()`（注意：样式未应用时回落默认宋体9pt，勿把默认值当模板字号）

## 五附、样式悬空缺陷（2026-08-22 修复闭环）

**现象**：仓库 cpt 骨架 XML 声明了 StyleList 字号（80/72），但引擎渲染回落默认宋体 9pt。

**根因（不是引擎，也不是现版代码）**：存量 `ckzl/hbfa\cpt骨架\*.cpt` 是**旧版 gen_skeletons
产物**——StyleList 注入静默失败，产物为空 `<StyleList></StyleList>` + 单元格 `s="0"`
**悬空引用** → 引擎按设计回落默认字体。`frm_title_block`（内联样式路径）是死代码，frm 无此缺陷。

**修复四件套**：
1. 全量重生成（现代码注入正确：`<C ... s="0">` → StyleList[0]=微软雅黑 bold 10pt 白字）
2. 活 JVM 端到端验证：模板态+渲染态（execute 后）均读到微软雅黑 Bold 10pt fg=white ✅
3. 永绝机制：gen_skeletons 生成后自检——`s=` 引用最大值必须 < StyleList 样式数，悬空即 AssertionError
4. 样式感知层：injected_render.js 每 sheet 提取实际应用字体直方图（`fonts` 字段）——悬空/未应用样式在渲染 JSON 直接现形
