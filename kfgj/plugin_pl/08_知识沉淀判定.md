# 工作流中的知识沉淀判定 v1.0

> 对应交付要求："工作流中增加思考沉淀知识的判定，对于工作节点的扩展，工作节点知识的增改优化，范例"。
> 本机制衔接 AGENTS.md STEP 6（实践→知识回路）与 EXEC_CONTRACT P5（台账回写建议），是 SN-12 的知识部分细则。

---

## 1. 触发判定：每个工作节点收尾时强制过一遍（30 秒）

> 规则：**每个标准节点执行完（或每次开发会话收尾），必须回答判定表并留一行结论**——答"无"也要写"定性：无新知识"。这是 EXEC_CONTRACT v1 教训（自然语言会被跳过）在本机制里的对冲：结论落进 todo.md/动作日志，收尾闸门核对此行存在。

| # | 判定问题 | 是 → 动作 |
|---|---|---|
| Q1 | 本节点遇到了**新问题→修正**对（旧台账/知识库没有）？ | 先入台账（§2），再按 Q5 决定是否进节点知识 |
| Q2 | 本节点**实证了新 API/协议行为**（javap/实测确认的签名、协议字段、平台约束）？ | 写进对应 SN 文档"实测依据"栏或 `ckzl/zsk/gczsk`（对齐 AGENTS.md 知识回路"单一事实源固化"） |
| Q3 | 产出了**可复用工具/脚本**（≥2 个场景用得上）？ | 落 `kfgj/fzpy/` 或本流水线 `scripts/`，AGENTS.md 路由表补指针 |
| Q4 | 发现**既有知识/节点文档有错或过期**？ | 台账加"纠错"行 → 直接修正该 SN 文档 → 版本 bump（§3） |
| Q5 | 该问题**可能在任何插件复发**（而非本项目特有）？ | 是 → 绑定标准节点检查项（§3）；否 → 只进项目经验 |
| Q6 | 都不是？ | 写一行"定性：无新知识"收工 |

**判定纪律**：宁可错收（MITIGATED 后可降级），不可漏收——漏收就是下一个复发链的种子（P01-P08 全是漏收的产物）。

## 2. 台账行生命周期（问题的知识化）

```
新问题 → 入台账（02_复盘问题台账.md 新行：现象/出处/根因类/拦截节点/机制）→ 状态 OPEN
  → 对应标准节点补检查项（§3）→ 状态 MITIGATED（有拦截物，未实战验证）
  → 连续 2 个新插件零复发 → 状态 CLOSED（检查项保留，台账归档段）
  → 任何一次复发 → 回 OPEN，并复盘"节点为什么没拦住"→ 修补节点 → 再 MITIGATED
```

- 状态晋级由**实跑数据**驱动（下一个插件的首跑记录），不由"感觉不会再犯"驱动。

## 3. 工作节点知识的增改优化（SN 文档的变更规程）

**谁能改**：任何 agent 在实战中发现缺口即可提案修改；**怎么改**按下述五步：

1. **查台账**：先确认该知识没被已有行覆盖（避免同一坑两行）。
2. **入台账**：新行或旧行加复发记录（版本/日期/出处到章节）。
3. **绑节点**：把台账行的"拦截节点"列指向 SN 文档；在该 SN 文档的检查清单加一条**可执行**的检查项（写法对齐现有条目：判定标准+出处编号），机器可查的尽量给 sn_gate 增检查项（C 编号续排）。
4. **版本 bump**：SN 文档头部 KB_INDEX `summary` 若变→同步；`07_干跑校验报告.md` §5 修订记录追加一行（版本/日期/变更摘要/触发的台账 ID）。
5. **同步索引**：`jcxt/data/_kb_index.yaml` 增量重建（`python jcxt/js\build_vector_index.py`）＋可选 `项目经验回写（~/.fr_dev_kit/experience/，个人版 evolve_kb 已移除）` 写使用备注（对齐 AGENTS.md §1.7.2）。

**红线**：
- 禁止"只改聊天记录/只改项目经验"不进台账——那等于没沉淀（复发链的根因）。
- 禁止把检查项写成不可判定的形容词（"注意性能"❌ → "冷缓存计算>600s 时必须走异步通道（P/demo_plugin_repo §8.6）"✔）。
- 节点文档保持自包含懒加载（B1）：改完仍应能单独读。

## 4. 范例

### 范例 1｜单插件坑 → 节点检查项（P14 的完整走线）

- **现象**：demo_plugin_repo 挂载树实体报表丢失预览入口（zTree 节点 isParent=true 被早退跳过，README §4.9）。
- **判定**：Q1 是（新问题）→ Q5 是（"单一布尔早退"是通用反模式，任何插件的树/列表判定都会遇到）。
- **入台账**：B 段 P14 行（根因类=单一布尔判据早退；拦截节点=SN-02;SN-08）。
- **绑节点**：SN-02 §2.3 加红线"判定逻辑禁单一布尔早退"；SN-08 §8.2 加 FineUI 判据项（isParent 早退/addDiyDom 注入口径）。
- **版本**：本次 v1.0 干跑后修订记录即含此项（07 报告 §5）。
- **验证**：映射核对 P14→SN-02/SN-08 双命中（07 报告 §3）。

### 范例 2｜复发坑升级为机器闸门（P04 的完整走线）

- **现象**：demo_plugin_repo 资源路径点杠混改 22 处损坏+RequestMapping 漏改（KNOWLEDGE §9/§10）；aicopilot `getResourceAsStream("/...")` 前导斜杠 9 帧全 null（v0.14.4）。
- **判定**：Q1 是且 Q4 部分（原知识散在两份文档无总表）→ 按 P04 复发链处理。
- **绑节点**：SN-03 建"资源路径形式总表"（唯一权威表，含 5 行正反例）；sn_gate 增加 C05（前导斜杠 grep）、C06（ScriptPath 形式）两个**机器检查项**——从"清单提醒"升级为"闸门强制"。
- **干跑实证**：aicopilot 实跑 C05 PASS（确认 v0.14.4 修复未回退）、负例注入前导斜杠立刻 FAIL（07 报告 §1）。
- **效果**：此类问题从"两个插件各踩一次"变为"收尾一条命令必拦"。
