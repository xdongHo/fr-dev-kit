# SN-10 生成物断言与目标环境实测（S4 自测）

**类型**：标准节点（确定性，attest 型）｜**拦截**：P07 复发链（demo_plugin_repo pgMar 嵌套 / aicopilot 透明窗全白）、P12 四处对齐、P22(半) Swing 视觉
**输入**：本插件生成的产物清单（XML/文档/图像/UI）｜**输出**：断言记录 + 目标环境实测留痕

## 检查清单

### 10.1 结构断言（机器可跑）

- [ ] 生成 XML：**良构校验（ET.parse）+ 关键结构 contains 断言 + 嵌套层级断言**（父子关系显式断言，如 DSColumn 必在 Cell 内——aicopilot CptGenerator 基准）
- [ ] 结构断言对照**真实样本**（抄真实 reportlets 文件，三份样本交叉；aicopilot"模板结构抄自真实文件"为基准）
- [ ] 有条件时用**独立第二实现交叉验证**（demo_plugin_repo 正面案例：CptGenerator 产物用 Python ElementTree 再验一遍）
- [ ] 二进制产物过**魔数校验**（xlsx=PK、pdf=%PDF、zip=PK\x03\x04；对齐 kit `export_gate.py` 思路）
- [ ] 多处写同一值（P12：tblW/tblLayout/tblGrid/tcW 同一组 twips；类比 cpt 的 RowHeight/ColumnWidth/StyleList 索引）→ 断言四处一致，单一来源拼接为上策

### 10.2 目标环境实测（attest，P07 灵魂条款）

- [ ] **"代码正确"≠"合成正确"**：凡视觉/格式产物，必须在**目标环境**验证，不能只信开发机单一客户端：
  - Word/PDF：至少两个客户端打开核对（Word+**WPS**；Word 静默修复策略随版本不同——demo_plugin_repo pgMar 事故：本地 COM 正常、用户端纸张回纵向）
  - PDF 验证技巧：SimHei 子集无法字节搜索 → 用文件大小差异 + DOCX 明文 + MD/HTML 文本三路验证（demo_plugin_repo 实战）
  - Swing/透明窗：**截屏+像素采样**（aicopilot v0.13.4：100 采样点 90 纯白才实锤"全白不可见"）
- [ ] 生成 XML 前先解开断言**结构本身**：XmlCursor `toEndToken()` 是"元素内容末尾"不是"元素之后"——插兄弟元素用 `toNextToken()`（demo_plugin_repo pgMar 教训的机制级总结）
- [ ] attest 格式：收尾报告写 `--attest SN-10 <产物> <验证环境列表> <日期>`

## 反例

- P07：两个插件用不同技术（iText XML 结构 / AWT 窗口合成）踩了**同一哲学坑**——验证只做到"我机器上看着对"。目标环境实测是这类问题的唯一解，且必须 attest 留痕防跳过。
