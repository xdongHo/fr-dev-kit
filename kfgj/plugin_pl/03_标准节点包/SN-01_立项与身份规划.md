# SN-01 立项与身份规划（S1 需求）

**类型**：标准节点（确定性）｜**拦截**：P09 双插件命名空间冲突、P23 范围失控（远程分支建后全删）
**输入**：需求口述/工单｜**输出**：身份表 + 范围卡（用户在 D1 确认）

## 检查清单（全部勾完才准进 S2）

- [ ] **身份表五项已填且全库唯一**（对照 `C:\baidunetdiskdownload\FR_plugin\packages` 官方库与两款既有插件）：
  - 插件 ID（点形式，如 `com.fr.plugin.<名字>`）：
  - Java 包名（与 ID 一致的层级，如 `com.fr.plugin.<名字>` 或独立包）：
  - HTTP 路径族（HttpHandler 单段路径 + Spring 前缀，如 `/demo_plugin_repo*`、`/url/demo_plugin_repo`）：
  - 菜单节点 id（如 `decision-management-plugin-<名字>`）与前端 shortcut value：
  - 配置/数据目录（如 `~/.<名字>/`）
- [ ] **五个 ID 互相同源可 grep**（改名时一处规则可覆盖五处；参照 demo_plugin_repo 改名口诀 `grep -rn "com[./]fr[./]plugin[./]<名>[^p]" src plugin.xml`）
- [ ] **范围卡含"不做"清单**（P23 教训：示例插件A v0.13.0-0.13.7 建了远程设计器通道，v0.14.0 整体移除——"将来可能要"不是需求）：
  - 本期不做：＿＿＿（如：远程设计器 / 子代理 / 任意 Java 执行）
  - 明确边界（参照 aicopilot v0.10.0"明确不裁"写法：哪些在 harness 内、哪些明确排除）
- [ ] **单进程优先默认**（跨进程/独立进程必须在 D1 由用户拍板，禁止默认引入第二个 JVM——P08/P23 双重教训）
- [ ] 商业档位/授权体系是否要做 → 用户拍板（demo_plugin_repo 做了 LicenseService+GuardFilter，属重投入项）
- [ ] 需求确认记录落盘（一页纸即可，放工程根 `docs/需求卡.md`）
