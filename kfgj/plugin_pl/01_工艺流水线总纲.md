# 插件开发工艺流水线总纲 v1.1

> **适用范围**：fr_dev_kit 体系内的 FineReport 自研插件（Java + plugin.xml + FineUI/前端资源），含设计器插件与决策平台插件。
> **不适用**：报表模板开发（走 `ckzl/gzjd/NODE-01~10`）、纯 Python 工具（走 ckzl/lc/08 选型）。
> **两个来源插件**：归档盘点专业版 `com.fr.plugin.demo_plugin_repo`（v1.0→v2.1.8，九轮迭代）＋ 示例插件A `com.fr.plugin.aicopilot`（v0.3→v0.17.x，40+ 轮迭代）。
> **核心立场**：检查清单只解决"知不知道"，**闸门才解决"做不做"**。每个确定性节点都配机器检查或 attest 留痕，与 kit 的 kfgj/guard.py 同一哲学。

### 1.3 复盘核心结论（台账 §A 摘要）

- **8 类问题跨插件复发**（P01-P08）：浏览器路径无实测、键归一化两端不一致、PowerShell 陷阱、FR 资源路径形式、版本不同步、清理破坏运行资产、生成物只信单一客户端、生命周期状态失效。
- **复发≠没写教训**：P01 的浏览器路径待办在 2026-08-26 复核文档里白纸黑字，三天后照样复发——**教训没有执行点 = 没有教训**。
- 因此流水线的每个确定性节点都有三类拦截物之一：**机器检查**（sn_gate 可跑）、**清单强制项**（勾选+留痕）、**attest 声明**（过程闸门，声明即留痕）。

## 6. 与 kfgj/guard.py 的关系（建议，不代改）

本流水线自带 `sn_gate.py` 独立可跑（无 kfgj/guard.py 依赖）。`05_AGENTS修订建议_v1.0.md` 建议将 `--task plugin` 收进 kfgj/guard.py（P 闸门引用 SN 编号），合并与否由用户确认。在合并之前，插件任务的收尾命令约定为：

```
python kfgj/plugin_pl\scripts\sn_gate.py --config <工程>\sn_gate.config.json --report <工程>\_runs\sn_gate_report.md
```

退出码 0=通过 / 1=有 FAIL / 2=仅 WARN，与 fr_check/guard 同口径；非 0 = 任务未完成。

## 8. 复刻实践模式（v1.1 新增）

> 用复刻既有插件的方式做流水线实战走线（2026-09-15 首跑：5 路并行 agent 复刻 demo_plugin_repo v2.1.12 全量 46 类，集成编译 0 错、ProUnitTest 78/78）。复刻粒度规则固化为四条：
>
> 1. **类/方法签名与公共契约 100% 复刻**（编译器强制）；
> 2. **核心确定性逻辑**（解析/扫描/归一化/门控/配置持久化/端点契约）完整实现；
> 3. **重型可视化排版细节**允许精简实现＋注释标注参考实现行号与行为差异；
> 4. **任何偏离必须进问题清单**（现象/根因/对策/映射 SN 或新节点候选）。
>
> 实践产出：新台账 P27-P37（台账 D 段）、sn_gate v1.1（C06 修复+C13 新增）、七份 SN 文档增补、复刻件与完整证据见 `..\kfgj/plugin_pl/flks\`。
