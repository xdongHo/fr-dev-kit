```
#### 流程 P：插件开发（自研插件）

0. 定档：新建/新功能模块=全流程；小修（1-2 文件）=SN-06+SN-08+SN-12 最小环
1. 读 kfgj/plugin_pl/01_工艺流水线总纲.md（七阶段+节点规格）
2. 新插件：先跑 kfgj/plugin_pl/scripts/sn_scaffold.py 出骨架（SN-03）
3. 按阶段走标准节点（03_标准节点包/SN-01~12），每个节点的机器检查项由 sn_gate.py 代跑
4. 人工决策点 D1-D5 见总纲 §4（范围/架构/UI 验收/发布窗口/归档范围）
5. 收尾：python kfgj/plugin_pl\scripts\sn_gate.py --config <工程>\sn_gate.config.json（退出码 0 才算完成）
6. 新问题 → 先入 kfgj/plugin_pl/02_复盘问题台账（单一事实源），再按 08_知识沉淀判定.md 落知识库
```

## 增量 4｜kfgj/EXEC_CONTRACT.md 建议：kfgj/guard.py 增加 `--task plugin`

> 这是**建议**：需另起小任务改 kfgj/guard.py 代码（本流水线不代改）。P 闸门设计如下，与 G01-G12 同构：

| 闸门 | 标题 | 类型 | 判定 | 对应节点 |
|---|---|---|---|---|
| P1 | plugin.xml 四道门+扩展点 class 存在 | 自动·硬 | sn_gate C01-C04 全 PASS | SN-03 |
| P2 | 资源/URL 路径形式合规 | 自动·硬 | sn_gate C05/C06/C09 PASS | SN-03/SN-04 |
| P3 | 版本多处一致 | 自动·硬 | sn_gate C07 PASS | SN-11 |
| P4 | 浏览器路径实测 + 目标环境实测 | 声明·硬 | `--attest P4`（含 G-BROWSER 与 SN-10 证据指针） | SN-08/SN-10 |
| P5 | 台账回写 | 声明·硬 | `--attest P5`（新问题已入台账/旧问题状态更新） | SN-12 |

合并后插件任务收尾命令统一为 `python kfgj/guard.py --task plugin --attest P4,P5`（内部调 sn_gate）。
