# pipeline_v1 — 插件开发工艺流水线 v1.1

> **一句话**：把归档盘点专业版（demo_plugin_repo）和示例插件A（demo_copilot）两款插件踩过的坑，固化成 7 个阶段、12 个标准节点、1 台机器闸门，让同类问题不再第二次发生。
>
> **版本**：v1.1（2026-09-15，复刻实践修订；v1.0 2026-09-14）｜**来源插件**：`com.fr.plugin.demo_plugin_repo`（文档快照）、`com.fr.plugin.aicopilot`（本机源码）

---

## 0. 为什么要有这套流水线（30 秒版）


根因不是"没写教训"，而是 **教训只存在于自然语言文档里，没有绑定到任何强制执行点**。这正是 kit 现行 `kfgj/EXEC_CONTRACT.md` v1→v2 已经验证过的教训（v1 的 1000+ 处"必须/禁止"频繁被跳过，v2 收敛为 kfgj/guard.py 硬闸门）。报表任务有 G01-G12，**插件任务没有任何闸门**——本流水线补的就是这一层。

## 2. 阅读顺序

- **要开新插件**：`01_工艺流水线总纲.md` → `06_交接使用手册.md`（按手册走线，节点文档按需读）。
- **想知道为什么会复发**：复盘中复发链分析（台账原件已迁出，方法见 SN-12）。
- **要接闸门进 CI/收尾**：`scripts\sn_gate.py --help` + `03_标准节点包\SN-12`。
- **要合并进 AGENTS.md**：先读 `05_AGENTS修订建议_v1.0.md`，确认后由用户另行执行合并（本目录不代改）。

## 3. 与 kit 现行机制的关系

- 遵守而不替代：本流水线沿用 AGENTS.md 的 STEP 0 定档、铁律指针、知识回路（STEP 6）、侧车文档纪律（§7）；插件任务在这些通用机制之上叠加插件专属节点。
- 机器闸门对齐 kit 惯例：退出码 0=通过 / 1=有 FAIL / 2=仅 WARN，与 `fr_check.py`/`kfgj/guard.py` 同一口径。
- `05_AGENTS修订建议_v1.0.md` 提出 `kfgj/guard.py --task plugin` 增补建议（引用本目录），**是否合并由用户确认后另行执行**。
