# 交接使用手册——下一个插件首跑指南 v1.0

> 面向对象：下一个接手插件开发的 agent（或人机协作对）。按顺序执行，不要跳步。
> 全程参照物：`01_工艺流水线总纲.md`（规格）＋ `03_标准节点包\`（操作细节）＋ 复盘台账（开源版沉淀于用户目录 experience/，原件已迁出）。

---

## 第 0 步：开工前 10 分钟（CP0 检查点）

1. 读 `00_README.md`（本目录索引与回滚方式）——**必读**。
2. 读 `01_工艺流水线总纲.md` §1（经验基线）+ §2（七阶段总图）。
3. 定档（AGENTS.md STEP 0 口径）：新建插件=全 12 节点；既有插件小修=SN-06+SN-08+SN-12 最小环，裁剪决定写进 todo.md 首行。
4. 确认工具可用：`python kfgj/plugin_pl\scripts\sn_gate.py --help` 能跑通。

## 第 1 步：需求（S1）→ CP1

1. 用 `scripts\sn_scaffold.py` 前先填需求卡草稿（不必先建工程）。
2. 走 `SN-01`：身份表五项（全库查重，参照 packages 官方库与两款既有插件）＋范围卡含"不做"清单。
3. **用户拍板 D1**：范围（单进程默认/远程不做）＋商业档位做不做。
4. CP1 通过标准：需求卡落盘且 D1 有用户确认记录。

## 第 2 步：设计（S2）→ CP2

1. 走 `SN-02`：生命周期矩阵三行填齐（重启/重载/独立进程）；依赖 javap 实证清单落盘；Swing/FineUI 红线过一遍。
2. **用户拍板 D2**：架构形态确认（对照架构一页纸）。
3. CP2 通过标准：架构一页纸＋矩阵＋依赖实证三件齐。

## 第 3 步：开发（S3）

1. 一条命令出骨架：`python kfgj/plugin_pl\scripts\sn_scaffold.py --id <ID> --version 0.1.0 --vendor <域> --out <工程根>`（SN-03）。
2. 按 `SN-04~SN-07` 写端点/键归一化/构建脚本/shell 模板。
3. 开发中随时可跑 `sn_gate.py --config <工程>\sn_gate.config.json` 自查（C01-C12）。
4. 无 CP——S3 退出标准＝sn_gate 0 FAIL。

## 第 4 步：自测（S4）→ CP3（最硬的一道门）

1. 走 `SN-08`：单测（合成 fixture＋沙箱隔离）＋e2e＋**G-BROWSER 浏览器路径实测**（attest：起 FR→登录→真浏览器走每个入口，看服务端副作用）。
2. 走 `SN-09`：回归基线落盘（若本版有"默认输出等价旧版"诉求，做字节等价比对）。
3. 走 `SN-10`：生成物结构断言＋目标环境实测 attest（Word→双客户端；UI→截图像素采样）。
4. **用户拍板 D3**：UI/体验验收（截图/录屏/实机）。
5. CP3 通过标准：单测全绿＋e2e 全绿＋两项 attest 留痕＋D3 确认。

## 第 5 步：打包与发布（S5/S6）→ CP4

1. 走 `SN-06` 打包纪律段（jar 顶层目录/白名单清理/先停 FR）。
2. 走 `SN-11`：版本对全等（C07）＋change-notes＋版本协商验证。
3. **用户拍板 D4**：发布窗口（默认：设计器先验证 24h 再上服务器）。
4. 发布后冒烟：核心端点三连＋真浏览器主入口＋版本协商（清单在 SN-11 §11.3）。
5. CP4 通过标准：冒烟全绿＋发布记录含回滚一步话（重装上一版 jar）。

## 第 6 步：归档（S7）→ CP5（终检查点）

1. 跑终闸：`python kfgj/plugin_pl\scripts\sn_gate.py --config <工程>\sn_gate.config.json --report <工程>\_runs\sn_gate_report_<日期>.md`，退出码必须 0（WARN 逐条豁免理由写进报告）。
2. **台账回写**（`SN-12` §12.2）：新问题入 `02_复盘问题台账`；旧问题复发加记录；零复发保持 MITIGATED。
3. **知识沉淀**（`08_知识沉淀判定.md`）：强制定性六选一，定性"是"的按流程落库。
4. 交付记录＋归档件（对齐 AGENTS.md §7 侧车纪律：归档件自含，`_runs/` 关键结论摘录进来）。
5. **用户拍板 D5**：归档范围（哪些进 kit，哪些留工程仓库）。
6. CP5 通过标准：终闸 0 FAIL＋台账/知识/归档三件完成。

## 需要用户拍板的决策点速查

| 决策点 | 在哪一步 | 问题 |
|---|---|---|
| D1 范围与档位 | S1 末 | 做不做远程/跨进程/商业层；"不做"清单确认 |
| D2 架构形态 | S2 末 | 技术选型与依赖集确认 |
| D3 UI/体验验收 | S4 末 | 实机/截图验收 |
| D4 发布窗口 | S6 前 | 何时上真实环境、是否灰度 |
| D5 归档范围 | S7 | 归档产物去向 |

## 常见急转口（出问题时去哪）

| 症状 | 去处 |
|---|---|
| sn_gate 某 C 项 FAIL | `03_标准节点包\SN-03/SN-04/SN-06/SN-11`（按 C 编号查对应节点） |
| 疑似踩了老坑 | 在 `~/.fr_dev_kit/experience/` 复盘台账检索现象关键词 → 命中则按"拦截节点"清单自检 |
| 台账没收录的新坑 | 按 `08_知识沉淀判定.md` 当场定性入台账，别等收尾 |
| 流水线本身有问题 | 在台账加"流水线断点"行并修补（参照 07 报告 §1.2 的两例），版本号 bump |
